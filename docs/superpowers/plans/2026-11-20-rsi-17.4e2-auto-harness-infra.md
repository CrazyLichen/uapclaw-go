**偏差执行口径（spec 已拍板，直接执行不再讨论）：**
- D-e2-1：Python `runtime_extension_merger` 用 `ast.NodeTransformer` 重写 Python import → Go 无 Python AST，用**行级文本解析**（正则识别 `import X` / `from X import Y` 行，语义对齐 `_ImportRewriter` 的改写规则与顺序）。
- D-e2-2：Python `@lru_cache`（gitcode_pr_template）→ Go `sync.Once` / 包级缓存 map。
- D-e2-3：Python pydantic `BaseModel`（runtime_manifest）→ Go struct + `Load*` 校验函数（字段缺失/类型错误返回 error，等价 pydantic ValidationError 语义）。
- D-e2-4：Python `async def` → Go 同步方法；异步语义由调用方（e4 orchestrator）goroutine 化，infra 内部零 goroutine。
- D-e2-5：Python `Model`（foundation.llm.model）→ Go 项目既有 foundation LLM Model 类型；`Optional[Model]` → 指针字段。

**通用实现纪律（每个 Task 适用）：**
- `raise ValueError/RuntimeError(msg)` → `errors.New(msg)`/`fmt.Errorf`，消息逐字照抄（含 f-string 变量位置）。
- dict 字面量键序按 Python 源码出现顺序；`isinstance` 判定 bool 先于 int；默认值逐字段照抄。
- 声明顺序遵守规范 2；注释全中文；包级 `const logComponent = logger.ComponentAgentCore`（子包按既有 rsi 包惯例），Python `logger.warning/info` 逐条同步（对照规则 3）。
- subprocess 命令（git/gh/python/uv 等）一律经 `CommandRunner`；不经 runner 的 spawn 属实施错误。
- 每个 Task 完成即 `git add <本任务文件>`（禁 -am/-A，工作区常有他任务脏文件）+ commit。
