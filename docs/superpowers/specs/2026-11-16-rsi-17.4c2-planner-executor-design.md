## 2. 关键设计点（源码已核对）

### 2.1 action_groups 子包

- **policy.go**：常量三集（ALLOWED_ACTION_GROUPS 5 组 / ALLOWED_OPERATIONS 4 操 / ALLOWED_EXECUTOR_TOOLS 6 工具）+ GROUP_PATH_PREFIXES 表；`ActionPolicyCheck`；`ActionPolicyPrompt()`（提示词模板逐字，品牌键替换）；`FilterActionDefinitions`；`SanitizeAllowedTools`；`ValidateActionPolicy`（约 200 行校验矩阵：config 仅 runtime.yaml、prompt 保护 identity/soul、skill/add SKILL.md 契约、tool/rail 的 yaml manifest 联锁、snake_name 校验等——错误文案逐字）。
- **definitions.go**：`_BUILTIN_GROUP_OPERATIONS` 五组×三操内置定义展开；`LoadActionDefinitions(configPaths)`（符号组名短路 + YAML/JSON 文件装载 + filter）。
- **scheduling.go**：`BuildActionWaves`（depends_on 拓扑排序，环 → ValueError 等价错误）/ `BuildActionWavesFromData` / `BuildWavesFromDepsOnly`（无视 LLM 声明的 action_waves）/ `BuildRoleSubwaves`（声明写路径重叠分组）。

### 2.2 worktree_coordinator.go

- 角色哈希目录（role 名 sha1 前 8 位）；`wt/{role_hash}/i` 整合区 + `wt/{role_hash}/a/{n}/{action_hash}` 手术区；`_validate_worktree_path`（相对、不越界、禁 `current_harnesses`/`current_harness_refs.yaml`/`.publish_tmp`）；legacy 路径回退（`resolve_integration_worktree_path`）。

### 2.3 action_planner.go

- `MemberActionPlanner`（LLM 出单）+ `ActionPlanRejectedError`（反馈耗尽）。
- 外层严审：`_validate_plan_structure`（容器形态）→ 逐 action `validate_action_policy`（action_groups.policy）+ run_if ∈ 3 值 + 每问题最多 3 条手术（`_MAX_ACTIONS_PER_ISSUE`）+ 波次与依赖一致性（以 `build_waves_from_deps_only` 重算为准）。
- 两道护栏：HarnessStructureRail（agents/rails/harness_structure_rail.py 61 行）+ PlannerEvidenceRail（agents/rails/planner_evidence.py 60 行）——**归 agents 包**（Python 同归属），文件归属本子节落地，经 bridge/c2 扩展接入。
- lever 决策：`build_action_lever_decision`（c1 lever.go 已落）绑定每条手术 `constraints.lever_decision`。
- 提示词 `agents/prompts/action_planning.md`（102 行，embed 已在 c1 落）。

### 2.4 action_executor.go

- `MemberActionExecutor` 编排 + `MemberActionExecutorAgent` 单手术执行。
- 波次循环：全局波（拓扑序）→ 角色组（并发）→ 角色内子波（写路径互斥）→ 每手术独立手术区 → 子波合并进整合区（`_merge_subwave`）。
- LLM 手术：声明文件上下文（`_build_declared_file_context` + `_render_file_context` 截断）→ 结构化文件写入（`_apply_structured_file_writes`）→ before/after 快照对比（`_changed_files`）→ 越界改动拦截。
- 确定性手术：`_execute_deterministic_remove` 直接删；`_execute_deterministic_add_scaffold`（tool/rail 代码模板脚手架 `_tool_scaffold`/`_rail_scaffold`）。
- 登记簿同步：技能登记簿（`_sync_skill_registry_for_written_files` + frontmatter 名称规范化 `_normalize_skill_frontmatter_name` + salvage）+ 插件 manifest（plugin_manifest.py 89 行 ⤴️本节）。
- run_if 条件（`_should_run_action`：dependency_succeeded/failed/always）。
- 失败动作落盘 `_write_failed_action_result`；`_validate_generated_action_resources`（生成资源校验）。

## 3. 桥接与依赖

- agents 包 bridge 增 `CreateActionPlanningAgent` / `CreateActionExecutionAgent` 适配器（AttributionAgentParams 扩展或新增 PlannerAgentParams/ExecutorAgentParams——**采用后者**，c1 类型不动，避免破坏既有签名）。
- planner/executor 结构化调用继续走 `agentsBridge.InvokeStructured`。
- schema（c1）已含 MemberOptimizationAction/Plan/ExecutionResult/MergeResult 全量契约。
- harness ChangeVerifier（c3）本节不触碰；executor 产物按 Python 语义落 execution_results.json。
