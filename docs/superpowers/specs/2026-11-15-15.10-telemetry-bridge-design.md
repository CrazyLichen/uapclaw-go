## 1. 在 agent 会话流程中的位置与作用

15.10 是「第三方 CLI 黑盒 → 协议事件」的观测桥，位于 provider 轮循环旁路的可观测性基础设施（best-effort，失败永不阻塞 harness 启动）：

```
宿主 (cli / agent_teams)
  └─ BaseProvider harness 会话（15.5 基座）
       ├─ provider.start → attach observer（15.7/15.8）
       │    └─ 15.10 SharedOtlpReceiver：进程级回环 OTLP 接收器
       │         ↑ CLI 子进程把自身 OTel 导出指向这里（env 注入）
       ├─ begin_turn → observer.begin_turn(emit)
       ├─ 轮循环：SDK 消息流 + OTLP 日志/span 配对 → ModelRequestEvent
       │    └─ tool item 被 hold 到所属 reply 的请求事件发出（因果序）
       └─ end_turn(wait)：终态前结清欠着的请求事件
              └─ 15.2 事件面 → 15.11 轨迹 / 领域二十二 可观测性
```

对应计划原文三点：
1. **第三方模型请求作为协议事件上报（破坏性语义）**：SDK 消息流只有回复没有请求；observation 把 `api_request_body`/`api_response_body` 日志 + `claude_code.llm_request` span 配对成 `ModelRequestEvent`。"破坏性语义" = tool item 被持有到其所属 reply 的请求事件发出为止，重排事件时序以保证因果序。
2. **tool facts 取 provider 自身遥测**：工具执行窗口（`claude_code.tool` span）/成败（`tool_result` 日志）/权限决策（`tool_decision` 日志）合并进 tool item observation。
3. **auth 重试可见**：span 的 `attempt`/`success`/`ttft_ms` 等诊断进 `data["claude-code"]`（`_native_diagnostics`），失败分类器（401/403→auth_required、retryable）依据这些原始遥测。

### 3.1 导出面（对齐 Python `__all__`）

- `OTELResourceSourceID = "uapclaw.harness.source.id"`（见偏差 D-tel-3）
- `SharedOtlpReceiver` 结构体：
  - `Subscribe(callback func(event map[string]any)) (subscriberID int, ok bool)` —— 首次订阅惰性启动；`ok=false` = 已禁用/绑定失败，调用方回落无原生 span 模式（Python `subscribe` 返回 None）
  - `Unsubscribe(id int)`
  - `EndpointURL() string`（`http://127.0.0.1:{port}/v1/traces`，可能为空）；`BaseURL() string`（origin，`rsplit("/v1/")` 等价截断）；`GrpcEndpoint() string`
  - `Aclose(ctx)` —— 关 HTTP/gRPC、排空在途请求（1s 超时后 cancel）、清订阅者、**永久置禁用**（Python `aclose` 语义）
- 包级单例 `GetSharedOtlpReceiver()`（Python `get_shared_otlp_receiver`）

### 3.2 传输层（双门）

| 门 | Python | Go | 裁决 |
|---|---|---|---|
| OTLP/HTTP | `asyncio.start_server` 裸 TCP + 手写解析 | **Go 标准库 `net/http`**（方案①，用户 2026-11-15 拍板） | 偏差 D-tel-2 |
| OTLP/gRPC | `grpc.server` + 生成的 Servicer | `grpc.NewServer` + `go.opentelemetry.io/proto/otlp v1.3.1` 自带 `TraceServiceServer`/`LogsServiceServer` 桩（已核实 v1.3.1 含 `*_grpc.pb.go`） | 一比一，零新依赖 |

- HTTP handler 逐条保留业务校验：仅 `POST /v1/traces` `/v1/logs`（405/404）、Content-Length 校验（400）、`_MAX_REQUEST_BYTES=16MiB`、gzip 有限解压 `_MAX_DECOMPRESSED_BYTES=32MiB`、header 上限（由 net/http 承担，等价 64KiB）、读超时 5s（`http.Server.ReadTimeout`/handler ctx）与写超时 2s（`WriteTimeout`），400/408 语义保持。
- gRPC bind 失败仅 Warn 不致命（HTTP 侧继续服务）；HTTP bind 失败 → 进程级永久禁用（`_disabled`）。
- 解码：`proto.Unmarshal` 到 `commonv1.AnyValue` 等，`WhichOneof` → `GetValue()` 类型 switch；`_decode_spans`/`_decode_log_records` 产出的 `map[string]any` 事件形状（signal/name/start_time_ns/end_time_ns/attributes/resource_attributes/scope_name/trace_id/span_id/parent_span_id/status_code/status_message/time_ns/body 侧的 time_ns）逐字段保留。
- `_fanout`：同步广播全部订阅者，单 callback panic 由 `defer recover` 吞掉记 Warning（best-effort）。
- 在途请求集合：Python `_tasks` → `sync.WaitGroup`；`Aclose` 1s 排空超时后 cancel，语义等价。

### 3.3 订阅者契约（15.7/15.8 实现时遵守）

fanout callback 可能来自任意 goroutine（HTTP handler 或 gRPC worker），**必须非阻塞**；跨线程投递（Python `loop.call_soon_threadsafe`）由订阅者自己解决（channel/事件），见偏差 D-tel-1。
