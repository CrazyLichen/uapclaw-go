## 1. 目标与定位

`HarnessTrajectoryRecorder` 是 **host 侧适配器**：把任意外部 harness provider 的 `HarnessEvent` 观测流，转成与 in-process agent 完全同构的轨迹 OTel span（turn root → inference → tool 三类 span），使第三方 CLI 成员在轨迹查看器中按执行主体（`ExecutionSubject`）归入成员泳道。

**与相邻层的关系**（讨论结论，2026-11-28）：

- **15.10 telemetry 桥**：旁路信道，接收第三方 CLI 自带 OTel SDK 导出的 OTLP（provider 自家词汇表，如 `claude_code.tool` span / `claude_code.api_request_body` log 事件），只做线格式解码 + 分发，不翻译语义。
- **15.7/15.8 observation**：语义翻译层，按 provider 官方公布的事件名匹配（signal=="trace" && name=="claude_code.tool" 等），转成 protocol 的 `ModelRequestEvent` / tool facts。
- **15.11 本体**：主信道，消费**已统一的协议事件流**（15.1/15.2 已落），在 host 侧重放出统一轨迹 span。协议流缺 host 才知道的上下文（用户原文 external_user 标记、宿主 turn 编号、执行主体身份、脱敏、schema 版本），由 recorder 的 `RecordInput`/`RecordTurnIdentity`/构造参数补齐。

**因果归位机制**：provider 在工具 `ItemLifecycleEvent` 信封的 `causation_ids` 写上引发它的 `ModelRequestEvent.request_id`；recorder 记账 `requests[request_id] = (inference_id, step_number)`，工具事件到达时 `_owningRequest` 沿 causation_ids 找第一个命中者，给 tool span 盖 `OJ_INFERENCE_ID` / `OJ_STEP_NUMBER` / `OJ_TOOL_AUTHORITATIVE=true`。查不到主人的工具不盖权威标（查看器契约：标了权威却无法归位的会被丢弃）。

**零生产消费者属预期**（同 15.10 模式）：host 接线点为 Python `agent_teams/external/reliability.py`、`member_runtime.py`、`spawn/external_cli_spawn.py` 三处 `create()` + observe 驱动，对应 Go **⤵️ 15.13 / 15.16**。
