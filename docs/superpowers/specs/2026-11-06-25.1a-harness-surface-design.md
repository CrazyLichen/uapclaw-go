# 25.1a Harness 表面与接口 设计

> 上游对齐目标：`openjiuwen/agent_teams/harness/` 的 **L1→L2→L3 三层**中，把 **L2（NativeHarness）与 L3（TeamHarness）** 落到 Go，并把团队侧流控从"控制器自己跑轮次"切成"订阅驱动"。
> 本 spec 只覆盖 **25.1a**；25.1b（spec 驱动装配）、25.1c（pause/resume + 快照回滚）、25.1d/e/f（异步工具 / turn 身份 / native_v2）另立。
> 状态：2026-11-06 定稿（讨论已逐节确认；结论已登记 `IMPLEMENTATION_PLAN.md` 领域二十五）。

## 1. 概述

### 1.1 一句话

Go 目前**只有 L1**（`DeepAgent` 交互面，9.87 已 1:1 落地），缺 **L2 `NativeHarness`** 与 **L3 `TeamHarness` 协议面**；团队侧由 `StreamController` 自己驱动每一轮（971 行）。25.1a 补 L2+L3，并把 `StreamController` 改成"只订阅、只转播、只映射"。

## 2. 流程位置

```
用户请求 → Gateway → AgentServer → swarm 层
                                     │
                   ┌─────────────────┴──────────────────┐
             单 Agent 路径                          团队路径
       DeepAdapter → DeepAgent            TeamAgent（协调/调度/任务板）
                     │                            │
                     │                    ┌───────┴───────────────┐
                     │             StreamController        其他协调组件
                     │             （转播 + 状态映射）              │
                     │                            │                 │
                     │                    TeamHarness (L3) ◄──────────┘
                     │                            │ 持有 HarnessProtocol
                     │                    NativeHarness (L2)   ← 本 spec
                     │                    ├ supervisor（命令队列，唯一写者）
                     │                    ├ 任务循环内核（PrepareInteractionTaskLoop）
                     │                    └ forwarder（session 流 → 输出队列）
                     │                            │
                     └──────────────► DeepAgent (L1) → ReActAgent → LLM / 工具
```

**关键**：控制与输出是**两条独立通路**，supervisor 不搬输出。

```
① 控制通路（进）   调用方 → control queue → supervisor → 交任务循环内核跑一轮
② 输出通路（出）   session.stream_iterator() → forwarder → 输出队列 → consumer
③ 事件通路（旁路） supervisor → 事件总线 → subscribe(onState, onRound)
```

### 5.2 `HarnessProtocol`（`protocol.go`）

```go
// HarnessProtocol 并发安全的多轮交互契约。
// 契约：所有方法可从任意 goroutine 调用；外部只入队并等应答；
// 状态单写者（supervisor）；订阅回调在 supervisor 协程内同步执行，
// 必须便宜且不可阻塞。
type HarnessProtocol interface {
    State() HarnessState
    SessionID() string
    Start(ctx context.Context, sess *session.Session) error
    Stop(ctx context.Context) error
    Outputs() *OutputIterator
    Send(ctx context.Context, content any, immediate bool) error
    Abort(ctx context.Context, immediate bool) error
    Pause(ctx context.Context) error
    Resume(ctx context.Context, query any) error
    Subscribe(ctx context.Context, onState StateHandler, onRound RoundHandler) error
}
```

- 12 成员**一次性定义**（2 属性 + 10 方法，对齐上游 `protocol.py`）。
- `Pause`/`Resume` 本阶段返回 `ErrPauseUnsupported`（哨兵，`errors.Is` 可判），⤵️ 25.1c 换真实现；接口面不再扩张。
- 事件载荷：`HarnessStateEvent{Old, New HarnessState; SessionID string}`、`HarnessRoundEvent{Kind string; RoundID int; Result map[string]any}`。
- `Kind` 取值：`started` / `finished` / `aborted` / `paused` / `failed`。

### 5.3 `state.go` / `control.go` / `outputs.go`

| 类型 | 本阶段内容 | 推后 |
|---|---|---|
| `HarnessState` | 5 态 `idle/running/pausing/paused/terminated` | `pausing`/`paused` 只定义不产生 |
| `HarnessInternalState` | phase、round 计数、输出队列、supervisor/forwarder 句柄、started/stopping 标记、`ActiveRound` | 快照字段 ⤵️ 25.1c |
| `ActiveRound` | roundID / taskID / 原 query / 取消函数 / steering 队列 / 完成信号 | `preRoundSnapshot`/`lastSafeSnapshot`/`iterPhase`/`turn` ⤵️ 25.1c |
| 控制命令 | `cmdSend{content, immediate, reply}`、`cmdAbort{immediate, reply}`、`cmdPause{reply}`、`cmdResume{query, reply}`、`cmdRoundFinished{roundID, result, reply}`、`cmdStop{reply}` | — |
| `OutputIterator` | 包 `<-chan stream.Schema`；`Next()` 返回 `(chunk, ok)`；`stop` 时投 `END` 一次；**单消费者**契约 | 广播/重连由外层包 |

### 5.4 `NativeHarness`（`native_harness.go`）

**结构**：组合，不嵌入。

```go
type NativeHarness struct {
    agent   *agentcoreharness.DeepAgent
    spec    *atschema.DeepAgentSpec
    st      *HarnessInternalState
    cmd     chan controlCmd
    events  *callback.CallbackFramework
    startMu sync.Mutex
}
```

**为什么组合不嵌入**：
1. 嵌入后 `DeepAgent.Abort(ctx)` 与 `NativeHarness.Abort(ctx, immediate)` 撞名，Go 不允许同名不同签名，而 `DeepAgent.Abort` 已被 `deep_adapter.go`:1517/1533 生产使用，不能改名；
2. 跨包拿不到 DeepAgent 私有成员，嵌入只能复用到"本来就能直接调的导出方法"，收益≈0；
3. 组合后无需任何注入缝就避免"两套 supervisor 同时跑"——只要不调 `DeepAgent.Start`，L1 supervisor 永不启动。

**`Start` 六步**（对齐 `native_harness.py`:348）：

1. 幂等 + 并发守卫（已在跑直接返回）
2. `_prepare`：`agent.EnsureInitialized(ctx)` → 有 `agent_template_spec` 则 `LoadAgentTemplateSpec`
3. 定 session：外部注入 or 自建（自建则 `ownSession = true`，stop 时 `post_run`）
4. `coordinator, controller, err := agent.PrepareInteractionTaskLoop(ctx, sess)` → `controller.BindSession(sess)` → `coordinator.Reset()`
5. 起两条 goroutine：supervisor、forwarder
6. 等 supervisor 抵达首个等待点后再返回（否则调用方 `Send` 会落空）

**supervisor 循环**（对齐 `_supervisor` + `_dispatch`）：

```
for {
    select ctx.Done → 收尾退出
           c := <-cmd
    switch:
      send          : 立即转向（steer 进当前轮） / 排队（follow-up 等本轮结束）
      abort         : 优雅 → 本轮自然收尾；立即 → 取消调度任务（本阶段不做回滚）
      pause / resume: 返回 ErrPauseUnsupported
      roundFinished : 结算本轮 → 决定是否继续下一轮 → 发 round 事件
      stop          : 取消在飞 → 停 controller → 投 END → 退出
    c.reply <- err      // 每条都必须应答
}
```

三条纪律：
1. **唯一写者**：所有状态改动只发生在此协程；
2. **每条命令必须应答**，含 panic 兜底（对齐 `_fail_remaining_commands`）：`defer` 把队列中剩余命令统一回错误，绝不留下永久阻塞的调用方；
3. **订阅回调同步执行**（契约，不是建议）。

**forwarder**（对齐 `_forward_outputs`）：

```
for chunk := range sess.StreamIterator() { outputQueue <- chunk }
outputQueue <- END     // 只在结束时投一次
```

- 从 session 直接读，**不经过** L1 输出租约；
- 整条队列从 start 活到 stop（**多轮共用一条流**）；
- forwarder 崩溃只记日志 + 投 END，不拖 supervisor。

**`subscribe` 复用框架**：`agentcore/runner/callback.CallbackFramework`
- 注册：`fw.OnCustom("harness.state", fn, callback.WithNamespace("native_harness"))`，key 同理 `harness.round`
- 触发：`fw.TriggerCustom(ctx, "harness.state", map[string]any{"old":…,"new":…,"session_id":…})`
- 上游 `enable_metrics=False, enable_logging=False` 的噪声开关在 Go 框架中不存在，无需对齐
- 上游框架会把 kwargs 裁剪到回调声明的参数；Go 无此机制，回调自行按 key 取值

**`run_once`**（对齐 `native_harness.py`:301）：前提 supervisor 未启动（启动了返回错误）；走 `agent.Invoke({"query": content}, sess)`，不建 supervisor、不开流；自建 session 则自己 `pre_run`/`post_run`；结束 `agent.AbilityManager().TeardownTools()`。

**`dispose`**（对齐 `:464`）：`Stop()` + 关 memory managers + 清 session。

**`Outputs`/`Send`/`Abort`**：全部只入队 + 等 reply，无任何状态直读。

### 9.4 覆盖率与门禁

- 项目门禁：**改动行覆盖率 ≥85% / 新增文件同等要求**。
- 风险：`protocol.go`/`state.go`/`outputs.go` 偏声明，可能出现"字段行恒 0%"，且行级豁免对未插桩文件无效（本仓先例）。策略：
  1. 把可测逻辑（`transition`、`OutputIterator.Next`、`END` 处理、事件载荷构造）放进**实现文件**；
  2. 纯声明文件若仍不达标，按本仓既有流程**整文件**登记豁免，本 spec 约定最多豁免 `protocol.go`、`state.go` 两个文件；`outputs.go` 必须靠 `OutputIterator.Next` / END 的用例达标，不予豁免。
- 集成审计：新增目录须通过 `cmd/integration-audit -verify` 两层门禁（调用跨度 ≥3 子系统 / 覆盖交叉验证）。
