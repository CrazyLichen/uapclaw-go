## 1. 概述

### 1.1 一句话

25.1a 把 L2 `NativeHarness` / L3 `TeamHarness` 的表面搭起来了，但**"建脑"的方式仍是临时拼装**：`AgentConfigurator` 手工 new 6 个 rail、手工传给 `BuildTeamHarness`、`BuildTeamHarness` 手工 `AddRail` 6 次、再包成 `NativeHarness`。25.1b 把这套改成上游的 **spec 驱动前向构造**：rail 只在 spec 里**声明**（`RailSpec{Type, Params}`），由 `NativeHarness` 自己 `resolve_parts` → 统一挂载 → `ensure_initialized`。

#### 3.4.1 三个未实现 rail 的声明策略（决策 C8，2026-11-08 定）

**声明 8 个常量，5 个注册真工厂，3 个注册占位工厂。** 目的：`RailSpec` 的 `type` 字符串契约**从第一天就完整**，后续实现时只需替换工厂函数体，不动常量、不动调用方、不动 spec 声明点。

```go
// 三个 rail 的 Go 实现尚未落地。这里注册占位工厂而不是省略注册：
// 常量与类型名是持久化契约（checkpoint 里的 RailSpec.type），先占位
// 可以让后续实现只替换工厂体，不牵动调用方与已持久化的 spec。
// ⤵️ 实现归属见各常量注释。
const (
    TeamReliability   = "core.team.reliability"    // ⤵️ 上游 agent_teams/reliability/ 整个域未迁
    TeamSkillUse      = "core.team.skill_use"      // ⤵️ 25.10（团队技能）
    TeamObservability = "core.team.observability"  // ⤵️ 领域二十二（trajectory v2）
)

// buildTeamReliabilityRail 占位工厂。
// ⤵️ 上游实现：agent_teams/rails/elements.py:365-433 → rails/reliability/rail.py
// 依赖 agent_teams/reliability/{factory,monitor,detectors,remediation,anomaly}.py
// 整域未迁；落地时把本函数体替换为真正的构造即可，签名不变。
func buildTeamReliabilityRail(params map[string]any, ctx hschema.BuildContextInterface) (any, error) {
    logger.Warn(logComponent).
        Str("rail_type", TeamReliability).
        Msg("team reliability rail provider is not implemented; skipping")
    return nil, nil   // 与「未知 type」同语义：跳过但不中断构建
}

// buildTeamSkillUseRail / buildTeamObservabilityRail 同上。
```

**占位工厂的返回值语义**：`nil, nil` —— 与 §5.5「未知 type → warn + `nil, nil`」完全一致。这样：
- spec 里声明了这三个 rail 的成员**不会构建失败**，只是不挂载该 rail；
- 日志有明确的 `rail_type` 字段，能区分“没声明”与“声明了但未实现”；
- 实现落地时把 `return nil, nil` 换成真构造，**一行都不牵动上层**。

**为什么不省略注册**：省略的话 `EnsureHarnessElementsRegistered` 之后表里查不到，`RailSpec.Build` 走“未知 type”分支，日志只能报“unknown rail type”，与“版本回退导致的旧 spec”混为一谈（上游 `:283-290` 的告警就是给这种情况的）。占位注册把两者区分开。

### 5.4 `ConstructionInput` 双源取值（`internal/agentcore/harness/schema/construction_input.go`）

**决策 D3 的落点：tag 驱动 + 显式 Resolve，不走 reflect 通用化。**

```go
// ConstructionInput harness 元素的双源构造输入基类。
// Python: ConstructionInput (harness/manifest/inputs.py:98-130)
//
// 字段用 tag 标注来源：
//   source:"params"   → 读 params[tag 里的 key（默认字段名）]，缺失用 default
//   source:"context"  → 读 ctx 的 attr（或调 resolver），nil 丢弃让 default 生效
type ConstructionInput interface {
    // Resolve 从 params + ctx 取齐所有字段并校验。
    Resolve(params map[string]any, ctx hschema.BuildContextInterface) error
}
```

**为什么不用 reflect**：Go 无 pydantic 的 `model_fields` 元数据遍历 + `**values` 按名构造。用 reflect 需要：① 按 tag 遍历字段；② 类型转换（`any` → 具体类型，含 `[]string`/`*string`/枚举）；③ 未知类型 panic 风险。本项目此前因 reflect 出过问题（`payload-list-typed-assertion-todo-panel` 记忆里的 `toSlice`），且 reflect 的**收益只是省掉每个 input 约 20 行 `Resolve`**。手写更可控。

**辅助函数**（每个 input 的 `Resolve` 用它，避免重复）：

```go

func ParamInt(params map[string]any, key string, def int) int
func ParamBool(params map[string]any, key string, def bool) bool
func ParamStringSlice(params map[string]any, key string) []string
func ParamStringPtr(params map[string]any, key string) *string
```

```go
func (am *AbilityManager) TeardownTools() {
    if am.ownerID == "" {

    }

        if card.Stateless || card.ID != name+"_"+am.ownerID {

        am.Remove(name)
        ids = append(ids, card.ID)
    }
    if len(ids) > 0 {
        _, _ = am.resourceMgr.RemoveTool(ids)
    }
}
```
