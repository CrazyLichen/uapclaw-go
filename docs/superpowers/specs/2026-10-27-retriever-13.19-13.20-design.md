## 1. 背景与定位

领域13 读取侧（检索查询管线 13.19-13.28）首两节。Retriever 是"查"侧的统一门面：把 VectorStore 的三种搜索能力（向量/稀疏/混合）包装成带 mode 校验、结果归一化、BM25 兜底的可编排检索器，供 KB 编排层（13.27/13.28）按 index_type 多态分发。

Agent 会话流程位置（**不在 DeepAgent ReAct 主循环内**，工作流组件链入口）：

```
用户查询 → [工作流图节点] KnowledgeRetrievalComponent (8.25 ⤴️ 依赖 13.26-13.28)
  → retrieve_multi_kb_with_source (13.27 模块级函数)

        ├→ 按 index_type 自动构造：vector→VectorRetriever / bm25→SparseRetriever / 其他→HybridRetriever
        ├→ [agentic 配置] AgenticRetriever 包装 (13.25)
        └→ ★13.19 Retriever 接口★
            └→ ★13.20 VectorRetriever / SparseRetriever★ → VectorStore (13.2/13.3 ✅) → Milvus/Chroma
```

对照写入侧（全就绪）：`KB.add_documents → Parser(13.10-13.16✅) → Chunker(13.5-13.9✅) → Indexer(13.1-13.4✅) → 同一 VectorStore`。

注意两点：
- DeepAgent 侧记忆检索走领域七 memory 体系，与本管线无交集（context_evolver 仅复用 retrieval 的 OpenAIEmbedding）

## 3. 依赖验证结论（讨论期间核实）

- Python retrieval 层 VectorStore **基类无 close()**（base.py L19-147 逐行核对）——三兄弟 close 的 `getattr` 鸭子探测在 Python 是真实防御；Go 13.2/13.3 接口已静态含 `Close()`，探测天然消解
- AgenticRetriever/GraphRetriever **不覆写 retrieve_search_results**（grep 全 retriever 目录仅三兄弟+base 四处定义）——Python 对 Agentic/Graph 调用该"可选 API"返回 None
- 三兄弟 `batch_retrieve` 均裸 `asyncio.gather(*tasks)` 无 return_exceptions（vector L114-120 / sparse L87-93 / hybrid L138-144 逐行核对）；13.25 Agentic 同款（L530-537）
- **chunk_id 双来源不一致**：vector_retriever.py L102 `metadata.get("chunk_id")` vs sparse L76 `result.id` vs hybrid L126 `result.id`——Python 测试三文件均不断言 chunk_id（盲区）
- Vector.Retrieve L65-69 的 155201 分支永不可达（L59-63 的 mode 校验先抛 155200）——死分支
- Sparse.Retrieve 无 score_threshold 校验（L34-80 全文核对，归一化循环无过滤）；Vector.retrieve_search_results 无 mode 校验（L122-161）；Sparse.retrieve_search_results **有** mode 校验（L115-119）——三处不对称字面复刻
- Vector.Retrieve 调 `vector_store.search(query_vector, top_k)` **不传 filters**（L79-82）——kwargs 有 filters 也不透传，字面复刻
- 工厂 store.py 40 行：三分支+else 155402（文案 `unavailable vector store provider: {provider}, and available providers are: milvus, chroma, pgvector`）
- Python 构造参数联合类型：chroma `vector_field: str | ChromaVectorField = "embedding"`、milvus 同款（str→ChromaVectorField/MilvusAUTO 内部转换）——Go 既有构造器已强类型（`*ChromaVectorField`/`MilvusVectorFieldConfig`），工厂层做 str→强类型转换
- Go 既有构造器：`NewChromaVectorStore(config, chromaPath, textField, vectorField *ChromaVectorField, sparseVectorField, metadataField, docIDField string, ...)`、`NewMilvusVectorStore(config, milvusURI, milvusToken, textField, vectorField MilvusVectorFieldConfig, ...)`——chromaPath 空→155400、milvusURI 空→155400、vectorField nil→155109（构造校验链路已就绪）
- vector_fields 包：`NewMilvusAUTO(fieldName)`、ChromaVectorField 构造可用（foundation/store/vector_fields/）；pg_fields.go 先例在（PGVectorField HNSW/IVFFlat）
- 错误码 Go 侧已定义零消费：155200/155201/155202/155203-155211（codes_context.go L105-154）、155402（L189-192）
- Python 三兄弟+工厂**零 logger 调用**（逐行确认）→ Go 零日志对齐
- Python `result.score is not None` 检查：pydantic 必填字段恒非 None → Go float64 无 nil 对应物（语言等价物归档）
- Go embedding 包先例：`embedding.BaseEmbedding` 接口（foundation/store/embedding/base.go L21-37）EmbedQuery/EmbedDocuments/Dimension/DimensionWithContext 四方法

## 4. 类型与接口设计

### 4.1 retriever/base.go

```go
// Retriever 检索器抽象接口。
//
// Python: retrieval/retriever/base.py (Retriever)
// retrieve/batch_retrieve 为抽象方法；retrieve_search_results/close 在
// Python 基类是非抽象"可选 API"（空方法体，裸调用返回 None），Go 接口
// 无默认实现，四方法全进接口（决策 2）。AgenticRetriever(13.25)/
// GraphRetriever(13.23) 届时自行决定是否返回 nil,nil 对齐 Python None。
type Retriever interface {
    // Retrieve 检索文档，返回归一化的 RetrievalResult 列表。
    // mode 零值 "" 时由实现回落各自默认模式（决策 1 已知偏差 §8-1）。
    Retrieve(ctx context.Context, query string, topK int, scoreThreshold *float64, mode RetrievalMode, opts ...RetrieveOption) ([]common.RetrievalResult, error)
    // BatchRetrieve 批量并发检索（裸 errgroup 首错即返回，决策 4）。
    BatchRetrieve(ctx context.Context, queries []string, topK int, opts ...RetrieveOption) ([][]common.RetrievalResult, error)
    // RetrieveSearchResults 检索原始 SearchResult（不归一化）。
    RetrieveSearchResults(ctx context.Context, query string, topK int, mode RetrievalMode, opts ...RetrieveOption) ([]common.SearchResult, error)
    // Close 关闭检索器并释放底层资源。
    Close()
}

// RetrievalMode 检索模式，对齐 Python Literal["vector","sparse","hybrid"]。
type RetrievalMode string

const (
    RetrievalModeVector RetrievalMode = "vector"
    RetrievalModeSparse RetrievalMode = "sparse"
    RetrievalModeHybrid RetrievalMode = "hybrid"
)

// RetrieveOptions 检索选项（Python **kwargs 收纳）。
// 本节 Vector/Sparse 收而不用（对齐 Python 死参数）；
// 13.21 Hybrid 消费 alpha；13.27 SimpleKB 写入 filters。
type RetrieveOptions struct {
    Extra map[string]any
}
type RetrieveOption func(*RetrieveOptions)
```

## 5. 核心流程设计

### 5.1 VectorRetriever.Retrieve（对齐 vector_retriever.py L38-106）

```
 1. mode 零值 "" → RetrievalModeVector（子类默认，决策 1）
 2. mode != vector → 155200 "VectorRetriever only supports 'vector' mode, got {mode}"
 3.【死分支跳过】Python L65-69 的 155201（threshold+mode≠vector）永不可达，归档 §8-2
 4. embedModel == nil → 155202 "embed_model is required for vector search"
 5. queryVector, err := embedModel.EmbedQuery(ctx, query)；err 原样透传（不包装）
 6. searchResults, err := vectorStore.Search(ctx, queryVector, topK, nil)
    【Python 不传 filters——字面复刻：kwargs 有 filters 也不透传给 store.search】
 7. len(searchResults) == 0 → BM25 兜底：searchResults, err = vectorStore.SparseSearch(ctx, query, topK, nil)
 8. 归一化循环（决策 7）：
    for _, r := range searchResults:
        if scoreThreshold != nil && r.Score < *scoreThreshold → continue
          【Python result.score is not None 的 nil 检查在 Go 无对应物，§8-4】
        append(common.RetrievalResult{
            Text: r.Text, Score: r.Score, Metadata: r.Metadata,
            DocID:   metadataString(r.Metadata, "doc_id"),
            ChunkID: metadataString(r.Metadata, "chunk_id"),   ← Vector 从 metadata 取
        })
 9. 返回 results, nil
```

### 5.2 SparseRetriever.Retrieve（对齐 sparse_retriever.py L34-80）

```
 1. mode 零值 "" → RetrievalModeSparse
 2. mode != sparse → 155200 "SparseRetriever only supports 'sparse' mode, got {mode}"
```

### 5.3 RetrieveSearchResults（两实现）

- **Vector**（对齐 L122-161）：仅 embedModel nil → 155202；**无 mode 校验**（字面复刻）；检索同 Retrieve 步骤 5-7（embed→search→空兜底）；**直接返回 []SearchResult 不归一化、不 threshold 过滤**

### 5.4 BatchRetrieve（两实现同构，对齐三兄弟 L108-120）

```go
results := make([][]common.RetrievalResult, len(queries))
var g errgroup.Group                      // 裸 errgroup：不派生 ctx、不 cancel
for i, q := range queries {
    i, q := i, q
    g.Go(func() error {
        res, err := r.Retrieve(ctx, q, topK, nil, "", opts...)
        //  【细节】Python batch_retrieve 不传 mode → 子类默认（Go 传零值 ""）；
        //  score_threshold 不传 → None（Go 传 nil）
        if err != nil { return err }
        results[i] = res
        return nil
    })
}
if err := g.Wait(); err != nil { return nil, err }   // 首错即返回（裸 gather 语义）
return results, nil
```

- 空 queries → `[][]common.RetrievalResult{}` 非 nil 空切片（对齐 Python `[]`）
- Python `tasks` 全启动后 gather；Go goroutine 全启动，首错不阻止已启动者（裸 errgroup 无 cancel，字面一致）

## 8. 已知偏差归档（Go vs Python）

| # | 偏差 | 说明 |
|---|------|------|
| 1 | mode 零值回落 | Python 显式传 `""` → 155200；Go `""` 等同未设回落子类默认。Python 测试与生产无此场景（invalid mode 测试传的都是合法但冲突值） |
| 2 | 155201 死分支跳过 | Vector.Retrieve 的 threshold+mode≠vector 校验永不可达（前置 mode 校验先抛 155200）——13.12 恒真判断先例；155201 留 13.21 HybridRetriever 真实消费 |
| 3 | metadata lax 强转 | Python pydantic v2 lax 模式 non-str 强转 str（如 123→"123"）；Go 类型断言失败→空串。正常数据链路（uuid 字符串）不受影响 |
| 4 | Score nil 检查消解 | Python `result.score is not None` 分支（pydantic 必填恒非 None，防御性死代码）；Go float64 无 nil 对应物 |
| 5 | Sparse 无 threshold 校验 | Python SparseRetriever 收 score_threshold 参数但全文无校验无过滤；Go 字面复刻（opts 收纳不读）。可能是 Python bug 但非修正授权范围 |
| 6 | milvus_alias 死参数 | Python Milvus 构造收 milvus_alias（默认 None）但 Go 既有 NewMilvusVectorStore 无此参数——工厂不引入（Python 侧参数实际被构造器存字段但无消费差异，13.3 实施时已裁） |
| 7 | 鸭子 close 探测消解 | Python `getattr+iscoroutinefunction` 二态探测（retrieval 层 VectorStore 基类无 close，子类各自定义）；Go 接口静态含 `Close()` 直调——语言特性级等价物 |
| 8 | rsr 校验不对称 | Vector.retrieve_search_results 无 mode 校验、Sparse 有——Python 两作者不一致，字面复刻（决策 10） |
