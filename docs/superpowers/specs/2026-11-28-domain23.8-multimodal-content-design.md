## 4. 批2·图片注入链（核心）

### 4.1 数据流（已向用户逐步确认）

1. **入口（adapter，每轮一次）**：invoke 入口 `ExtractMultimodalImageFiles(request.Params)`（对齐 `user_prompt_builder.py:44`）——挑 `type=image` 且 mime 在内联白名单（png/jpeg/webp/gif）的条目，归一化为 `{type, filename, path, mime_type, size_bytes}`；Python 在 set 前 `inputs.pop("_multimodal_image_files")`，Go 同样删键防进模型输入。
2. **ctx 携带（D-23.8-1）**：有图 → `ctx = context.WithValue(ctx, multimodalImageFilesKey, files)`；无图 → 不写 key（rail 读到零值=空）。**语义：袋子每轮一换**——Python set→reset 区间 = 一次 invoke；Go ctx 随 invoke 创建/丢弃，天然等价且无忘清空风险。历史轮注入过的块随会话历史持久化保留，下一轮不重复注入（本轮无图则注入 0 块）。
3. **rail（priority 75，BeforeModelCall）**：开关判定 = 构造显式 `enableImageMultimodal *bool` > `ShouldEnableReadImageMultimodal(agent, nil)`（复用 23.7 四级解析，`rails/multimodal.go`）。
   - **开启路径**：从 ctx 读图片列表 → 非空则向上下文窗口变形器列表（Python `_window_mutators`）注册 mutator；**替换式去重**——先按属性标记清掉旧的多模态 mutator 再挂新的（对齐 Python `ensure_multimodal_image_window_mutator:277` 的清旧逻辑）。日志对齐：`Installed multimodal image context-window adapter for %d image attachment(s)`。
   - **关闭路径**：`StripImageContentFromModelContext(ctx)` 遍历全部消息剥 image 块；content 全剥光 → 置 `IMAGE_CONTENT_OMITTED` 对应常量（协议字符串不本地化）；有剩余文本块 → 合并为单个文本段。日志对齐：`Removed %d image content block(s) from chat-model context`。
4. **mutator 执行（组装窗口时）**：`PrepareMultimodalImageMessages(window.ContextMessages, files)` → 定位**最后一条 user 消息** → 每张图读文件 → base64 → `data:image/<mime>;base64,…` URI → content 变为 `[{text: {"query":…,"file":[{filename,path,mime_type}]} JSON 文本块}, {image_url 块}×N]`；原 content 为纯文本时同样转 parts 结构（对齐 `_append_image_files_to_content`）；窗口对象做值拷贝（对齐 Python `model_copy(update=…)`）。

### 4.2 `_window_mutators` 挂点（spec 预留槽位）

## 6. 批4·video_gen（视频生成与聊天交付）

### 6.1 两个工具

- `generate_video`：提交 → 同步轮询（10s 间隔、上限 120s）→ 到期未完返回 "Video job \<id\> submitted and still \<status\>"，让 Agent 转调 `check_video_status`；时长域 4–15s（MiniMax-H3 下限抬至 5s）。
- `check_video_status`：受限轮询；返回终态或 "Video job \<id\> is still \<status\>"。
- 终态集合：completed/failed/cancelled/expired；直接 OpenRouter 式路径 + `gen_toolkits` 多后端分发结构一并对齐。

### 6.2 盯单 goroutine（对齐 Python 结构，启动位置一一对应）

- 触发：两工具自身轮询窗口到期且非终态 → 在**工具闭包内同一调用点**起 goroutine（对齐 Python 协程启动位置）。
- 参数：20s 间隔、上限 30 分钟；job_id 集合（map+`sync.Mutex`，D-23.8-2）防同一单重复起盯单。
- 终态交付：完成 → 提取 `Saved to: (.+?)\n`；失败 → 命中 `^\[ERROR]: video job \S+ ended with status \w+` → `SendRuntimePush`（对齐 `send_runtime_push`，Go 既有 push 链入口实施时核对）→ payload 经 `AnnotateChatFinal` 补 `final_mode=append`（已有显式值不覆盖）。
- 30 分钟仍未终态：放弃 + 日志。会话 ctx 取消 → goroutine 退出；panic → recover + Error 日志。
- 正则 `_PENDING_JOB_ID_RE`（`^Video job (\S+) (?:submitted and still|is still) \w+`）用于识别 pending 形状、防重复交付，一比一移植。

### 6.3 chat_final 协议

`jiuwenswarm/common/chat_final.py` → `internal/swarm/common/chat_final.go`：三个 `final_mode` 常量（patch_segment/replace_turn/append）+ `AnnotateChatFinal`（仅 chat.final payload、不覆盖既有值）。若 Go 已有等价物则并入并删旧（规则 8）。

### 6.4 配置与权限

- 独立 `VIDEO_GEN_{API_KEY,API_BASE,MODEL_NAME,PROVIDER}` 槽，三样必填（自部署 vLLM-Omni 只需 URL）；与批3"视频模型槽"两套独立配置，无内置默认端点。
- 权限钩子：Python `RootDecisionContext` → 对齐 auto_permission 既有上下文注入点。

## 7. 错误处理

- 配置不完整 → 工具不注册 + 装配 Warn（对齐 `complete_multimodal_model_configured` false 行为）。
- 图片读取失败（路径不存在/mime 超白名单）→ 单张跳过 + Warn；全部失败 → 只留原文本不注入。
- HTTP 失败/超时 → Error 日志含 `event_type=LLM_CALL_ERROR`、`method`、`model_provider`、`.Err(err)`（规则 3.4）；video_gen 端点失败按失败终态交付。
- asyncio→Go 常规偏差：模块级共享集合加锁（D-23.8-2），已用户确认方向。
