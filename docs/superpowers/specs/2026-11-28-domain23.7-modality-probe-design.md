## 1. 背景与作用

Agent 会话链路中，当工具（read_file/浏览器/skill 提示词等）拿到图片时，需要知道「当前模型能否接收原生图片输入」。配置不一定声明、声明也不保证正确，猜错代价不对称：给盲模型塞图=请求报错；对能看图的模型只给文字描述=Agent 丧失视觉。23.7 的作用是在正式干活前确定该结论并全局共享，23.8/23.9 是其下游。

## 3. Go 侧现状与缺口

- `EnableReadImageMultimodal`：`harness/schema/config.go:250` 为非指针 `bool` 默认 true——**漂移**：Python 是 `Optional[bool]=None`（None=auto→声明/探测），本批改 `*bool`，删除默认 true 回填（`config.go:440` 与 config_test 相应断言）。
- `supports_vision` 字段、探测器、缓存、预热、热重载：**全缺**（grep 零命中）。
- 已具备前置：`RouterScope *string`（`schema/config.go:114`，Python router_scope 对应）、intellirouter 路由缓存。
- sys_operation rail 的 `enableReadImageMultimodal *bool`（rails/sys_operation.go:29）推断逻辑需改接 `_multimodal` 解析链。

## 5. 已知偏差登记（唯一出口，均需对齐 asyncio↔goroutine 语义）

1. **单 loop 生命周期差异**：Python「探测 task 随一次性 loop 死亡→永远无结论」的边界场景在 Go goroutine 不存在（goroutine 不随 loop 死）。warmup docstring 的两条动机中「code adapter 一次性 loop 取消探测」在 Go 侧天然不成立，「子代理补发杂散探测」仍然成立——预热仍需实现（对齐触发点与行为，偏差仅在动机半条失效），登记为平台差异。
2. **`enable_read_image_multimodal` 类型修正**：Go `bool(true)` → `*bool(nil)`，属既有漂移修复而非偏差。
