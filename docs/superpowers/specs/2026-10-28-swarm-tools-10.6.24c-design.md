## 1. 目标与流程位置

10.6.24 Swarm 内置工具集 c 子节——会话级工具：

1. **MultiSessionToolkit**（agent.fast 快速模式）：并行子代理执行。LLM 调 `session_new(task_descriptions)` 为每个任务 spawn 一个子 ReActAgent 并发执行；子任务完成/取消/异常通过 `chat.session_result` 推送前端（SubtaskStatus 实时进度）；全部完成后自动触发一次汇总 agent 回答并以 `chat.final`（is_complete=true）收尾。生命周期：从创建新 session 到所有协程结束。
2. **user_todos**（code 模式）：管理**用户本人的**待办/日程（会议、提醒、计划），与内部任务规划的 todo_create 严格区分（工具描述显式声明）。按 channel 隔离、markdown+YAML frontmatter 持久化于 `{agent_workspace}/memory/user_todos/{safe_cid}.md`。

依赖盘点结论：**全部就绪，无需提前实现其他章节、无换章节必要**——Runner.RunAgent/RunAgentStreaming（agentcore/runner）、ReActAgent+ReActAgentConfig（agentcore/single_agent，Config 含 ModelClientConfig/ModelRequestConfig）、24a GetMcpTools、24b 注入先例（SetSendFilePushFunc）、AgentManager.GetAgentNoWait（空参→default channel 优先 mode="agent"）、EventTypeChatSessionResult/EventTypeChatFinal（web 白名单已含）、team 白名单 "user_todos"（runtime_inheritance.go:112，10.6.19 已带出）、tool.NewMapFunction 构造（skill_toolkit 先例）。

Go spawn 子进程机制（agentcore/runner/spawn）与 MultiSessionToolkit **无关**：Python 侧前者走 Runner.spawn_agent 独立进程（jiuwenswarm 仅 remote_member_bootstrap 使用，10.6.21 未实现章节），后者是进程内 asyncio 协程。Go 对应映射为 goroutine + ctx.CancelFunc。

### 3.2 notify 推送与汇总链数据流

```
notify(ctx, sessionID, status, result, errStr)
  ① pushFunc==nil → warn "[MultiSessionToolkit] sendPushFunc not injected, skip notify" + return
  ② 读 sessions（RLock）：description=匹配项/""，index=第一个匹配下标+1，total=len(sessions)
  ③ payload_status：COMPLETED→"completed"（message=result or ""）；
     否则→"error"（CANCELLED 时 message=errStr or "任务已取消"；ERROR 时 message=errStr）
     对齐 Python: message = error or "任务已取消" if status == CANCELLED else error
  ④ msg = {"request_id": t.requestID, "channel_id": t.channelID, "session_id": t.sessionID,
     "payload": {"event_type": "chat.session_result", "session_id": 子sessionID,
                 "description": description, "status": payloadStatus, "index": index,
                 "total": total, "result": message, "is_parallel": true},
     "is_complete": false}
  ⑤ pushFunc(ctx, msg) → err 时 Warn 继续不中断
  ⑥ allTasksDone() 为真且 sumOnce.Do 进入汇总（sync.Once，第二个并发完成者自动跳过）：
     - summaryCtx = context.WithoutCancel(ctx)（父请求 ctx 可能已结束/取消，汇总是独立执行）
     - agentProvider()==nil → Error 日志 + return（见 §7 偏差#4）
     - 汇总文本："后台会话任务均已完成：\n" + 每项 "\nsession_id: {}\ndescription: {}\nresult: {}\n"
     - inputs = {"conversation_id": t.sessionID,
         "query": json.Marshal({"source": "system", "content": summary, "type": "notify"})}
     - RunAgentStreaming(summaryCtx, ByAgent(agent), inputs, **空 SessionRef**（同上，conversation_id 从 inputs 取——Python `run_agent_streaming(server.get_agent(), inputs=inputs)` 亦不传 session；该调用路径的注释说明用 streaming 正是为让 session.post_run() 持久化历史）, nil, nil, nil)
     - 聚合 chunk（§3.3）：accumulated []string、finalOutput *string
     - result = {"output": final or join(acc), "result_type": "answer"}
     - msg2 = {"request_id", "channel_id", "session_id": t.sessionID,
         "payload": {"event_type": "chat.final", "task_id": t.sessionID, "content": result},
         "is_complete": true}
     - pushFunc(summaryCtx, msg2)
```

### 3.3 stream.Schema 聚合适配（偏差#1）

Python `_run_and_notify` 汇总块消费 chunk：`hasattr(chunk, "type")` / `hasattr(chunk, "payload")` 守卫 + `chunk.type == "content_chunk"` / `"answer"` 双分支。Go 的 `stream.Schema` 是接口（OutputSchema/TraceSchema/CustomSchema 三实现），适配：

- `OutputSchema`（有 Type/Payload 字段）→ 直接判 `.Type`
- `CustomSchema`（有 Type/Data 字段）→ 判 `.Type`，payload 从 Data 取
- `TraceSchema`（无 Type 消息语义）→ 跳过（对齐 `not hasattr(chunk, "type")` continue）
- content_chunk：`payload["content"]` 非空 append；answer：`payload["output"]` 三态（map 且 map["output"] 非空字符串→取之；否则非 nil 标量→fmt；nil→accumulated fallback，acc 空则 ""）

### 3.4 并发与注入（决策记录）

- **并发模型**（方案A 定案）：goroutine + context.CancelFunc。每任务派生 WithCancel ctx；cancel_session 调 cancel + wg.Wait；取消传播靠 ctx 到 RunAgent（heartbeat 11.11 已验证 Canceled≠failed 语义）。
- **子任务 ctx 基座**（自审补充，偏差#7）：Python asyncio.Task 独立于请求生命周期（session_new 的工具调用返回后子协程继续跑）。Go 侧子任务 goroutine 的 ctx **不能直接用工具 Invoke 收到的请求 ctx**（请求结束/中断时 ctx cancel 会杀死后台子任务）——用 `context.WithoutCancel(请求ctx)` 作基座再 WithCancel 派生：既保留 ctx values（RuntimeCronContext 等），又切断父请求的取消传播；取消仅来自 cancel_session 的 CancelFunc。汇总链同样 WithoutCancel（§3.2 已定）。
- **注入链**（方案A 定案，24b 先例）：包级 `SetSessionPushFunc(fn func(ctx, map[string]any) error)` + `SetSessionAgentProvider(fn func() agentinterfaces.BaseAgent)`。agent_server.go 两行接线：
  ```go
  swarmtools.SetSessionPushFunc(s.SendPush)
  swarmtools.SetSessionAgentProvider(func() agentinterfaces.BaseAgent {
      u := s.AgentManager().GetAgentNoWait("", "", "", "")
      if u == nil { return nil }
      return u.GetInstance()   // *harness.DeepAgent，实现 interfaces.BaseAgent
  })
  ```
- **汇总链并发安全**（方案A 定案）：`sumOnce sync.Once` 保证"触发 all_tasks_done 从 false→true 的那一个"协程独占汇总（Python 靠 GIL+协程原子性）；汇总执行用 `context.WithoutCancel`。
- **工具实例生命周期**（方案A 定案，逐字对齐）：updateToolsForMode 每次移除三张卡→新建 toolkit→注册新卡；**旧 toolkit 的运行中 goroutine 不取消**（Python 泄漏式设计，跑到自然结束；notify 仍走包级 pushFunc，只是旧 sessions 状态不再被新实例看到）。

## 6. 错误处理与降级矩阵

| 场景 | Python | Go |
|---|---|---|
| push 失败 | send_push 内部 try/except warn | pushFunc 返回 err → Warn，notify 不中断 |
| 推送函数未注入 | MessageHandler RuntimeError → warn+return | pushFunc==nil → warn+return |
| 子协程异常 | except Exception → ERROR+notify+re-raise | defer recover → ERROR+notify；goroutine 退出等价 |
| 取消 | CancelledError → CANCELLED+notify+re-raise | errors.Is(Canceled) → CANCELLED+notify；goroutine 退出等价 |
| 汇总 agentProvider nil | get_agent None → run_agent_streaming 抛异常 → notify 内无 try/except → 冒泡到 _run_and_notify except → 二次 ERROR notify | **nil 守卫 + Error 日志 + return**（偏差#4：不对齐 Python 的二次 notify error 行为——该路径是 Python 的 bug 性行为，Go 侧更稳） |
| 汇总 RunAgentStreaming err | 同上冒泡链 | err → Warn 日志，不推送 chat.final（偏差#4 同源决策） |
| user_todos 异常 | 整体 try/except → success:false | defer recover + err → `{"success": false, "error": ...}` |
| AddTool 重复注册 | add_tool 重复时 Result 内含 exception（不抛出，静默失败） | **直接 AddTool 不判存**（对齐 Python：multi_session_toolkits.py L2960 `Runner.resource_mgr.add_tool(ms_tool)` 裸调、无 get_tool 判存——Python 重复注册静默失败，Go AddTool 返回 "工具已存在" err 时忽略即可，行为等价）；与 cron/send_file 的判存模式不同是有意差异（那两处 Python 源码确实有 get_tool 判存） |
| 旧 toolkit 重复注册 | 移卡+新建，旧协程放跑 | 同（3.4 生命周期决策） |

## 7. 偏差归档（11 项）

1. **stream.Schema 聚合适配**：Python chunk 对象 hasattr 判定 → Go 接口三态类型断言（OutputSchema/CustomSchema 判 Type，TraceSchema 跳过）。必要等价。
2. **parseTodosFile 正则**：Python lookahead 正则 RE2 不支持 → Go 手动逐行状态机，产出一致。必要等价（24a 先例手法）。
3. **params 转换**：Python dict→UserTodosParams dataclass 容错转换 → Go 直接 map 取键（零值默认天然等价）。简化等价。
4. **汇总 agentProvider nil / 汇总 err**：Python 冒泡到 except 链产生二次 ERROR notify → Go nil 守卫/err 日志直接 return。**有意偏差**（Python 该路径为 bug 性行为）。
5. **user_todos channel 绑定**：Python 两处 set contextvar（初始化 + 每请求）→ Go 仅 Invoke 时读 ctx（BindRuntimeCronContext 已覆盖运行期全部读取时机；初始化 set 在 Go 无对应时机但语义等价——首请求必经 ProcessMessage 绑定）。简化等价。
6. **时间解析格式**：Python `datetime.fromisoformat`（多格式宽容）→ Go `time.RFC3339`（最接近等价）；解析失败两侧行为一致（→""）。
7. **子任务 ctx 基座**：Python asyncio.Task 天然独立于请求生命周期 → Go 子任务 goroutine 用 `WithoutCancel(请求ctx)`+WithCancel 派生（保留 values、切断父取消传播）。必要等价（Go ctx 树形取消语义与 asyncio Task 独立性的差异）。
