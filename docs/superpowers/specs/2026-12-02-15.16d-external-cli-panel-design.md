## 0. 在 Agent 会话中的流程位置与作用

15.16「团队集成」拆 a–e 五个子章节：a（成员事件循环 ✅）、b（spawn 编排主体 + team-mcp ✅）、c（平台 seed 工厂 ✅ 已推未合）、**d（本节）**、e（experts 回填）。

d 建的是「用户如何在配置面板上**决定**哪些外部 CLI 成员存在、用哪个二进制、leader 能挑哪些模型」。三条消费链：

1. **团队装配链**（本节内闭环）：保存配置时探测 CLI 上报模型清单并存报告（`runtime/external-cli-models.json`）；装配时 `apply_reported_models` in-place 修正 entries 的 `builtin_models`；`_ensure_external_team_transport` 给 spec 挂 hybrid transport（web/tui publish URL），接通 15.16b 已交付的两端（成员侧 stdio server + hybrid messager ↔ gateway `team.mq.publish` 中继）；
2. **spawn 模型选择链**（本节内闭环）：`spawn_teammate` 的 `builtin_model`/`model`/`effort` 参数 → `plan_external_model` 校验解析（互斥/池过滤/目录校验/effort 限集）→ `ExternalCliModelConfig` → `ModelChoice` 经 adapter 传给 provider；
3. **15.18 会话接入链**：`_merge_host_external_cli_config` 读面板 `external_cli_agent_*` 扁平键（本节先落键投影，18 消费）。

### 0.1 三角色模型（对齐讨论结论）

| 角色 | 存哪 | 谁写 | 谁读 |
|---|---|---|---|
| **策略**（builtin_models 目录） | config yaml | 用户手写 / refresh 播种自定义条目 | 前端 config.get 展示（始终展示声明目录，事实不展示，漂移只进日志） |
| **事实**（CLI 上报清单） | `runtime/external-cli-models.json` | 保存时探测 | 只在装配时消费 |
| **对拍** | 不落盘 | 保存时（仅警告）+ 装配时（in-place 修正） | spawn 用修正后目录 |

### 0.2 dsh 能力声明（讨论核实，两侧对齐）

dsh `capabilities = {MCP_TOOLS, ENDPOINT_MODELS}`（Python harness.py:53 / Go harness.go:28），未声明 `MODEL_DISCOVERY`：

- spawn 主链路 ✅（15.13/15.16a/b 已交付，不依赖 catalog）；
- `model` 池路径 ✅（ENDPOINT_MODELS：模型跑我们自己的团队模型池端点，端点+凭据经 plan → ModelChoice → provider）；
- `builtin_model`/`effort` ❌（无目录可挑，工具侧明确报不可用）——**dsh 上游能力声明决定，不是移植缺口**；将来 dsh 声明 MODEL_DISCOVERY 后探测链自动覆盖。
