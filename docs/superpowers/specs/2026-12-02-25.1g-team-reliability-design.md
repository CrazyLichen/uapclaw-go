## 1. 上游范围与流程位置

上游 `openjiuwen/agent_teams/reliability/`（15 个 py 文件，~2,162 行：核心 10 文件 1,283 + detectors 681 + remediation 149）。

**机制定位**：团队的「医疗监测系统」。每个成员的 DeepAgent 上挂一条低优先级 rail（priority=5，跑在行为 shaping rail 之后），采集生命周期信号；成员进程内 detector 判定异常；分层 remediation 策略把异常路由为三类出口：

| 出口 | 触发条件 | 路径 | 过 supervisor |
|---|---|---|---|
| ① 本地 steer | 策略含 LOCAL_STEER（强度预算内） | rail → LocalAutoRemediator → ctx.push_steering → 本轮下一模型调用边界 drainSteering 消化（**轮内自愈**） | 否 |
| ② 上报 leader | 策略含 REPORT_LEADER/ESCALATE_USER | EventAnomalyReporter → messager TEAM topic → leader kernel → dispatcher → ReliabilityHandler → deliver_input | 是 |
| ③ leader 自检 | 异常者是 leader 自己 | LocalAnomalyReporter → 本地 sink（绑定时直调，绕过 self-filter） | 是（sink 直调，不走 messager） |

**信号管线**（已逐行核对，与既有 coordination 设施吻合）：
rail 钩子 → Signal（值对象，不出成员进程）→ ReliabilityMonitor.feed（扇出全部 detector，坏 detector 隔离跳过）→ Anomaly → RemediationPolicy.actions_for(severity) 查表分流。

**leader 侧 handler**：`ReliabilityHandler`（消费 ANOMALY_DETECTED / MESSAGE / BROADCAST；`on_message` 喂团队级 PingPongDetector——成员间互踢皮球只有 leader 能看见全貌；route notice 按 `(pinned_model, deployment_id, reason, status_code)` 去重）+ `ExternalRuntimeHandler`（消费 EXTERNAL_RUNTIME_RETRYING，SDK 重试中进度通告，恒注册，leader-only 守卫；终态失败不在此处理，走 15.13 已落的 external_runtime_failed 信箱消息）。

**注册时机**（上游 dispatcher.py:258-286）：`EventDispatcher.__init__`（kernel.setup 阶段，每成员进程各一个 dispatcher；ReliabilityHandler 仅 `spec.reliability.enabled` 时创建，ExternalRuntimeHandler 恒建）。handler 列表顺序：既有 7 个之后 append reliability（非 nil 时），external_runtime 恒最后——与上游一致。

**本地 sink 绑定时机**（上游 team_agent.py:807 `_register_reliability_local_sink`）：DeepAgent 建完 + dispatcher 存在后；多重守卫（reliability 未启用 → dispatcher.reliability 为 None → no-op；非 leader 成员 rail 无 LocalAnomalyReporter → find_rails 空转）使其实际只对 leader 生效。

**不进本批**（边界）：
- `external/reliability.py`（430 行）+ `schema/external_runtime_reliability.py` 发布侧 ⏵ 15.7/15.8（D-15.13-m 已登记范围）；
- `EXTERNAL_RUNTIME_RETRYING` 事件的发布方 emit ⏵ 15.7/15.8；
- 17.4d 的 single_harness 消费侧接线（本批只保证占位工厂收窄后可被调用）。

## 3. 关键实现决策

### D1 rail 挂载与钩子映射
继承 `BaseRail`，**priority=5**；7 钩子映射 `AgentRail` 既有事件（OnUserMessage / BeforeModelCall / AfterModelCall / BeforeToolCall / AfterToolCall / OnToolException / OnModelException）。本地纠偏调 `AgentCallbackContext.PushSteering`（callback.go:690 已有）。**必须覆盖接口方法 `GetCallbacks()`**（不得定义成 `Callbacks()`——15.5 实锤的静默失效陷阱）。

### D2 稳定哈希复刻
`stable_call_hash` / `stable_result_hash`：Go 标准库 `encoding/json` 对 map 递归按键排序，与 Python `json.dumps(sort_keys=True)` 天然等价；非可序列化值以 `fmt.Sprintf("%v")` 兜底对齐 `default=str`；`stable_result_hash` 三分支优先序（str 原文 / ToolOutput / str 兜底 / None→"none"）逐分支映射。**序列化一律 struct json tag 直接走 `encoding/json`，禁止手写独立 marshal/unmarshal 包装层**（2026-12-02 用户拍板）。验收：与 Python golden 对拍（gen_golden.py 手法，字节级一致）。

### D3 model_failure 提取
`exception.BaseError.Details()` 已携带 routing/errors.go:202 的 `route_case/reason/pinned_model/failures/usable/status_code` 全套字段（字段名与上游逐字一致）。Go 提取函数沿 `errors.Unwrap` 走错误链，对齐上游 `_MODEL_FAILURE_FIELDS` 6 字段白名单，`failures[0]` 为触发记录。零新依赖，纯读取。

### D4 route notice 去重
`map[routeNoticeKey]struct{}`，key 为定长 struct `{pinnedModel, deploymentID, reason, statusCode}`（避免 any 键比较陷阱）；`_pending_route_notices` 普通切片 + take 清空。无锁（单 supervisor 消费线程，偏差 D-g1 登记）。

### D5 事件 payload
typed struct + json tag 对齐上游 snake_case；`EventMessage.GetPayload()` 按 union 惯例补注册分支；`evidence map[string]any` 保持上游自由形状不收窄（结构忠实）。测试断言遵守 `InterruptIDsOf` 式兼容（不硬断言 `[]string`）。

### D6 detectors 并发模型
无锁（偏差 D-g1 登记：asyncio 单线程 → Go 单 supervisor 协程序列化，语义等价）。

### D7 config 装配
`ReliabilityConfig` struct + 默认值函数（enabled=False 总门卫；5 个 detector 子配置默认 enabled=True、阈值逐字段对齐 pydantic 默认）。dispatcher 构造点严格对齐 dispatcher.py:258-286。

### D8 本地 sink 绑定
装配尾（`_register_team_completion_callbacks` 等价点之后）：`find_rails(ReliabilityRail)` → `BindLocalSink(handler.HandleLocalAnomaly)` + `BindRouteNoticeSource(handler.TakePendingRouteNotices)`；未启用/nil dispatcher 时 no-op（多重守卫对齐）。

### D9 route notices 前插
rail 的 OnUserMessage 读 `ctx.Inputs.Parts`（25.0a 已落 `UserMessageInputs.Parts`），`notices[0:0]` 前插语义复刻；前插失败只告警（notices 已取出，下一 notice 搭下次输入）。

## 4. 测试策略

- **单测**：window 边界驱逐；稳定哈希；6 detector 四档递进各档边界（edge-triggered 只升不降 / reset）；monitor 扇出隔离；remediator 强度预算（第 6 次拒发 + MODEL_UNAVAILABLE/MODEL_ROUTE_NOTICE 不 steer）；policy 表；route notice 去重；leader 守卫（非 leader 恒 return）；
- **golden 对拍**：稳定哈希 + summary 渲染，gen_golden.py 手法调上游真跑；
- **集成**（`tests/integration/agentteams/reliability/`，≥3 子系统过审计）：
  1. 成员内链路：MockLLM 驱动重复同参工具 → TOOL_CALL_LOOP → 本地 steer → 模型输入含纠偏文案；
  2. 跨进程上报：EventAnomalyReporter publish → leader 收 ANOMALY_DETECTED → deliver_input → leader 轮次收到 `[HIGH] coder: ...` 摘要；
  3. leader 自检：本地 sink 绑定绕过 self-filter；
  4. route notice 去重：两成员同 deployment 失败只通告一次；
  5. config 未启用全链 no-op（回归保护）。
- **既有回归**：elements.go 换真身不破坏 rail 装配测试；17.4a runtime_reliability_test.go 改断言新签名。
