### 0.1 分层与数据流（与用户对齐的三层模型）

```
CLI 子进程 stdout / SDK 通道               ← 源
   │ provider（SerializedTurnHarness 子类，15.5/15.6/15.9 已移植）
   │ 解析成 HarnessEvent 信封 → BoundedEventBuffer
   ▼
HarnessIOAdapter 消费循环（io_adapter.go:757 处调 EventObserver）
   │ 每信封先调 EventObserver ★ 本节泵挂在这里
   │ 再投影成 OutputSchema 块 → outputs 队列
   ▼
onEvent（= Python _on_event，member_runtime.py:676）一个入口，四个汇：
   ① OnState/OnRound 回调（subscribe 面，Go Subscribe :548 已有）
      → 成员 TeamAgent 壳：状态机 + StreamController 转发 round 给 leader
      （Python 消费者：stream_controller.py:316 / external_turns.py:175 / avatar_session_backend.py:985）
   ② activitySink → AGENT_ACTIVITY 结构化事件 → leader 成员活动面板
   ③ trajectory recorder → record_turn_identity + observe → OTel span（15.11）
   ④ reliability ctx → finalize_failure / publish_retrying → leader 信箱 ERROR（15.13 缝）
```

命名说明（对齐用户疑问的裁决）：`OnEvent`（`_on_event`）是**输入侧**原始信封入口，只有 runtime 自己消费；`OnState/OnRound`（`_EVENT_STATE/_EVENT_ROUND` → `subscribe(on_state, on_round)`，member_runtime.py:658）是**输出侧**成员语义事件，命名照抄 Python 两层，不合并为一个 OnEvent。
