## 1. 流程位置与作用

显式缓存作用于每次模型调用的**两端**：

- **写链（本节主体，Go 全缺）**：请求出网前，在 `_build_request_params` 末尾（Python :1083）调用 `_apply_openrouter_profile`（:1087-1161）。当 endpoint profile 为 `openrouter` 且模型 provider 前缀属于显式缓存支持集合时，在 `tools` 尾块、`messages[0]`、最长公共前缀尾消息、`messages[-1]` 上打 `cache_control: {type: "ephemeral", ttl?: "1h"}` 标记。OpenRouter 透传给底层 provider（anthropic/qwen）做显式 prompt 缓存，命中部分按缓存读计价（约 1/10 原价），降低 ReAct 多轮循环的重复前缀成本与首 token 延迟。
- **读链（Go 已交付，本节只核对）**：响应解析处（:2824/:2941）把 provider 各异字段形态归一为 UsageMetadata 的 cache 读/写/miss token。Go `model_clients/usage_extract.go` 已一比一复刻（`_extract_cache_tokens`/`_cache_usage_metadata`/`_extract_cache_creation_tokens`，Python base_model_client.py:86/152/253），含测试。

实例状态 `_previous_openrouter_prompt_cache_messages`（:455）与 client 同生命周期，跨轮次保留——上一轮 messages 的深拷贝留作下一轮最长前缀 diff 的基线；缓存是前缀匹配，标记必须打在"分叉点"收益最大。

- Responses API 分支不插（Python :1876-1880 Responses 分支在 `_build_request_params` 之前返回，本就不经过）。

`applyOpenrouterProfile` 方法体按 Python :1088-1161 逐步复刻：

1. profile 非 `openrouter` → 直接 return（注意：Python 此分支**不重置** previous_messages）。
2. `enableOpenrouterExplicitCaching == false` → 置空 previous_messages 并 return。
3. 模型不支持显式缓存 → 两条 warning 日志（显式缓存不支持 + 若开启 1h TTL 再补一条），置空 previous_messages 并 return。
4. prefix matching 开启：取 previous_messages 并深拷贝存本轮 current；否则 previous 置 nil、previous_messages 置 nil。
5. `messages` 与 `tools` 深拷贝后再改写（避免污染调用方结构，Python deepcopy 对齐）。
6. 计算 `enable1HTTL`（开关开 && provider 支持），开关开但不支持时补 warning。
7. 调 `applyOpenrouterPromptCacheControl`。

日志对齐规则 3：llm_logger.warning → `logger.Warn(logComponent)`，字段 `model_name` / `model_provider` 带上。
