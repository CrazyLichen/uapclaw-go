## 集成验收硬要求（用户强调）

集成用例必须**验证团队真的收到了消息**，不能只断言发送侧：

1. **失败消息入信箱**：外部成员轮失败 → 断言 leader 信箱/消息表中真实出现
   `external_runtime_failed` JSON 消息（from=成员、to=leader、protocol=json、
   内容可反序列化为 ExternalRuntimeFailure 且 failure_id/category/phase 正确）；
2. **leader 可消费**：消息经 MessageHandler 交付进 leader 轮输入（对齐 Python
   `MessageHandler` 交付链），断言 leader 的轮输入/会话状态里可见该失败内容；
3. **成员状态翻转**：启动失败/任务异常退出路径断言成员状态翻 ERROR（经
   update_status_cb 真实落库，非 mock 断言回调被调用）；
4. **exactly-once**：同一次尝试重复触发 finalize 后信箱仍只有一条失败消息；
5. **retrying 进度事件**（可实现范围内）：messager publish 路径断言团队 topic 收到
   ExternalRuntimeRetryingEvent（非持久、不改变成员状态）。若依赖跨客户端共享 DB +
   inprocess 总线的既有 15.16b 集成模式（adapter 路成员真实调 send_message），沿用之；
   SDK 流内 retrying 信号源 ⤵️15.7/15.8 的部分不在此覆盖。
