## 1. 定位与作用

Workflow 是工作流编排层门面 + 会话生命周期管理器，位于 Pregel 图引擎（8.1-8.9 已完成）之上、具体组件（8.18-8.26）之下。一次执行的链路：

```
调用方 → Workflow.Invoke / Stream            ← 8.14 本体
  → createWorkflowSession                    ← WorkflowSession/SubWorkflowSession + ActorManager(8.12) + StreamWriterManager + Tracer
  → BaseWorkflow.Compile                     ← 构图校验 + auto_complete_abilities + 嵌套深度检查
  → CompiledGraph.Invoke (8.1)               ← INPUTS_KEY 信封进 Pregel 调度
  → Vertex.Call (8.11) × N                   ← 各组件执行；End 节点流帧经 _processChunk(①分支) 进 session emitter 队列
  → 主循环 range StreamOutput                ← 首帧/帧超时、逐帧日志、INTERACTION 收集
  → 收尾：task.Wait → WORKFLOW_FINISHED → 补发 workflow_final → 清理
```

type WorkflowComponent struct {

## 9. 关键机制注记（实施参考）

1. **帧路径**：`Vertex._processChunk` 三分支（vertex.py:632-650，8.11 已实现）——①End 主图→outputWriter→emitter→AsyncStreamQueue→StreamOutput；②End 子图→sub_workflow_stream；③普通节点→ActorManager.produce→StreamActor 内部队列。8.14 只消费 StreamOutput，不新建队列。
2. **转发层必要性**：workflow 主循环中转一跳承载四件事——收尾补发 workflow_final、三取消分支事件编排、逐帧日志/INTERACTION 收集、生产者（session 墙内管道）与消费者生命周期解耦。禁止省略直透 emitter 通道。
3. **协程拓扑**：Python 2 并发体（stream_process 任务 + _stream 协程）；Go 按 A' 签名为 2 内部 goroutine（图执行+转发循环）+ 调用方 range。
4. **StreamWriterManager 为内部构造**：createWorkflowSession 每次调用现场新建并挂 session，生产者只看得到 session。
