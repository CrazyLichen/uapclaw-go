# 30.3 source_locators 全量 设计 spec

> 日期：2026-12-09 · 状态：设计定稿（用户逐项拍板）· 性质：领域三十第 30.3 批
> 对应计划章节：`IMPLEMENTATION_PLAN.md` 领域三十 30.3 行；上层方案 `2026-11-28-domain30-kb-admin-design.md` §8
> 性质：`retrieval` 包**唯一侵入点**（整体方案定稿口径），本批单独提交、单独登记偏差

## 1. 目标

为 kbadmin 解析链产出的每个 chunk 携带原文定位信息（`source_locators`），落 `kb_chunk_meta.locators_json`，支撑前端 30.8 的 pdf.js bbox 高亮与 docx 段落跳转：

- **pdf**：页码 + 行级 bbox 矩形（PDF 原生坐标，单位 1/72 inch，pdf.js viewport 直接可用）
- **docx**：段落号锚
- **txt/md**：全文字符区间锚
- **图片 caption 块**：锚到宿主（pdf=图片 bbox 的 `image` 类型锚；docx=所在段落号）

## 2. 已拍板决策（brainstorming 逐项确认）

| 决策点 | 结论 |
|---|---|
| PDF 坐标提取库 | **go-fitz（MuPDF cgo 绑定），硬依赖无回退**（方案B）。CI/开发机装 `libmupdf-dev`；静态链接，交付二进制自包含，部署机零运行库 |
| PDF 解析统一 | **go-fitz 统一承担文字+word bbox+图片字节提取+图片 placement**；`ledongthuc/pdf`、`pdfcpu` 从 pdf 链路退役（规则 8 同改动删除引用；仓库其他包若仍用 pdfcpu 则依赖保留） |
| bbox 聚合粒度 | **行级合并**：同页 word 按 y 坐标聚合成行矩形，跨行保留；不存词级几十矩形，不做段级外接框 |
| locator 内部承载 | **`common.TextChunk` 新增导出字段 `SourceLocators []SourceLocator`**（方案A）；不用 Metadata 约定键（避免坐标数据混入向量库）；不改 Parser 接口签名 |
| 图片 caption 锚定 | **锚到宿主**：pdf caption 块 locator = 该图 placement bbox（`image` 类型锚）；docx caption = 所在段落号 |
| caption LLM | **本批启用**：`parseStep` 传入视觉 LLM（平台模型配置解析）；无可用视觉模型或调用失败 → captioner 禁用态/软失败（Error 日志+跳过 caption），解析不阻塞 |
| 测试基线 | 既有单测/集成全量保持通过；pdf 文本断言随替换同改动更新为 MuPDF 基线；新增覆盖用**真实 pdf 文件**（复用 `parser/testdata` + 新增多页/含图样本），禁替身 |

## 3. 数据模型与侵入面

### 3.1 新类型（`retrieval/common`，与 TextChunk 同包）

```go
// BBox 页面矩形 [x0, y0, x1, y1]，PDF 原生坐标（1/72 inch）
type BBox [4]float64

// SourceLocator 单条原文定位
type SourceLocator struct {
    Type       string   // "text" | "image" | "paragraph" | "char_range"
    PageNo     int      // pdf 专用（1 起），其余 0
    LineBBoxes []BBox   // pdf text/image 锚：行级合并矩形
    Paragraph  int      // docx 段落号锚
    CharStart  int      // txt/md 字符区间锚（全文 offset，半开区间）
    CharEnd    int
}

// TextChunk 新增字段（唯一公共结构体改动）
SourceLocators []SourceLocator `json:"source_locators,omitempty"`
```

### 3.2 侵入清单（全部登记，共 5 处）

| # | 位置 | 改动 |
|---|---|---|
| ① | `retrieval/common/document.go` | `TextChunk` 加 `SourceLocators` 字段 |
| ② | `parser/pdf_parser.go` | 文本+图片通道整体替换为 go-fitz；产出页-词映射 sidecar |
| ③ | `parser/word_parser.go` + `docx_model.go` | 产出段落号映射 sidecar（`extractImages` 已有 paragraphNum，补文本段落文本映射） |
| ④ | `chunker/text_chunker.go`（含 `text_splitter`/`text_preprocessor`） | 消费 sidecar/offset，按 chunk 全文区间算块级 locators |
| ⑤ | kbadmin `chunkStep`（`pipeline.go`）+ `models.go` | `kb_chunk_meta` 加 `locators_json` 列（GORM AutoMigrate），chunkStep 序列化 `SourceLocators` 写入 |

不产出 locator 的 parser（excel/html/web_page/wechat/image/json/csv）不碰；对应 chunk `SourceLocators` 为空、`locators_json` 落空值。

## 4. PDF 解析链（go-fitz 统一）

`PDFParser.ParseContent` 重写（覆写面不变，仍是 BaseParser 模板派发）：

1. go-fitz 打开文件 → 逐页取 words（自带 bbox）拼页文本；逐页取展示图片对象并提取字节落盘（原 `images/` 归档语义保持，含 `CpImage` 等价归档路径策略）
2. 全文文本组装语义保持：非空页文本 + 该页图片 caption 紧随其后（caption 顺序/位置不变）；过滤空行后拼接
3. 同步产出 sidecar `[]PageMap`：
   ```
   PageMap{ PageNo, PageText,
            Words:  [{BBox, CharStart, CharEnd}],   // offset 以产出全文为基准
            Images: [{BBox, ArchivePath}] }          // placement bbox + 归档路径
   ```
4. caption 生成：`ImageCaptioner`（本批启用 LLM 传入，见 §6）；caption 文本块的 locator 在 §5 映射阶段按宿主锚生成
5. sidecar 随 `reranker.Document.Metadata` 以专用键 `source_page_map` 携带（**仅内部传递用**；chunker 消费后从最终入库 metadata 中剔除，保证坐标数据不进向量库；键名常量归 `common` 包统一维护，doc.go 注明内部约定）

## 5. chunk 映射与落库

1. `TextChunker.ChunkDocuments` 切分产物已可推导 chunk 全文 `[start,end)`；`text_preprocessor` 清洗产生文本变形处补 offset 折算表（清洗→原文映射）
2. chunk 区间 ∩ 页-词表 → 同页 word 按行 y 聚合为行矩形 → `text` 型 locator（`PageNo` + `LineBBoxes`）
3. docx：chunk 区间 ∩ 段落映射 → `paragraph` 型 locator；txt/md：直接 `[start,end)` → `char_range` 型
4. caption 块识别（文本 = caption 生成产物、位于图片归档位置）：pdf → `image` 型锚（宿主图 placement bbox）；docx → 宿主段落号
5. kbadmin `chunkStep`：`json.Marshal(chunks[i].SourceLocators)` → `kb_chunk_meta.locators_json`；向量库/embedding/检索链零改动

## 6. caption LLM 启用

- `parseStep` 增加视觉 LLM 解析（复用平台既有模型配置装配），以 `WithLLMClient` 传入 AutoFileParser 链
- 无视觉模型配置：captioner 禁用态（只归档不描述），Warn 日志，解析继续
- 单图 caption 调用失败：软失败（Error 日志 + 跳过该 caption），对齐既有 captioner 语义；不阻塞解析、不置任务 failed

## 7. 已知偏差登记（规则 9/12 出口）

| # | 偏差 | 理由 | 回收条件 |
|---|---|---|---|
| D-30-3-1 | PDF 文本通道由 ledongthuc（对齐 Python pdfplumber 语义）整体替换为 MuPDF，字符级空白/换行与旧基线存在差异 | 用户拍板「直接替换不保留原来」；bbox 坐标面只有 MuPDF 提供；单一库消除双库分工 | 无（有意替换） |
| D-30-3-2 | `common.TextChunk` 新增 `SourceLocators` 字段，Python 对齐面无对应物 | WeKnora 对标新增能力域（领域三十无上游 Python），locator 是管理面必需数据 | 无 |
| D-30-3-3 | sidecar（PageMap）经 Document.Metadata 专用键或 chunker 并行参数传递，为 Go 侧内部传递机制 | Python/上游无对应物；不进向量库、不外显 | 无 |

## 8. 测试策略（用户硬性要求）

- **既有回归**：`go build ./...` + `go vet ./...` + `CGO_ENABLED=1 go test -tags "sqlite_fts5 test" ./...` 全量零 FAIL；`pdf_parser_test.go` 既有断言随 MuPDF 基线同改动更新
- **新增单测**（真实文件，禁替身）：
  - PageMap offset 对齐：多页/跨行/图片穿插样本，逐 word 断言 charStart/CharEnd 切出的子串 == word 文本
  - chunker 映射边界：chunk 起止切在词中间、preprocessor 折叠空行后 offset 折算正确
  - 行级合并矩形：同页同行多 word 合并断言
  - docx 段落号 / txt 字符区间：真实小文件（复用 `parser/testdata` docx/txt 样本）
  - caption 两态：有视觉 LLM（fake transport 层）生成入正文+宿主锚；无 LLM 禁用态软失败
- **新增集成**（`tests/integration/kbadmin` 扩展，过双层审计门禁）：真实 pdf 小样本走 WS→gateway→agentserver→worker 全链，断言 `kb_chunk_meta.locators_json` 非空且 page/bbox 结构合法、`kb.chunk.list` 可查
- 覆盖率：触及包整体 ≥85%（项目口径）
- CI/环境：CI 镜像与开发文档补 `libmupdf-dev` 安装说明

## 9. 边界与不做

- pdf.js 高亮渲染、docx 段落跳转 UI 属 30.8 前端批，本批只保证 `locators_json` 数据面就绪
- 独立图片文件（ImageParser）整文档即一图，不产 locator
- excel/html 等其余格式 locator 延后（`locators_json` 留空），需求出现再立项
