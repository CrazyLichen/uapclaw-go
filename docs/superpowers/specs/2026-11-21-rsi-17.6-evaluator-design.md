## 4. 判分链路（对齐基准，步骤顺序不可调换）

以 case `support_ticket_triage_01` 为例（详见 brainstorming 会话记录）：

1. **判分器路由**（base.go）：build_judger 按 case 内容路由——有 `swebench` 字段 → script_based（官方验证）；只有 answer → exact_match；有 rubric/required_behaviors → llm_as_judge。构造期校验：judge_success_score∈[0,1]、judge_agent_max_iterations/judge_timeout_sec 正整数（bool 拒绝）、judge_max_retries∈[0,5]。
2. **评分契约展开**（scoring.go `scoring_contract`）：required_behaviors 带 weight（默认 1.0）→ rubric 逐条编 `rubric_NNN` → 有参考答案且 answer_role=criterion 时**自动首位插入** `reference_answer` → forbidden_behaviors 带 penalty（默认 0.3）。ID 必须唯一。
3. **证据工作区**（judge_evidence.go）：`judge/evaluation_<uuid12>/evidence/` 下写 request.json（题目+回答+轨迹摘录+打分清单），裁判只能读卷宗。
4. **裁判 agent**（judge_runtime.go）：提示词逐字对齐（Evidence workspace 指路 + FINAL OUTPUT CONTRACT：每 ID 恰好打一次分、`{"status":"unavailable","reason":...}` 仅限评估器自身局限、漏做不算局限）。工具事件流水落 tool_events.jsonl。
5. **判决解析**（`parse_judge_output`）：每 ID 恰好出现一次（多评/漏评 ValueError）；score 必须 0~1 有限数字（bool/NaN/Inf 拒收，`finite_number`）；混入竞争判决对象拒收（`_contains_judge_payload`）。
6. **重算分数**（`score_judge_output`，裁判顶层 score 仅参考）：
   - `base = Σ(score_i × weight_i) / Σweight`
   - penalty_mode=subtract：`max(0, base - Σpenalties)`
   - penalty_mode=ceiling（默认）：`min(base, 1.0 - max(penalty))`（封顶扣除，不叠加）
7. **verdict 恢复链**（`_parse_with_format_repair`）：直接解析失败 → repair_judge_json（LLM 修复格式）→ 修复截断（finish_reason=length）判 `truncated` 不可信 → 修复非法或 `repair_unavailable` 判 `repair_invalid` → 本轮作废进入重试轮（judge_max_retries 次，换 `run_judge_closeout`：冻结卷宗禁用工具只交终审判决）→ 全部烧完报 `EvaluationInfrastructureError`。每次尝试留档：`response_N.json` / `validation_error_N.json` / `diagnostics_N.json` / `error.json`。
8. **快捷出口**：agent 崩溃（execution_status≠passed）不进裁判直接 score=0/passed=false（transport 瞬态错误除外，`transient_transport_error` 判定）；`unavailable` 判决不得按 0 分计（需重评估）。
9. **最终 JudgeResult**：`{method, score, passed(score≥judge_success_score), reason, metadata(overall_score/base_score/penalty_mode/total_deduction)}`。
