## 0. 在 Agent 会话中的流程位置与作用

15.16「团队集成」是领域十五的团队侧消费终点，拆 a-e 子章节（用户 2026-12-01 拍板，不换顺序）；a（成员事件泵，a732f8579）、b（spawn 编排主体 + team-mcp，5d298bd5c）已合入 main。

15.16c 卡在 spawn 的**跨进程缝**上：

```
leader 收 spawn_teammate 请求
  → enrich_team_spec_for_swarm（jiuwenswarm/agents/swarm/assembly.py）
      base = SwarmBuildContext(...)（assembly.py:485-535）★ 本节承担
      spec.build_context = base（:536）★
      spec.build_context_seed = base.to_seed()（:540 ★）
  → spec 序列化 → 跨序列化边界（spawn 子进程 / 分布式远端 / 冷恢复）
      → MaterializeBuildContext → BuildContextFromSeed（Go blueprint.go:363）
      → 注册工厂 _build_swarm_context_from_seed（registry.py:160-198）★ 本节承担
      → SwarmBuildContext.from_seed(seed, config=本进程, trajectory_span_processor=…)
  → setup_agent → derive() 填 per-member 视图（member_name/role/workspace）
  → ExternalHarnessMemberRuntime / provider 消费（paths.go cwd 选择、InstallSkills、workspace meta）
```

**作用**：BuildContext 本体不可序列化，seed 是它跨进程的存档快照。15.16b 已把 spawn 编排主体交付，但 Go 侧**全仓没有任何代码生产 `BuildContextSeed`**（grep 零命中）——spawn 出去的成员拿到的 context 是空壳，project_dir / team_outputs_dir / team_ws_root 全缺。本节从"空壳"变"有血肉"，并回收偏差 D-15.13-k（过渡默认工厂），接上 install_skills 门卫所需的 project_dir（15.9 dsh / 15.12 skills 既有约定）。

### 0.1 方案 A 裁决（用户 2026-12-02）

**窄种子切片**：只移植三条线——①平台子类 SwarmBuildContext（context.py 1:1）；②种子工厂 `_build_swarm_context_from_seed` + 幂等注册缝（registry.py 对应段，**不含** rails 目录注册）；③生产端 base 构造段（assembly.py:485-541）接进 Go enrich 路径 + team_artifacts 依赖文件。

`enrich_team_spec_for_swarm` 其余段（register_swarm_providers 的 rails 目录注册、build_member_deep_agent_spec/config_specs、mcp_configs、agent_group 应用）**不属于本节**：rails 目录注册属 15.7/15.8 provider 面；config_specs/mcp 属成员配置源装配；agent_group 属 15.16e。Go 侧 enrich 主缝呈"部分对齐"状态，⤵️ 登记见 §6。

## 4. 测试面

### 4.1 单测

1. `ToSeed`/`FromSeed` 往返：16 键逐键值断言 + per-member 五字段与活句柄不入 seed + trusted_dirs nil/空两形态。
2. `NewSwarmBuildContext` cron 桥：request_metadata 带 "cron" → extras["is_cron"]；不带 → 无。
3. `resolve_member_skill_visibility_path` 三分支：workspace.root_path 命中 / (team_id, member_name) 稳定布局 / 双缺 nil。
4. `resolve_member_work_dir`：有 task_workspace_root → `work/<slug>/`；无 → nil。
5. `buildSwarmContextFromSeed`：经 `atschema.RegisterBuildContextFactory` 覆盖注册后 `MaterializeBuildContext` 走新工厂；字段逐键还原。
6. `GetTeamArtifactWorkspace`：chat-<n> 递增分配（已有目录跳号）、outputs 目录形状；`ResolveMemberWorkDir` slug 化。
7. `EnrichTeamSpecForSwarmSeed`：project_dir 有值 → task_workspace_root/team_outputs_dir 为 nil；为空 → 分配产物目录；team_ws_root 两级选择。
8. `GetTrajectorySpanProcessor`：Set 后返回同实例（幂等）；未 Set 返回 nil（懒构造 ⤴️，D-15.16-c2②）。
9. `ConfigureGlobalSkillsDir`/`GlobalSkillsDir`：Set 后返回配置值；Reset 后回落 `{openjiuwen_home}/workspace/skills` 默认布局（paths.py:82-120 对齐）。

### 4.2 集成（tests/integration/，真实跨 ≥3 子系统）

spawn 准备路径端到端：`GetEnrichedTeamSpec → EnrichTeamSpecForSwarmSeed → spec 序列化/反序列化 → MaterializeBuildContext → 重建 SwarmBuildContext → externalcli ResolveExternalPaths 吃到真实 project_dir/team_outputs_dir`。断言 seed 跨 JSON 边界后 project_dir / team_outputs_dir / team_skill_visibility_path 不丢；基线空壳（无 seed）行为不回归。审计自检 `go run ./cmd/integration-audit -verify`（跨 swarm/schema/externalcli ≥3 子系统）。
