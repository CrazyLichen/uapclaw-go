## 1. 在 agent 会话中的流程位置与作用

### 1.1 调用链

```
宿主启动一次 agent 会话（web / chat / team 任一入口）
  │
  ├─ 单 Agent 路径（本仓 Go 已通）：
  │    DeepAgentSpec.build() → DeepAgent.Invoke / RunStreaming → _run_task_loop 自驱
  │    ❌ 不经过 harness_protocol
  │
  └─ 外部 CLI 成员路径（领域十五要新建，当前 Go 全缺）：
       spawn_teammate(external_cli)                        ← 15.16 / 15.13
         → HarnessProvider.Create(config)                  ← 15.5
         → harness.Start(HarnessContext)                   ← 15.1 ✅
         → harness.Send(HarnessInput) → SendReceipt        ← 15.1 ✅
         → ⭐ turn_events(turn_id) / events()              ← 15.2（本节）
         → TurnResult（终态）                              ← 15.1 ✅
         → checkpoint / 交互 / 钩子                         ← 15.3 / 15.4
```

15.2 是整条链上**唯一的「provider → 宿主」单向出口**。它缺失时宿主只能拿到最终 `TurnResult`，看不到外部 CLI 的任何中间过程（说话、思考、调工具、用量）。

### 1.2 会话内的具体落点

| 时点 | 15.2 负责什么 | Python 依据 |
|---|---|---|
| 子进程 `start` 之后 | 声明有界观测缓冲契约（容量 1024，满时按 `EventOverflowPolicy` 合并/阻塞） | `events.py:97-106` |
| `send` 之后每轮 | `TurnLifecycleEvent STARTED → … → FINISHED/ABORTED/FAILED`；每轮恰好一次 STARTED + 一次终态；PAUSED/RESUMED 同 `turn_id` 且不结束 | `events.py:31-48,281-303` |
| 流式过程中 | `OutputEvent`（DELTA/SNAPSHOT/FINAL × ANSWER/REASONING/SYSTEM，稳定 `output_id` + `content_index`） | `events.py:141-160` |
| 工具调用 | `ItemLifecycleEvent(item_type="tool")` STARTED / UPDATED / COMPLETED | `events.py:163-174` |
| 一次物理模型请求 | `ModelRequestEvent`（请求消息、工具定义、采样参数、回复、TTFT、本次 usage） | `events.py:185-271` |
| 背压 | `event_retention(payload)` 是 retention 的**唯一来源**；REQUIRED 永不丢 | `events.py:378-389` |
| 信封关联 | `sequence`（严格递增）/ `timestamp` / `turn_id` / `item_id` / `correlation_id` / `causation_ids` | `events.py:392-426` |

### 1.3 作用

1. **可观测性**：把外部 CLI 的黑盒过程转成结构化、有序、可关联的事件流。
2. **流式对话的前提**：`harness_providers/io_adapter.py:452-555` 逐事件投影成 DeepAgent 方言（`llm_output`/`llm_reasoning`/`tool_call`/`tool_result`），没有 15.2 就没有逐字输出。
3. **背压与不丢**：有界缓冲 + 由载荷推导的 retention，保证慢消费者不会丢终态事件。
4. **因果可审计**：`ModelRequestEvent` 的「先于它引发的 item 与轮终态」+ `causation_ids` 供 15.10 telemetry / 15.11 轨迹 / 领域二十二消费。

### 1.4 首个生产消费者

15.2 交付时**仍无生产消费者**（与 15.1 相同的预期，不是缺陷）。首个消费方是 **15.5 provider 基座**（`BoundedEventBuffer` 生产事件 + `BufferedEventCursor` 消费事件）。

## 3. 已确认的设计决策（brainstorming 结论）

| # | 议题 | 决策 |
|---|---|---|
| Q1 | `harness_providers/stream.py`(168 行) 有界缓冲/游标实现归属 | **方案 A**：15.2 只做协议包（`events.go` + `stream.go` 接口 + 形状）；实现留 **15.5**，15.2 计划行标 `⏵ 15.5` 并注明 `stream.py:19-155` |
| Q2 | `HarnessEventPayload` 10 分支 union 的 Go 表示 | **方案 1**：接口 + 10 个具体结构体 + `type switch` 分派，分派顺序对齐 `serialization.py:_payload_to_wire` 的 10 个 `isinstance` |
| Q3 | `EventRetention` 与 `event_retention` | **方案 1**：导出包级函数 `EventRetentionOf(payload) EventRetention`，完全照搬 5 条 `if` 顺序，未知兜底 `required` |
| Q4 | `HarnessEvent` optional ID 的 Go 类型 | **用户变体**：用 `string`（不用 `*string`），**空串即非法**，`NewHarnessEvent` 构造期强制 4 个 optional ID 与每个 `causation_id` 非空；「未提供」用空串表达 |
| Q5 | 章节顺序 | **(a) 维持原序** 15.2 → 15.3 → 15.4 → 15.5 → 15.6，不提前不换节 |

**Q4 的偏差登记（必须写进 §6）**：Python `str | None` 区分「未提供（None）」与「空串非法」；Go 统一用 `string` 后二者合一为**空串 = 未提供**。影响面：
- `serialization.py:460-463` 的 `_optional_string(...)` 在空串时抛错，Go 侧 15.4 解码须**先判断 `== ""` 再决定是否校验**，或直接接受空串为「未提供」。
- `HarnessEvent` 的 `ProviderSessionID`/`TurnID`/`ItemID`/`CorrelationID` 四字段 Go 可读性略降（`== ""` 判空），但**不变量更严**（不存在「有值但为空」的中间态）。
- 该偏差**只影响 optional 字段**，`HostSessionID`/`AgentID` 本来就是必填非空，语义不变。

### 5.2 `stream.go` ← `stream.py`(30 行)

```go
// ──────────────────────────── 全局变量 ────────────────────────────

// ErrEventStreamDone 观测游标到达末尾的哨兵，等价 Python 的 StopAsyncIteration。
var ErrEventStreamDone = errEventStreamDone{}

// ──────────────────────────── 结构体（接口定义）────────────────────────────

// HarnessEventCursor 可提前释放消费者租约的有序观测游标。
// Python: stream.py:13-27 HarnessEventCursor（3 方法）
type HarnessEventCursor interface {
    // Iter 返回本游标（对齐 __aiter__）
    Iter() HarnessEventCursor
    // Next 返回下一条有序事件；耗尽时返回 ErrEventStreamDone（对齐 __anext__）
    Next(ctx context.Context) (*HarnessEvent, error)
    // Close 幂等释放观测消费者租约（对齐 aclose）
    Close(ctx context.Context) error
}

// ──────────────────────────── 非导出函数 ────────────────────────────

type errEventStreamDone struct{}
func (errEventStreamDone) Error() string { return "harness event stream exhausted" }
```

**本节只搬接口，不实现任何游标行为**（Q1 方案 A）。租约语义（单消费者、`peek` 避免 pop-then-push 竞态、per-turn 结束条件、`Close` 后 `Next` 返回 `ErrEventStreamDone`）在 **15.5** 落实，Python 依据 `harness_providers/stream.py:19-155`。

`ErrEventStreamDone` 的用法约定（写进注释）：`errors.Is(err, ErrEventStreamDone)` 判定「正常结束」，与「真实错误」区分 —— 这是 Go 对 `StopAsyncIteration` 的等价物（`errors.Is` 可穿透包装）。

## 7. 数据流与错误处理

- **事件产生**（15.5 实现）：`SerializedTurnHarness._emit(payload, turn, item_id, causation_ids, timestamp)` → `NewHarnessEvent` 组装信封（`sequence` 自增、`timestamp` 取 now、`correlation_id = turn.message_id`、`causation_ids = message_id + 额外 causes`）→ `BoundedEventBuffer.put`（阻塞背压）。
- **事件消费**（15.5 实现）：`BufferedEventCursor.Next` → 单消费者租约 + per-turn 结束条件；`Close` 幂等释放。
- **本节职责**：只保证 `NewHarnessEvent` 不接受坏信封（sequence 负数、timestamp NaN、`turn_lifecycle` 缺 `turn_id`），从而「坏事件根本进不了缓冲」。
- **异常路径日志**（规则 3）：Python 的 `events.py` / `stream.py` **零 `logger.` 调用**（已用 `grep -n "logger\." events.py stream.py` 复核，0 命中），故 Go 侧**不新增日志**；校验失败统一返回 `&HarnessProtocolError{Msg: ...}`（`errors.py` 层次已在 15.1 落地），由 15.5+ 的发射方决定是否记日志。
- **错误分类**：
  - 构造期非法 → `HarnessProtocolError`（等价 `ValueError`）
  - 游标耗尽 → `ErrEventStreamDone`（非错误，正常结束）
  - 游标并发消费 / turn 不匹配 → `HarnessStateError`（15.5 抛，15.2 只定义接口）
