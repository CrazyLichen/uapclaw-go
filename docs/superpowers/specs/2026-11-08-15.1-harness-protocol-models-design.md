## 1. 在 agent 会话中的流程位置与作用

### 1.1 调用链

```
宿主启动一次 agent 会话（web / chat / team 任一入口）
  │
  ├─ 单 Agent 路径（本仓 Go 已通）：
  │    DeepAgentSpec.build() → DeepAgent.Invoke / RunStreaming → _run_task_loop 自驱
  │    ❌ 不经过 harness_protocol
  │
  └─ 外部 CLI 成员路径（领域十五要新建，当前 Go 全缺）：
       spawn_teammate(external_cli)                        ← 15.16 / 15.13
         → HarnessProvider.create(config)                  ← 15.5
         → harness.start(HarnessContext)                  ← 15.1 的 HarnessContext 在此被消费
         → harness.send(HarnessInput) → SendReceipt       ← 15.1
         → turn_events(turn_id) / events() 事件流         ← 15.2
         → TurnResult（终态）                            ← 15.1 的 results.py
         → checkpoint / 交互 / 钩子                      ← 15.3 / 15.4
```

15.1 **不在「每次用户说话就走一遍」的热路径上**，它是**宿主 ↔ 第三方 CLI 进程之间的边界数据契约层**。会话内的具体落点：

| 时点 | 15.1 被用到的类型 | 上游文件:行号 |
|---|---|---|
| 成员 spawn / 建卡 | `HarnessCard`（能力声明、`validate_host` 协议版本与宿主能力协商） | `models.py:144-195` |
| `start(context)` 注入宿主服务 | `HarnessContext`（agent 身份、host 能力集、resume policy、tools/mcp/hooks/interactions/telemetry；`env` 不落日志） | `models.py:330-373` |
| 每轮投递输入 | `HarnessInput`（`freeze_json_value` 冻结）+ `SendReceipt`（message→turn 关联） | `models.py:198-222` |
| 工具面桥接 | `ToolDefinition` / `ToolInvocation` / `ToolExecutionResult` / `McpServerConfig`（三选一 target 强校验） | `tools.py` 全文件 |
| 轮次终态 | `TurnResult` / `TurnStatus` / `TurnTermination` / `TurnError` / `TurnUsage` / `MonetaryAmount` / `ContentBlock` | `results.py` 全文件 |
| 生命周期相位 | `HarnessState`（idle/running/pausing/paused/terminated） | `state.py:9-20` |
| 协议违规 | `HarnessError` 5 类错误层次 | `errors.py` 全文件 |

### 1.2 作用

1. **解耦**：把「OpenJiuwen 宿主」与「Claude Code / Codex / DSH 等第三方 CLI」之间的所有交换数据定成 provider-neutral 的强校验值对象。provider 只认这一层，不认宿主内部结构——上游 `harness_providers/AGENTS.md:4-6` 明确 "Contracts live in `harness_protocol`; nothing here changes them"。
2. **防脏数据跨进程**：`freeze_json_value` / `freeze_json_object` 递归冻结并拒绝 NaN/Inf/非字符串 key（`models.py:30-57`），因为数据要跨 stdio 进程序列化；`TurnResult` 的 10 步 `__post_init__` 不变量、`McpServerConfig` 的「恰好一个 transport target」、时间戳有限性，都是**在边界处 fail fast**，避免坏值进到子进程才炸。
3. **能力协商**：`HarnessCard.validate_host` 在 `start` 时挡住协议版本不兼容 / 宿主缺必需能力，是 15.7-15.9 各 provider 无需重复写的前置门卫。
4. **为后续章节定地基**：15.2 事件、15.4 序列化、15.5 provider 基座、15.6 native、15.10 telemetry、15.11 轨迹、15.13 生命周期、15.16 spawn 全部 import 这些类型。`IMPLEMENTATION_PLAN.md:968` 明确「十五（协议层，被 I/H 组缺陷与后续所有外部 agent 能力依赖）」，`:1316` 明确「15.6 压在 15.1-15.5 之上，不宜提前」。

### 1.3 首个生产消费者

`harness_providers/native/harness.py:34-63,218,269,278,331,614,633` 直接 import `HarnessCard` / `HarnessContext` / `TurnResult`，即 **15.6 native provider 是 15.1 的首个真实消费者**。

**15.1 交付时零生产消费者属预期**，不是缺陷亦非「结构悬空」：计划 `:968` / `:1316` 已定优先级，25.1a 已把 L1 交互面（`DeepAgent.start/attach_output/send_input`）接到 NativeHarness → TeamHarness；本批交付的契约面靠单测覆盖，不造「实现了但没消费方」的行为代码（4 个占位是**契约形状**，不是行为实现）。

## 7. 数据流与错误处理

- **入站**（宿主→provider）：`HarnessProvider.Create(JsonObject)` → `HarnessProtocol.Start(HarnessContext)`；`HarnessContext` 构造期挡住身份缺失 / env 类型错 / 非法 JSON；`HarnessCard.ValidateHost` 在 `Start` 内挡住协议版本与必需能力缺失。
- **每轮**：`Send(HarnessInput, DeliveryMode)` → `SendReceipt`；`HarnessInput` 构造期 `freezeJsonValue` 挡住 NaN/Inf / 非 string key。
- **出站**（provider→宿主）：`TurnResult` 构造期 10 步不变量保证终态与 `error`/`termination` 互斥且自洽；`ToolGateway.Invoke` 返回 `ToolExecutionResult`。
- **异常路径日志**（规则 3）：本批为纯值对象层，Python 对应 5 个文件**无 `logger.` 调用**（已用 `grep -n "logger\." models.py tools.py results.py state.py errors.py` 复核，0 命中；`errors.py` 只定义异常类），故 Go 侧**不新增日志**；`HarnessProtocolError` 等错误由 15.5+ 调用方记录。
- **错误层次**：所有校验失败包装为 `HarnessProtocolError`（`ValueError/TypeError` 等价），`CheckpointConflictError` 作为其子类供 15.4 使用；`HarnessStateError` / `UnsupportedHarnessCapabilityError` 供 15.5+ 使用。
