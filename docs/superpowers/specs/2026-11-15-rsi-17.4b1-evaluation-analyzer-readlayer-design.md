## 3. 关键实现决策

### 3.1 Task 0 归属核对表

dataclass 归属逐符号核对（Python 定义处为准，规则 9.2）：
- 定义在 `harness_rsi/schema.py`（17.4a schema.go 已落）：TeamIssue、EvaluationResultAnalysisArtifact、EvaluationResultAnalysisInvocation 等 → **复用**；
- 定义在 `case_reader.py`（EvaluationSummaryInput / CaseAnalysisInput / DeterministicSignals）→ **进本包 case_reader.go**，不重复定义；
- Task 0 产出完整核对表写入 plan，实施中按表执行。

### 3.2 interface 对齐 Protocol（已知偏差 D-1）

`interfaces.py` 两个 Protocol：属性 `name: str` → Go `Name() string` 方法；
`async def analyze(...)` → `Analyze(ctx context.Context, invocation schema.EvaluationResultAnalysisInvocation) (schema.EvaluationResultAnalysisArtifact, error)`。
偏差性质：语言层不可能等价（鸭子类型属性 vs 方法）；无回收条件。
`EvaluationResultAnalysisStrategy.Analyze` 的 ctx 参数为 Go 惯例新增（Python async 取消经事件循环），登记偏差 D-2。

### 3.3 Windows 路径预算（已知偏差 D-3）

`diagnosis_paths.py` 的 `os.name == "nt"` → Go `runtime.GOOS == "windows"`（对齐审查要点：platform 语义逐字段核对）。预算函数为纯函数，测试注入两种 GOOS 值断言，不使用 build tag（可 mock 代码禁止 tag，规范 3.3）。

### 3.4 config 私有件提升导出（已知偏差 D-4）

`harness_context.py` import 了 config 包私有函数 `_build_prompt_section_specs`、`_normalize_prompt_section`、`_resolve_section_file`。Go 小写私有没有跨包可见性 → 在 config 包提升为导出（`BuildPromptSectionSpecs` 等），归属不变，仅可见性变更。理由：跨包复用；回收条件：无（Go 语言层必然）。

### 3.5 signal_extractor 注册工厂

- `register_signal_extractor` / `build_signal_extractor`：包级 map + sync.RWMutex（并发注册 -race 干净），缺省 method 回 `GenericSignalExtractor`；
- 已知注册者：generic（default/exact_match）、pytest（script_based，读 pytest 证据簇，缺失时降级 generic 并标记 `pytest_evidence_missing`）——按 Python 源完整对齐，实施时逐类核对。

### 3.6 指纹归一化顺序敏感

`_fingerprint_error` 五条正则替换顺序即语义（时间戳 → UUID → 路径 → hex → 行号 → 压空白），Go 逐条对应不调序（规则 12.1）。RE2 语法核对：Python `\b`、字符类在 RE2 下等价，实施时逐条验证语义一致。

### 3.7 compactor 排序键逐条对应

`_select_calls` 多级排序键（observed_failure → state_mutation → content_evidence → first/last_use_of_tool → terminal_window → 输出长度倒序 → 原序稳定）→ `sort.SliceStable` + 显式比较链，顺序逐条对应。预算公式 `min(20, max(8, (n*2+2)/3))` 边界钳制必须有测试。跨 trial：`_deduplicate_selected_payloads` / `_cross_trial_contrast` / `_first_sequence_divergence` / `_terminal_action_variants` 全部对齐；`compression_stats` 计数用精确断言（13.24 审查惯例）。

### 3.8 snapshot 部分失败契约

`repository_snapshot.py` docstring 明确：拷贝循环单文件失败不中断整体，收集失败清单返回。Go 保持同一契约；`.git/.mypy_cache/.../node_modules` 排除集与 `_ROOT_RUNTIME_DIRS` 白名单逐条对齐。

### 3.9 路径逃逸防护

`harness_context.py` 的 `is_relative_to(root)` 检查 → Go `filepath.Rel` + 前缀校验等价实现；`resolve()` 语义对齐（含 symlink：Go 须 `filepath.EvalSymlinks`；错误处理按 err != nil 判断而非仅 IsNotExist——对齐审查要点 os.path.exists 教训）。

### 3.10 错误与日志

- Python 异常 → Go 哨兵 error（如 `AnalysisUnavailableError` 归属 member_optimizer/loader 前置件）；错误信息文案：日志 Msg 译英文（feedback-logs-english），提示词/契约文本逐字中文（提示词一比一纪律）；
- 日志按规则 3 逐条对照 Python logger 调用；组件常量沿用 17.4a spec 既定选择（实施时核对，不自创）。

### 4.2 集成用例（`tests/integration/`）

1. **"成绩单→信号→压缩证据包"链路**：case_reader 读 fixture 评估目录 → signal_extractor 聚类 → compactor 出 digest → 断言 digest 结构与计数。跨 harness_rsi/evaluation_result_analyzer + evaluator + member_optimizer（前置件）子系统；
2. **"成绩单→证据工作区落盘"链路**：load_eval_ref（loader 前置件）→ repository_snapshot 拷贝 → diagnosis_paths 预算校验 → harness_context 投映，断言工作区文件树与失败清单行为。跨 member_optimizer + evaluation_result_analyzer 子系统；
3. 契约回归：TeamIssue / EvaluationResultAnalysisArtifact 等 17.4a schema 契约在上述链路中真实序列化/反序列化（YAML/JSON 双向）。

集成测试文件带 `//go:build integration` 标签 + `suite.Run(`，mock 只在文件系统边界外（无网络/进程 mock 需求）。

## 6. 已知偏差汇总

| 编号 | Python | Go | 性质 | 回收条件 |
|------|--------|----|------|---------|
| D-1 | Protocol 属性 `name: str` | `Name() string` 方法 | 语言层不可能（鸭子类型 vs 显式方法） | 无 |
| D-2 | async analyze（事件循环取消） | `Analyze(ctx, ...)` 显式 ctx | Go 惯例 | 无 |

| D-4 | config 包私有函数跨包引用 | 提升为导出（归属不变） | Go 可见性规则 | 无 |
| D-5 | dataclass frozen/slots | struct + 构造函数 + 校验 | 语言层不可能 | 无 |
| D-6 | dict/Mapping 动态键 | map[string]any（数据契约型 any，与 13.x 惯例一致） | 语言层不可能 | 无 |

任何未列出的偏差须按规则 9.6/12.3 当场提出经用户确认，禁止注释里自行宣布。
