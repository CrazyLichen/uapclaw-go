## 1. 背景与目标

Python 侧 external memory 由两个文件组成，位于 swarm memory 包并全部包级导出：

- `external_memory_config.py`：engine 门禁（builtin/external/both/none）、`memory.external` 段解析、openjiuwen provider 配置映射
- `external_memory_builder.py`：`build_external_memory_rail` 单入口，四路 provider 分发（openjiuwen/mem0/openviking/plugin），任何失败返回 None

Go 现状：**等价逻辑散在 adapter 非导出函数里**（`internal/swarm/server/adapter/deep_adapter_rails.go` L569-676 + L1420-1560），swarm memory 包从未建过这两个文件的对应物。这是 10.3.4-6 回填时内联的占位实现。

Agent 会话中的挂载链路（Python 与 Go 一致，本次不改变运行时链路）：

```
process_message(_stream)_impl
  → _update_runtime_config
    → _update_rails_for_mode(mode)
      → plan/fast 两分支
        → _handle_external_memory_rail_by_config   [保留在 adapter]
           ├─ 启用且未注册 → build_external_memory_rail → register_rail
           └─ 禁用且已注册 → on_session_end → unregister_rail
```

目标：

1. 迁移结构对齐：两个新文件进 swarm memory 包，adapter 瘦身为薄调用
2. 行为对齐：修复 9 项与 Python 基线的偏差（见 §3）
3. 为 10.6.18（memory_rpc，TUI 消费）提供包级导出函数

## 5. 函数清单与签名

### external_memory_config.go

常量：`defaultExternalUser = "__default__"`、`defaultExternalScope = "__default__"`、`ltmSubdir = "memory/ltm"`、validEngines 集合。

| 函数 | 对齐 Python | 说明 |
|------|------------|------|
| `GetMemoryEngine(cfg map[string]any) string` | get_memory_engine | 空白/非法回落 "builtin"；cfg nil 走包内 loadConfig() |
| `IsBuiltinMemoryAllowed(cfg) bool` | is_builtin_memory_allowed | engine ∈ {builtin, both} |
| `IsExternalMemoryAllowed(cfg) bool` | is_external_memory_allowed | engine ∈ {external, both}（Go 缺失，新增） |
| `GetExternalMemoryConfig(cfg) ExternalMemoryConfig` | get_external_memory_config | 结构体返回（Provider/UserID/ScopeID/AllowedPlugins/OpenJiuwen/Mem0/OpenViking），默认值填充 |
| `IsExternalMemoryEnabled(cfg) bool` | is_external_memory_enabled | **engine 放行 && Provider != ""** |
| `ResolveLtmDir() (string, error)` | _resolve_ltm_dir | WorkspaceDir()/memory/ltm + MkdirAll(0755) |
| `BuildOpenJiuwenProviderConfig(extCfg, cfg) (map[string]any, error)` | build_openjiuwen_provider_config | kv shelve/vector chroma/db sqlite；embedding 复用包内 GetEmbedConfig（embed_base_url 键 + EMBED_* env 回退）；mkdir 失败返回 error（沿链传播为 builder nil） |

### external_memory_builder.go

全局变量：`builtinProviders = {"openjiuwen","mem0","openviking"}`（Python `_BUILTIN_PROVIDERS`；agentarts 不进集合）。

| 函数 | 对齐 Python | 说明 |
|------|------------|------|
| `BuildExternalMemoryRail(cfg map[string]any, workspaceDir string) agentinterfaces.AgentRail` | build_external_memory_rail | 任何失败 → warn + nil；sessionID 传 ""（等价链：空串 → provider 忽略 → ltm.DefaultValue `__default__`，与 Python 不传参数等价，注释固化）。返回类型 agentcore/single_agent/interfaces.AgentRail，与 adapter 现签名 sainterfaces.AgentRail 为同一类型（adapter 的 import 别名） |
| `buildOpenJiuwenProvider`（非导出） | _build_openjiuwen_provider | BuildOpenJiuwenProviderConfig + NewOpenJiuwenProvider |

## 6. 数据流与错误处理

### 失败降级矩阵（对齐 Python「任何失败不阻断主流程」）

| 失败点 | 行为 | 日志 |
|---|---|---|
| provider 构建失败/panic | builder 返回 nil，rail 不注册 | Warn build provider failed |
| mem0 缺 api_key / viking 缺 endpoint | isAvailable=false → nil | Warn unavailable |
| 未知 provider（含 agentarts） | loadPluginProvider → nil | Warn plugin_discovery not yet available |
| ResolveLtmDir mkdir 失败 | **整链 builder 返回 nil**（对齐 Python 异常传播路径：_resolve_ltm_dir 抛 → builder 外层 except → None） | Warn |
| RegisterRail 失败 | 保持未注册，下轮重试（既有行为） | Error |

### 热重载语义变化（修正后对齐 Python）

| 配置变化 | 迁移前 | 迁移后 |
|---|---|---|
| provider 清空（engine 仍 both） | rail 保持注册 | **rail 注销**（#5 修正） |
| mem0 配置从 config 转为 env-only | 失败 | env 回退生效 |
| kv_type 缺省 | memory 后端（进程内丢失） | **shelve 后端（持久化）** |

### 日志同步（规则 3）

逐条对齐 Python logger 调用（`[ExternalMemoryBuilder]`/`[external_memory]` 前缀 → 结构化 `event_type` 字段），组件 `ComponentAgentServer`（包内 forbidden.go 既有约定）。
