## 1. 本节在 agent 会话中的位置与作用

`ProactiveEngine` 是**旁路后台引擎**，不在 chat 请求链路上，不跑自有循环
（上游 docstring：`It does NOT run its own background tick loop`）。完整链路：

```
Gateway CronScheduler
  └─ cron job mode="proactive.tick"（由 proactive_cron_sync 按 config.enabled 自动注册/删除）
       │  默认 cron "20 0 * * * * *"（每小时整点后 20 秒错峰）；默认 target_channel "web"
       └─ WS 请求 proactive.tick { target_channel }
            └─ AgentServer handle_proactive_tick
                 └─ ProactiveEngine.tick_now(target_channel)
                      ├─ Step 0  注入回调检查 channel 有无活跃 agent（避免 evict 后白调 LLM）
                      ├─ Gate    当日计数 ≥ max_recommend_per_day → 推纯文本提醒后跳过
                      ├─ Step 1  build_situation_report()（扫 mode 前缀 agent 的会话 ≤10 个，
                      │            每会话最近 ≤20 轮压成 [User]/[Assistant] + MCP 日历）
                      ├─ Step 1.5 consume_feedback_buffer → update_gradients（反馈→策略梯度）
                      ├─ Step 2  _analyze_and_decide()：专用轻量 DeepAgent 单轮 invoke → JSON
                      │            → RecommendationDecision{type,target,reason,urgency}
                      │            skill_recommend 的 target 必须存在于候选 skill 集，否则 reject
                      ├─ Step 4  冷却 gate 已整段移除（去重由决策 LLM 看历史推荐承担）
                      ├─ Step 5  选投递会话（target_channel 优先，否则全局最活跃）
                      └─ Step 6  _trigger_main_agent() → 主 agent 跑一轮生成话术
                                 → 话术进主 agent context engine → 流式推前端
                                 → 送达后回调 _on_delivered 计数 + 写 recommendation_history
```

反馈回流（与 a 同节闭环）：

```
用户点赞/踩  → proactive.feedback → record_explicit_feedback → feedback_buffer
用户文本回复 → chat.send 入口 try_record_implicit_feedback → find_latest_recommendation
                                                    → record_implicit_feedback → feedback_buffer
下次 tick Step 1.5 批量消费 → gradient_updater → strategy_gradients（≤20）
                                         → 决策层规则 10 条喂 Step 2 / 话术层 10 条喂 Step 6
```

**作用一句话**：每小时一次「情境聚合 → 单轮 LLM 决策 → 主 agent 用自己的口吻说一条推荐」，
把推送内容嵌进主 agent 上下文，使后续对话能接上（这是它刻意不走裸 `model.invoke` 的原因）。

三种推荐类型（优先级从高到低）：`task_reminder`（待办/日程未闭环）→
`skill_recommend`（已装 skill 命中用户要做的事）→ `need_exploration`（从现有内容延伸新话题）。

func getBuiltinSkillsDir() string {
	resDir, err := pathutil.ResourcesDir()

> `:714` 去掉多余的 `filepath.Abs` 二次比较（`Abs` 不解析软链，反而漏判）。
>
> **语义澄清**：内置技能安装走 `copyDir` **复制**而非软链，两侧是不同实体 → `resolve()` 不等
> → 个人版下已安装的内置技能**可卸载**。这与 Python 注释一致：

> 因此原测试断言「内置技能应返回 false（不可删）」的用例是按企业版语义写的，
