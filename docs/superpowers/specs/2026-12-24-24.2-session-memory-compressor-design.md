## 1. 背景与现状

上游把上下文压缩扩展为两套并行链：旧链（`processor/compressor/`，Go 已迁移并修完 24-A 缺陷）与 **forked 链**（`processor/forked/`，上游产品默认 preset，41 文件/9,173 行，= 24.15）。异步会话记忆是 forked 链的"记忆侧减压层"：

- **写侧**（Go 已有，9.19-23 批交付）：`SessionMemoryManager`（1373 行）+ `ContextProcessorRail` 半区——after_model_call 时按 token 阈值（70%）调度后台更新，把"已完成 API 轮"的对话增量提炼为 15-section 会话笔记，pending→active 文件原子替换，runtime 维护 `notes_upto_message_id` 锚点。取消安全（per-session WithCancel + Shutdown 全表取消）已实现。
- **读侧**（本批交付）：`SessionMemoryCompressor`——token 达 80% 阈值时把笔记物化为 `<memory_block_session>` user message，替换锚点之前的原始消息；被替换消息整段归档并在笔记块尾部贴 `[[COMPRESSION_RECALL: id=…]]` 标记，供 compression_recall 工具（15b）捞回原文。

`notes_upto_message_id` 锚点语义：写侧用它决定增量摘要范围；读侧用它决定"锚点之后的消息保留原样、锚点之前的才可替换"。

Go `SessionMemoryAgentUpdater` 现为骨架（外部 `SetAgent` 注入，生产 0 调用方）；agent_edit 模式（默认 update_mode）执行体（Python `session_memory_agent.py` 260 行 + `forked_agent.py` 支撑类 + `_prime_notes_file_as_read` 注入）**不随本批**，⤴️ 已登记 24.15 行随 15b 回填。本批 direct_replace 路径完整可用。

### 2.2 配置与接线

1. **`CompressionRecallConfig`**（Python `schema/config.py`）：Go 新增类型（enabled=false / chunk_size_tokens=3000 / chunk_overlap_tokens=300 + overlap<size 校验）；`ContextEngineConfig` 加 `compression_recall` 键；`ModelContext` 加 `compression_recall_config()` 访问器（Python getattr 可调用协议 → Go 显式接口方法）；config.yaml 同步（默认关）。
2. **rail preset 装配**：`ContextProcessorRail.buildPresetProcessors` 插入 `SessionMemoryCompressor` 项（默认 disabled + 内嵌 SessionMemoryConfig + debug 旗标传播），槽位对齐 Python `_build_preset_processors` 顺序（Offloader 之后、Dialogue 之前；Offloader 本身属 15b，本批 preset 链只含 SessionMemory 一项 + 现有旧链四件，其余槽位 15b 补齐）。
3. **配置键**：沿用现有 `session_memory_config` 解析（`SessionMemoryConfigFromMap` 已有），`enabled` 同时驱动 ①Compressor trigger ②SessionMemoryManager 创建（Python `_maybe_setup_session_memory_manager` 同语义，Go rail 逻辑已对齐，只补配置合并到 Compressor）。
4. **`enable_context_debug` 旗标**：`ContextEngineConfig` 传播给 Compressor 与 context_debug 目录链。

### 2.3 取消安全核验

- `MaybeScheduleUpdate` per-session `WithCancel` + `Shutdown` 全表取消（已有实现）对照 Python `asyncio.Task` 语义补集成用例：会话中途 Shutdown 不留脏 pending、cancel 后不发生 commit、同 session 单飞跳过。
- Compressor 侧 `on_get_context_window` 为同步调用链（无后台任务），取消安全仅在 manager 侧。
