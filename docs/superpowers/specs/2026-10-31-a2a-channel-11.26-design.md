## 1. 背景与定位

11.26 是 uapclaw 对外**入站**暴露 A2A（Agent2Agent）协议能力的通道。外部 A2A 客户端（其它 Agent、编排器、MCP Hub）通过 HTTP JSON-RPC（含 SSE 流式）把本网关当成一个 A2A Agent 调用：先用 `/.well-known/agent-card.json` 读能力，再 `SendMessage` / `SendStreamingMessage` 拿结果。

前置资产全部就绪：11.1 BaseChannel ✅ / 11.2 ChannelManager ✅ / 11.3 MessageHandler ✅ / 11.7 SessionMap ✅ / 11.9 GatewayServer ✅ / 10.2.10 E2A A2A 适配器 ✅（**本节不消费，见 §8**）。因此 11.26 零前置依赖。

**出站 A2A（Agent 主动调外部 A2A）不在本节**：属领域九的 9.81 `openjiuwen/extensions/a2a/`（1192 行，A2AServer/A2AClient/A2ARemoteClient/A2AServerAdapter，状态 ☐），Python `docs/zh/A2A.md §7` 亦明确"当前仓库未包含"。

流程位置：

```
外部 A2A 客户端（a2a-sdk / a2a-go / 自研）
   │ ① POST {rpc_path}  JSON-RPC（A2A-Version: 1.0）
   │ ② GET  {card_path} Agent Card
   ▼
A2AChannel（独立 HTTP 监听，默认 127.0.0.1:19100）
   │ a2asrv.NewJSONRPCHandler → 11 方法分派 + 任务状态机 + SSE
   │ AgentExecutor.Execute：pending 队列 → a2a.Event
   │ on_message 回调（ChannelManager.RegisterChannel 注入）
   ▼
ChannelManager.onChannelMessage（存活检查 → 转发）
   ▼
MessageHandler.HandleMessage（req_method=chat.send，params={query,files?}）
   │ 注意：a2a 不在 controlChannelTypes，session_id(=context_id) 原样穿透
   ▼ E2A 协议（swarm/transport byte 管道）
AgentServer → Agent 会话
   │ 回程事件
   ▼
MessageHandler → robot_messages → ChannelManager.dispatchRobotMessages(channel_id="a2a")
   ▼
A2AChannel.Send(msg)：按 msg.ID 命中 pending → Executor 转 artifact/status 事件 → SSE
```

**作用**（四条）：

1. 入站协议适配：A2A `Message.parts` ⇄ 内部 `params.query` + `params.files`；内部 `payload` ⇄ A2A `Part`（文本 / 多模态 url·data·raw / 工具事件文本化）。
2. 对外自描述：`AgentCard` 名称/描述/版本/能力 + 单技能 `chat`，`capabilities.streaming=true`。
3. 状态机映射：`CHAT_ERROR → TASK_STATE_FAILED`、`CHAT_INTERRUPT_RESULT → TASK_STATE_CANCELED`、其余终态 `→ TASK_STATE_COMPLETED`；artifact 首块 `append=false`、终块 `lastChunk=true`。
4. 不建档：`params["a2a"]` 不写、E2A A2A 适配器不走（与 Python 一致）。

## 2. 拍板决策

| # | 决策 | 内容 |
|---|---|---|
| D1 | 协议实现口径 | 选 **P3：引官方 Go SDK** `github.com/a2aproject/a2a-go/v2 v2.7.0`。协议本身同一份（`a2a.Version = "1.0"`，与 `a2a-sdk 1.0.0` 的 `PROTOCOL_VERSION_1_0='1.0'` 一致），只是语言 SDK 版本不同。对比：手写服务端 1200-1500 行；严格复刻 Python 失效 bootstrap 约 300 行但功能不可用 |
| D2 | 对外服务面 | **JSON-RPC + Card + Extended Card** 三路由（REST/HTTP+JSON 与 gRPC 不挂，Python 侧无此线） |
| D3 | 基线声明 | Python `a2a_connect.py` 的**启动路径与其钉死的 SDK 1.0.0 不兼容**（详见 §2.1），故其"运行时行为"不可作为对齐基线；对齐基线改为「通道层语义 1:1 复刻 Python 源码 + 服务端行为 1:1 对齐 SDK 1.0.0 源码」 |
| D4 | 章节顺序 | 11.26 就地实施，不插队（零前置依赖；若后续需先铺 IM，则改为 11.24 platform_adapter → 11.16 飞书，本节顺延） |

### 2.1 基线失效证据（Python 侧 bootstrap 三处硬伤）

已按 `uv.lock` 地址解包 `a2a_sdk-1.0.0-py3-none-any.whl` 核验：

| 1 | `from a2a.server.apps import A2AFastAPIApplication`（L205） | 无 `a2a.server.apps` 模块（改为 `a2a.server.routes.create_jsonrpc_routes` + `create_agent_card_routes`，app 由用户自建） | ImportError |

## 3. 架构总览

```
┌─────────────────── uapclaw app 进程（12.7 单体） ───────────────────┐
│                                                                    │
│  AgentServer ←─E2A(ws/chan)─→ AgentClient                          │
│        ↑                                                           │
│  MessageHandler ←── ChannelManager ←── RegisterChannel(a2a)        │
│        │                    │ Send(msg)                            │
│        │                    ▼                                      │
│        │            A2AChannel（本包）                              │
│        │              ├ pending: map[requestID]chan *schema.Message │
│        │              ├ a2asrv.RequestHandler（任务状态机/存储/SSE） │
│        │              └ http.Server 127.0.0.1:19100                 │
│        │                ├ POST /a2a                                │
│        │                ├ GET  /.well-known/agent-card.json        │
│        │                └ GET  /agent/authenticatedExtendedCard    │
└────────────────────────────────────────────────────────────────────┘
                                ▲
                    外部 A2A 客户端（HTTP）
```

架构含义：

- A2A 与 Web/ACP 通道**并列而非嵌套**：自带 HTTP 监听，不注册 GatewayServer 路由（Python 同样只 `register_channel`），因此 `config.yaml` 的 `routes`/`route_bindings` 不涉及 a2a。
- A2A 通道内部把「协议栈」交给 SDK、把「网关桥」留给自己，边界与 Python 完全一致（Python 交 SDK 的是 FastAPI/uvicorn 三件套，Go 交 SDK 的是 `a2asrv` 三件套）。
- 会话维度：`a2a` **不在** `controlChannelTypes`（`message_handler/channel_state.go` L310-317，仅 feishu/xiaoyi/dingtalk/whatsapp/wecom/wechat），故 `ApplyChannelState` 早退，`session_id`(=A2A `context_id`) 不被 config 的 `channels.a2a.default_session_id` 覆盖，也不注入 `params["mode"]`。会话连续性完全由调用方的 `contextId` 承载。

### 4.3 A2AChannel（实现 `cm.BaseChannel`）

| 方法 | 行为 |
|---|---|
| `ChannelID()` | `Config.ChannelID` 去空回落 `"a2a"` |
| `ChannelType()` | `cm.ChannelTypeA2A`（Go 侧新增枚举，Python 无对应项，见 §9-D10） |
| `Config()` | 返回 `*A2AChannelConfig` |
| `IsRunning()` | 原子 `running` 标志 |
| `OnMessage(cb)` | 保存入站回调（由 `RegisterChannel` 注入 `cm.onChannelMessage`） |
| `Start(ctx)` | ① `running` 已真 → 直接返回；② `!Enabled` → Info 日志 `disabled by config` 并返回 nil（**对齐 Python L200-202**）；③ 建卡 → `a2asrv.NewHandler(exec)` → mux 三路由 → `net.Listen`；④ `go srv.Serve(ln)`；⑤ 等待 200ms 后检查 `Serve` 是否已带错返回，有错则向调用方返错（对齐 Python L263-267）；⑥ `running = true` + Info 日志带 URL |
| `Stop(ctx)` | ① `running=false`；② `srv.Shutdown(ctx)`；③ 遍历 pending 各投一条 `a2a_shutdown` 唤醒消息（`event_type=CHAT_ERROR`，`payload={"error":"a2a channel stopped","is_complete":true}`，对齐 Python L287-301）；④ 清空 pending；⑤ Info 日志 `stopped` |
| `Send(ctx,msg)` | `pending[msg.ID]` 命中则投递；未命中**静默丢弃**（对齐 Python L305-309） |

pending 表：`map[string]chan *schema.Message`，容量 64，`sync.Mutex` 保护。投递一律「非阻塞写 + 满则丢弃并 Warn」，避免 `MessageHandler` 出站派发被单个慢消费者阻塞（Python 的 `asyncio.Queue` 无界，属 Go 侧有意的背压差异，见 §9-D11）。

### 4.5 A2AAgentExecutor（`a2asrv.AgentExecutor`）

SDK 以 `iter.Seq2[a2a.Event, error]` 消费事件，逐条写入任务存储与订阅队列，并自动完成：任务建档、状态机推进、非流式聚合（把事件折叠为一个 `Task`）、SSE 分帧。我们只负责产出事件序列。

```
Execute(ctx, ec):
  ① yield a2a.NewSubmittedTask(ec, ec.Message)          // SDK 强制：首事件必须 Task/Message
  ② query, files := MapA2APartsToParams(ec.Message)
     query == "" → 尝试 JoinTextParts(ec.Message)；仍空 →
        yield StatusUpdate(FAILED) 并 return            // 对齐 Python L65-78
  ③ yield StatusUpdate(WORKING)                          // 对齐 Python L81-87
  ④ pending := DispatchA2ARequest(requestID=string(ec.TaskID), sessionID=ec.ContextID,
                                   query, files, metadata=ec.Metadata)
  ⑤ loop:
       msg, ok := <-pending；!ok → return
       parts := MessageToA2AParts(msg, fallbackToText=false)
       terminal := IsTerminalMessage(msg)
       if terminal && len(parts)==0 && msg.EventType==CHAT_ERROR → 用 fallbackToText=true 重取
       过滤 sentinel 文本 Part
       len(parts)>0 → yield TaskArtifactUpdateEvent{
                          Artifact{ID: taskID+"_response", Name:"response", Parts:parts,
                                   Metadata: msg.Metadata},        // 对齐 Python metadata=response_msg.metadata or None
                          Append: artifactStarted, LastChunk: terminal }
                      artifactStarted = true
       terminal → yield StatusUpdate(终态) 并 break
  ⑥ defer：ClearPendingRequest(requestID)

Cancel(ctx, ec):
  yield StatusUpdate(CANCELED)                            // 对齐 Python L164-176
```

`requestID` 取 `string(ec.TaskID)`：客户端带 `taskId` 续跑时即复用该 id，未带时由 SDK 生成。

### 4.6 a2a_parts.go（6 个映射函数 1:1）

| 函数 | 行为（逐条对齐 Python L348-500） |
|---|---|
| `MapA2APartsToParams(*a2a.Message) (string, []map[string]any)` | 遍历 `Parts`：`Text` 段收进 `textSegments`；有 `URL`/`Data`/`Raw` 之一则产 files 条目——`name`+`filename` 双键（`filename` 空则 `a2a_part_{idx}`，**idx 为 Part 原下标，含纯文本 Part**）、`media_type`+`type` 双键（原值非空才写）、`url`+`uri` 双键、`data` 附带 `encoding="base64"`、`raw` 原值。`query = strings.Join(nonEmpty(textSegments), "\n")` 再 `TrimSpace` |
| `MessageToA2AParts(*schema.Message, fallbackToText) []*a2a.Part` | ① `type=event && event_type=CHAT_ERROR` → 单 `TextPart(error → content → "agent request failed")`；② `payload.content` 为 string 且 trim 后非空且非 sentinel → TextPart；为标量（非 dict/list）→ `TextPart(str)`；③ `payload.result` 同上（string + 非 sentinel）；④ `CHAT_TOOL_CALL` 且 `payload.tool_call` 是对象 → `TextPart("[tool_call] "+name||"tool")`；⑤ `CHAT_TOOL_RESULT` → `payload.result` 为 string 且非空 → `TextPart("[tool_result:<tool_name>] "+result)`（无 tool_name 用 `[tool_result] `）；⑥ `payload.files[]` → 逐项 `URL`/`Data`/`Raw` 三类 Part，附 `Filename`/`MediaType`；⑦ 无产出时按 `fallbackToText` 决定是否回退 `MessageToText` |
| `IsCompletionSentinelText(string) bool` | 去掉**所有**空白后 lower ∈ `{'is_complete':true}` / `{"is_complete":true}` |
| `IsTerminalMessage(*schema.Message) bool` | `type=="res"` → true；非 event → false；`CHAT_ERROR`/`CHAT_INTERRUPT_RESULT` → true；`payload.is_complete == true`（严格 bool）→ true |
| `BuildRequestParams(query, files)` | `{"query":…}`，`files` 非空才加键 |
| `MessageToText(*schema.Message) string` | CHAT_ERROR 优先 `error→content→"agent request failed"`；`content` 键存在取字面；payload 非空整体字符串化；否则 `""` |

## 5. 数据流与关键时序

### 5.1 非流式 `SendMessage`

```
客户端 POST /a2a {method:"SendMessage", params:{message:{messageId, contextId, role:"ROLE_USER", parts:[{text}]}}}
  → SDK 分派 onSendMessage → RequestHandler.SendMessage → 起 Execute 协程 + 本地订阅
  → Execute 事件序列：Task(submitted) → StatusUpdate(WORKING) → [ARTIFACT...] → StatusUpdate(COMPLETED)
  → SDK 聚合为 Task（含 history=入站 Message、artifacts、status）
  ← {"jsonrpc":"2.0","id":…,"result":{"task":{…,"status":{"state":"TASK_STATE_COMPLETED"}}}}
```

实测样例（原型验证）：

```json
{"result":{"task":{"id":"01a19240-…","artifacts":[{"artifactId":"…_response","name":"response",
  "parts":[{"text":"hello-from-gateway"}]}],"contextId":"c1",
  "history":[{"messageId":"m1","contextId":"c1","parts":[{"text":"ping"}],"role":"ROLE_USER"}],
  "status":{"state":"TASK_STATE_COMPLETED","timestamp":"2026-10-31T13:57:13.674Z"}}}}
```

### 5.2 流式 `SendStreamingMessage`

`Content-Type: text/event-stream`，每帧 `data: {"jsonrpc":"2.0","id":…,"result":{"artifactUpdate"|"statusUpdate":{…}}}`。
artifact 首帧 `append` 缺省（false）、末帧 `lastChunk:true` 且紧接终态 `statusUpdate`；`CHAT_ERROR` 导致终态 `TASK_STATE_FAILED`，`CHAT_INTERRUPT_RESULT` 导致 `TASK_STATE_CANCELED`。

### 5.3 停止唤醒

`Stop` 时向每个在途 pending 投 `a2a_shutdown`（`CHAT_ERROR` + `is_complete:true`）→ executor 读到后产出 FAILED 终态并结束 → 客户端收到失败而非挂死（对齐 Python L287-303）。

### 5.4 取消 `CancelTask`

SDK 收到 `CancelTask` → 调 `executor.Cancel` → 产 `StatusUpdate(CANCELED)`。注意与 5.2 的"Agent 中断"区分：后者由 `CHAT_INTERRUPT_RESULT` 触发，不经 `Cancel`。

## 6. 协议面与错误矩阵

方法集（与 Python `METHOD_TO_MODEL` 完全一致，由 SDK 分派）：

| 方法 | 处理者 |
|---|---|
| `SendMessage` / `SendStreamingMessage` | 本节的 executor |
| `GetTask` / `ListTasks` / `CancelTask` / `SubscribeToTask` | SDK（内存 TaskStore + 订阅） |
| `GetTaskPushNotificationConfig` / `Create…` / `List…` / `Delete…` | SDK（未配置 push → `PUSH_NOTIFICATION_NOT_SUPPORTED`） |
| `GetExtendedAgentCard` | SDK（未配置 → `EXTENDED_CARD_NOT_CONFIGURED`） |

错误矩阵（SDK 统一产出，JSON-RPC `error.code`）：

| 场景 | code | reason |
|---|---|---|
| 请求头缺 `A2A-Version` 或 ≠1.x | `-32009` | `VERSION_NOT_SUPPORTED` |
| 未知方法 | `-32601` | `METHOD_NOT_FOUND` |
| params 反序列化/校验失败 | `-32602` | `INVALID_PARAMS` |
| executor 首事件非 Task/Message、内部 panic | `-32006` / `-32603` | `INVALID_AGENT_RESPONSE` / `INTERNAL` |
| 非法 JSON | `-32700` | `PARSE_ERROR` |

## 9. 偏差归档

| # | 偏差 | 原因 / 处置 |
|---|---|---|
| D1 | 首事件必须为 `Task`/`Message`（用 `NewSubmittedTask`），不能像 Python 直接发 WORKING status | `a2asrv` 实测约束：`-32006 first event must be a Task or a message`；Python 有 SDK 预建 task 故可直接发 status |
| D2 | `protocolBinding` 用 `"JSONRPC"`（Python 写小写 `"jsonrpc"`） | 两侧 SDK 规范常量均为 `JSONRPC`/`GRPC`/`HTTP+JSON`；Python 小写属 lax string（proto 字段为 `str` 不校验），会破坏客户端 transport 匹配 |
| D3 | task/context id 为 SDK 生成的 UUID，不保留 Python 的 `a2a_<12hex>` / `a2a_ctx_<8hex>` 格式 | `a2asrv` 无可注入 ID 生成器（`a2a.NewTaskID()` 内部生成） |
| D4 | `Part.Raw` 走 base64 解码；Python 传 `str` 给 proto `bytes` 会抛 TypeError | 修正而非复刻（仅 payload/files 带 `raw` 时触发） |
| D5 | `MessageToText` 的"整块 payload 字符串化"形态与 Python `str(dict)` 不同 | 仅非 content/error 分支的兜底文案，不进入协议字段 |
| D6 | Extended card 未配置 → `EXTENDED_CARD_NOT_CONFIGURED` | Python 该路径在 1.0.0 下不可达（bootstrap 失效），取 SDK 既定语义 |
| D7 | `A2A-Version` 缺失按 0.3 处理并拒绝（`-32009`） | SDK 既定语义，与 Python SDK 一致；代价：文档示例必须带头（Python 文档示例缺该头，本身跑不通） |
| D8 | 启动失败日志给真实原因，不再输出"请安装 `[a2a]` extra" | Python `_raise_missing_a2a_sdk` 在 1.0.0 下属错误归因 |
| D9 | 品牌串映射：`JiuwenClaw → UapClaw`、`jiuwenswarm → uapclawswarm` | 项目既有品牌约定 |
| D10 | 新增 `ChannelTypeA2A` 枚举 | Python `ChannelType` 无 a2a；Go `BaseChannel` 强制要求 `ChannelType()`，且 A2A 必须 `RegisterChannel` |
| D11 | pending 队列有界（64）+ 满则丢弃告警；Python 为无界 `asyncio.Queue` | 避免 `dispatchRobotMessages` 被单个慢消费者阻塞；丢弃时打 Warn 保证可观测 |
| D12 | 不再有 `_pending` 的 `finally: pass` 空转（Python L341-343 死逻辑） | 无行为差异，Go 侧不写死代码 |
| D13 | JSON-RPC 路由包一层 POST-only（非 POST → 405） | `a2asrv.NewJSONRPCHandler` 对任意 HTTP 方法都回 200；Python `create_jsonrpc_routes` 显式声明 `methods=['POST']`，故按 Python 对齐 |
| D14 | 扩展卡双出口：HTTP 路由用 `AgentCardProducer`（`NewAgentCardHandler`）、JSON-RPC `GetExtendedAgentCard` 用 `WithExtendedAgentCardProducer`，两者返回同一张卡 | Go SDK 没有「扩展卡 HTTP 路由」的现成 handler（`ExtendedAgentCardProducerFn` 只服务 RPC 方法）；D6 的落地形态 |
| D15 | 依赖传递升级：`grpc v1.79.3→v1.83.2`、`protobuf v1.36.10→v1.36.11`、`genproto/googleapis/{api,rpc}`、`gonum v0.16.0→v0.17.0` | `a2a-go/v2` 的 go.mod 显式要求这些版本，MVS 取最大值；本包只 import `a2a`/`a2asrv`（标准库 + uuid + x/sync），升级项不参与新包编译，但会牵动既有依赖链，以全量回归兜底（已通过 294 包） |

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| `a2asrv` 事件语义强约束（首事件、状态机顺序、artifact 归属），实施中可能再撞约束 | 已用最小原型验证主路径；实施首步写「executor 事件序列」单测，先定契约再接 HTTP |
| 版本头严格导致手工 curl 全部失败 | 文档与 e2e 统一带 `A2A-Version: 1.0`；启动日志打印该提示 |
| 19100 端口冲突（与 Web 19001/ACP 端口相邻） | `Start` 返错 → gateway 记 Error 继续启动（不阻塞）；文档提示改 `A2A_SERVER_PORT` |
| 第三方 SDK 演进（v2 主路径仍在加版本） | go.mod 精确钉 `v2.7.0`；包内仅依赖 `a2a`/`a2asrv` 两个稳定面，不用 alpha 能力 |
| 流式与 `MessageHandler` 出站节奏不匹配（首块 artifact 可能只有 sentinel） | sentinel 过滤后空 parts 不产事件（Python 同），终态仍会补 `lastChunk` 前的最后一块 |
