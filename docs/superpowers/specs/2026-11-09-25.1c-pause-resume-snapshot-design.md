# 25.1c + 25.1e 合并交付设计：pause/resume、快照回滚与成员 turn 身份

> 本 spec 覆盖 **25.1c（pause/resume + 快照回滚）** 与 **25.1e（成员 turn 身份）**，两节一次交付。
> 同时收口 2026-11-07 48h 审查中挂在本节点回填的 S-01 / S-02 / M-01 / T-02 / T-03，并按 B+ 口径补上
> `pending_resume` 冷恢复、生命周期接线（kernel / StreamController / AgentServer）与网关流治理。
> 25.1d（异步工具）、25.1f（native_v2）不在本节。

## 1. 背景与流程位置

### 1.1 调用链（用户点“暂停”到成员脑停下）

```
前端 chat.cancel{intent:pause|resume}
  → 网关 message_handler.forwardLoop → handlePauseResume
      → sendInterruptToAgent（异步转给 AgentServer）
      → pause 在 AgentServer ack 后取消同 session 的团队流消费者（G2 / issue 5448）
  → AgentServer ProcessInterrupt → isTeamMode → processTeamInterrupt
      → TeamManager.PauseSessionRuntime → Runner.PauseAgentTeam
  → TeamRuntimeManager.Pause → TeamAgent.PauseCoordination
  → CoordinationKernel.Pause
      → StreamController.PauseAgent
  → TeamHarness.Pause → NativeHarness.Pause（入队 cmdPause，supervisor 单写者执行）
  → supervisor.onPause：
        · MODEL 相位（LLM 已发起、tool_calls 未提交）→ 硬取消 + 回滚到最近迭代边界
        · TOOL / BOUNDARY 相位 → 置 pause_requested，由 PhaseSnapshotRail 在下一个
          model-call 边界 force_finish（工具必须跑完，副作用不可逆）
      → 结算为 PAUSED，context 停在干净边界
  → resume：StreamController.ResumeAgent → NativeHarness.Resume → startRound(RESUME_CONTINUATION)
```

### 1.2 作用

- **暂停是就地停车，不是毁掉本轮**：已完成的迭代保留在上下文里，`resume` 从断点续跑，不追加新 user turn。
- **快照轨提供回滚目标**：迭代边界（`last_iter_snapshot`）、轮边界（`last_safe_snapshot`）、轮前基线（`pre_round_snapshot`）。
  暂停与硬中止都回滚到“最近一个干净边界”，保证上下文与 `DeepAgentState` 不残留半轮。
- **`round_aborted` 标记**：已转发给消费者的半轮 chunk 收不回，用 marker 让消费者丢弃该轮输出。
- **turn 身份**：一个 Team trace 里每个成员的每轮工作需要可区分；turn 号跨 run cycle 递增，供轨迹/观测映射。

### 4.1 `RoundPhase`（新）

### 4.2 `SafeStateSnapshot`（新）

```go
// SafeStateSnapshot 迭代/轮边界处捕获的可回滚快照。
// Python: SafeStateSnapshot (state.py L42-59)
type SafeStateSnapshot struct {
	// ContextMessages 当前轮上下文消息（with_history=False 段）的独立副本
	ContextMessages []llmschema.BaseMessage
	// DeepAgentState DeepAgentState.ToSessionDict() 的结果
	DeepAgentState map[string]any
	// IterationIndex 轮前基线为 0；其余为刚完成那一轮的 1-based 序号
	IterationIndex int

```

`ContextMessages` 必须是副本（`append([]llmschema.BaseMessage(nil), msgs...)`）：
`GetMessages` 的返回切片可能与内部缓冲共享底层数组，回滚时若被后续写入影响，快照即失真。

## 5. 快照轨

### 5.1 `captureSnapshot`

```go
// captureSnapshot 捕获当前轮上下文消息 + DeepAgentState。
// Python: capture_snapshot (snapshot_rail.py L48-92)
func captureSnapshot(
	agent *agentcore.DeepAgent,
	sess sessioninterfaces.SessionFacade,
	previous *SafeStateSnapshot,
	index *int,
) *SafeStateSnapshot
```

步骤（顺序与上游一致）：
1. `react := agent.ReactAgent()`；`context := react.ContextEngine().GetContext(reactContextID, sess.GetSessionID())`
2. `context != nil` → `msgs, _ := context.GetMessages(0, false)`；否则空切片
3. `state := agent.LoadState(sess).ToSessionDict()`
4. `index == nil` → `previous.IterationIndex + 1`（`previous == nil` 时为 1）；否则用 `*index`

**contextID 取值**：`reactContextID = "default_context"`。这是 Go 内层 ReAct 实际创建/写入的上下文
（`react_helpers.initContext` 与 `react_invoke` 均使用该值）。上游默认值是 `"default_context_id"`，
但 Go 的 `DeepAgent.CreateNewContextEngine` 另用 `"default_context_id"`；若取错，快照恒空、回滚静默失效。
故：捕获前 `context == nil` 必须打 Warn 日志（`event_type=HARNESS_SNAPSHOT_NO_CONTEXT`），并登记偏差 D-3。

### 5.2 协作停止载荷

```go
// COOPERATIVE_STOP_TYPE 协作停止的 result_type。
// Python: COOPERATIVE_STOP_TYPE = "cooperative_stop"（snapshot_rail.py L101）
const cooperativeStopType = "cooperative_stop"

// cooperativeStopResult 内层循环在干净迭代边界强制收尾的载荷。
var cooperativeStopResult = map[string]any{"result_type": cooperativeStopType}
```

### 5.3 `PhaseSnapshotRail`

```go
// PhaseSnapshotRail 跟踪内层循环相位、捕获边界快照、驱动协作停止。
// Python: PhaseSnapshotRail (snapshot_rail.py L105-240)
type PhaseSnapshotRail struct {
	agentinterfaces.BaseRail
	// harness 反向引用；ContextVar 在 TaskScheduler 执行协程里读不到，必须直连
	harness *NativeHarness
}
```

- 构造：`&PhaseSnapshotRail{BaseRail: *agentinterfaces.NewBaseRail().WithPriority(1000), harness: h}`
- 注册：`NewNativeHarness` 内、`ApplyDeepAgentParts` 之后 `h.agent.AddRail(snapshotRail)`（对齐上游 `self.add_rail(self._snapshot_rail)`）。
  事件路由由 `DeepAgent` 的 `bridgeEvents` 自动完成：model/tool/react-iteration 走内层 ReActAgent，
  `AFTER_TASK_ITERATION` 留外层 DeepAgent。
- `GetCallbacks()` 用 `BuildCallbacks(CallbackFrom(...))` 声明 5 个钩子。

| 钩子 | 行为 |
|---|---|
| `BeforeModelCall` | `IterPhase=MODEL`；`ModelCallInFlight=true`；`PauseRequested‖GracefulAbort` → `cbc.RequestForceFinish(cooperativeStopResult)` |
| `AfterModelCall` | `ModelCallInFlight=false`；仅 `PauseRequested` → force_finish（优雅中止必须跑完本轮工具） |
| `BeforeToolCall` | `IterPhase=TOOL`；`ToolStarted=true`；**永不** force_finish |
| `AfterReactIteration` | `IterPhase=BOUNDARY`；`ToolStarted=false`；`LastIterSnapshot=captureSnapshot(..., previous=LastIterSnapshot)` |
| `AfterTaskIteration` | `LastSafeSnapshot=captureSnapshot(..., previous=LastSafeSnapshot)` |

`active := r.harness.st.Active()`；为 nil 时所有钩子直接返回（对齐上游 `if active is None: return`）。
`ctx.Session()` 为 nil 时跳过快照并打 Warn（迭代边界）/静默返回（轮边界，对齐上游）。

## 6. pause / resume / abort 状态机

### 6.1 `Pause` 入口

`NativeHarness.Pause(ctx)` → 入队 `cmdPause{reply}` → `waitAck`。
**删除** `ErrPauseUnsupported` 与 `dispatch` 里的哨兵分支。

### 6.2 `onPause`（supervisor）

```
phase := st.Phase()
if phase != RUNNING: ack(nil); return            // PAUSING/PAUSED/IDLE/TERMINATED 幂等
active := st.Active()
if active == nil: transition(PAUSED); ack(nil); return

st.pausedQuery = queryText(active.OriginalQuery) // InteractiveInput → ""
st.hasPausedQuery = true

active.PauseRequested.Store(true)                // 先 arm：正确性权威

if active.ModelCallInFlight.Load():
    hardCancelRound(active)                      // 取消 + 等轮协程退出
    rollbackToSnapshot(firstNonNil(active.LastIterSnapshot, active.PreRoundSnapshot))
    resetCoordinator()
    emitRoundAborted(active.RoundID, "pause")
    emitRound("paused", active.RoundID)
    st.SetActive(nil)
    transition(PAUSED)
    ack(nil)
    return

active.PauseAck = cmd.reply                      // 延迟到轮末结算
transition(PAUSING)
```

辅助函数：

```go
// queryText 把本轮查询压平成可重放的纯文本。
// Python: _query_text (native_harness.py L120-131)
// string → 原样；[]string → "\n" 连接；*InteractiveInput → ""（单轮载荷不可重放）
func queryText(query any) string

// hardCancelRound 取消在飞轮次并等其协程退出。
// Python: _hard_cancel_round (native_harness.py L1527-1574)
// Go 无 scheduler.cancel_task，取消即 active.Cancel()；
// 等 Done 不设超时（cmdRoundFinished 已去 ack，Done 会及时关闭），
// 由 supervisor ctx 兜底避免永久阻塞。
func (h *NativeHarness) hardCancelRound(ctx context.Context, active *ActiveRound)
```

### 6.3 `onResume`

```
phase := st.Phase()
switch {
case phase == PAUSED:
    query = st.pausedQuery
case phase == IDLE && cmd.query != nil:
    query = toString(cmd.query)                  // 冷恢复
default:
    ack(nil); return                             // no-op
}
st.pausedQuery = ""; st.hasPausedQuery = false
active := startRound(query, startModeResumeContinuation, nil)
transition(RUNNING)
emitRound("started", active.RoundID)
ack(nil)
```

### 6.4 `onSend` 的 PAUSED 分支

```
case PAUSED:
    if _, ok := msg.Content.(*interaction.InteractiveInput); ok {
        st.pausedQuery = ""; st.hasPausedQuery = false
        active = startRound(msg.Content, startModeDefault, nil)
    } else {
        query := st.pausedQuery
        st.pausedQuery = ""; st.hasPausedQuery = false
        active = startRound(query, startModeResumeContinuation, nil)
        steerActive(msg.Content)                 // 新内容 steer 进续跑轮
    }
    transition(RUNNING)
    emitRound("started", active.RoundID)
```

> `InboxMessage` 无 `RunContext`（偏差 D-5），故新轮 runContext 传 nil；25.2 引入 `run_context` 后改为透传。

> **与计划旧文本的差异**：`IMPLEMENTATION_PLAN.md` 原写“resume = 原话与新话拼接重来”，那是上游已废弃的
> legacy 行为（会丢掉暂停轮已完成的全部迭代）。本 spec 采用上游现行语义：**续跑 + steer**，并同步修正计划文本。

### 6.5 `onAbort`

```
phase := st.Phase()
if phase == IDLE: ack(nil); return
if phase == PAUSED:
    st.pausedQuery = ""; st.hasPausedQuery = false
    transition(IDLE); ack(nil); return

active := st.Active()
if active == nil: transition(IDLE); ack(nil); return

// abort 取代仍在等边界的协作暂停
if active.PauseRequested.Load():
    active.PauseRequested.Store(false)
    resolvePauseAck(active)

if cmd.immediate:
    hardCancelRound(active)
    rollbackToSnapshot(firstNonNil(active.LastIterSnapshot, active.PreRoundSnapshot))
    resetCoordinator()
    emitRoundAborted(active.RoundID, "abort")
    emitRound("aborted", active.RoundID)
    st.SetActive(nil)
    transition(IDLE)
else:
    active.GracefulAbort.Store(true)
    if phase == PAUSING: transition(RUNNING)     // 协作暂停升级为优雅中止
ack(nil)
```

关闭 25.1a 偏差 D-2（`abort(immediate=true)` 不回滚）。

### 6.6 `emitRoundAborted`

```go
// emitRoundAborted 投递“本轮已作废”标记，让消费者丢弃已收到的半轮 chunk。
// Python: _emit_round_aborted (native_harness.py L1675-1688)
chunk := stream.OutputSchema{
	Type:    "round_aborted",
	Index:   0,
	Payload: map[string]any{"round_id": roundID, "kind": kind},
}
```

写入采用**非阻塞**：`select { case h.queue <- chunk: default: Warn("output queue full, round_aborted dropped") }`。
Python 是无界队列永不丢；Go 队列 256，supervisor 阻塞会死锁，故以“丢标记 + 大声告警”换活性（偏差 D-2）。

### 6.7 `rollbackToSnapshot`

```go
// Python: _rollback_to_snapshot (native_harness.py L1694-1734)
if sess == nil || react == nil { return }
context := react.ContextEngine().GetContext(reactContextID, sess.GetSessionID())
if snapshot != nil && context != nil {
    context.SetMessages(snapshot.ContextMessages, false)   // with_history=false
    if restored, err := hschema.DeepAgentState{}.FromSessionDict(snapshot.DeepAgentState), error(nil); err == nil {
        h.agent.SaveState(sess, restored)
    } else {
        Error("failed to deserialize DeepAgentState; skipping state rollback")
    }
    Info("rolled back", iteration, msgs)
    return
}
react.ClearContextMessages(ctx, sess)                      // 无快照：只清本轮段
Info("no snapshot; cleared current-round messages")
```

`FromSessionDict` 在 Go 侧不返回 error（畸形输入退化为默认值），因此“反序列化失败”分支在 Go 中不可达；
保留 `ClearContextMessages` 退化路径，该语言差异登记为偏差 D-11。

## 7. 轮次驱动与结算

### 7.1 `startRound`

```go
// Python: _start_round (native_harness.py L1287-1359)
func (h *NativeHarness) startRound(query any, mode startMode, runContext *agentinterfaces.RunContext) *ActiveRound
```

步骤：
1. `roundID := st.NextRoundID()`；`taskID := uuid.NewString()`
2. `preRound := captureSnapshot(h.agent, h.sess, nil, intPtr(0))`
3. `keepsTurn := mode ∈ {continuesTurn, failureRetry, resumeContinuation} || query 是 *InteractiveInput`
4. `turn, opened := ResolveMemberTurn(h.sess, keepsTurn)`
5. 构造 `ActiveRound{...}` 并 `st.SetActive`
6. `go h.runRound(roundCtx, active)`
7. Info 日志：round_id / query 前 120 字符 / follow_up / turn 号 / opened

`startMode` 枚举：`startModeDefault`、`startModeFollowUp`、`startModeFailureRetry`、`startModeResumeContinuation`、`startModeContinuesTurn`。

### 7.2 `runRound`

对齐 `_run_round`（L1361-1447）：
1. `commitOpenedTurn`：`TurnOpened` 为真时 `sess.Commit(ctx)`，失败只 Debug 日志（turn 编号不如成员工作重要）
2. 构造 `InvokeInputs{Query: toInvokeQuery(active.OriginalQuery), ConversationID: sess.GetSessionID(), RunContext: active.RunContext}`
   与 `cbc := agentinterfaces.NewAgentCallbackContext(h.agent, inv, sess)`
3. `cbc.FireLifecycle(ctx, CallbackBeforeInvoke, CallbackAfterInvoke, func() error { ... })` 包住：
   - `controller.SubmitRound(ctx, sess, queryText, isFollowUp, true, RunKindNormal, runContext, WithTaskID(taskID), WithTurnNumber(turn.TurnNumber), WithResumeContinuation(bool))`
   - `result = controller.WaitRoundCompletion(ctx, nil)`
   - `isControlResult(result)` 为假时 `WriteRoundResultToStream`
   - `inv.Result = nil`（控制结果）或 `result`
4. 轮协程 `finally`：投递 `cmdRoundFinished{roundID, result, err}`（**无 ack、不等待**，偏差 D-4）

`SubmitRound` 的两个新选项（`task_loop/controller.go`）：
- `WithTurnNumber(int)` → metadata `_turn_number`
- `WithResumeContinuation(bool)` → metadata `_resume_continuation`

`task_loop/executor.go` 在构建 `effective` 时透传这两个键（对齐上游 executor L231-234）：

```go
if v, ok := task.Metadata["_turn_number"]; ok && v != nil {
    effective["_turn_number"] = v
}
if v, ok := task.Metadata["_resume_continuation"]; ok && v == true {
    effective["_resume_continuation"] = true
}
```

`normalizeInputs` 已把 `_` 前缀键收进 `InvokeInputs.Extra`，无需再改。

**核心 ReAct 改动（必需，否则续跑会重复 user turn）**：`single_agent/agents/react_invoke.go` 需读
`curInputs.Extra["_resume_continuation"]`，并：
1. 空 query 校验放宽：`plainText == "" && !IsInteractiveInput() && !resumeContinuation` 才报错
   （Python: `if not user_input and not resume_continuation: raise`，react_agent.py L2989-2991）
2. `else` 分支的 `admitUserMessage(..., "query", "")` 仅在 `!resumeContinuation` 时执行
   （Python: `elif not resume_continuation:`，L3081）

> 注意：续跑轮的 `originalQuery` 是**非空**的 `pausedQuery`，所以“空 query 自动跳过 admit”的既有守卫
> 挡不住重复；必须显式读 `_resume_continuation`。
>
> `_turn_number` 的消费方（`ctx.extra["_turn_number"]` → span 属性）属领域二十二；本节点只保证元数据
> 到达 `InvokeInputs.Extra`，不新增 `InvokeInputs.TurnNumber` 字段（上游同样走 dict 键而非类型字段）。

### 7.3 `settleRoundDone` 全序

对齐 `_settle_round_done`（L1098-1237），**顺序不可调换**：

1. 记录 `wasGraceful := active.GracefulAbort`、`isResume := originalQuery 是 *InteractiveInput`
2. `resultError`、`taskFailed`（排除 `cancelled` / `no active round`）、`runtimeCrashed := cmd.err != nil`
3. `st.SetActive(nil)`
4. **协作暂停**：`active.PauseRequested && !runtimeCrashed && !taskFailed` → `emitRound("paused")` → PAUSED → `resolvePauseAck` → return
5. 事件：`err` → `failed`；`taskFailed` → `failed`；否则 `finished`
6. `sess == nil || coordinator == nil` → IDLE
7. `coordinator.IncrementIteration()`；`SetLastResult`；落 `StopConditionState`
8. `wasGraceful` → `drainFollowUpsDiscard(sess)` → IDLE
9. `runtimeCrashed` → `resetCoordinator()`；`replayable && !active.FailureRetry` → `startRound(originalQuery, failureRetry)`；否则 Warn + IDLE
10. `result_type == "interrupt" || coordinator.IsAborted()` → IDLE
11. 外部待驱动队列非空 → 连续字符串合批（遇 `*InteractiveInput` 停止，单独成轮）→ `startRound(batch, followUp, nil)`（偏差 D-5：Go 无 `run_context`，不做上下文切分）
    批量以 `[]string` 交给 `startRound`：`runRound` 用 `queryText` join 出提交查询，同时 `WithInputParts` 把未 join 的批次写进
    metadata `_input_parts`，经 handler/executor 传到 `effective`，使 ON_USER_MESSAGE rails 仍能看到单条输入（偏差 D-13）
12. 内部 follow-ups（controller + `state.pending_follow_ups`）→ 合并成一批 → `startRound(batch, followUp, nil)`
13. `isResume` → IDLE（resume 单轮语义）
14. `hasRemainingTasks() && originalQuery 非空` → `startRound(originalQuery, continuesTurn, nil)`
15. IDLE

`resolvePauseAck` 必须在**每条路径**的 `defer` 里执行（含崩溃/失败），否则 `Pause()` 调用方永久阻塞。

### 7.4 `isControlResult`

```go
// Python: _is_control_result (L1484-1494)
return result != nil && (nonEmptyString(result["error"]) || result["result_type"] == cooperativeStopType)
```

收口 M-01：补 `cooperative_stop` 分支，避免协作停止载荷被写成回答、发 `chat.final`。

### 7.5 每轮 BEFORE/AFTER_INVOKE

`runRound` 用 `cbc.FireLifecycle` 包住轮次主体，原因：supervisor 绕过 `DeepAgent.Invoke`，
invoke 级回调在 harness 路径上没有别的触发点，每个外圈轮就是一个逻辑 invoke。
`ctx` 取消时 `FireLifecycle` 自动跳过 AFTER（已有实现），与上游 `lifecycle()` 一致。

> 实施前置检查：`grep` 已注册的 `BeforeInvoke`/`AfterInvoke` rail（`stream_event`、`task_completion`、
> `task_planning`、`progressive`、`security`、`model_anomaly`、`context_processor`、`skill_use`、`user_hook`），
> 确认它们在团队路径上当前**零触发**（supervisor 绕过 Invoke），补齐后不会二次触发。

| I-02 | model 相位暂停 | 半轮消息被回滚；`round_aborted{kind:"pause"}` 到达消费者 |
| I-03 | immediate abort | 上下文回退到最近边界；marker 到达；成员回 IDLE |
| I-04 | kernel pause | 成员相位 PAUSED（不是 TERMINATED）；前台流被取消；可续跑 |
| I-05 | pause → stop → start（冷恢复） | 新 harness 自动续跑；`pending_resume` 被清除 |
| I-06 | 网关 pause | 团队流消费者被取消；单 agent 流保留；`is_processing=false` |

集成审计要求：每条用例真实跨越 ≥3 个 internal 二级子系统（harness / task_loop / session / agent_teams / gateway）。
