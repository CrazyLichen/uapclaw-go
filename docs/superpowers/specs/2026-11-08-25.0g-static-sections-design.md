## 1. 流程位置与作用

### 1.1 在 agent 会话里的位置

```
成员 TeamAgent 构造（agent_configurator.go 步骤 10）
  └─ buildTeamPolicyRail → NewTeamPolicyRail
       ├─ [本节] buildStaticSections(...)       ← 构造期一次，之后永不重建
       │    ├─ role == LEADER  → buildLeaderSections()      （1~3 段）
       │    └─ role != LEADER  → BuildTeamStaticSections()  （最多 9 段）
       ├─ [本节/D-3 闭环] policyText = <team-policy> 块
       │    条件：role == LEADER && bootstrapMode == "framework"
       └─ tracker.NewTeamContextTracker(..., policyText)

每轮模型调用前（BeforeModelCall）
  │   for s := range staticSections { builder.AddSection(s) }   ← 静态前缀，每轮重插
  └─ announceUnattachedState → PendingText → 追加历史

每段被受理的用户输入（OnUserMessage）
  ├─ dropSuperseded(parts)                         ← 25.0a
  ├─ 前插 <team-clock>                             ← 25.0b inboundtags
  ├─ foldTaskOutcomes                              ← 25.0c 三兄弟
  ├─ queueTeamContextAttachment（team.context 附件，priority=80）
  │     └─ tracker.PendingText → composeBlocks(identity, info, policy, roster)
  │           policy 块 ← [本节] policyText（sha256 基线，变了才重投）
  └─ 兜底：PendingText 直接前插

leader 调用 build_team 工具
  └─ BuildTeamTool.Invoke → [本节] MapResult
       ├─ 首行 "Team created:" / "Existing team taken over:"   ← 本次新增
       ├─ 接管提示语 / task_verification 回带                    ← 本次新增
       └─ 追加 BuildLeaderPolicyDisclosure(...)                 ← 本次新增（F_76）
```

### 1.2 两件事的分工

| | 系统提示词（`buildTeamStaticSections`） | 对话历史（`TeamContextTracker`） |
|---|---|---|
| **内容** | 角色策略、HITT 契约、bridge 自契约、工作流、任务下发、任务状态机、生命周期、用户附加提示、入站标签说明 | 本成员身份、团队元信息、政策块、同伴名册 |
| **会变吗** | 不变。同一角色的所有成员逐字节相同 → KV 缓存前缀可共享 | 会变。增量宣告，基线记在成员 session state |
| **谁负责** | 本节 25.0g | 25.0c（已完成） |
| **leader 特殊情况** | 只留 `team_bootstrap`（或 `team_prebuilt`）+ 可选 `team_bound_group` + `team_extra`；其余全部延迟到 `build_team` 工具结果 | 同上，额外承载 `policyText` |

上游原文（`sections.py` 模块 docstring）："Team *state* is not a section at all"。

### 1.3 缺了会怎样

| 缺失项 | 后果 |
|---|---|
| `team_dispatch`（P:15） | 成员不知道任务怎么到自己手上（自主认领 vs 调度指派）；leader 不知道要 `create_task(assignee=...)` 还是等成员 `claim_task` |
| `team_task_state`（P:16） | leader 不知道状态机有哪些状态、哪些转换、验证闸怎么触发；会把 autonomous 模式写出 `in_review` 导致任务永久卡死 |
| `team_bridge`（P:12） | BRIDGE_AGENT 不知道自己只是"调度员"，会试图自己生产内容 |
| leader 分支（bootstrap/prebuilt） | leader 前缀仍塞着 teammate 的全套策略，但拿不到"第一步就调 `build_team`"这一句起手指令 |
| `policyText` / `build_team` 追加 disclosure（D-3） | **leader 拿不到任何协作准则**——建队后不知道职责、不知道决策原则、不知道任务怎么下发 |

| `taken_over` | 接手已有团队的 leader 看到 "Team created:"，误以为要重新 spawn 成员 → 名册重复 |

### 3.3 `internal/agent_teams/prompts/loader.go` —— `Render` 收敛

```go
// Render 渲染模板，只替换双花括号 {{var}}。
// 单花括号 {var} 视为字面文本，原样保留——对齐上游 PromptAssembler
// 的 placeholder_prefix="{{" / placeholder_suffix="}}"（template.py L33-34）。
// Python: PromptTemplate.format(**kwargs) (core/foundation/prompt/template.py L58-75)
func (t *PromptTemplate) Render(vars map[string]string) string {
    if t == nil {
        return ""
    }
    result := t.content
    if vars == nil {
        return result
    }
    for k, v := range vars {
        result = strings.ReplaceAll(result, "{{"+k+"}}", v)
    }
    return result
}
```

**删除**：原先的第二轮 `strings.ReplaceAll(result, "{"+k+"}", v)` 循环，以及函数头注释里"同时支持双花括号和单花括号"的说明。
