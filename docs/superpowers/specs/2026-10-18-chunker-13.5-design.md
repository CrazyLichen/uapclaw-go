# 13.5 Chunker 抽象接口 + registry 设计

> 对应 Python：`openjiuwen/core/retrieval/indexing/processor/chunker/base.py` + `chunker/__init__.py`
> 实施计划：领域十三 13.5（Chunker 层第一步）

## 背景与流程位置

Chunker 位于知识检索入库管线的分块断点：

```
KnowledgeRetrievalComp（workflow）
  └─ KnowledgeBase.add_documents(documents)
       ├─ chunker.chunk_documents(documents)   ← 本设计（13.5）
       │    └─ TextChunk[]{ID, Text, DocID, Metadata{chunk_index, total_chunks, chunk_id}}
       └─ index_manager.build_index(chunks)    ← 13.2/13.3 已完成
            └─ ComputeChunkEmbeddings          ← 13.4 已完成
```

13.1-13.4 完成了入库后半段（嵌入+写库），`BuildIndex` 的 `chunks []TextChunk` 入参
此前没有真实生产者。13.5 补上管线断点：解析后的 Document → 可嵌入的 TextChunk。

Chunker 四个作用：
1. **管线断点补齐**——为 BuildIndex 提供分块生产者
2. **检索粒度控制**——默认 512 字符 / 50 重叠，决定召回精度与上下文完整性平衡
3. **溯源与删除支持**——chunk 携带 doc_id + chunk_index/total_chunks/chunk_id，
   支撑 Indexer DeleteIndex 按 doc_id 整体删除
4. **可插拔策略入口**——registry 支持按名选取分块策略（"char"/"hybrid"）

## 接口与类型签名

```go
// Chunker 文本分块抽象接口（三方法对齐 Python chunk_text/chunk_documents/process）
type Chunker interface {
    // ChunkText 对单段文本分块。空文本返回空切片。
    ChunkText(text string) ([]string, error)
    // ChunkDocuments 对文档列表分块，产出带溯源 metadata 的 TextChunk。
    ChunkDocuments(ctx context.Context, docs []common.Document) ([]common.TextChunk, error)
    // Process Processor 契约入口，等价 ChunkDocuments（ctx 透传包装）。
    Process(ctx context.Context, docs []common.Document) ([]common.TextChunk, error)
}

// BaseChunker 默认适配器（Python Chunker 基类的可嵌入部分）
type BaseChunker struct {
    ChunkSize      int
    ChunkOverlap   int
    lengthFunction func(string) int // 对齐 length_function，默认 len
}

// NewBaseChunker 构造并校验（决策 7）
func NewBaseChunker(chunkSize, chunkOverlap int, lengthFn ...func(string) int) (*BaseChunker, error)
```

### ChunkDocuments 默认实现语义（对齐 Python chunk_documents）

遍历 docs → `ChunkText(doc.Text)` → 每块生成 `TextChunk`：

- `ID = uuid.NewString()`
- `Metadata = {**doc.Metadata, "chunk_index": i, "total_chunks": len(texts), "chunk_id": uid}`
- 任何一块 error 即中断，返回 `nil, err`（Python None 会在 enumerate 处崩，Go 侧更稳）

### Process 默认实现

`return bc.ChunkDocuments(ctx, docs)`

### 构造校验（一比一对齐 Python）

| 条件 | 异常码 |
|------|--------|
| `chunkSize <= 0` | StatusRetrievalIndexingChunkSizeInvalid (155100) |
| `chunkOverlap < 0` | StatusRetrievalIndexingChunkOverlapInvalid (155101) |
| `chunkOverlap >= chunkSize` | StatusRetrievalIndexingChunkOverlapInvalid (155101) |

### 子类模式

```go
type CharChunker struct {

```

## registry（registry.go）

```go
type chunkerEntry func(opts ...ChunkerOption) (Chunker, error)
var chunkerRegistry = map[string]chunkerEntry{}

func RegisterChunker(name string, entry chunkerEntry, overwrite bool) error
func GetChunker(name string, opts ...ChunkerOption) (Chunker, error)
```

- **工厂返回 error**：Python 工厂 `entry(**kwargs)` 构造抛 ValueError；Go 工厂签名
  `(...) (Chunker, error)` 承载构造校验错误（决策 7 联动）
- `ChunkerOption`（`func(*ChunkerOptions)`）：`WithChunkSize` / `WithChunkOverlap` /
  `WithInnerChunker` / `WithNoSplitWhen` 等，对齐 Python `**kwargs`
- hybridFactory（对齐 `_hybrid_factory`）：
  - inner 缺省 → 由 chunk_size/chunk_overlap 构造默认 CharChunker，多余参数透传（前向兼容）
  - inner 已给 + 多余 kwargs → 报错（对齐 Python TypeError）
  - inner 非 Chunker → 报错（对齐 Python TypeError）
  - ⤵️ 13.8 HybridChunker 落地前，hybridFactory 为回填占位
- `"char"` 注册项随 13.6 CharChunker 落地（⤵️）
- 注册名校验：空名 / 重名且 overwrite=false → 报错（对齐 Python ValueError）
- GetChunker 未知名错误信息含已注册名列表（对齐 Python KeyError 消息格式）
- Python 侧 registry 为纯 SDK 接口，生产链路（KnowledgeBase）走构造注入，Go 同
