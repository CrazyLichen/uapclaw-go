## 4. 数据流与状态机

### 4.1 owner 表结构

```go
// agentExecutionOwnerKey 执行 owner 表的键。
type agentExecutionOwnerKey struct {
	// ChannelID 归一化后的渠道标识（TrimSpace → ToLower → 空则 "default"）
	ChannelID string
	// SessionID 去空白后的会话标识（空则不建键）
	SessionID string
}

// AgentRuntime 新增字段
agentExecutionOwners  map[agentExecutionOwnerKey]*RuntimeAgentExecution
agentExecutionOwnerMu sync.Mutex
```

### 4.2 三端闭合

**写端**（`invokeAgent` / `streamAgent`）：

```
validateAgentDefinition(definition, mode)  →  *RuntimeAgentExecution
     内部：prepareAgentExecution + resolveModelCapability 校验 model 存在
bindAgentExecutionRequest(request, execution)  →  绑 params.mode / work_mode / model_name
claimAgentExecutionOwner(request, execution)
     ├ key == nil（无 sessionID）→ 直接返回
     ├ 已有条目 且 fingerprint 不同 → RuntimeAgentDefinitionError(SESSION_CONFLICT)
     ├ 已有条目 且 fingerprint 相同 → 幂等返回
     └ 无条目 → 写入
invoke(boundRequest, agentExecution)
```

**读端**（三个交互回答方法）：owner 为空则正常执行，**不报错**（Python 是 `if owner:` 判断，非 assert）。

**清端**：`CleanupSession` → `forgetAgentExecutionOwner`（无论前面清理成功与否）；`Close()` → 整表 clear。

### 4.3 fingerprint 逐字节对齐

Python（`agent_definition.py:225-238`）：

```python
payload = {"schema": _DEFINITION_SCHEMA, "definition": self.to_dict()}
canonical = json.dumps(payload, ensure_ascii=False, separators=(",", ":"), sort_keys=True)
return hashlib.sha256(canonical.encode("utf-8")).hexdigest()
```

Go 等价实现要点：
- `sort_keys=True` → 用 `map[string]any` 交给 `json.Marshal`（键自动有序）
- `separators=(",", ":")` → `json.Marshal` 无空格，符合
- `ensure_ascii=False` → 必须用 `json.Encoder` + `SetEscapeHTML(false)`（`json.Marshal` 会转义 `<>&`）
- **`json.Encoder` 追加尾随换行** → 必须 `bytes.TrimSuffix(buf, []byte("\n"))`，否则 sha256 不同
- 用 golden 测试硬编码 3~5 个 Python 实算值对拍

### 4.4 `CleanupSession` 四步状态机

严格按 `service.py:3024-3070`，短路顺序即语义：

```
CleanupSession(ctx, channelID, sessionID, resetPlanState) (bool, error)
  0. closed 检查 → RuntimeStateError                        // :3037
  1. if ownsSession(sessionID):                             // :3052
         coordinator.CloseSession(sessionID)                // 超时 → SessionCloseTimeoutError
  2. managers := [resolveManager(request)] 或 扫租户池        // :3058-3064
     for m in managers: m.CleanupSessionRuntime(channelID, sessionID)
         cleaned = cleaned || result                        // 单条失败：Warn 继续（D-2）
  3. forgetAgentExecutionOwner(channelID, sessionID)        // :3066 ★R-4
  4. if resetPlanState: planController.ResetSession(sessionID)  // :3070
  return cleaned, nil
```

第 2 步循环结构保留（虽然本批只有一个 manager），将来接企业版不改。

### 4.6 `invoke_agent` 完整数据流

```
调用方传 (request, definition)
  ├─ start()                                  幂等启动
  ├─ requireOwnedSingleAgentSession(request)  session_catalog + coordinator 快照（fail-closed，抛 SessionCatalogError NOT_FOUND）
  ├─ mode := resolveModeCapability(params["mode"]).Mode
  ├─ execution := validateAgentDefinition(definition, mode)
  │      └ prepareAgentExecution → name 正则 / instructions 非空 / max_iterations>0
  │      └ definition.Model != "" → resolveModelCapability 校验，否则 MODEL_NOT_FOUND
  ├─ boundRequest := bindAgentExecutionRequest(request, execution)
  │      ├ reqMethod != CHAT_SEND → INVALID_REQUEST (field=request)
  │      ├ params 非 map → INVALID_REQUEST (field=request.params)
  │      ├ params["mode"] = execution.Mode
  │      ├ params["work_mode"] = "code" if mode 前缀 "agent.code." else "work"
  │      └ definition.Model != "" && params["model_name"] 空 → 填 selection_key
  ├─ claimAgentExecutionOwner(request, execution)   ★R-4 写端
  └─ invoke(boundRequest, agentExecution)
```

**关键澄清**：`_agent_execution` 是**方法参数**，不是 `schema.AgentRequest` 字段。原 spec §10 写"`_agent_execution` 请求参数"易误导去改 schema，须改正。

## 5. 错误处理

### 5.1 错误码全映射（4 成员，不裁剪）

| Python 枚举 | 触发点 | Go 哨兵 |
|---|---|---|
| `INVALID_MODE` | `_runtime_agent_mode` :241-254 | `ErrAgentDefinitionInvalidMode` |
| `INVALID_REQUEST` | `_bind_agent_execution_request` :1556-1568 | `ErrAgentDefinitionInvalidRequest` |
| `MODEL_NOT_FOUND` | `validate_agent_definition` :711-714 | `ErrAgentDefinitionModelNotFound` |
| `SESSION_CONFLICT` | `_claim_agent_execution_owner` :1610-1615 | `ErrAgentExecutionSessionConflict` |

Go 形态：一个 `RuntimeAgentDefinitionError` 结构体承载 `code` + `field` + `message`（对齐 `:54-65`），4 个哨兵作 `code` 常量，用 `errors.Is` 判断（非 4 个错误类型）。

`field` 有效值必须保留：`name` / `instructions` / `description` / `model` / `tools` / `skills` / `max_iterations` / `mode` / `agent` / `request` / `request.params`。

**两类错误不得混**：`requireOwnedSingleAgentSession` 抛 `SessionCatalogError("session not found", code="NOT_FOUND")`，不是 `RuntimeAgentDefinitionError`。

### 5.2 字段校验（逐条对齐 `__post_init__`）

| 字段 | 规则 | Python 行 |
|---|---|---|
| `name` | 必填、去空白后非空、匹配 `[A-Za-z0-9_-]{3,50}`，**校验后写回去空白值** | :168-172 |
| `instructions` | 必填、**`preserve=True`（保留内部与首尾空白）** | :173-177 |
| `description` / `model` | 可选，`_optional_text`（None/空白 → nil） | :178-184 |
| `tools` | `"*"` 或字符串元组 | :185 |
| `skills` | `_string_tuple`（每个元素非空字符串） | :186 |
| `max_iterations` | 非 bool 的 int、> 0 | :187-196 |

**陷阱**：`instructions` 与 `name` 行为不同——前者保留原值只做非空校验，后者校验后写回去空白值。

### 5.3 `from_mapping` 严格性

Python `_strict_definition_mapping`（:130-149）**拒绝未知键**。Go 用 `json.Decoder.DisallowUnknownFields()` 等价实现；未知键 → `RuntimeAgentDefinitionError`，`field` 为该键名。

**这与项目里"JSON 未知字段保留"的常见做法相反**，不得套用 pyjson 容错逻辑。
