# 15.6 native provider 设计（2026-11-14）

## 1. 目标与定位

把 in-process DeepAgent 适配到 harness protocol v1（`internal/agentcore/harness_protocol/`，15.1-15.4 交付），作为**协议层首个真实消费者**接通 15.1/15.2/15.3/15.4 的全部零消费面。上游对应 `openjiuwen/harness_providers/native/`（`harness.py` 791 行 + `provider.py` 75 行 + `__init__.py` 22 行）。

计划勘误维持：上游 `provider="native"` 用的是 plain `DeepAgent`（`native/harness.py`:298/359/363），不是 NativeHarness；`native_v2`（NativeHarnessProtocolAdapter + checkpoint + pause-resume）归 25.1f，本节不做。

### 在 agent 会话中的流程位置

```
宿主（CLI 15.5 / Web 面板 / 测试宿主）
   └─ harness_protocol（协议面：HarnessCard / HarnessContext / TurnResult / 事件）
        └─ BaseProvider（15.5 基座：turn 队列 / _emit / _request_interaction / checkpoint）
             └─ 15.6 DeepAgentHarness   ← 本节
                  └─ DeepAgent.start / attach_output / send_input（9.87 L1 交互面）
                       └─ ReAct 循环 + rails（15.5 factory.go CreateAgent 全量装配）
```

一次外部 Turn = 一次 `attach_output` 流消费，输入经 `send_input` 派发；中断保持 turn 打开，通过宿主 interaction 解决后 resume。

## 4. 核心行为（对齐 Python 步骤，规则 9/12）

### 4.1 生命周期

- `_open_session`（harness.py:278-313）：工厂建 agent（支持同步/异步工厂 → Go 仅同步函数字段）→ `AddRail(observationRail)` → 上下文提示词追加（`harness_context` section，priority=10，三语言同值）→ `EnsureInitialized`（**时序敏感**：pending rails 注册与 cwd ContextVar 种子必须在 Start 前，对齐 Python 注释 harness.py:290-293）→ `create_agent_session`（session_id = `host_session_id:agent_id`，可 override）→ `session.PreRun({})` → `agent.Start(session)` → `LoadAgentTemplateSpec`（方案 B 提前实现）。任何失败包 `ProviderStartupError`（`TurnError.category=sdk_error`，message 只含异常类型名）。
- `_validate_context`（harness.py:269-276）：`REQUIRE_RESUME` 或带 checkpoint → `UnsupportedHarnessCapabilityError`（不恢复协议 checkpoint）；context 声明 mcp_servers → 同错误（须在 agent manifest 里声明）。
- `_close_session`（harness.py:315-329）：agent.stop + session.post_run，各自吞异常记日志（`[deepagent] stop failed during teardown` 等）。

### 4.2 Turn 主循环

- `_execute_turn`（harness.py:331-356）：`TurnTiming` + `turnState` → 循环 `_run_round` → 有 pending 中断且未中止且无错 → `_resolve_interrupts` → 答案装 `InteractiveInput` 作为新 query 再跑一轮；任何异常（非中止）→ `TurnError(category=sdk_error)`。
- `_run_round`（harness.py:358-367）：`AttachOutput`（None → `HarnessProtocolError`"output stream already has a consumer"）→ `SendInput(request_id=turn_id, inputs={"query": query})` → 逐 chunk `_consume_chunk` → finally `stream.Close(abort_active_round=turn.abort_requested)`。
- `_build_result`（harness.py:609-649）：中止 → ABORTED + `interrupted_result`；有错 → FAILED；否则 COMPLETED，`stop_reason = result_type or "answer"`，有 pending 中断时 `stop_reason="interrupt"` 且 `provider_data` 带 `pending_interrupt_ids` + `pending_interrupts`（每项 `{tool_call_id, interrupt_id, kind}`）。
- `_steer`（harness.py:651-662）：`SendInput(STEER mode)`，request_id = `steer-{uuid}`。
- `_interrupt_turn`（harness.py:664-669）：`agent.CancelRound("harness_abort")`。

### 4.3 中断解析（通俗语义）

DeepAgent 卡住时往流里丢 `INTERACTION` chunk 就停；本节是中间翻译官：

1. **审批类**（permission/confirm/team tool/skill evolution）：宿主声明 `TOOL_APPROVAL` → `ToolApprovalRequest`（ALLOW/ALLOW_FOR_SESSION/DENY/ABORT + updated_arguments + interrupt + reason）；否则 `UserInputRequest` 给 `APPROVAL_CHOICES` 三选，文字答案经 `interrupt_answer` 归一，其余内容原样返回。**宿主改参数 = 拒绝该调用**（feedback"编辑参数不支持"）；`ALLOW_FOR_SESSION` 且 `provider_data.persist_allow is True` 时应答加 `persist_allow: true`。
2. **客户端工具**：宿主声明 `DYNAMIC_TOOL_CALL` → `DynamicToolCallRequest`（provider_data 额外带 `client_request`），结果按 str/list 原样、其他 JSON 转 `_result_text`+data；未声明 → 直接回答"宿主跑不了客户端工具"算工具错误；FAILED → ERROR；非 COMPLETED → CANCELLED。
3. **其他一切**（ask_user、未声明 kind、其他 rail 的 kind）→ `UserInputRequest` 原样回答（空 content = 空文本）。
4. **排序**：client call 排最后（`_is_client_call` 稳定排序）——宿主答了②这轮必须带结果继续，先问可中止的①③。
5. **workflow 交互不是中断**：`request_id` 用自身 id，`interrupt_id`/`kind` 为空串。
6. **无宿主交互处理器**：返回 None，turn 停留等待态，不猜答案。

⤴️ 本节消费 15.5 待回填②：`interrupt_answer` 6 个消费点（`native/harness.py:500/505/509/557/564/568`），消除 `single_agent/interrupt/answers.go` 的 ⏵ 标注。

### 4.4 流消费映射

- `llm_output`/`llm_reasoning` → `OutputEvent` delta（ANSWER/REASONING channel，output_id = `deepagent-output:{turn_id}:{channel}`）。
- `tool_call`/`tool_result`（observationRail 镜像）→ `ItemLifecycleEvent` STARTED/COMPLETED + ContentBlock/TurnMessage 累积；`rendered_result` 为字符串时进 block_data 与 item_data（结构解析不受影响，对齐 harness.py:128-131 注释语义）。
- `answer` → final_output（非字符串 JSON 序列化）+ result_type。
- `INTERACTION` → `interactionPayload` 三形态解析（二元组 / 对象属性 / Mapping）入 pending_interrupts。
- `execution.error` → TurnError。
- 其余 → `ProviderEvent` 透传（schema_version="1"）。

### 4.5 observationRail

对齐 `_ObservationRail`（harness.py:92-139，priority=5）：`BeforeToolCall` 写 `tool_call` chunk（tool_call_id 缺省回退 `{tool_name}:{react_iteration}:{uuid8}`）；`AfterToolCall` 写 `tool_result` chunk（`to_json_safe` 结构值 + `resolve_tool_result_text` 的 model-facing 文本）。
