## 1. 流程位置与作用

25.5 处于两条链路的交汇点：

1. **成员 spawn 链（fork 半区）**：leader 调 `spawn_teammate` 工具携带 `fork`/`fork_source`/`fork_mode` 参数 → `mark_fork_on_spawn` 记 pending（`tool_member.py:850`）→ 成员创建回调 `_on_teammate_created`（`team_agent.py:1480-1491`）`consume_fork_on_spawn` 取 fork_info → 五种 fork_mode 分派构造 `ForkContext`（`team_agent.py:1500-1620`）→ 注入新成员 context engine（`inprocess_spawn.py:108-124`），compact 模式再由 `compact_context` 压缩对面半区。它是 25.4 任务板"改派/新领任务带上下文继承"的支撑件。
2. **暂停恢复链（checkpoint 半区）**：25.1c 已落 pause/resume 与 `pending_resume` 冷恢复；本节补**命名 checkpoint**——成员调 `checkpoint` 工具存快照 → 发布 `CHECKPOINT_CREATED` 事件 → leader coordination handler 渲染 announcement 进 leader 上下文 → 后续成员 `fork="<name>"` 继承；leader 侧映射镜像进 per-team session namespace 扛进程重启，冷恢复还原。

**作用一句话**：让团队成员间可以"按名字继承对话上下文"（五种裁剪模式），并让快照索引能跨重启存活。

## 2. 核心语义（对齐确认结论）

- checkpoint 记录**只存下标不存内容**：`name → {count, description, created_by}`；`count` = 成员当前上下文消息条数（`snapshot_context_length` 回调）。
- leader 内存 `_named_checkpoints` 是权威源；in-process 成员经 `set_store_checkpoint_fn` 回调直写 leader 命名空间（`team_agent.py:731-741`）；回调未接线（外部 CLI 成员）退回本地 fallback dict（`team.py:654-691`）——leader 权威表看不到，但 `CHECKPOINT_CREATED` 事件照发。
- leader 侧 `_merge_checkpoints_into_session`（`team_agent.py:1799-1813`）把全量映射镜像进 bound team session 的 per-team namespace（`TEAM_CHECKPOINTS_KEY = "checkpoints"`，`metadata.py:43/:129/:158`）。
- **fork 解析发生在 leader spawn 成员时**（不是"从 db 恢复快照"）：查索引取 count → `_resolve_fork_native` 拿源成员 DeepAgent → `ForkContext.from_agent` **现场**读上下文截断；源成员内存上下文取不到（pause/resume/restart 重建过）回落读源成员绑定 child session 持久化 messages（`_read_persisted_messages`，`fork.py:120-148`）。
- 外部 CLI 成员作为 fork **源**：`_resolve_fork_native` 返回 None（warning + skip），成员不带继承上下文启动——上游明确不支持，Go 照此不做扩展。
- creator/fork_source 不匹配：count 下标属于另一成员的上下文不可信 → `ckpt_idx` 清空降级 full + `_notify_fork_name_not_found`（`team_agent.py:1517-1545/:1664-1683`）。
- 事件而非 send_message：mailbox 消息带 reply hint 会污染 leader 上下文；框架事件渲染为 `<team-event kind="checkpoint">` + `announcement-only` note，`deliver_input(use_steer=False)`（`handlers/checkpoint.py:31-66`）。

## 5. 设计分节

### 5.1 数据与持久化

- TeamAgent 增 `namedCheckpoints map[string]CheckpointRecord`（`CheckpointRecord{Count int; Description, CreatedBy string}`），读写单锁（对齐 Python 单线程语义，按 asyncio→Go 并发惯例加锁）。
- `SetCheckpoint(name, count, description, createdBy) *CheckpointRecord`：冲突返回既有记录（nil=成功）；role==LEADER 时调 `mergeCheckpointsIntoSession`。
- `metadata` 包新增 `MergeTeamCheckpoints(sess interfaces.SessionFacade, teamName string, mapping map[string]CheckpointRecord)` / `ReadTeamCheckpoints(...) map[string]CheckpointRecord`，键 `TEAM_CHECKPOINTS_KEY="checkpoints"`，走既有 per-team namespace（`merge_team_namespace` 等价通道），形态对齐 pending_resume 三函数。
- 冷恢复还原：leader 冷恢复构造点（25.1c pending_resume 续跑链所用的 agent 构造路径，实施时按 `team_agent.py:2175-2179` 对应的 Go 恢复构造函数接线）读表后 `setCheckpointsFrom`。

### 5.2 fork 继承链

- `agent/fork.go`：`ForkContext` 结构 + `ForkContextFromAgent`（strip SystemMessage → checkpoint 截断：before 侧跨边界携带闭合 ToolMessage 块 / after 侧剥孤儿 ToolMessage → 内存取不到回落读源成员 child session state messages）+ `normalizeMessages` + `toMessages` + `isEmpty`。消息编解码走 `encoding/json` + 既有消息 schema 的 json tag（feedback：不写独立 marshal 包装层）。
- `agent/fork_compact.go`：`CompactContext(deepAgent, splitAt, sessionID, direction)`——splitAt 越界 skip（info 日志）；direction=after 时 head 延伸到闭合 ToolMessage 块尾；压缩用模型摘要（`_COMPACTION_PROMPT` 一比一复刻英文原文，feedback：提示词一比一复刻不翻译）。**实施核实项**：Go DeepAgent 侧"注入后取上下文 + 用模型压缩回写"的缝，若 context engine 无对应能力缺口，按规则 13.2 上台面讨论（挂 ⤵️ 或本批补），不自行决定。
- TeamAgent fork 段（`onTeammateCreated` 内，步骤顺序对齐 `team_agent.py:1480-1620`）：consume fork_info → resolve native → is_named 判定 → 默认 mode（live=full/named=before）→ creator 不匹配降级+通知 → 分派五模式构造 ForkContext → 日志（compacted/checkpoint/live fork 三态 info，含 msgs/split_at 字段）→ 异常兜底 warning + 无继承继续 spawn。
- `resolveForkNative(source)`：空/自己 → leader DeepAgent；`spawned_handles[source]` → 队友；未命中/非 in-process → warning + nil。
- `notifyForkNameNotFound(member, forkName, detail)`：message_manager 发 leader，best-effort（失败 warning 不阻塞 spawn）；available 列表来自索引表（空表显示「（无）」——沿用 Python 原文，协议字符串不本地化，此处为日志/消息文案按 Python 原样）。
- spawn_teammate 工具补 fork/fork_source/fork_mode 入参解析（对齐 `tool_member.py:845-854`：fork_value 非 "false"/False 即 mark），参数描述槽 locales 已有。

### 5.3 事件与渲染半区
