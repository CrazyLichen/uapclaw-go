# 9.88 Goal 域模型设计

## 概述

9.88 是持续目标（Goal）能力的**状态层**：定义 `GoalRecord` 领域模型、会话级持久化（`SessionGoalStore`）、唯一写者（`GoalManager`）与完成度评估器（`GoalEvaluator`）。

它**不调用模型、不注入提示词、不注册工具、不暴露 RPC**——只回答两个问题：

1. **现在该不该再排一轮 goal**（`ensure_active_goal_work_locked`）
2. **这一轮的结论还能不能写回记录**（`begin_attempt` / `apply_assessment` 的代际校验）

### 作用（4 条）

1. **状态独占**：`GoalRecord` 的所有读写只经 `GoalManager`；rail / 工具 / 服务面只走公开方法（上游 S_11 不变量 1）
2. **代际栅栏**：`goal_id + revision` 组成 generation token；`pause`/`clear`/覆盖**不中断在飞轮**，只让旧代际的写回被丢弃
3. **调度触发**：`_ensure_goal_work_locked` 是"下一轮从哪来"的唯一来源，且与 attach/detach 共用同一把控制锁
4. **判定落点**：`GoalEvaluator` 输出三态 → `ApplyAssessment` 决定记录状态与是否续跑

### 判定语义（continue / complete 是怎么定的）

"Goal 是否继续、是否完成"走三道关，主模型自报只是第一关：

```
一轮 attempt 结束
 ① agent_report（submit_goal_report 工具，continue/complete/blocked）
 ② transcript assessor（独立无工具 LLM 调用，看 objective + current_instruction + 本轮上下文）
 ③ 硬上限（max_attempts / token_budget，只拦 CONTINUE）
 ▼
GoalAssessment → ApplyAssessment → 状态转移
```

默认策略 `HYBRID` 的判定表（`evaluation.py` `_assess_hybrid` L155-208 + `_verify_with_transcript` L210-262）：

| 情况 | 结果 | 依据 |
|---|---|---|
| 无 agent_report | 用 transcript 结论；transcript 也没有 → CONTINUE | L173-175 |
| agent_report = CONTINUE | **直接信**（除非命中抽检点） | L179-188 |
| agent_report = COMPLETE/BLOCKED | **必须** transcript 复核，冲突时 transcript 赢 | L190-208 / L256-262 |
| transcript 未调 / 调用失败 / JSON 解析失败 | **退回 CONTINUE**（保守） | L225-254 |
| 最终仍 CONTINUE 且 `attempt_count >= max_attempts` | 改判 BLOCKED（`max_attempts_exhausted`） | L301-312 |
| 最终仍 CONTINUE 且 `total_tokens >= token_budget` | 改判 BLOCKED（`token_budget_exhausted`） | L314-331 |

抽检（`should_spot_check` L264-269）：`verification_interval` 非空且 `attempt_count % interval == 0` 时对 CONTINUE 也复核。**生产路径从不给该字段赋值**（`GoalStopConfig` 全仓只在 `GoalEvaluator()` 默认构造处出现），故当前不可达——实现照做，spec 里登记为"生产不可达"。

状态转移（`apply_assessment` L303-343）：

| 判定 | 记录变化 | 是否续排 |
|---|---|---|
| CONTINUE + ACTIVE | `settle_active_time(keep_active=true)` | 是 |
| CONTINUE + PAUSED | `settle_active_time(false)`，保持 PAUSED | 否 |
| COMPLETE | `COMPLETED` + `last_stop_reason="completed"` | 否 |
| BLOCKED | `BLOCKED` + `last_stop_reason="blocked"` | 否 |

## 关键设计决策

| # | 决策 | 说明 |
|---|------|------|
| K1 | **共用 DeepAgent 的 `interactionControlMu`，不自造锁** | Python 传的就是 `self._interaction_control_lock`（L3975）。`sync.Mutex` 与 `asyncio.Lock` 同为非重入，`xxxLocked` 后缀约定"调用方已持锁"。`CancelActiveRound` 回调必须注入 `cancelActiveRoundLocked`（`deep_agent.go` L3914），否则 `Set()` 持锁时再取锁立即死锁 |
| K2 | `set`/`pause`/`resume`/`clear` 全程持锁；`peek` **不**持锁 | 对齐上游注释（L89-95）：宿主用它做"这个 `chat.final` 是不是中间态"的显示决策，必须无阻塞 |
| K3 | `Coordinator` 接口放 **`goal` 包**，`BeginAttempt` 返回 `(*GoalRecord, error)` | 撤销 9.87 K8/D9。`hschema` 不能引用 `*goal.GoalRecord`（`goal → hschema` 已是单向），`interfaces` 也不行（`goal → task_loop → interfaces` 会成环）。规则 10.2 允许窄接口（DeepAgent 依赖他人），precedent `hinterfaces.GoalCoordinator` |
| K4 | `GoalRecord` 内存用结构体，**边界一律 `map[string]any`** | Session state 存 map（`UpdateDict` 语义）、`goal.updated` payload 是 map、服务面/前端读 map。跨边界只走 `ToDict`/`FromDict` |
| K5 | 时间戳产出 **Python 同形字符串**：`2006-01-02T15:04:05.999999-07:00` | Python `datetime.now(utc).isoformat()` 产出 `2026-11-06T06:10:22.123456+00:00`（微秒为 0 时无小数位）。该 layout 在 UTC 下产出 `+00:00`，`.999999` 自动省略全零小数 → 字符串级一致；解析用 `time.RFC3339Nano` + 空格分隔兜底，缺时区即报错 |
| K6 | 包级 `var utcNow = func() time.Time`，测试同包覆盖 | 对齐上游 `monkeypatch.setattr(goal_schema, "datetime", ...)`；`time_used_seconds` 的 5 个用例必须能冻结时钟 |
| K7 | `pyInt` 兼容 `int/int32/int64/uint*/float64/string` | Python `int(value)` 接受 `"3"` 与 `3.9`（截断）。Go 侧值来自内存 `int` 或 checkpoint JSON 还原的 `float64`，只认 `int` 会在恢复后必炸（本仓历史高频缺陷） |
| K8 | `GoalStopConfig` 可选字段用 `*int`，`0` 视为"未设置" | Python `self._config.max_attempts or record.max_attempts`：`0` 是 falsy。`*int` 不能表达 falsy，必须显式判 `!= 0` |
| K9 | `GoalOperationError` 实现 `error`，用 `errors.As` 取 code | Python `RuntimeError` 子类带 `operation/code/goal`。`Goal` 字段存 `Clone()` 副本（上游 `copy_for_response()`），防止错误对象被外部改写污染 store |
| K10 | `GoalStore` 接口 + `GoalSession` 窄接口双层 | `GoalStore` 是 GoalManager 的持久化面（Python Protocol）；`GoalSession` 是 store 的会话面（Python 直接吃具体 `Session`）。双层使 store 可在无真 session 下单测 |
| K11 | `BuildGoalTaskQuery` 收 **`GoalTaskView`** 只读视图，不收 `*GoalRecord` | 若 sections 收 `*goal.GoalRecord` 则 `sections → goal` 与 `goal → sections` 成环（Python 靠 `TYPE_CHECKING` + 函数内 lazy import 绕开）。视图类型定义在 `sections`，`goal` 提供 `(*GoalRecord).TaskView()` 单向转换（D4） |

### 锁与调用约定示意

```go
// 公开写方法：自己加锁
func (m *GoalManager) Set(ctx context.Context, objective string, opts SetOptions) (*GoalRecord, error) {
	m.controlMu.Lock()
	defer m.controlMu.Unlock()
	// ... 校验（校验失败在持锁前？上游在持锁前，见 L112-130）
	return m.setLocked(ctx, objective, opts)   // 内部不再加锁
}

// 监督器回调：要求调用方已持锁（9.87 在 controlMu 内调用）
func (m *GoalManager) EnsureActiveGoalWorkLocked() bool { /* 不加锁 */ }
```

⚠️ 上游 `set()` 的三处参数校验（L112-130）在 **`async with` 之前**执行，即"非法参数不阻塞在其他写者后面"。Go 必须保持在同一位置（锁外），否则 `invalid_objective` 的时序特性会变。

## 持久化形态

Session state 键 `harness.goal.record`，值是 `GoalRecord.ToDict()` 的 map：

```json
{
  "harness": { "goal": { "record": {
    "goal_id": "3f2a9c1b7d40", "session_id": "s1", "objective": "…",
    "status": "active", "revision": 0, "attempt_count": 1,
    "token_usage": {"input_tokens": 10, "output_tokens": 20, "cached_input_tokens": 0, "total_tokens": 30},
    "max_attempts": 5, "token_budget": null,
    "last_assessment": {"status": "continue", "evidence": "…", "remaining_work": "…", "next_instruction": "…"},
    "last_stop_reason": null, "time_used_seconds": 30,
    "active_started_at": "2026-11-06T06:10:22+00:00",
    "created_at": "…", "updated_at": "…"
  }}}
}
```

三个必须照抄的行为（否则"读回来就变样"）：

1. **点号即嵌套路径**：`harness.goal.record` 在两边都被当作三层路径（Python 同样如此），不是平坦键
2. **嵌套 `null` = 删键**：`UpdateDict` 遇到 `nil` 会删掉该键（`session/utils/dict.go` L25）。因此 `pause`/`complete` 后 `active_started_at` 是**键缺失**而非 `null` → `FromDict` 必须容忍缺失
3. **ACTIVE 时钟自愈**：`status == ACTIVE && active_started_at == nil` → 用 `updated_at` 顶上（`schema.py` L255-258），否则累计工时会从 0 重新开始

## 代价与风险

1. **deadcode 窗口**：9.88 落地后到 9.89/10.3.27 之前，`GoalManager` 无生产调用方（只有 `deep_agent.go` 的 nil 守卫与单测）。风险可控：所有符号最终必经 9.89 接线
2. **动已验收章节**：P4 撤销 9.87 的 `GoalCoordinator` 收窄会改动 4 个已 ✅ 的文件。缓解：先落 P1~P3（新增为主），P4 单独一个提交，便于回滚
3. **锁约定无编译期保障**：`EnsureActiveGoalWorkLocked` 若被外部误调会数据竞争。防线：注释 + 仅两处调用点（均在 `controlMu` 内）+ G1 竞争测试
4. **时间语义脆弱**：`time_used_seconds` 依赖 6 个入口的正确 `settle/start` 组合，任一漏掉都会让前端工时归零。防线：M8~M16 九个用例 + 冻结时钟
5. **上游文档不可信**：`S_11_goal-and-evaluation.md` 与代码有 4 处出入（pydantic/revision/stop_reason/五态），本设计一律以代码为准
