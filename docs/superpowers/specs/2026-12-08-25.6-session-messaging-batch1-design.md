## 0. 在 agent 会话流程中的位置与作用

25.6 是团队成员之间"说话"与"被打断后体面收尾"的唯一通道。三条通信平面在 25.6 交汇但实现独立：

| 平面 | 载体 | 归属 | 落盘 |
|---|---|---|---|
| messager 总线（team 事件） | 无 DB，纯内存事件总线（inprocess/hybrid） | `agent_teams/messager` | 不落盘，纯通知面 |
| team 消息（成员点对点/群聊广播） | TeamDatabase | `agent_teams/tools/message_manager.py` | send 时先落库，总线只发"有新信"事件 |
| session mailbox（跨会话） | `session_messages.sqlite3`（独立 SQLite，WAL） | server 面（AgentServer 装配） | send_message 工具栈内同步 enqueue，先于 worker 拾取 |

## 1. 裁决记录（brainstorming 结论，全部经用户确认）

1. **拆两批**：批一消息面（本 spec），批二收尾面（暂停链 adapter 消费点 + BroadcastEvent channel 参数 D-25.3-1 + publish_pause_completed 消费点 + HeartbeatJobService 真服务注入 + roster + D-25.3-1/2 勘误），批二另起设计轮。
2. **pyzmq_backend 不移植**：Go 侧跨进程场景已有 team-mcp/外部 CLI 链路（15.16b hybrid + gateway 中继），登记「Python 侧有、Go 侧不移植」。
3. **messager 逐方法盘点先行**：批一实施前先做 Python base/inprocess/hybrid 与 Go 现状的逐方法对照，产出缺口表，缺口随批一补齐。
4. **mailbox 归属方案 A**：`internal/swarm/server/`，对齐 Python `agent_ws_server._install_session_message_service` 装配位；admission/execute/status_callback 经窄接口注入，执行面由现有会话执行链提供。
5. **store 独立 sqlite**：`session_messages.sqlite3`，WAL；溢出落盘（async_tools result-spill，spill_threshold=32768）按 Python 原文归属 harness 层，各自归属，不共库。
6. **施工顺序方案一（自底向上）**：T1 messager 盘点 → T2 store DAO → T3 service/worker → T4 server 装配+execute 回调 → T5 toolkit/rail → T6 group_chat。
7. **投递机制 = 事件驱动 worker，非定时轮询**：per-(target, input_mode) goroutine，队空退出，退出回调再查一次队列关闭 enqueue/exit 竞态；`start()`/`set_available()` 对 queued_targets 做一次补扫（崩溃恢复）。
8. **测试覆盖硬要求**：本 spec §3.8 列出的每一个讨论过的行为点均须单测 + 集成测试双覆盖。

## 2. 层级模型（Go 侧事实，实施时勿混淆）

```
AgentServer (internal/swarm/server)            ← WS/HTTP 入口，装配 SessionMessageService
  └─ AgentRuntime (internal/swarm/runtime)     ← 裁决+账本层（组合关系，非代理）
       ├─ work_scheduler / ExecutionRegistry   ← admission 对应物
       ├─ AgentManager (swarm/server/runtime)  ← 花名册：channel_key → cache_key（含 mode/subMode/projectDir）→ 门面
       │    └─ UapClawSwarm 门面
       │         └─ AgentAdapter (swarm/server/adapter)  ← "代理"对应物
       │              └─ sessionAdapterCache：key = 裸 session_id（空回退 "default"）
       │                   └─ DeepAgent（执行体）
       └─ set_session_message_service(service) ← Python 同款：服务本体在 server，runtime 拿引用
```

- `sessionAdapterKey(sessionID)`：裸 session_id（deep_adapter_sessions.go:116-124），**不是** mode.projectordir 复合键——复合键是 AgentManager 的 cache_key。
- mailbox execute 回调 = `execute_internal_session_message`（server 方法）：内部同时过裁判（admission）和找执行体（adapter）。

## 3. 设计分节

### 3.1 T1 messager 逐方法盘点与补缺

- 对照表：Python `Messager` 抽象（publish/subscribe/unsubscribe/send/register_direct_message_handler/unregister_direct_message_handler/start/stop）× Go `internal/openuapclaw/agent_teams/messager/` 现状（base/inprocess/hybrid/messager）。
- 缺口逐条补齐（重点疑点：点对点面 `send` + `register/unregister_direct_message_handler`）。
- 闭合 D-15.16-b7：核实 gateway `team.mq.publish` 中继 handler 的回收点。
- pyzmq 不移植登记入 spec §1.2 与 IMPLEMENTATION_PLAN.md。

### 3.2 T2 SessionMessageStore

对齐 `session_message_store.py` 全量 DAO：

- schema：`session_messages` 表（含幂等键唯一约束、hop_count、chain_id、parent_message_id、input_mode、effective_input_mode、status、execution_request_id、run_id）。
- 方法：`enqueue`（幂等冲突返回 IdempotencyConflict，同幂等键同内容去重）/ `get` / `queued_targets` / `queued_for_target` / `continue_queued_for_target` / `next_queued`（支持 defer_steering 过滤）/ `waiting_for_target` / `waiting_for_pause` / `supersede_waiting_for_target` / `defer_steering` / `claim`（乐观占用，写 execution_request_id + run_id）/ `transition_status`。
- sqlite 姿势：WAL（`normalize_journal_mode` 对齐）、`t.TempDir()` 测试、禁真实共享目录。

### 3.3 T3 SessionMessageService

对齐 `session_message_service.py`：

- **校验链**（顺序忠实 Python send_message :489-598）：target 去空白 → input_mode 枚举（""/steer/follow_up）→ session_id 合法性 → 自发拒绝 → 空内容 → 32KB 上限 → hop+1 > MAX 拒 → 源/目标 metadata 存在 → owner 归属（同 user_id）→ `_supported` → `_blocked_targets`（删除中）→ enqueue。
- **投递 worker**：`_ensure_worker(target, input_mode)` → goroutine `_consume_target`：`next_queued` → steer 模式下 `_must_queue` 则 `_defer_steering` 重排队 → task 模式 `admission.begin_session_message` → `claim` → `wait_for(execute, watchdog)` → 状态回写 → 队空退出。退出回调 `_restart_worker_if_queued` 关竞态。
- **执行结果状态机**：delivered / succeeded / failed / cancelled / waiting_user / unknown。watchdog 超时：先 `end_session_message` 释放 admission，再置 unknown（顺序不可颠倒，Python :1154-1158 注释明确）。
- **steer 被拒自动降级**：错误码 ∈ {SessionInputQueueRequired, SessionInputRejected, SessionInputTarget} 时 defer 重排队（仅 SDK 提交前发生；unknown 绝不自动降级）。
- **waiting_user**：从 store 重读记录、挂 on_abandoned_wait 释放缝。
- 窄接口注入：`admission`（begin/end_session_message + 能力探针）、`execute`、`status_callback`（推送超时容忍，debug 日志不中断）、`requires_task_queue`、`available`。
- `start()` / `stop()` / `set_available(available)`：补扫 queued_targets 起 worker。

### 3.4 T4 server 面装配与 execute 回调

- `AgentServer` 装配（对齐 `_install_session_message_service`）：store 路径 = agent 根目录 / session_messages.sqlite3；admission = 心跳运行时 admission 对应物；execute = `executeInternalSessionMessage`；status_callback = WS 推帧；requires_task_queue = runtime 判定；available = 连接态。
- `executeInternalSessionMessage` 复用 10.3.28 链：`getOrCreateSessionAdapter` 冷会话唤醒 → steer 注入运行轮 / admission 开新轮 → ExecutionRegistry 登记 → watchdog → 状态返回。**不新写会话执行逻辑**。
- `set_session_message_service` 把引用递给 runtime（对齐 Python `self._runtime.set_session_message_service(service)`）。

### 3.7 错误处理面

`SessionMessagingError` 错误码全保留（前端契约键，不得本地化）：
`MISSING_TOOL_CALL_ID` / `SELF_SEND_NOT_ALLOWED` / `INVALID_ARGUMENT` / `LIMIT_EXCEEDED` / `NOT_FOUND_OR_FORBIDDEN` / `UNSUPPORTED_SOURCE` / `UNSUPPORTED_TARGET` / `IDEMPOTENCY_CONFLICT` / `PERSISTENCE_UNAVAILABLE` / `EXECUTION_WATCHDOG_TIMEOUT`。
sqlite 瞬态 busy 错误按 `_is_transient_store_error` 姿势重试（基延迟退避），worker 保持存活。

### 3.8 测试覆盖矩阵（硬要求：讨论过的每个点双覆盖）

| # | 讨论过的行为点 | 单测 | 集成 |
|---|---|---|---|

| 2 | 幂等键（sha256 三元组）去重 / IDEMPOTENCY_CONFLICT | store 幂等分支 | 重复工具调用去重返回 deduplicated=true |
