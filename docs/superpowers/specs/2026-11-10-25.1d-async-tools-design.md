### 1.3 作用

1. **两阶段解耦**：长任务（swarmflow、大报告）不阻塞 ReAct 轮；`tool_use` 立即闭合，真实结果后置注入。
2. **单写者模型**：完成回灌走 `send(immediate=false)`，与轮驱动串行，避免并发开轮。
3. **控制面**：`list/get/wait/cancel` 供模型查询进度与取消。
4. **上下文保护**：超过 32KB 的结果落盘 `{team_home}/sessions/{sid}/async_tools/{task_id}.output`，注入摘要 + 取回指针。
5. **生命周期**：`stop` 取消在飞任务，避免完成注入与停机竞态。

## 4. 状态与数据结构

### 4.1 `AsyncToolRecord`

```go
type AsyncToolRecord struct {
    TaskID          string
    ToolName        string
    Description     string
    Status          string // running | completed | error
    Result          any
    Error           string
    OutputFile      string
    FormatCompleted func(any) string
    FormatFailed    func(error) string
}
```

状态常量：

```go
const (
    AsyncToolStatusRunning   = "running"
    AsyncToolStatusCompleted = "completed"
    AsyncToolStatusError     = "error"
)
```

### 4.2 `AsyncToolRuntime`

```go
type AsyncToolRuntime struct {
    inject            func(context.Context, string) error
    mu                sync.Mutex
    registry          map[string]*AsyncToolRecord
    order             []string // 保 launch 顺序，对齐 Python dict 插入序
    tasks             map[string]*asyncTask
    outputDirResolver func() string
    spillThreshold    int
}

type asyncTask struct {
    cancel context.CancelFunc
    done   chan struct{}
    once   sync.Once
}
```

- `registry` / `order` / `tasks` 在 runtime 生命周期内保留（不因完成而删除）；`Stop` 时 `CancelAll`。对齐 Python 的 `_events` 不删除；`_tasks` 的 pop 差异见 D-5。
- `order` 用于 `ListAll` 保序；重复 `task_id` 时覆盖记录但不重复追加（task_id 由 `GenerateID` 保证唯一）。
- **快照返回**：`Get` / `ListAll` / `Wait` 返回记录的值拷贝（`*AsyncToolRecord` 指向拷贝），避免调用方读取 `Status`/`Result` 时与后台 goroutine 的字段写入构成 race；runtime 内部仍持原指针并在 `rt.mu` 下写。

构造与选项（对齐 Python dataclass 的可注入字段，测试需要低阈值）：

```go
func NewAsyncToolRuntime(inject func(context.Context, string) error, opts ...AsyncToolRuntimeOption) *AsyncToolRuntime
type AsyncToolRuntimeOption func(*AsyncToolRuntime)
func WithSpillThreshold(n int) AsyncToolRuntimeOption
func WithOutputDirResolver(fn func() string) AsyncToolRuntimeOption
```

`NativeHarness` 用默认阈值（32768）+ 注入 `inject`/resolver；单测用 `WithSpillThreshold(1000)` 覆盖落盘路径。

### 4.3 `AsyncTool`

```go
type AsyncTool struct {
    tools.TeamTool
    parent   tools.AsyncToolHost
    language atschema.Language
    worker   AsyncToolWorker
}

type AsyncToolWorker interface {
    RunBackground(ctx context.Context, taskID string, inputs map[string]any) (any, error)

```

`AsyncTool.Invoke` 调 `t.worker.RunBackground(...)`，动态派发到子类。

## 5. `AsyncToolRuntime` 行为

### 5.1 `Launch`

```go
func (rt *AsyncToolRuntime) Launch(taskID string, factory func(context.Context) (any, error), opts tools.AsyncToolLaunchOptions) {
    ctx, cancel := context.WithCancel(context.Background())
    task := &asyncTask{cancel: cancel, done: make(chan struct{})}
    rt.mu.Lock()
    if _, exists := rt.registry[taskID]; !exists {
        rt.order = append(rt.order, taskID)
    }
    rt.registry[taskID] = &AsyncToolRecord{...Status: AsyncToolStatusRunning...}
    rt.tasks[taskID] = task
    rt.mu.Unlock()
    go rt.run(ctx, taskID, factory, opts.ToolName)
}
```

- `factory` 是零参闭包，保持构造惰性（对齐 Python `coro_factory`）。
- `context.Background()` + 显式 `cancel`：Python 的 task 独立于 tool 调用 ctx；Go 用 `CancelAll`/`Cancel` 作为唯一取消源。

### 5.2 `run`

```go
result, err := factory(ctx)
switch {
case errors.Is(err, context.Canceled):
    rt.markError(taskID, rec, "cancelled") // 不注入
case err == nil && ctx.Err() != nil:
    // factory 忽略了取消仍返回成功：以取消为准，不注入。
    rt.markError(taskID, rec, "cancelled")
case err != nil:
    rt.reportFailure(ctx, taskID, rec, toolName, err)
default:
    rt.reportCompleted(ctx, taskID, rec, toolName, result)
}
```

`ctx.Err()` 兜底对齐 Python 的取消语义：Go 的 factory 可能在取消后仍返回 `nil`，不能把已取消任务当成功注入。

### 5.3 完成/失败注入

- `reportCompleted`：`RenderResultText(result)` → `maybeSpill` → 记录 `completed`/`Result` → `signal` → `FormatCompleted(result)` 或 `T("async_tool.completed", {tool, result})` → `inject`。
- `reportFailure`：记录 `error` → `signal` → `FormatFailed(err)` 或 `T("async_tool.failed", {tool, error})` → `inject`。
- `inject` 失败只 debug 日志（对齐 `_inject` 的 best-effort；停机竞态不得上抛）。
- `signal` 用 `sync.Once` close `done`，防 `Cancel` 与 `run` 双关。

### 5.4 控制面

| 方法 | 语义 |
|---|---|
| `HasRunning(toolName string) bool` | 遍历 registry：`status == running && toolName == name` |
| `Get(id string) *AsyncToolRecord` | 未知返回 nil；返回记录快照（值拷贝） |
| `ListAll() []*AsyncToolRecord` | 按 `order` 返回记录快照 |
| `Cancel(id string) bool` | 未知 false；已知：`cancel()` + running 记录改 `error/cancelled` + signal + true |
| `Wait(ctx, id, timeout) *AsyncToolRecord` | 未知 nil；非 running 直接返回；running 等 done/timer/ctx，返回当前记录 |
| `CancelAll()` | 遍历 tasks 逐个 `cancel()`，不注入 |

`Cancel` 对已完成任务返回 true（记录存在即真），对齐上游 docstring；上游代码因 `add_done_callback` 提前 pop `_tasks` 实际返回 false，见 D-5。

### 5.5 `maybeSpill`

1. `len([]rune(text)) <= spillThreshold` 或 resolver 为 nil/返回空 → 原样返回。
2. `path := filepath.Join(dir, taskID+".output")`；`os.MkdirAll` + `os.WriteFile`。
3. 写失败 → `logger.Warn` + 原样返回（降级 inline，不丢结果）。
4. 成功 → `record.OutputFile = path`；`runes := []rune(text)`，若 `len(runes) > spillSummaryChars` 则截到 1024；`notice := T("async_tool.spilled_notice", {path, task_id})`；返回 `string(runes) + "\n\n" + notice`。

**必须按 rune 切**：Python `text[:1024]` 是码点切片；Go 按字节切会把 CJK 截成半个字。

### 5.6 `RenderResultText`

- `nil` → `""`。
- `string` → 原样。
- 反射判 `map` / `slice` / `array` → JSON（`SetEscapeHTML(false)` + `SetIndent("", "  ")`，去尾部换行）。
- 其他（含 struct）→ `fmt.Sprint`（对齐 Python 对非 dict/list 走 `str()`）。
- JSON 失败 → `fmt.Sprint`（对齐 Python 的 `except TypeError` 降级）。

## 6. `AsyncTool` 基类

```go
func NewAsyncTool(card *tool.ToolCard, parent tools.AsyncToolHost, lang atschema.Language, worker AsyncToolWorker) AsyncTool
func (t *AsyncTool) Invoke(ctx context.Context, inputs map[string]any, _ ...tool.ToolOption) (map[string]any, error)
func (t *AsyncTool) Stream(_ context.Context, _ map[string]any, _ ...tool.ToolOption) (<-chan tool.StreamChunk, error)
func (t *AsyncTool) MapResult(output map[string]any) string
func (t *AsyncTool) Parent() tools.AsyncToolHost
```

- `Invoke`：`taskID := agentteams.GenerateID(t.Card().Name)`；`desc` 默认 `Card().Name`，若 worker 实现 `LaunchedDescription(map[string]any) string` 则用之；`parent.LaunchAsyncTool(...)`；失败返回 `{"success": false, "error": "Internal error: ..."}`（不抛 error，对齐 Python `ToolOutput(success=False)`）；成功返回 `{"success": true, "data": {"status": "launched", "task_id": taskID}}`。
- `Stream`：`nil, tool.ErrStreamNotSupported`（对齐团队工具）。
- `MapResult`：失败取 `error`；成功取 `data.task_id`，`T("async_tool.launched", {tool, task_id})`。i18n 取词失败（key 缺失）返回稳定英文兜底 `"[Background task] {tool} started (task_id={task_id})"`，不返回空串（空串会被 `WrapInvokeWithLogging` 当作无映射，LLM 看不到启动提示）。
- `LaunchedDescription` 是可选覆盖，不是必需接口（Python 默认 `self.card.name`）。

### 7.1 字段与懒创建

- `injectAsyncCompletion`：`return h.Send(ctx, text, false)`。
- `SetAsyncToolOutputDirResolver`：保存到 h；runtime 已创建则持 `rt.mu` 同步写入（`maybeSpill` 也在 `rt.mu` 下快照，避免 race）。

### 7.2 `Stop` 步骤 0

在 `h.cmd <- &cmdStop` 之前：

```go
h.asyncMu.Lock()
rt := h.asyncRuntime
h.asyncMu.Unlock()
if rt != nil {
    rt.CancelAll()
}
```

对齐 `native_harness.py:401-404`：先取消在飞任务，再进 `cmdStop`，避免完成注入与停机竞态。

### 7.3 spawn-done 改道

复用现有 `SetScheduleAutoInvokeOverride`（把字段/注释从"仅测试使用"改为"生产（NativeHarness）与测试共用"），在 `NewNativeHarness` 末尾：

```go
agent.SetScheduleAutoInvokeOverride(h.ScheduleAutoInvokeOnSpawnDone)
```

`NativeHarness.ScheduleAutoInvokeOnSpawnDone(ctx, query, delay)`：

```go
go func() {
    if delay > 0 {
        timer := time.NewTimer(time.Duration(delay * float64(time.Second)))
        defer timer.Stop()
        select {
        case <-timer.C:
        case <-ctx.Done():
            return
        }
    }
    h.agent.SetAutoInvokeScheduled(false)
    if h.State() == HarnessStateTerminated {
        return
    }
    if !h.isStarted() {
        logger.Warn(logComponent).Msg("[NativeHarness] auto-invoke before start; skipping")
        return
    }
    if err := h.Send(context.WithoutCancel(ctx), query, false); err != nil {
        logger.Debug(logComponent).Err(err).Msg("[NativeHarness] auto-invoke send rejected")
    }
}()
return nil
```

- `context.WithoutCancel(ctx)`：handler 返回后原 ctx 可能已取消，延迟投递必须活下来。
- 走 `Send(false)` 而不是 `DeepAgent.invoke`，保住单写者 supervisor。
- `isStarted()` 在 `startMu` 下读 `started`，避免与 `Stop` 竞态。

### 7.5 PAUSED 交互（必须保留）

## 9. 并发与错误处理

1. **锁序**：`AsyncToolRuntime.mu` 只保护 registry/order/tasks/resolver/threshold，不在持锁时调 `inject`（避免 `Send` 阻塞持锁）。
2. **signal 幂等**：`sync.Once` close done；`Cancel` 与 `run` 可能同时 signal。
3. **inject 竞态**：`run` 在 `CancelAll` 后返回 `context.Canceled`，只 `markError` 不注入；若已完成则 `Send` 被 TERMINATED 守卫拒绝，`_inject` 吞错。
4. **Stop 顺序**：`CancelAll` 在 `cmdStop` 之前；`StreamController.Stop` 在 `harness.Stop` 之前。
5. **spill 失败降级**：写盘失败只告警，结果仍 inline，不丢。
6. **resolver 竞态**：resolver 由 rail init 在任何 launch 之前设置；`maybeSpill` 在 `rt.mu` 下快照，避免 race。
7. **typed-nil**：`HarnessAccessor()` 的实现方在无 harness 时必须返回无类型 `nil`，不得返回 `(*TeamHarness)(nil)` 包成的接口；`FinalizeRound` 的 `h != nil` 依赖此约定。S-01 测试覆盖"无 harness"场景。
