# 10.3.23 Hooks 系统对齐修复设计

## 背景

10.3.23 Hooks 系统（5 个子章节）已实现完毕，但与 Python 对齐审计中发现以下问题需要修复：

1. `RunAll` 中 goroutine panic 未捕获（Python `asyncio.gather(return_exceptions=True)` 会捕获异常）
2. `handleHooksList` 缺少错误保护（Python 用 try/except 包裹）
3. `RunAll` 未知 hook 类型不应占 result 位（Python 不加入 tasks）
4. `ToolCallInputs.ToolArgs` 类型为 string，Python 为 Any（运行时 dict）
5. `SecurityAllow.NewArgs` / `ApproveResult.NewArgs` 类型为 string，Python 为 dict | None
6. 各消费者因 ToolArgs 是 string 而存在冗余的 json.Unmarshal/parseToolArgs 调用
7. ability_manager 双向同步缺少类型转换

## 设计原则

- **ToolCall.Arguments 保持 string**：对齐 Python `ToolCall.arguments: str`，LLM API 协议要求
- **ToolCallInputs.ToolArgs 改为 map[string]any**：对齐 Python `ToolCallInputs.tool_args: Any`（运行时 dict），在 ForkForToolCall 时解析
- **NewArgs 改为 *map[string]any**：对齐 Python `dict | None` 语义，nil=不替换
- **Go 方案比 Python 更干净**：两个类型各司其职，同步点显式 Marshal/Unmarshal，无需 isinstance hack

## Section 1：基础类型变更

### 1.1 ToolCallInputs.ToolArgs 从 string → map[string]any

**文件：** `internal/agentcore/single_agent/interfaces/callback.go`

```go

// 改后

```

### 1.2 ForkForToolCall 中解析 Arguments → ToolArgs

**文件：** `internal/agentcore/single_agent/interfaces/callback.go`

```go
// 改前
ToolArgs: toolCall.Arguments,

// 改后
ToolArgs: parseToolArguments(toolCall.Arguments),
```

新增 `parseToolArguments` 辅助函数（放在 interfaces 包）：

```go
// parseToolArguments 将 JSON 字符串解析为 map[string]any
// 对齐 Python: json.loads(tool_call.arguments) if isinstance(str) else tool_call.arguments
func parseToolArguments(args string) map[string]any {
    if args == "" {
        return map[string]any{}
    }
    var result map[string]any
    if err := json.Unmarshal([]byte(args), &result); err != nil {
        return map[string]any{}
    }
    return result
}
```

### 1.3 SecurityAllow.NewArgs / ApproveResult.NewArgs 从 string → *map[string]any

**文件：**
- `internal/agentcore/harness/rails/security/base_security_rail.go`
- `internal/agentcore/harness/rails/interrupt/interrupt_base.go`

```go

// 改后
```

## Section 2：消费者适配

### 2.1 ability_manager.go 双向同步

**文件：** `internal/agentcore/single_agent/ability/ability_manager.go`

**ToolArgs → Arguments（L515-516）：**

```go
// 改前
if inputs.ToolArgs != "" {
    toolCall.Arguments = inputs.ToolArgs
}

// 改后
// 注意：Python 用 tool_args is not None 判断（空 dict {} 也会替换），
// Go 用 len > 0 判断（空 map 不替换）。实际场景中 hook 不可能将参数修改为空 map，
// 所以行为等价。如需严格对齐，改为 ToolArgs != nil（零值 map != nil 为 true）。

        toolCall.Arguments = string(argsJSON)
    }
}
```

**Arguments → ToolArgs（L529）：**

```go
// 改前
inputs.ToolArgs = toolCall.Arguments

// 改后
var args map[string]any
if err := json.Unmarshal([]byte(toolCall.Arguments), &args); err != nil {
    args = map[string]any{}
}
inputs.ToolArgs = args
```

## Section 3：Hooks 专属修复

### 3.1 RunAll goroutine panic 保护

**文件：** `internal/swarm/server/hooks/executor.go`

每个 goroutine 内部加 `defer/recover`，对齐 Python `asyncio.gather(return_exceptions=True)`：

```go
go func(idx int, c map[string]any) {
    defer wg.Done()
    defer func() {
        if r := recover(); r != nil {
            results[idx] = HookResult{
                Outcome: HookOutcomeNonBlockingError,
                Error:   fmt.Sprintf("hook panic: %v", r),
            }
        }
    }()
    // 执行 hook...
}(i, cfg)
```

### 3.2 RunAll 未知 hook 类型跳过 + results 动态收集

**文件：** `internal/swarm/server/hooks/executor.go`

类型判断移到协程外部，未知类型跳过（对齐 Python 不加入 tasks）；results 动态 append：

```go
// 先过滤有效配置，对齐 Python: 只把 command/prompt 加入 tasks
validConfigs := make([]map[string]any, 0, len(hookConfigs))
for _, cfg := range hookConfigs {
    hookType, _ := cfg["type"].(string)
    if hookType == "prompt" || hookType == "command" || hookType == "" {
        validConfigs = append(validConfigs, cfg)
    }
}
if len(validConfigs) == 0 {
    return nil
}

results := make([]HookResult, len(validConfigs))
var wg sync.WaitGroup
for i, cfg := range validConfigs {
    wg.Add(1)
    go func(idx int, c map[string]any) {
        defer wg.Done()
        defer func() {
            if r := recover(); r != nil {
                results[idx] = HookResult{Outcome: HookOutcomeNonBlockingError, Error: fmt.Sprintf("hook panic: %v", r)}
            }
        }()
        hookType, _ := c["type"].(string)
        if hookType == "prompt" {
            results[idx] = e.runPromptHook(ctx, c, hookInput)
        } else {
            results[idx] = e.runCommandHook(ctx, c, hookInput)
        }
    }(i, cfg)
}
wg.Wait()
return results
```

移除原来的"空 outcome → SUCCESS"兜底逻辑。

### 3.3 handleHooksList 错误保护

**文件：** `internal/swarm/server/handle_extensions.go`

正确处理 `config.Load()` error，对齐 Python `try/except` + `ok=False`：

```go
func (s *AgentServer) handleHooksList(_ context.Context, request *schema.AgentRequest) (*schema.AgentResponse, error) {
    configBase, loadErr := s.config.Load()
    if loadErr != nil {
        logger.Warn(logComponent).Err(loadErr).Msg("handleHooksList: config 加载失败")
        return schema.NewAgentResponse(request.RequestID, request.ChannelID,
            schema.WithResponseOK(false),
            schema.WithPayload(map[string]any{"error": loadErr.Error()}),
        ), nil
    }
    hooksCfg := hookscfg.LoadHooksConfig(configBase)
    summary := hooksCfg.GetEventSummary()
    return schema.NewAgentResponse(request.RequestID, request.ChannelID,
        schema.WithPayload(map[string]any{
            "events":            summary,
            "disable_all_hooks": hooksCfg.DisableAllHooks,
            "source":            "config.yaml",
        }),
    ), nil
}
```

## 实施顺序（自底向上）

1. **基础类型变更**：ToolArgs → map、NewArgs → *map、parseToolArguments
2. **消费者适配**：ability_manager 双向同步、各 Rail 写入、消除冗余解析
3. **Hooks 修复**：RunAll panic 保护 + 未知类型跳过 + handleHooksList error 处理
