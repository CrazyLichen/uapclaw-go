## 2. 测试文件设计

目录 `tests/integration/evolving/rsi/acceptance_pipeline/`，全部 `//go:build integration` 标签 + `suite.Run`，每个文件独立 suite：

### 2.1 engine_event_order_test.go — 引擎事件序

- 链路：fake LLM 端点驱动一轮完整演进会话（评估→诊断→动刀→评分）。
- 断言：按序收集 progress 事件流，逐条核对剧本顺序（任务开始 → 每场考试"考生进场" → "考试结束" → 裁判评分 → epoch 切换）；事件序号连续、无缺号、无重复、无乱序；epoch 边界事件位置正确。

### 2.2 promotion_gate_rejection_test.go — 晋级门拒绝路径

- 链路：fake 评委对特定 epoch 给低分制造考砸场景。
- 断言：连续两阶段晋级门拒绝；最终结论为拒绝、未发布新工件；后续轮次按拒绝分支继续（不携带坏结果晋级）。

### 2.3 judge_parse_tolerance_test.go — judge 解析容错

- 链路：fake LLM 端点按场景返回四种不规范形态：截断 JSON / 多余文字包裹 / 缺字段 / 超时。
- 断言：恢复逻辑兜住（JSON verdict 恢复路径）、考试继续进行、格式错误不误判为考生答错；超时走重试/收尾正确分支。

### 2.4 cancel_no_residue_test.go — 取消后不残留（两条）

1. **服务域全链**：经 17.9 真实服务入口下 terminate 订单 → 真实 singleharness 引擎运行中被取消（慢 fake LLM 制造取消窗口）→ 断言：引擎观测到取消、TERMINATED 状态落库、工件目录/登记簿无半成品残留、事件流终止于取消事件。
2. **引擎直调**：直接 `Run`（ctx 取消）验证清理面：临时目录/登记簿/事件流无残留、后续步骤不再执行。

## 3. fake 边界与审计合规

- 唯一 mock 点 = LLM HTTP 端点（httptest，OpenAI 兼容 fake），与既有 `evaluator_scoring_pipeline/scoring_pipeline_test.go` 同款手法，复用其端点构造与 dataset 夹具资产，不重复造轮子。
- 每文件真实调用跨度 ≥3 个 internal 子系统（harness_rsi / evaluator / agentserver / data_loader 等），过 `go run ./cmd/integration-audit -verify` 两层门禁（AST 调用跨度 + 覆盖交叉验证 ≥3 子系统各 ≥30 行）。
- 不留 Skip、不做假链；mock 只在网络边界（规则 7）。

3. `go run ./cmd/integration-audit -verify` 双层门禁通过。
4. 推送远端即交付（规则 11，不追 CI）。
5. `IMPLEMENTATION_PLAN.md` 17.10 ☐→✅，行内注明：harness 轨已完成、PUCT 轨 ⤴️17.3、paper 轨 ⤴️17.5 追加用例挂账。
