## 2. 关键语义（先钉死，防实现走样）

### 2.1 consent_epoch 的真实语义（★ 纠正占位实现）

```python
def consent_epoch() -> float | None:
    if not is_prompt_suggestion_enabled():   # ← None 只由 prompt 开关决定
        return None
    controls = load_recommendation_controls()
    return float(controls.get("deleted_at") or 0.0)   # ← 0.0 是合法 epoch（从未删除）
```

- epoch 值域是 `≥0` 的 float；`None` ⇔ prompt 开关关。
- Go 现有 `ConsentEpoch(config) int64`（nanotime 占位、0=关闭）**语义不等价且撞值域**，本节重写：

```go
// ConsentEpoch 返回当前同意 epoch。active=false 等价 Python 的 None。
func ConsentEpoch(config map[string]any) ConsentEpochValue

type ConsentEpochValue struct {
    Value  float64
    Active bool
}
```

- `Active = PromptSuggestionEnabled(config)`；`Value` = consent 表的 `deleted_at`（缺失 → 0.0）。
- epoch 相等比较：`Active` 与 `Value` 都相等才算相等（对齐 Python `==` 对 None/value 的区分）。
- 连带改调用点：`TurnEnded`（`:191` 的 `epoch == 0` → `!epoch.Active`）、`runFork` 循环内复查、5 处测试。

### 2.2 完成行（前置缺口的补齐目标）

上游每轮结束往 history.json 追加：

```
{"id": "<rid>:request_completed", "role": "assistant", "request_id": rid,
 "channel_id": "", "timestamp": ..., "content": "",
 "event_type": SESSION_REQUEST_COMPLETED_EVENT,   ← 字面值 "chat.request_completed"（上游测试
                                                     test_prompt_suggestion.py:554 断言实测）
 "feedback_only": true, "status": <terminal_status>}
```

- 写入走既有异步 history 队列，**返回落盘回执**（Python `Future[None]`）。
- 终态白名单 `{success, error, cancelled, failed, waiting_user, unknown}`，非法值报错。
- 心跳临时会话返回 nil 回执（不写行）。
- `_latest_completed_request` 消费方式：从记录末尾倒序找第一条 `event_type == 完成行`；要求 `status == "success"` **且其后所有行的 request_id 都等于它**，否则返回 None（语义：它是会话最新完成轮）。

### 2.3 推送三道闸（本节语义核心）

1. **等落盘闸**：runFork 出 candidate 后 `select { ctx.Done / Completion 回执 }`（对齐 `asyncio.shield`；无超时，对齐 `:527-530`）。
2. **保鲜闸**：StageDelivery 落库前查 `LatestCompletedRequest(session) == reqID`，不等 → 记 `delivery(status=suppressed, reason=stale_request)`，返回 nil 不推。
3. **送达记账闸**：过闸先记 `delivery(status=pushed, reason=null)` 再推 `prompt_suggestion.ready`。

### 2.4 CurrentSuggestions 回读与双复查

过滤链（逐条对齐 `:583-604`）：

1. epoch 不活跃 → `{enabled:false, suggestions:[]}`
2. `LatestCompletedRequest` 为空 → `{enabled:true, suggestions:[]}`
3. `QueryEvents(generation, policy=POLICY_ID, slate="prompt-suggestion:<reqID>", limit=2)`
4. 逐条：session 匹配 / `created_at ≥ epoch` / `payload.outcome == "candidate"`，否则跳过
5. 已消费判定：`QueryEvents(prompt_suggestion_{accepted,ignored,suppressed}, topic_id=..., limit=1)` 任一命中 → 跳过
6. 返回字段白名单：`session_id / request_id / suggestion_id / text`
7. **末尾双复查**：epoch 或 requestID 变了 → 整批作废返回空（值仍带当前 enabled 态）

### 3.1 结构决策（一删一留）

1. **删 `ForkResultPublisher` 窄接口**。Python `_record` 在 harness 层内直写 store，Go 同包直调即可；窄接口是"落库口未定"的预留，按规则 8 同改动删除（连带 3 处测试替身与 `SetForkResultPublisher`）。

## 4. 账本事件形状（五类）

统一五段主键（复用 10.7.1 `EventKeyOf`）：`session|prompt-suggestion:<reqID>|<event_type>|prompt-suggestion:<suggID>|`（第 5 段 feedback_record_id 恒空），天然幂等。

| event_type | 写入点 | payload 关键字段 |
|---|---|---|
| `prompt_suggestion_generation` | TurnEnded 抑制；runFork 终局（candidate/filtered/suppressed/cancelled/failed） | outcome、reason、text、prompt_version、latency_ms、parent_uncached_tokens、answer_tokens、provider_receipts[]、provider_response_id、usage、total_usage、missing_provider_receipts、usage_complete |
| `prompt_suggestion_delivery` | StageDelivery | status: pushed/suppressed、reason: stale_request 或 null |
| `prompt_suggestion_accepted` | RecordPageOutcome | method ∈ {click,tab}、time_to_accept_ms（`_plain_int` 且 ≥0） |
| `prompt_suggestion_ignored` | RecordPageOutcome | reason ∈ {dismissed, sent_other, left_session, typed} |
| `prompt_suggestion_shown` / `prompt_suggestion_suppressed` | RecordPageOutcome | shown 空 outcome；suppressed 仅 reason="timing" |

公共字段（对齐 `_record`）：`policy_id=POLICY_ID`、`selection_mode="prompt_suggestion"`、`propensity_reason="not_estimated"`、`created_at=time.time()`、payload 内固定 `suggestion_id / session_id / request_id / prompt_version`。

**runFork 记账字段语义**（补齐 10.3.30 半截，逐条对齐 `:447-536`）：

- 每次重放追加 receipt：`{model, provider_response_id, usage, latency_ms}`；`missing_provider_receipts` 进出配对
- `usage_payload`：prompt/completion/total_tokens + cached/reasoning 明细
- `total_usage` 按 `provider_response_id` 去重累加（counted_ids 集合）
- tool_call 续轮：追加 reply + `"生成建议无需使用工具"` ToolMessage（字面逐字，禁本地化）
- 取消路径：记 `outcome=cancelled` 后再传播取消
- 失败路径：记 `outcome=failed, reason=type(exc).__name__`（Go 用 error 分类字面映射）
- 首个非空字符串 content → SelectSuggestions（10.3.30 已有）

## 5. 错误处理（全对齐"账本失败不伤主流程"）

| 场景 | 行为 |
|---|---|
| LedgerEventRecord 写失败 / epoch 已变 | 吞掉 + Warn（`_record` try/except 语义）；epoch 已变直接 return |
| pushCheckedSuggestions 单条失败 | Warn 后继续下一条（对齐 `noqa BLE001` 注释） |
| RecordPageOutcome 校验不过 / 查无 generation / session 不符 / 非 candidate | 返回 nil → RPC 层 `BAD_REQUEST "unknown suggestion or outcome"` |
| RPC `input_changed` cancel 失败 | 仍答 `{cancelled:false}` |
| ConsentState 探测 | 库不存在/表不存在/OperationalError/其他异常 → 一律降级"未记录"（deleted_at=0）；**不建库不建表不产生文件**；缺表属正常（首次 opt-in 前无此表，不 Warn） |
| EnqueueHistoryRequestCompletion 终态非法 | 返回 error（对齐 ValueError）；心跳临时会话返回 nil 回执不写 |
| 完成行等待 | runFork 内 select ctx.Done / 回执；回执来自 history worker 写完即 close |
