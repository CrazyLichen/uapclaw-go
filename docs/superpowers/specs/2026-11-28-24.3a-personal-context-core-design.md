## 1. 背景与定位

PersonalContext 是进程内常驻宿主服务（不在 ReAct/rail 链路）：用户把外部源采集成本地
Markdown 知识图谱，agent 会话消费（24.3c），前端设置页管理。24.3 已交付 Host 壳
（`internal/swarm/server/personal_context/` 三文件一比一 + 26 个 ReqMethod 分发），
Core 空态运行（`coreRuntime` 窄接口恒 nil）。本批交付 **Core 基座 + 编排单例**并注入真身。

**Pipeline 核心思想**：知识图谱不是数据库——`workspace/context/` 是一棵发布的
Markdown 目录树（唯一事实源），图谱是查询时从该树即时算出的派生视图（无缓存无索引）。

## 4. 数据流全景（Go 终态）

```
Host(internal/swarm/server/personal_context, 既有)
   │ coreRuntime 窄接口（24.3a 起注入真身；nil 空态保留）
   ▼
*PersonalContext (personalContext.go) ── config/pipeline/工厂表(缝1)/cursor 存取/进度上报
   │ start(): scheduler goroutines(每 service 一个) + pipeline 消费者 goroutine(唯一)
   ▼
ContextPipelineService (contextPipeline.go)
   ├─ 消费 chan 事件(batch/finish/retain/abort/rollback 五元组 struct)
   ├─ batch → sandbox 落盘(records+processed)；finish → 编译+原子发布
   ├─ 缝2: agent_use 函数类型（24.3c 前=桩）
   └─ 查询面: contextGraph/sourceMetadata/sourceLinkBook 纯函数
```

### Pipeline 五阶段（语义摘要，实施时逐行对齐）

1. **入队**：fetch 协程 `prepare_run`（变更检测，cursor 比对，规则各源自定义）→
   `fetch`（下载+解析，`FetchBatch.items` 为成品）→ `_submit_batch` 入队；空批次只推进 cursor。
2. **确定性归一**（`_process_deterministic` :8642）：Markdown 规范化/NFKC/切块/哈希
   block_id/source_links 注册，写 `sandbox/inputs/{records,processed}/`。
3. **finish 事件**（:8017）：run 唯一一次编译+发布入口。
4. **三档目录组织**（`_filesystem_with_fallback` :8713，`_PROFILE_RANK rules<balanced<agent`
   逐级回退）：rules=纯规则+容量钳制；balanced=LLM 页语义（组包 JSON：summary≤450 字/
   keywords/page_title≤80 字）+ 聚类（见下）；agent=DeepAgent+recluster 工具（桩，缝2）。
   编译含导航块渲染（`<!-- personal-context:navigation:(start|end) -->`）、briefing 页、
   description.md 呈现签名。
5. **原子发布**（`_publish_processed` :9515 → `_commit_context_tree` :1348）：发布锁
   串行 → symlink 断言 → 删已删源页 → rename `sandbox/context → workspace/context`，
   同步 source-meta；成功删 sandbox，失败 rollback。

### 聚类算法（balanced/agent 档）

- 向量：稀疏（title+headings+preview 字段加权 BM25 风格）⊕ 稠密（embedding，失败永久
  降级稀疏）；来源分布重叠惩罚（跨 provider 拉低相似度）。
- `_capacity_constrained_clusters`（:511）：全对相似度 → `_adaptive_accept_cut` 自适应
  阈值（F_05）→ 连通分量（保语义孤岛）→ affinity_groups 预连边 → 分量内
  `_build_hierarchical_cluster_tree` 层级分裂，硬约束 max_pages/max_subdirectories。
- **新旧一起聚**（作用域=子树整体重建），三重保护：旧目录标签作伪条目参与（页↔目录
  通道，实测最强信号）；affinity 保组（旧目录成员 ≥2 个且相似度 ≥
  `_SEMANTIC_ACCEPT_FLOOR` 整体存活）；LLM 语义卡只对变更+新增页调用。

### 图谱（查询时现算，无缓存）

`build_context_slice`（context_graph.py:141）纯函数：节点=每 `.md` 页
（`description.md`→directory，label=H1 或文件名）；边两种——
`contains`（文件挂所在目录 description.md，:170-181）、`references`（正文 Markdown
链接 `_MARKDOWN_LINK` 解析到仓内页，已构成 contains 的不重复，:211-219）；BFS 按
depth（默认 3）裁剪。**无来源边、无语义相似边**——跨源关联已物化为目录结构
（聚类决定"谁跟谁放一起"，图谱只读目录树+文内链接）。

## 5. 并发模型映射（asyncio → Go）

| Python | Go |
|---|---|
| scheduler 协程 × N | 每 service 一个 goroutine（WithCancel） |
| `_consume` 消费者协程 | 唯一消费者 goroutine + `chan pipelineEvent`（五元组 struct，带 `done chan struct{}` 代 Future） |
| `asyncio.Lock` 发布锁 | `sync.Mutex`（延续 D-24.3-1） |
| `_cancel_safe_to_thread` | 磁盘重操作 goroutine + 轮询取消标志助手（结构对齐同名 Python 函数） |
| `Semaphore + gather` | `errgroup` + 信号量，分组顺序保持 |
| `wait_for_commit_point` shield | `done` channel + `select ctx.Done()` |

**不变量**（集成断言）：①单消费者串行（同一 sandbox 无并发写）；②发布锁全局互斥；
③fetch 只入队不触盘（除 cursor），pipeline 只消费不联网；④事件完成语义（fetch 等
completion 才 commit cursor）。
