## 1. 背景与定位

数字分身（`group_digital_avatar`）模式的两条预处理管线，在 agent 会话流程中的位置：

```
【入站】Channel(feishu/wecom) → ChannelManager → MessageHandler.HandleMessage
                                                        ↓ userMessages chan
                                  forwardLoop ── 步骤1/2/3（slash/channel state/hook）
                                                        ↓
                                   ★ 步骤6 InboundPipeline.Apply(msg) ←← 11.12 入站点
                                   （无适配器/异常 → 兜底转发；不相关 → 丢弃）
                                                        ↓
                                   步骤7-10（@file 解析 → E2A → AgentServer）

【出站】AgentServer → AgentClient → handleAgentServerPush → PublishRobotMessages
                                                        ↓
                                   ★ OutboundPipeline.Apply(msg) ←← 11.12 出站点
                                   （入队前路由决策：群发 vs 私发 + 追问前缀解析）
                                                        ↓ robotMessages chan
                                  ChannelManager.dispatchRobotMessages → Channel.Send（只读 metadata 执行私发）
```

**作用**：
- **入站**：群聊消息相关性过滤（@提及/必答规则直接放行；否则 LLM 改写消息为更清晰的请求）+ PendingInteraction（11.8）追问上下文回填 + resume 消息放行
- **出站**：回复投递路由决策（LLM 分类 DM/CHAT + 关键词兜底，判定私发时写 `reply_scope=dm`）+ `[群聊追问@xx]`/`[私聊追问]` 前缀解析创建 PendingInteraction 落盘

**消费点全景**（Python 侧核对）：
- message_handler 两处挂接：入站 forward_loop 步骤6（L2440-2446）+ 出站 `publish_robot_messages` 入口（L1196-1198）
- app_gateway 装配（L851-856）+ feishu/wecom 适配器注册（L1279/1355/1568，⤵️ 11.16/11.21）
- cron scheduler 群聊任务推送前置 metadata（Go 侧 scheduler.go L768-804 **已对齐预埋**，等本管线消费）

**关键事实（Go 现状）**：`PublishRobotMessages` 是全部出站消息的单一汇聚点——stream chunk、cancel 通知、slash 通知、heartbeat relay、cron push、web ack 共 17 处调用全走这里，与 Python `publish_robot_messages` 13 处调用完全同构。**出站管线单点接入即可全覆盖**，Python 靠管道内部 4 层短路条件（非数字分身 → 4 跳过事件类型 → 非群聊 → 无适配器）防误伤；stream chunk（chat.delta）在跳过集内不触发 LLM。

**SYSTEM_PROMPT_TEMPLATE**（逐字复制 Python 原文，含 `{principal_name}`/`{bot_mention_hint}` 两占位符；`bot_mention_hint = strings.Join(tokens, " / ")`，空列表回退 `"@机器人"`）——提示词一比一纪律，**禁止翻译或改写**。

### 4.2 IMInboundPipeline（适配器注册表 + Apply）

```go
// InboundProcessResult 入站处理结果（对齐 dataclass InboundProcessResult）
type InboundProcessResult struct {
```

- `NewIMInboundPipeline(processor, adapters)`：processor nil → `NewIMConversationProcessor("", "")` 默认构造（对齐 Python `processor or IMConversationProcessor()`）；adapters nil → 空 map

**Apply(ctx, msg) bool**（对齐 Python L470-616，执行顺序纪律，顺序不可调换）：

1. `!msg.GroupDigitalAvatar` → return true（放行）
2. `adapters[msg.ChannelID]` 无 → return true
3. **resume 消息分支**（`metadata["is_resume_message"]` truthy）：
   - `dm_pending_interaction_id` strip 非空 → `routing.LoadPendingInteraction(id)`
   - pi 非 nil：`answer` = params.query or params.content（strip）；`resumeContent = pi.BuildResumeContent(answer)`；双写 `params.query` + 条件写 `params.content`（仅当原 params 为 map 且已含 content 键）；`metadata.interaction_context = resumeContent`；`pi.Status="completed"` → `pi.Save()` → `pi.Remove()`；Info 日志两条（dm_resume + resume_content，字段对齐）
   - Info 日志「resume 消息直接放行」（channel/id 字段）→ return true
4. `originalQuery` 提取（params.query 非空 strip 优先，否则 params.content——仅字符串类型参与）
5. `peekPending(msg)`：session_id + sender_user_id（`im_sender_user_id` → `open_id` → `sender_id` 三键回退）均非空 → `routing.FindGroupPending(session, sender)` → pi 非 nil 时拼四段中文模板（逐字对齐 Python L630-640，含 `pi.TargetUserName or "用户"` 双处回退）；非空时 Info 日志 pending_context
6. `processor.Process(msg, adapter, pendingContext)`
7. `result.MetadataPatch` 非空 → merge 进 msg.Metadata
8. `result.RewrittenContent` 非空 → 双写 params.query + 条件写 params.content
9. `originalQuery` 非空 → `msg.Metadata["avatar_original_query"] = originalQuery`
10. `pendingContext` 非空且 `result.ShouldForward`：`metadata.interaction_context = pendingContext`；`interaction_answered_user_id = sender`（非空时）；session+sender 均非空 → 二次 `FindGroupPending` → pi 非 nil：`answer = result.RewrittenContent or originalQuery` → `BuildResumeContent(answer)` → 双写 params（Info 日志 find_group_pending + resume_content）
11. `result.ShouldForward && result.Reason != "non-group-chat"`：avatar_detail 四键 merge（`avatar_mode=true` + `avatar_channel_type=adapter.PlatformName()` + 条件 `avatar_principal_name`/`principal_user_id`）
12. 尾部 Info 日志（channel/request/should_forward/reason/rewritten(original_preview/rewritten_preview 各 120 截断+`\n`→`\\n`)/metadata_keys sorted/pending 九字段）
13. return `result.ShouldForward`

**peekPending 模板**（逐字复制 Python 中文原文）：

```
【追问上下文】你之前在处理以下任务时向 {target_user_name or 用户} 追问了信息：
- 原始请求：{pi.OriginContent}
- 你的追问：{pi.Question}
现在 {target_user_name or 用户} 已回复，请综合「原始请求」和「用户回复」中的所有信息继续完成任务，
原始请求中已明确提供的信息（如时间、地点等）直接使用即可，不要再次追问。
不要与群聊历史中的其他任务混淆。
```

### 5.1 常量与跳过集

### 5.3 出站挂接（PublishRobotMessages 单点接入）

```go
// forward_loop.go
// PublishRobotMessages 将 Agent 响应写入出站 channel。
// Python: MessageHandler.publish_robot_messages()：
//   Outbound Pipeline（数字分身出站路由）在入队前运行；
//   异常 logger.exception("Outbound pipeline error, message queued without routing") 后照常入队。
func (mh *MessageHandler) PublishRobotMessages(msg *schema.Message) {
    if mh.outboundPipeline != nil {
        mh.applyOutboundPipeline(context.Background(), msg)
    }
    select {
    case mh.robotMessages <- msg:
    default: ... // 原入队逻辑不变
    }
}

// applyOutboundPipeline 执行出站管线，panic/error 均降级为 Warn 不阻塞入队。
func (mh *MessageHandler) applyOutboundPipeline(ctx context.Context, msg *schema.Message) {
    defer func() {
        if r := recover(); r != nil {
            logger.Error(logComponent).Any("panic", r).Str("msg_id", msg.ID).
                Msg("Outbound pipeline error, message queued without routing")
        }
    }()
    if err := mh.outboundPipeline.Apply(ctx, msg); err != nil {
        logger.Error(logComponent).Err(err).Str("msg_id", msg.ID).
            Msg("Outbound pipeline error, message queued without routing")
    }
}
```
