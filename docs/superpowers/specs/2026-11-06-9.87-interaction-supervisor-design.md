# 9.87 交互监督器（Goal 前置基座）设计

## 概述

9.87 是持续目标（Goal）能力的**前置基座**：在 `DeepAgent` 与 `TaskLoopController` 之间新增一层**会话级常驻调度器**，把原来的"一次 `Stream()` 开一条独立管道、跑完即拆"改为"**一个会话一条常驻管道 + 多个 work item 排队串行执行**"。

Python 侧由三部分构成：

| Python | 行数 | 内容 |
|--------|------|------|
| `openjiuwen/harness/schema/interaction.py` | 368 | 12 个交互域对象（相位、work item、租约、事件、输出流） |
| `openjiuwen/harness/task_loop/event_manager.py` | 146 | `EventManager`：user/goal 双队列调度 |
| `openjiuwen/harness/deep_agent.py` L3728-4567 | ~840 | `DeepAgent` 交互监督器 33 个方法/属性 |

Go 侧现状：**goal 与交互监督器相关符号 0 个**；现有 `DeepAgent.runTaskLoop` 是旧单入口路径（自持 `for coord.ShouldContinue()`，finally 会 `UnbindSession/Stop` 拆控制器）。

本设计**不删除**旧路径（S1 约束 ⑤），新增出口不改道。

**作用（6 条）**

1. 会话生命周期与相位机（idle/running/terminated，terminated 不可逆）
2. 单消费者输出租约（解决多前端/重连/切会话抢同一条 chunk 流导致"撕流"）
3. 双队列调度（user 优先、goal 次之，goal 按 `(goal_id, revision)` 去重）
4. 回合执行适配（`RoundWorkItem` → 现有 `SubmitRound`/`WaitRoundCompletion`）
5. 结构化事件出口（`goal.updated` / `execution.error` 作为 `OutputSchema` 帧）
6. 给 Goal 层提供三个挂点（control lock、`EnsureActiveGoalWorkLocked`、`BeginAttempt`/`CancelActiveRound`）

## 关键设计决策

| # | 决策 | 说明 |
|---|------|------|
| K1 | 三把锁用 `sync.Mutex`，`xxxLocked` 后缀约定"调用方已持锁" | Python `asyncio.Lock` 亦不可重入；Go 版 `xxxLocked` 变体**绝不自行加锁**，靠注释 + `AssertHeld()` 单向断言守护（`TryLock` 成功 ⇒ 一定没人持锁 ⇒ panic） |
| K2 | `RoundWorkItem.Context` 用结构体 | `RoundContext{GoalID string; Revision int; SessionID string; ResetLoop bool}`；`Inputs` 保持 `map[string]any`（本来就要原样传给 invoke） |
| K3 | `EventManager` **无内部锁**，所有调用点在 `controlMu` 内 | Python 靠单线程；Go 由 supervisor 在 4 个短点新增持锁（`NextWork` / `MarkStarted` / `PushUser(next)` / `MarkFinished`），`MarkStarted` 与 `MarkFinished` 之间**必须放锁**跑完整轮 ReAct |
| K4 | 输出队列 `chan leaseFrame` cap **128**，满则**丢新帧** | Python `asyncio.Queue()` 无界；Go 必须有界。丢新帧保留已有前缀（中间空洞更难排查），`Warn` 限流 1s 一条 + `dropped_total` 计数 |
| K5 | 队列元素类型 `stream.Schema`（不伪造假帧） | 唯一非 Schema 的入队物是结束哨兵，用信封 `leaseFrame{schema, end bool}` 表达。**不用 `any`**：服务层一旦需要断言就会出现"具体类型断言静默吞空" |
| K6 | 非阻塞投递在锁内完成 | 与 Python `put_nowait` 在 `_lock` 内一致 ⇒ `Emit` 与 `Detach`（锁下 drain）天然互斥，**不需要票号信封**，`NextItem` 也不需要丢弃过期帧 |
| K7 | `roundBoundaryFrame` + `Session.StreamEmitter()` | 边界帧必须与普通 chunk 走**同一条队列**才有顺序保证；`outputWriter.Write` 有类型白名单（只认 `OutputSchema`），链一走不通 |
| K8 | goal 依赖用窄接口 `GoalCoordinator` | Python 是具体类 `GoalManager`（L3964-3981 `start()` 里构造）。9.87 只声明它用到的 3 个方法：`HasActiveRecord() bool`、`EnsureActiveGoalWorkLocked()`、`BeginAttempt(goalID string, revision int) (bool, error)`；9.89 注入具体 `*goal.GoalManager`。好处是 S2/S3 阶段即可用 fake 覆盖 goal 分支（否则只能等 9.88），且 9.87 不依赖 9.88 的任何类型（Python 的 `record.status is ACTIVE` 三处判定收敛为 `HasActiveRecord()`） |
| K9 | 取消在飞轮有界 1.5s | `abort()` 先 → 取消 round goroutine → `TaskScheduler.CancelTask` 用 `select + time.After(1500ms)`，超时记 Warn 并让 cancel 后台完成（等价 `anyio.fail_after(shield=True)`） |

### 队列与租约实现骨架

```go
const outputQueueSize = 128

// leaseFrame 队列元素：schema + 结束哨兵标记
// Python: Any + _OUTPUT_END = object()
type leaseFrame struct {
	schema stream.Schema
	end    bool
}

// Emit 非阻塞投递：满则丢新帧
// Python: OutputLeaseManager.emit (interaction.py L287)
func (m *OutputLeaseManager) Emit(item stream.Schema, expectedToken string) {
	m.mu.Lock()
	defer m.mu.Unlock()

	lease := m.lease
	if m.closed || lease == nil || lease.IsClosed() || lease.Finishing.Load() {
		return
	}
	if expectedToken != "" && lease.Token != expectedToken {
		return
	}
	if len(m.queue) == cap(m.queue) {
		m.dropped.Add(1)
		m.logDropThrottled(lease.Token)
		return
	}
	m.queue <- leaseFrame{schema: item}
}

// NextItem 取一条；票作废或读到哨兵返回 false
// Python: OutputLeaseManager.next_item (L297)
func (m *OutputLeaseManager) NextItem(ctx context.Context, lease *OutputLease) (stream.Schema, bool) {
	m.mu.Lock()
	if m.lease != lease || lease.IsClosed() {
		m.mu.Unlock()
		return nil, false
	}
	m.mu.Unlock()

	for {
		select {
		case <-lease.closed:
			return nil, false
		case <-ctx.Done():
			return nil, false
		case f := <-m.queue:
			if f.end {
				m.mu.Lock()
				if m.lease == lease {
					m.lease = nil
					lease.Close()
				}
				m.mu.Unlock()
				return nil, false
			}
			return f.schema, true
		}
	}
}
```

`FinishCurrent` 的哨兵**不允许丢**：队列满时先丢弃队首一帧再入队 `end`（结束信号优先于尾部数据），并记 `Warn`。

## 实现步骤

### S1：交互类型与调度器（零依赖，纯单测）

产出 `schema/interaction.go` + `task_loop/event_manager.go` + 三处回填。

1. `interaction.go`：12 个类型 + `OutputLeaseManager`（9 方法）+ `InteractionOutputDriver` 窄接口 + `GoalCoordinator` 窄接口（K8，仅声明不放实现）
2. `event_manager.go`：`EventManager` 双队列（`userQueue`/`goalQueue` 切片）+ `dequeued`/`active` 字段 + 12 方法
3. 回填 `RunKindGoal = "goal"` + `IsGoal()`（`single_agent/interfaces/callback.go`）
4. 回填 `RunContext.GoalID/Revision` 并让 `normalizeInputs` 解析 `run.context.goal_id/revision`（`harness/deep_agent.go` L2198-2213）
5. 回填 `Session.StreamEmitter()`（`session/agent.go`，返回 `inner.StreamWriterManager().StreamEmitter()`，管理器为 nil 时返回 nil）

3. `Start`/`Stop`/`stopInteractionLocked`（含 9.89 三段留白 ⤵️）

### S3：输入路径与回合执行（端到端一轮）

6. `CancelRound`/`cancelActiveRound`（有界 1.5s）
7. `DeepAgentInterface` 补 `Start/Stop/AttachOutput/NextOutput/DetachOutput/SendInput/CancelRound/RunOneRound/Phase/HasOutputStream`

**验收**：假宿主一轮问答端到端；follow-up 续跑；打断恢复。
