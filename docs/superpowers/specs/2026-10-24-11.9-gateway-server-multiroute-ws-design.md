## 0. 背景与范围拍板

### 0.1 问题陈述

Go 侧 11.9 此前标 ✅，但实际只完成了 **HTTP 宿主+组装器**（对应 Python `_run()` 函数的组装职责）。Python `app_gateway.py` 中 **GatewayServer 类本体**（多路由 WebSocket 服务器，L240-720）完全缺失，导致：

- 19001 端口无监听（Python 侧 CLI/TUI/ACP 客户端接入点不存在）
- `register_external_channel` 出站装配路径无对应实现
- 后续 11.15（TUI 路由）/11.25（ACP 桥）无承载框架

### 0.2 已拍板决策（用户逐项确认）

| 决策项 | 选择 | 含义 |
|--------|------|------|
| **A** 范围 | 补齐 Python GatewayServer 类本体 | 完整复刻 L240-720 类 + RouteConfig/GatewayServerConfig/_InboundGatewayServer/_build_* 工厂 + register_external_channel 出站装配 |
| **A1** 路由来源 | 空路由 + 接口就绪 | 路由注册能力完整（RouteConfig/RouteBinding→RouteConfigMap 工厂链），但装配时不注入任何路由（`routes: 空 map`），11.25/11.15 到位后再接线 |
| **B2** Inbound 层 | 严格对齐双层 chan | `_InboundGatewayServer` 完整复刻为 `InboundGatewayServer`（独立 chan 层），不与 MessageHandler 内部队列去重合并 |
| **C1** 出站装配 | ExternalChannel 窄接口 | `channel_manager` 新增 `ExternalChannel{Send}` 接口 + `RegisterExternalChannel` 方法，channels 表不强行统一 |
| **D3-strict** 命名 | 现有类改名让位 | 现有 `gateway.GatewayServer`（HTTP 宿主+组装器）改名 `AppGatewayServer`；新类占用 `GatewayServer` 名字（逐字对齐 Python） |
| **满队语义** | 有界 256 + Warn 丢弃 | `InboundGatewayServer.queue` 容量 256，满时 `select/default` 丢弃 + Warn 日志（与 MessageHandler.userMessages 既有 256 容量链路一致；Python asyncio.Queue 无界语义按 Go 侧链路一致性对齐） |

### 0.3 端口布局（平级渠道，无嵌套）

| 端口 | 组件 | 协议 | 客户端 |
|------|------|------|--------|
| 19000 | WebChannel（既有） | HTTP + 静态文件 + WS `/ws` | 浏览器 |
| **19001** | **GatewayServer（本次新增）** | 纯 WS 多路径路由 | CLI / TUI / ACP 客户端 |

两者平级出站渠道，共享 ChannelManager/MessageHandler/AgentClient 中枢。环境变量：`GATEWAY_HOST`（默认 `127.0.0.1`）/ `GATEWAY_PORT`（默认 `19001`），与既有 `UAPCLAW_GATEWAY_*`（19000）并存不冲突。

## 2. RouteConfig / GatewayServerConfig / ExternalChannel 接口

### 2.1 RouteConfig（route_config.go，对齐 Python L208-219）

```go
// RouteConfig 单条路由的配置（/acp、/tui 等）。
type RouteConfig struct {
    Path                         string                      // 路由路径
    ChannelID                    string                      // 渠道标识（"acp"/"tui"）
    ForwardMethods               map[string]bool             // 转发到 MessageHandler 的 method 集合
    ForwardNoLocalHandlerMethods map[string]bool             // 仅转发无本地 handler 的集合
    LocalHandlers                map[string]LocalHandlerFunc // 本地 handler（method → handler）
    InboundInterceptor           InterceptorFunc             // 入站拦截器（可 nil）
    OutboundInterceptor          InterceptorFunc             // 出站拦截器（可 nil）
    CleanupHandler               CleanupFunc                 // 清理钩子（可 nil）
    DisconnectHandler            DisconnectFunc              // 断连钩子（可 nil）
}

// LocalHandlerFunc 本地 handler（对齐 Python Callable[..., Awaitable[None]]，
// Python 签名 (ws, req_id, params, session_id)）。
type LocalHandlerFunc func(ctx context.Context, ws *websocket.Conn, reqID string, params map[string]any, sessionID string) error

// InterceptorFunc 入/出站拦截器（对齐 Python Awaitable[bool]，返回 true 短路）。
type InterceptorFunc func(ctx context.Context, ws *websocket.Conn, data map[string]any) (bool, error)

// CleanupFunc 断连清理（对齐 cleanup_handler，无 disconnect_handler 时的兜底）。
type CleanupFunc func(ws *websocket.Conn)

// DisconnectFunc 断连回调（对齐 disconnect_handler，带 staleSessionKeys）。
type DisconnectFunc func(ws *websocket.Conn, staleSessionKeys [][2]string)
```

### 2.4 ExternalChannel 接口（channel_manager 包，C1 决策）

```go
// channel_manager/channel_manager.go 追加

// ExternalChannel 仅出站能力的渠道接口（对齐 Python register_external_channel 的 duck typing 语义：
// Python 只要求对象有 send 方法即可入表）。
type ExternalChannel interface {
    // Send 向该渠道投递出站消息（对齐 Python channel.send(msg)）。
    Send(ctx context.Context, msg *schema.Message) error
}

// RegisterExternalChannel 登记一个已由外部完成入站装配的渠道实例。
// 对齐 Python channel_manager.py L86-88：不做存活检查、不设 onMessage，仅入 channels 表供出站派发。
func (cm *ChannelManager) RegisterExternalChannel(channelID string, ch ExternalChannel)
```

**channels 表类型问题**：现表为 `map[string]BaseChannel`（8 方法宽接口），ExternalChannel 只有 Send。Go 无 duck typing，两个接口类型不同不能同表。方案：**channels 表不动**，新增平行表：

```go
// ChannelManager 追加字段
externalChannels map[string]ExternalChannel  // 外部渠道（仅出站）
```

`dispatchRobotMessages` 出站派发时先查 `channels`（BaseChannel），miss 后再查 `externalChannels`（ExternalChannel.Send）。若同一 channelID 在两表都有注册，出站派发以 `channels` 表优先（BaseChannel 是完整渠道，含入站装配）；同表内重复注册时后写覆盖前写并 Warn（对齐 Python 单 dict 赋值覆盖语义）。BaseChannel 的 8 方法接口不窄化，既有 WebChannel 注册路径零改动。

## 3. GatewayServer 类本体（gateway_server.go，对齐 Python L240-720）

### 3.1 结构体与字段

```go
// GatewayServer 通用多路由 WebSocket Gateway Server。
// 对齐 Python app_gateway.py L240-720 GatewayServer 类：
// 支持多个路径（如 /acp、/tui），每条路径有独立 channel_id 和本地 handler；
// 本地 handler 优先处理请求，未处理或无匹配则 forward 到 MessageHandler。
type GatewayServer struct {
    config          *GatewayServerConfig
    bus             any                  // 对齐 Python router/_DummyBus 占位（Go 暂未消费，保留字段）
    httpServer      *http.Server         // 独立监听 19001（对齐 websockets.serve）
    upgrader        websocket.Upgrader   // CheckOrigin 复用 wsorigin.GorillaCheckOrigin
    running         atomic.Bool
    onMessageCb     func(ctx context.Context, msg *schema.Message) error  // 对齐 _on_message_cb
    clientsMu       sync.RWMutex
    clients         map[*websocket.Conn]struct{}  // 对齐 _clients set
    requestToClient map[[2]string]*websocket.Conn // (channel, reqID) → ws
    sessionToClient map[[2]string]*websocket.Conn // (channel, sessionID) → ws
    // acpBridge ⤵️ 11.25：AcpGatewayBridge 注入点，A1 下不建模
    wg              sync.WaitGroup        // 连接 handler 生命周期
}
```

关键映射决策：

- **路由键 `[2]string`** 对齐 Python tuple `(channel_id, scoped_id)`；`clientRouteKey(channelID, scopedID) ([2]string, bool)` 对齐 `_client_route_key`（L265-271：任一空值返回不可用）
- **acpBridge 整体不建模**（A1 拍板）：Python 中 acp 桥的 5 个触点（构造注入 dispatchOnMessage/bindAcpSessionClient、`_install_default_route_hooks` 的 acp 路由钩子注入 L286-298、`_handle_raw_message` 的 acp 分支 L573-579、`send` 的 acp 分支 L468-471）在 Go 侧以**注释占位 + ⤵️ 11.25 标记**呈现，分支逻辑不写（空路由下永不触达；写死 nil 检查反而引入死代码）
- **`_install_default_route_hooks` 不实现**：该方法逐条 route 注入 acp 桥拦截器（L286-298），A1 空路由下为空操作，且其存在意义完全属于 acp 桥（⤵️ 11.25 一并实现）

### 3.2 Start / Stop（对齐 L371-410）

**Start**：

```go
func (s *GatewayServer) Start(ctx context.Context) error {
    // 对齐 Python start()：if self._running or not self.config.enabled: return
    if s.running.Load() || !s.config.Enabled { return nil }
    mux := http.NewServeMux()
    mux.HandleFunc("/", s.connectionHandler)      // 路径分流在 handler 内做（对齐 websockets 单 handler 模式）
    s.httpServer = &http.Server{Addr: fmt.Sprintf("%s:%d", s.config.Host, s.config.Port), Handler: mux}
    // gorilla upgrader：CheckOrigin 复用 wsorigin.GorillaCheckOrigin
    // 读循环内 conn.SetReadLimit(8MB) — 对齐 Python ws_max_size = 8*2**20 + web_connect.go 既有先例
    go s.httpServer.ListenAndServe()  // 错误经 channel 回传
    s.running.Store(true)
    logger.Info(...).Str("addr", ...).Str("paths", join(routes)).Msg("Gateway server started")
}
```

**Stop**（对齐 L395-410，顺序严格）：

```
1. running=false
2. 遍历 clients 逐个 conn.Close()（gorilla 无 code 参数，1001 语义用 CloseMessage 实现或注释说明差异）
3. 清空 clients / requestToClient / sessionToClient
4. httpServer.Close()（等价 await self._server.wait_closed()）
5. wg.Wait()（等所有连接 handler 退出）
6. Info 日志 "Gateway server stopped"
```

### 3.3 connectionHandler（对齐 _connection_handler L501-559）

```
1. requestPath := r.URL.Path
2. route, matchedPath := resolveRoute(requestPath)
   route == nil → conn.CloseHandler 设 1008 + "unsupported path" + return
   （gorilla 无异步 close(code,reason)，升级失败前用 HTTP 404 拒绝；升级成功后立即 CloseMessage 1008）
3. clientsMu.Lock(); clients[ws]=struct{}{}; Unlock()
4. 发 connection.ack 帧：
   {"type":"event","event":"connection.ack",
    "payload":{"protocol_version":"1.0","transport":route.ChannelID}}
   ⚠️ 与 transport.BuildConnectionAckFrame（AgentServer 侧 {status:ready}）格式不同，
   本包内新建 buildConnectionAckFrame 通道帧构建（gateway 包私有函数）
   发送失败 → clients.discard(ws) + return（对齐 L523-525）
5. for { _, raw, err := conn.ReadMessage(); err != nil → break
       handleRawMessage(ctx, ws, raw, matchedPath, route) }
6. finally 语义（对齐 L532-559）：
   - clientsMu.Lock(); delete(clients, ws); Unlock()
   - 清理 requestToClient/sessionToClient 中 value==ws 的 stale 键（快照后删，对齐 stale_* 列表推导）
   - route.DisconnectHandler != nil → 调用（带 staleSessionKeys）
     elif route.CleanupHandler != nil → 调用
     两者 error/panic 均 Warn 不中断（对齐 except + logger.warning）
```

### 3.4 resolveRoute（对齐 _resolve_route L304-316，四分支严格对齐）

```
输入 requestPath（已 strip）：
1. 空串            → (nil, requestPath)
2. 精确命中 routes[p]              → (routes[p], p)
3. p 尾斜杠且 p.rstrip("/") 命中   → (routes[去斜杠], 去斜杠)
4. p 无尾斜杠且 p+"/" 命中          → (routes[补斜杠], p+"/")
5. 未命中          → (nil, p)
```

### 3.5 handleRawMessage（对齐 _handle_raw_message L561-720）——三层处理

```
0. json.Unmarshal 失败 → 发 {"type":"res","id":"","ok":false,"error":"invalid json"} + return
1. [acp 分支 ⤵️11.25 占位注释，不写逻辑]
2. route.InboundInterceptor != nil → 调用；handled=true → return；error → Warn 继续
3. data 非 map 或 type != "req" → 发 "invalid request" res + return
4. reqID/method 校验（strip 后空 → "invalid request" res，id 带回 reqID）
5. params 非 map → 空 map
6. sessionID = params.session_id(strip) 或回退 reqID（对齐 L619）
7. method ∈ ForwardMethods：
   a. ParseReqMethod 失败 → "unknown method: {method}" res + return
   b. 记录 requestToClient[(channel,reqID)] = ws、sessionToClient[(channel,sessID)] = ws
   c. defaultMode = channelID=="tui" ? ModeCodeNormal : ModeAgentPlan（对齐 L645）
   d. mode = schema.ParseMode(params["mode"], defaultMode)（ParseMode 等价 Mode.from_raw）
   e. params 拷贝后 setdefault("mode", mode.String())
   f. metadata = {"method": method}；params.cwd 为非空 string → metadata["cwd"]=strip 后值
   g. isStream = data["is_stream"]（bool 断言）
   h. 构建 schema.Message{ID/Type:req/ChannelID/SessionID/Params(json)/Timestamp/OK:true/
      ReqMethod/Mode/Metadata/IsStream}
   i. onMessageCb != nil → 调用（error 只 Warn 不中断，对齐 Python await 无 except）
   j. [acp early-return ⤵️11.25 占位注释]
   k. method ∈ ForwardNoLocalHandlerMethods → return（无本地 ack）
8. 本地 handler：route.LocalHandlers[method] 存在 →
   调用；error 时：
     - ws 已关判定（对齐 getattr(ws,"closed")）：调用前先做写探针
       `conn.SetWriteDeadline(time.Now().Add(time.Millisecond)) + WriteMessage(PingMessage)`，
       失败 → Warn + return（不发 INTERNAL_ERROR，避免向死连接写）
       语义上：error 且探针失败 = "aborted on closed ws"；error 且探针成功 = 内部错误
     - 否则 Error 日志 + sendResponse(ok=false, error="handler error: {e}", code="INTERNAL_ERROR")
     （sendResponse 自身失败仅 Debug，对齐 L700-705）
   return
9. 无 forward 无本地 → "unknown method: {method}" res
```

### 3.7 Send（对齐 send() L412-499）——出站四段路由

```go
// Send 实现 ExternalChannel 接口（出站派发入口，对齐 Python send(msg)）。
func (s *GatewayServer) Send(ctx context.Context, msg *schema.Message) error
```

四段顺序严格对齐：

```
1. request 定向：requestKey = clientRouteKey(msg.ChannelID, msg.ID)
   requestToClient[key] 命中 → ws
   ⚠️ Python 二次裸键查找 get(request_key[1])（L417-418）是 dict 对 tuple 的意外回退，
      Go map[[2]string] 无此行为——**不实现**（语义差异备注：Python 侧该分支实际永不命中
      request_to_client，因键都是 tuple；Go 侧如实省略）
2. session 定向：sessionKey = clientRouteKey(msg.ChannelID, msg.SessionID)
   sessionToClient[key] 命中 → ws
   （同上省略裸键回退）
3. ws == nil 时广播 fallback（对齐 L423-439）：
   channelID 非空 且 != "acp" 且 msg.Type != "res"：
     clients = findChannelClients(channelID)  // sessionToClient 中 key[0]==channelID 且 !closed
     非空 → frame = buildEventFrame(msg) → 逐 client Send → return
   否则（含 clients 空）→ Warn "message dropped: no WebSocket client found for channel_id=... session_id=... id=..."
4. ws != nil 时（对齐 L441-499）：
   a. [acp 分支 ⤵️11.25 占位注释]
   b. outbound 拦截器：遍历 routes 找 channel_id 匹配且 OutboundInterceptor 非 nil 的 route
      → 调用；handled=true → return；error → Warn 继续；break（只处理第一条匹配，对齐 L453-467）
   c. msg.Type == "res" → res 帧：payload 拷贝（dict 断言失败 → 空 map）、
      ok=false 时 error = payload["error"] 或 "request failed"
   d. 否则 event 帧：event_name = msg.EventType 非空 ? 其值 : "chat.final"
      payload 为 map → 浅拷贝 + setdefault("session_id")；非 map → {"session_id":..., "content": str(payload)}
      ⚠️ msg.Payload 是 []byte（json.RawMessage）：先 Unmarshal 成 map 判断
```

**findChannelClients**（对齐 `_find_channel_clients` L273-278）：`sessionToClient` 中 `key[0]==channelID` 且 `!closed` 的 ws 列表。gorilla 判断 closed：`ws.UnderlyingConn() != nil` 不可靠——用写探针（`SetWriteDeadline(1ms) + PingControlMessage`）或维护 closed 集合。**决策：简化为不判 closed，直接尝试发送，发送失败仅 Debug**（对齐 Python `getattr(ws,"closed",False)` 是 websockets 库属性、gorilla 无等价物的客观差异；广播 gather(return_exceptions=True) 本就逐 client 容错，Go 侧逐 client error 忽略即可，行为等价）。

## 4. InboundGatewayServer（B2 双层 chan，对齐 _InboundGatewayServer L132-173）

### 4.1 结构体

```go
// InboundGatewayServer Gateway 内部入站服务：渠道消息经队列转发到 MessageHandler。
// 对齐 Python _InboundGatewayServer（asyncio.Queue + 独立 task）。
type InboundGatewayServer struct {
    inboundHandler func(ctx context.Context, msg *schema.Message)  // serveLoop 消费的处理器
    queue          chan *schema.Message  // 对齐 asyncio.Queue（B2 拍板：保留独立 chan 层）
    taskDone       chan struct{}         // serveLoop 退出信号（对齐 _task cancel/await）
    running        atomic.Bool
    cancel         context.CancelFunc    // 对齐 task.cancel()
}

// NewInboundGatewayServer(inboundHandler) — 对齐 __init__(inbound_handler)
//   queue 容量 256（满队语义拍板：对齐 MessageHandler.userMessages 链路容量）
// Start(ctx)  — 幂等（taskDone 已占用则 return）；running=true；go serveLoop()
// Stop()      — running=false；cancel()；<-taskDone 等 serveLoop 退出
//               （对齐 await task + CancelledError 吞掉）
// HandleMessage(ctx, msg) error — 入队。有界语义：select { case queue <- msg: default: Warn 丢弃 }
//               签名返回 error（恒 nil）以匹配 GatewayServer.OnMessage 回调类型
//               func(ctx, msg) error，对齐 Python handle_message 返回 True 的非短路语义。
//               ⚠️ 满队丢弃与 Python asyncio.Queue 无界 put 永不丢是**有意偏差**，
//                  理由：下游 MessageHandler.userMessages 是 256 有界 chan（Go 侧既有事实），
//                  上游无界只是把丢弃点后移；保持链路容量一致、丢弃点前置且可观测（Warn 日志）。
```

### 4.2 serveLoop（对齐 L162-173）

```go
func (s *InboundGatewayServer) serveLoop(ctx context.Context) {
    defer close(s.taskDone)
    for s.running.Load() {
        select {
        case <-ctx.Done():
            return                     // 对齐 CancelledError break
        case msg := <-s.queue:
            // 对齐 Python 每条消息独立 try/except + logger.exception
            func() {
                defer func() {
                    if r := recover(); r != nil {
                        logger.Error(logComponent).
                            Str("msg_id", msg.ID).Any("panic", r).
                            Msg("Gateway inbound handling failed")
                    }
                }()
                s.inboundHandler(ctx, msg)
            }()
        }
    }
}
```

`recover` 是 Python `except Exception: logger.exception` 的 Go 等价（inboundHandler 是注入回调，防 panic 拖死 serveLoop）。

## 7. 有意偏差清单（Go ≠ Python，逐条备案）

| # | 偏差 | Python 行为 | Go 行为 | 理由 |
|---|------|-------------|---------|------|
| 1 | InboundGatewayServer 队列容量 | asyncio.Queue 无界 | chan 256 有界，满时 Warn 丢弃 | 下游 MessageHandler.userMessages 是 256 有界 chan（Go 既有事实），上游无界只是把丢弃点后移；链路容量一致 + 丢弃点可观测 |
| 2 | send() 裸键回退 | `get(request_key[1])` 二次查找（dict 对 tuple 的意外行为） | 不实现 | Go map[[2]string] 无此行为；Python 侧该分支实际永不命中（键恒为 tuple），属死代码 |
| 3 | findChannelClients closed 判断 | `getattr(ws,"closed",False)` | 不判，直接尝试发送、失败忽略 | gorilla 无 closed 属性等价物；Python 广播 gather(return_exceptions=True) 本就逐 client 容错，行为等价 |
| 4 | ws.close(code,reason) | websockets 库支持异步 close(1008/1001, reason) | gorilla 用 CloseHandler/CloseMessage 实现，reason 经 control frame | 库能力差异，语义保留（code 1008 不支持路径 / 1001 停机） |
| 5 | 拦截器/handler 协程模型 | asyncio.iscoroutine 动态 await | 回调为普通 Go func，error 显式返回 | 语言差异，语义等价 |
| 6 | _install_default_route_hooks | 构造后立即逐 route 注入 acp 拦截器 | 不实现（空路由下空操作） | A1 拍板；11.25 与桥一并实现 |
| 7 | _build_acp_route_binding 的 on_message_cb 参数 | 存在但未存入 binding（死参数） | 不保留该参数 | Python 死参数（丢弃返回值的副作用冗余先例），Go 去重 |
| 8 | connection.ack 帧构建 | 内联 json.dumps | gateway 包私有 buildConnectionAckFrame | 与 transport.BuildConnectionAckFrame（AgentServer 侧）格式不同，不可复用 |
