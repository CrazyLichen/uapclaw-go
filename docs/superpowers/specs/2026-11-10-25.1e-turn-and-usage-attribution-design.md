# 25.1e 收尾 + 用量归属链设计

> 覆盖两件事：**25.1e（成员 turn 身份）的链路收尾**，以及 **24.14 遗留的用量归属链（usage attribution）**。
> 前者是补断链，后者是补齐"用量属于谁"这一整条从未迁移的子系统。

## 1. 背景

25.1e 已于 2026-11-09 随 25.1c 合并交付（`harness/turn.go` + `ActiveRound.Turn/TurnOpened` + `commitOpenedTurn`）。
核查发现三处未闭合：

1. **链路最后一跳断**：`WithTurnNumber` → metadata → `effective["_turn_number"]` 到 ReActAgent 后被丢弃。
   Python `react_agent.py:2966-2967` 会把它写进 `ctx.extra`，Go 的 `invokeImpl` 只处理了 `_streaming` / `_resume_continuation` / `_input_parts`。
2. **无读取面**：Python 的 `NativeHarness.active_round` property 供外部 rail 读取活轮；Go 只有同包可见的 `st.Active()`。
3. **测试缺口**：Python `test_member_turn.py` 12 例（7 纯单测 + 5 带真 harness 的集成例），Go 只有 6 例。

同时，24.14 行登记的"用量归属字段"遗留只覆盖两个字段（`_usage_build_context` / `_usage_agent_id`），
而实际缺口是整个 attribution 子系统：

| 环节 | Python | Go（改动前） |
|---|---|---|
| 请求级传递 | `rail/base.py:71-175` 三个 ContextVar + `current_/bind_/reset_` + `build_usage_delegation_attribution` | 全仓 0 命中 |
| 调用契约 | `InvokeInputs` 的 `parent_session_id`/`invocation_id`/`parent_invocation_id`/`delegation_id`/`agent_path`/`depth` | 结构体无这些字段 |
| 解析 | `react_agent.py:1294-1418`（`_call_usage_identifier`/`_usage_session_id`/`_usage_context_id`/`_context_usage_attribution`） | 无 |
| 落快照 | `analyzer.py:59/206/357-380` 的 `attribution` + `_attribution_fields`（14 键） | `SnapshotInput` 无 `Attribution`；快照的 6 个归属字段恒零值 |
| 委派 | `ability_manager.py:1660` / `task_tool.py:836` / `session_spawn_executor.py:123` | 三处均未绑定 |

## 2. 25.1e 在会话中的位置

```
TeamAgent 一轮对话
  └─ TeamHarness → NativeHarness.Send
       ├─ immediate=true（steer）→ EnqueueSteer，并入当前轮（不计新 turn）
       └─ 否则 → startRound(mode)
            ├─ captureSnapshot（轮前基线）
            ├─ keepsTurn := mode ∈ {continuesTurn, failureRetry, resumeContinuation} || InteractiveInput
            ├─ ResolveMemberTurn(sess, keepsTurn) → MemberTurn{ID,Number} + opened
            └─ ActiveRound{Turn, TurnOpened}
                 ├─ commitOpenedTurn → sess.Commit()（仅 opened）
                 └─ SubmitRound(..., WithTurnNumber(n)) → metadata["_turn_number"]
                      → handler → executor → effective["_turn_number"]
                      → ReActAgent.invokeImpl → ctx.extra["_turn_number"]   ← 本轮补上
                           → 观测 rail 映射 openjiuwen.turn.id / turn.number（领域二十二）
```

turn 是**纯观测身份**：不改变对话内容与模型行为，只给"成员的一次工作"发工单号，
让同一 trace 里混在一起的成员 span 能被正确归组。计数器存成员 session（键 `trajectory_member_turn`），
与 `deepagent` blob 分离，避免 pause/abort 回滚导致重号。

## 4. 已知偏差

| ID | 偏差 | 理由 | 回收条件 |
|---|---|---|---|
| D-1 | ContextVar → `context.Context` 派生 | Go 无协程级隐式变量，goroutine 不自动继承 | 不回收（语言约束） |
| D-2 | 不移植 `reset_usage_*` | ctx 不可变，"复位"即改用父 ctx，无需显式 token | 不回收 |
| D-3 | 能力探测 `getattr` → 可选接口断言 | Go 无 duck typing | 不回收 |
| D-4 | `context_usage_attribution` 用既有 `extraMuPtr` 保护 | Python 单线程；Go 的 rail 可能并行读 | 不回收 |
| D-5 | `SetUsageBuildContext` 导出 setter（Python 直接改私有属性） | Go 跨包必须走导出方法；`_usage_agent_id` 与 `card.id` 恒等，Go 不重复保存 | 不回收 |
| D-6 | `_usage_parent_session_id`/`_usage_parent_invocation_id`/`_usage_delegation_id`/`_usage_agent_path`/`_usage_depth` 已按 Python 声明并在回退链读取，但**永不赋值** | 与 Python 一致：上游这五个字段同样只有读取点、没有赋值点；结构一一对应优先于"删死代码" | Python 侧出现赋值点时同步接上 |
| D-7 | `ModelCallInputs.ContextUsageAttribution` 按 Python 的动态属性落成显式字段并写入 | Python `ctx.inputs.context_usage_attribution` 只写不读；Go 保留同一写入面以对齐契约 | 不回收 |
| D-8 | 手动压缩（post_compact）路径不带归属 | Go 的 post_compact 快照在 adapter 层构造，没有 ReActAgent 的归属解析入口；Python 走 `build_context_usage_snapshot` 合成 ctx | 22.9 团队成本视图需要 post_compact 归属时 |
| D-9 | `Session.GetCacheIdentity` 返回 `kv_cache.KVCacheIdentity`；`kv_cache` 包只迁身份层 | Python `kv_cache` 包 1189 行（runtime/model_hook 等未迁），本次只需身份与成员身份拼接 | KV cache 运行期迁移时 |
| D-10 | 归属用加锁盒子原地刷新（替代 ContextVar 的 dict 原地 clear/update） | ctx 值不可替换；原地改写共享 map 会与并发工具读竞争，故以盒子 + 读写锁等价实现 | 不回收 |
| D-11 | `MemberTurn.from_dict` 也接受 `int64` | Python 只认 `int`；Go 存储层可能给 int64，不接受会丢号退化为开新 turn | Go 存储层统一 int 后 |
| D-12 | `Session.BindParentSessionID` 以 `error` 表达"改绑冲突" | Python 抛 `ValueError`；Go 无异常，用返回值 | 不回收 |

### 4.1 本轮对齐（2026-11-10 收口）

用户裁决"按 Python 对齐、不按 Go 现状补"，因此以下三项由"登记偏差"改为"补齐实现"：

| 原偏差 | 对齐动作 |
|---|---|
| D-5 | `AgentTeamSession.CreateAgentSession` 补 `memberName` 参数 → `source_metadata["source_member_name"]` + `child.SetTeamCacheScope(...)`（`agent_team.py` L164-188）；调用方 `team_harness.go` 传 `MemberName()` |
| D-6/D-7 | 五个 `_usage_*` 字段声明并在回退链读取；`ModelCallInputs.ContextUsageAttribution` 显式字段 |
| D-9 | 新增 `internal/agentcore/kv_cache/`（身份 + env 键 + 成员身份拼接）；`Session` 补 `parentSessionID`/`teamCacheScope`/`GetParentSessionID`/`BindParentSessionID`/`SetTeamCacheScope`/`GetCacheIdentity`；`DeepAgent.prepareSingleRoundSession` 按 Python 移植（含 env 注入与 `ownsSession` 的 post_run 收尾），ReAct 的 `invoke`/`stream` 自建会话同步补 `WithCard` + 父会话 env |
| D-10 | 归属改为 `attributionBox`（加锁）+ `UpdateUsageAttribution` 原地刷新，ctx 链上可见完整 14 键 |
