## 1. 在 agent 会话链路中的位置与作用

27.8 位于领域二十七「Web 控制台后端契约」（IMPLEMENTATION_PLAN.md 领域二十七表 27.8 行，状态 ☐）。
作用是让 Web 控制台成为全双工多模态渠道，覆盖上行/下行两侧契约：

```
上行：浏览器选图/文档 → media.persist / document.persist（base64 落盘会话 uploads）
      → chat.send 携带 media_items → steer 图片引用校验（steer_images）
下行：agent 产出文件 → send_file 文件卡片（10.6.24b 已有）→ 下载令牌（已有）
      → file.download_verified_chunk 分块下载 / rsi.artifact.* 产物下载 → 前端预览（SVG/图片）
```

前端源码在本仓托管（`internal/swarm/channels/web/frontend`），Go 只承接后端契约。

## 3. 帧上限与分流的契约事实（设计依据）

`gateway/common/ws_limits.py`：

- `WEB_WS_MAX_MESSAGE_BYTES = 150 MiB` — 浏览器↔Gateway 腿（放宽以承载 100MiB 文档 base64 ≈133MiB）
- `AGENT_WS_MAX_MESSAGE_BYTES = 8 MiB` — 内部腿（Gateway↔AgentServer，设计注释：streaming events, no large file base64）
- `AGENT_WS_SEND_BUDGET_BYTES = 6 MiB` — 内部腿发送预算

分流逻辑（`app_web_handlers.py:2063 _rewrite_oversized_media`）：转发 media.persist 前逐 image item
检查 `base64 解码后字节数 > (E2A_PAYLOAD_MAX_BYTES - params 其余部分 JSON 开销)`；超预算 item 由
Gateway 解码落盘（单机档）并标 `_persistence` 痕迹，AgentServer 侧透传不重复解码。
**若不做分流，约 5.5~10MB 的图片会出现「过了浏览器腿、死在内部腿」的真空区**——这是 B1 的依据。
前端另有输入侧拦截：图片 >10MB（`InputArea.tsx:513 MAX_IMAGE_BYTES`）、文档 >100MB toast 拒绝。

## 5. 核心数据流

### 5.1 上行（媒体/文档上传）

```
浏览器（≤150MiB 帧）→ Gateway web 通道
 ├─ media.persist: _rewrite_oversized_media 逐 item 检查
 │   ├─ ≤内部腿预算: 原样转发 → adapter → normalize_chat_media_attachments 落盘
 │   │    agent/sessions/<sid>/uploads/（≤10MB×8 张；mime→规范后缀 .png/.jpg/.webp/.gif；
 │   │    .jpeg/.jfif 别名保留原名；atomic_write_unique 防并发同名覆盖）
 │   └─ >预算: Gateway 解码直写共享用户目录（单机档）→ 标 _persisted → adapter 只记落盘记录
 ├─ media.discard: 只删本会话 uploads 直接子文件（symlink/目录/跨会话/用户原图路径拒绝；
 │   重复删除返回 {"deleted": false} 即成功）
 ├─ document.persist: 扩展名黑名单（attachment_safety.forbidden_formats）→ ≤100MB×8 张
 │   base64 落盘 → 回 @path 引用 + document_errors + forbidden_formats
 ├─ document.formats: 只回 forbidden_formats 列表
 ├─ path.select_directory: workspace 内解析（commonpath 越界拒绝；无 initial_dir → UNSUPPORTED
 │   让前端回退手动输入；目录不存在 → {"path": null, "cancelled": true}）
 └─ path.select_files: workspace 内枚举（排除 "." "_" 前缀，上限 200 条；
     图片 ≤4MB 附 base64 供前端预览，kind=image/document 与桌面端同形）
```

### 5.2 chat.send steer 图片（上行末端）

`steer_images.py`：校验 steer 引用的 path 必须位于**本会话 uploads 目录内**（防伪造路径/跨会话），
用图像解码探测真实格式（Python 用 PIL，Go 用标准库 `image/jpeg|png|gif` + sniffs），失败即拒。

### 5.3 下行（文件卡片与产物下载）

```
agent send_file → 文件卡片（10.6.24b SendFileToolkit 已有）→ WebFileDownloadManager 令牌（已有）
 ├─ file.download_verified_chunk: token kind=verified_asset_v1 验签 + O_NOFOLLOW 打开
 │   + fstat 尺寸与 token claimed_size 一致性校验 → ≤512KB 分块 base64 回传
 │   （payload: data_base64/offset/chunk_size/size/eof/name/mime_type）
 │   错误矩阵：token 拒绝=FORBIDDEN；asset 变更=FORBIDDEN；range 非法=BAD_REQUEST；不可用=NOT_FOUND
 ├─ rsi.artifact.download / files.list / files.get: server 侧已有（领域十七）→
 │   补 web 通道三代理 methodHandler（app_web_handlers.py:6492-6494 同形）
 └─ SVG 渲染: 前端职责 + 静态服务 mime（Go file_api/dist 已有 image/svg+xml，实施时核实补缺）
```

### 5.4 分块上传三件（`file.*`）

- `file.upload_chunk`：首块 O_EXCL（`atomic_write_unique`）认领去重槽位，后续块 append 到已认领
  `resolved_path`；`target_rel_path` 拒绝绝对路径与 `..` 段（`invalid_target_path`）；越出用户目录
  （`is_path_within_user_dirs`，Go 已有 web_file_download 同源函数）→ `path_outside_workspace`；
  空块/非法 base64 → BAD_REQUEST
- `file.read_upload_chunk`：只读本会话 uploads 内文件；PermissionError→FORBIDDEN、
  NotFound→NOT_FOUND、ValueError/TypeError→BAD_REQUEST、OSError→FORBIDDEN
- `file.import_url`：外部 url 60s 超时下载落盘注入目录（`unique_upload_path` 去重），
  overwrite 开关，逐 item 失败不中断（`{**item, "error": str}`）；企业 OBS 分支不移植

## 6. 公共地基要点（attachment_safety，197 行纯函数）

- 文件名消毒：strip 目录部分 → BIDI 控制符剔除 → 非法字符 `[<>"|?*\x00-\x1f\x7f\\/:]` → `_`
  → 尾部 `.`/空格剥离（Windows 语义）→ Windows 保留名（CON/PRN/AUX/NUL/COM1-9/LPT1-9）拒绝
- 文件名 ≤180 UTF-8 字节截断（保扩展名、不劈 UTF-8 序列）；session id ≤120 字符消毒
- 扩展名黑名单（可执行/脚本/包类型，`FORBIDDEN_DOCUMENT_EXTENSIONS`）+ `forbidden_formats()` 列表
- `strip_data_uri_prefix`（`data:image/png;base64,` 前缀剥离）
- Go 落 `internal/swarm/gateway/common/attachmentsafety/`（gateway/runtime/server 三方共用，与
  Python 下沉位置一致）
