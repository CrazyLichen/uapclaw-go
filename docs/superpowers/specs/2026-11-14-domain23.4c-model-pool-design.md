## 1. 流程位置与作用

不在 ReAct 单轮循环内，位于「agent 启动前——选哪个模型可用」前置链的团队侧：

```
② 团队成员分配   agent_teams/models/{pool,allocator}.py（本批）
     ↓ ResolvedModelGroup（23.4b 编译器产出，生产入口 23.4d resolver）
   MaterializeModelGroup → 单条池 entry（"*"）→ IntelliRouterAllocator 摊给成员
     ↓ ModelClientConfig{client_provider=intelli_router}
   IntelliRouterModelClient → intellirouter.ReliableRouter（23.4a/b 已交付）
```

作用：把模型组摊给团队成员（整组单 entry、全员共享同一路由器与冷却状态）、成员可 spawn 时点名组内模型（route tag）、路由结果记账进成员名册（`model_group` / `models_used`），闭环 25.0c 的偏差 D-2。

通俗口径：模型组 = 一束话筒；成员默认整组共用（路由器现场挑一家、挂了自动换），可点名钉一根（route tag）；记账 = 名册显示"每个成员最近被路由到谁"。

## 3. MaterializeModelGroup 契约、两份 DTO 与 label/inherit

### 3.1 MaterializeModelGroup（pool.py:460-516 逐条对齐）

```
输入：*routing.CompiledModelSelection（Go 直接用 23.4b 具体类型；Python duck-type
      是为跨包复用，Go 无循环依赖风险，不设接口）
      + *routing.ModelSelection（可选，nil 跳过一致性校验）
校验序：compiled nil → selection.type/id 不匹配 → selected_type != "model_group"
      → client_provider != "intelli_router" → router.deployments 空（逐条 ValueError）
输出：单条 ModelPoolEntry{model_name:"*", api_key:"", api_base_url:"",
      api_provider:"intelli_router", description:"IntelliRouter model group {id}",
      metadata:{client:{intelli_router:routerDump, verify_ssl?}, request:requestDump}}
关键细节：requestDump 先 pop 掉 model/model_name（"*" 是团队逻辑名，组级请求模型
      必须保持 unset，否则覆盖 deployment 级默认值）
```

### 3.2 team 侧 DTO（pool.py:241-437 全量）

### 3.3 ModelGroupLabel（pool.py:519）

单 entry + `"*"` + intelli_router 才算组池；回退序：`metadata.model_group.display_name` → `router.model_group_id` → `"*"`。

### 3.4 InheritPoolIds（pool.py:566 + `_entry_signature`）

签名 = 全字段 JSON（sort_keys）剔除 `model_id` 与 `metadata.client.client_id`（否则每次 dump 的新 uuid 会让暂停团队被反复拆建——上游注释明确记载的教训，注释保留）。bit-exact 才继承；重复签名按池序一对一配对。**Go 签名序列化用「结构体 → map → JSON marshal + 键排序」复刻 sort_keys，不依赖 struct 字段序**。

### 3.5 IntelliRouterAllocator（allocator.py:639-909 逐行对齐）

整组单 entry 校验（非空 / 恰一条 / model_name=="*" / api_provider=="intelli_router" / metadata.client.intelli_router 非空）；`Allocate` 无 hint 返回组统一配置；`ListRouteTags`（跳过 ""/"*"）/ `ResolveCliModels` 支持 tag 选择；Restore 无操作（无轮转计数）；工厂 `strategy == "intelli_router"` 分支。

## 6. 23.4a isRequestSideError 缺陷修复（本批裁决项）

**根因**：`intellirouter/router/reliable_router.go:1182` 在 `IsDeploymentError` 命中后直接查 `status_code ∈ [400,500)`，**漏了 Python py:364-366 的 `not isinstance(error, (DeploymentAuthError, DeploymentRateLimitError))` 排除**——Go 的 `DeploymentAuthError struct{ IRBase }` 携带 `details["status_code"]=401` 且满足 IsDeploymentError，于是 401/403/429 被误判请求侧 → 不冷却 → 单 deployment 组 `usable` 恒非空 → ToModelError 永远 switchable（1s 无限重试同一坏 key），永远到不了 `exhausted_user_action`（"Please check the API key"）。代码注释自己写着"401/403 与 429 → 部署侧"，与实现不符，属移植漏项，**非上游行为**（PyPI wheel 0.1.0b1 `reliable_router.py:341-370` 原文复核确认：Auth/RateLimit 先排除、是部署侧、进冷却）。

**修复**：先判 Auth/RateLimit 专属类型（`errors.As` 同族判定，不引反射）→ 是则部署侧返回 false；再查 status_code。`ValueError/TypeError → 请求侧` 的 Go 等价分支（本地参数校验 error）与 JSONDecode 归部署侧的折算注释保留。

**400 不冷却是上游有意设计**（给 ContextEngine 溢出恢复留通道，23.4b 集成 I3 已按真实链路断言），不动。`exhausted_request_rejected` 分支只在被拒部署同时带历史冷却的混合场景到达。

**回归用例三条**：401/403/429 → `OnFailure` 被调用（进冷却）；单 deployment 组 401 → 分类 `exhausted_user_action`（`reason=all_deterministic` + fix_hint），不再 switchable。

**记录同步**：23.4b spec/memory 中"review-7 语义与四分类的张力未裁决"摘除，改为"已裁决：23.4a 移植缺陷，随 23.4c 修复"。

## 12. 实施补充（2026-11-14 实施期登记）

### 12.1 新增偏差 D-7（llm_route 流桥的会话注入）

Python `write_llm_route`（model.py:30-56）经框架 `register_sync` 全局注册一次，session 由 contextvar `get_current_session()` 注入。Go 无 contextvar，等价改为：**每次模型调用临时注册 OnCustom(LLMRoute) 处理器**（`react_model_call.go` 的 `writeLLMRouteDuring`，闭包捕获 sess），处理器体一比一复刻 write_llm_route（payload 拷贝 + result_type 兜底 answer + OutputSchema{llm_route, index:0}，session nil 跳过）。触发时机（路由器选路时同步触发、调用同 goroutine）与 chunk 形状不变；注册位置与注入方式偏差。回收条件：Go 引入会话上下文注入机制后改回全局注册。

### 12.2 存量差异修复：entrySignature 漏剔除 client_id

既有 `entrySignature`（9.64 迁移）漏了 pool.py:556-559 明确记载的 `metadata.client.client_id` 剔除——计入会让暂停团队每次请求被拆建重盘。本批修复（pool.go）。

### 12.3 存量接线补齐
