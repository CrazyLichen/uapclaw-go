## 2. 技术选型

### 2.1 用 `database/sql` + `mattn/go-sqlite3` 裸 SQL，不用 GORM

Go 侧同时具备 `gorm.io/gorm v1.31.1` 与 `gorm.io/driver/sqlite v1.6.0`（`go.mod:102-104`），
`internal/agent_teams/tools/database`、`internal/agentcore/memory` 等包在用。**本节主动不用**，
理由四条：

1. **本节一半 SQL 是 ORM 表达不了的**：`query_events` 的 `json_extract(payload_json,'$.f') IS
   json_extract(?, '$')`、`CAST(json_extract(...) AS INTEGER) <= ?`，以及 3 个表达式索引
   （其中 `idx_recommendation_event_manifest_compat` 是含 `CAST(...) DESC` 的 7 列索引）。
   GORM 的分支链式 API 一律落回 `db.Raw("原始 SQL")`，结构化收益归零。
2. **`query_events` 的动态拼装顺序有语义要求**：`ORDER BY` 的
   `order_by_payload_integer_desc` 前缀必须插在 `created_at` **之前**，GORM 控制不了子句物理顺序。
3. **`record_event` 的幂等判定依赖 `RowsAffected`**：`INSERT OR IGNORE` 后取
   `cursor.rowcount == 1`；GORM 的 `clause.OnConflict{DoNothing:true}` 要下探
   `tx.Statement.RowsAffected`，比 `res.RowsAffected()` 绕。
4. **规则 9 会卡住**：上游 `topic_starter.py` 是 `import sqlite3` 裸 SQL，一个
   `connection.execute(sql, params)` 对应 Go 一个 `db.Exec/Query(sql, params...)`，可逐行对拍；
   换成 GORM 就变成两次映射（Python SQL → GORM API → 最终 SQL），§14 对账无法一眼核对。

唯一受益点是 `_create_tables` 的 5 条 DDL，但 GORM `AutoMigrate` 不生成表达式索引，这 5 条仍要
`db.Exec(原文)`。**综合：裸 SQL，与上游一对一。**

> 代码注释中同步写一句理由（用户 2026-11-19 要求），避免后来人"顺手改成 GORM"。

## 4. 数据结构

### 4.1 `InterestDrift`

```go
// InterestDrift 兴趣漂移三信号结果（对齐 topic_starter.py:109）。
type InterestDrift struct {
	EntropyDelta    float64 // 熵差绝对值
	JaccardDistance float64 // 1 - 交集/并集
	JSDivergence    float64 // Jensen-Shannon 散度
	Score           float64 // 三信号加权和
	ShouldUpdate    bool    // Score > 0.8
}
```

字段均 `round(x, 12)`。Go 无内置 `round(x, n)`，用 `math.Round(v*1e12)/1e12`。
**注意** `_entropy` 用 `math.Log2`；`_js_divergence` 的 `_kl` 只累加
`probability > 0 && midpoint[label] > 0` 的项。

### 4.2 `QueryEventsOptions`

Python 是 keyword-only + 默认值（`:578-592`），Go 用 struct 对齐：

```go
// QueryEventsOptions query_events 的查询条件（对齐 topic_starter.py:578）。
type QueryEventsOptions struct {
	EventType                 string          // 必填；空串直接返回 nil
	SlateID                   *string         // None 表示不加条件
	TopicID                   *string         // None 表示不加条件
	PolicyID                  *string         // None 表示不加条件
	PayloadEquals             map[string]any  // payload 等值过滤
	PayloadIntegerLTE         *PayloadIntegerLTE
	PayloadPresent            *string         // payload 键存在
	OrderByPayloadIntegerDesc *string         // 整数降序前缀排序字段
	Limit                     int             // 默认 100；< 1 返回 nil
	Offset                    int             // < 0 返回 nil
	NewestFirst               bool            // created_at/event_key 的 ASC/DESC
}

// PayloadIntegerLTE payload 整数上界过滤。
type PayloadIntegerLTE struct {
	Field string
	Value int
}
```

`SlateID/TopicID/PolicyID` 用 `*string` 而非 `string`：Python 用 `None` 区分"不加条件"与
"值等于空串"，这两种语义在 `slate_id` 上不等价（空串是合法值）。

### 5.2 连接与事务

- `connect()`：`sql.Open("sqlite3", path+"?_busy_timeout=5000")`，**每次调用新建 `*sql.DB`**，
  调用方负责 `Close()`。对齐 Python `with self._connect() as conn`（用后即关）。
- `save_snapshot` / `record_event` / `record_events_atomic` / `prune` 等写路径用
  `db.Begin()` + `Commit/Rollback` 显式事务。
- **`VACUUM` 三条禁令**（用户决策「不用 `MaxOpenConns(1)`」带来的注意点）：
  1. 不得用 `db.Begin()` 包住 `VACUUM`——SQLite 报 `cannot VACUUM from within a transaction`；
     必须 `Commit()` 之后再 `db.Exec("VACUUM")`
  2. `Prune` 里 DELETE 批次要显式开事务并提交，**不能**在同一条 `*sql.Tx` 上接着 `VACUUM`
  3. 测试库不得用 `:memory:`（默认池下每条连接是独立空库），一律 `t.TempDir()` 落盘
- `delete_recommendation_data` 的 `PRAGMA secure_delete = ON` 是**连接级**设置，必须在执行
  DELETE 的同一连接上先设置。

### 5.3 逐方法对齐要点

#### `EventKeyOf`（`:485-497`）

```
parts = [session_id, slate_id, event_type, topic_id]
if event.get("feedback_record_id"):   # truthy 判断
    parts.append(str(event["feedback_record_id"]))
return "|".join(parts)
```

Go 实现注意三点：
- 前 4 段都用 `str(event.get(k) or "")` 语义 → nil / `""` 都得空串，且**非字符串值**要转字符串
- 第 5 段是 **truthy** 判断：`""`、`0`、`false`、`nil` 都不追加。Go 里写一个
  `pythonTruthy(v any) bool` 助手统一处理（`nil`/`""`/`0`/`0.0`/`false`/空容器为假）
- 分割符 `|`，5 段用 `strings.Join`

#### `RecordEvent`（`:498-526`）

`INSERT OR IGNORE`，5 层默认值兜底：

| 字段 | Python 兜底 | Go |
|---|---|---|
| `policy_id` | `or "topic-starter-mvp-v1"` | 空串 → 默认 |
| `selection_mode` | `or "unknown"` | 空串 → 默认 |
| `propensity_reason` | `or "not_estimated"` | 空串 → 默认 |
| `payload` | `or {}` | nil → `map[string]any{}` |
| `created_at` | `or time.time()` | 缺失/0 → `time.Now().Unix()` 浮点 |
| `session_id` / `slate_id` | `or ""` | 同 |
| `topic_id` / `position` / `profile_version` / `propensity` | 保持 `None` | `nil` 存 SQL NULL |

返回值 = `RowsAffected() == 1`（实测：冲突时为 0）。`payload` 序列化用
`json.Marshal` + `SetEscapeHTML(false)`，对齐 `ensure_ascii=False`。

#### `RecordEventsAtomic`（`:527-565`）

三条短路，**顺序不可改**：
1. `len(events) == 0` → `false`
2. **写库前**算所有 key，有重复 → `false`
3. 事务内**普通 INSERT**（不是 OR IGNORE），任一失败 →
   `errors.As(err, &sqlite3.Error{})` → `Rollback()` + `false`

注意第 3 条：`sqlite3.Error` 覆盖 `UNIQUE constraint failed`，但也覆盖其它约束错误；
对齐 Python 只捕 `IntegrityError`，Go 侧等价为判断 `sqlite3.ErrConstraint`。

#### `QueryEvents`（`:578-672`）

**4 条守卫必须按序提前返回**（Python 都是 early return）：

```
1. EventType == ""  → nil
2. Limit < 1        → nil
3. Offset < 0       → nil     ← 负数不报错，返回空
4. 触达字段差集白名单非空 → error
```

第 4 条：把 `PayloadEquals` 的键 + `PayloadPresent` + `PayloadIntegerLTE.Field` +
`OrderByPayloadIntegerDesc` 合并成 set，减去 `eventPayloadQueryFields`，非空则报错
（Python 报 `ValueError: unsupported event payload query fields: [...]`，Go 返回 error 并用
`sort.Strings` 保证消息稳定）。

SQL 拼装顺序（不可调）：

```
SELECT * FROM recommendation_event WHERE
  event_type = ?                        [1]
  AND slate_id = ?                      [2 若 SlateID != nil]
  AND topic_id = ?                      [3 若 TopicID != nil]
  AND policy_id = ?                     [4 若 PolicyID != nil]
  AND json_extract(payload_json,'$.f') IS json_extract(?, '$')   [5 每个 equals]
  AND CAST(json_extract(payload_json,'$.f') AS INTEGER) <= ?     [6 若 IntegerLTE]
  AND json_extract(payload_json,'$.f') IS NOT NULL               [7 若 Present]
ORDER BY
  [CAST(json_extract(payload_json,'$.f') AS INTEGER) DESC, ]     [8 若 OrderBy...]
  created_at <ASC|DESC>, event_key <ASC|DESC>
LIMIT ? OFFSET ?
```

关键点：
- `payload_equals` 用 **`IS`** 不是 `=`（`IS` 才能让 JSON `null` 匹配）
- 参数值是 `json.dumps(value, ensure_ascii=False, separators=(",",":"))` —— Go 用
  `json.Marshal` + `SetEscapeHTML(false)` 得到无空白、不转义非 ASCII 的等价串
- 字段名直接插进 SQL 字符串（上游是 f-string）。**存在注入面**，但字段名已被第 4 条白名单
  拦住，值全部走占位符。Go 侧必须**先做白名单校验再拼串**，顺序不能反
- `limit` / `offset` 作为最后两个参数（`int`）
- 行转 map：`payload_json` 解回 `payload`，其余列按列名直出

#### `SaveSnapshot`（`:437-468`）

同连接内 `SELECT COALESCE(MAX(version),0)+1` 取号 → 组装 `stored`（补 `version` /
`updated_at` / `evidence_until`）→ `INSERT`。`created_at` 用 `time.Now().Unix()` 浮点。
返回 `stored`（Python 返回 `dict`）。

#### `LoadLatestSnapshot`（`:469-484`）

`ORDER BY version DESC` 遍历，**跳过** `schema_version == "topic-starter-v4"` 的行，
返回第一条 v3 可读的 dict；无非 dict 值或全被跳过 → `nil`。

#### `Prune`（`:233-288`）

流程顺序（不可调）：
1. `query_events(event_type="store_pruned", limit=1, newest_first=True)` 取最新一条
2. 若存在且 `created_at > now - 20h` → 返回 `{}`（节流）
3. **单事务内**：按 16 项 TTL 逐类 DELETE（`rowcount` 非 0 才记入 `removed`）
4. 同事务内依次 `_prune_superseded_summaries` → `_prune_profile_snapshots` → `_prune_short_intent`，
   各自非 0 才记入 `removed`（键名 `session_summary_superseded` / `profile_snapshot` / `short_intent_state`）
5. 提交
6. **`if removed` 才** `VACUUM`（新开连接，事务已结束）
7. **无论有无删除**，写 `store_pruned` 事件（`session_id/slate_id="maintenance"`、
   `topic_id="maintenance:<int(now)>"`、`policy_id="recommendation-retention-v1"` 等）

#### 三个 prune 助手

- `pruneSupersededSummaries`：按 `json_extract(payload_json,'$.session_id')` 排序，
  逐行数每会话，超过 2 条的删除（保最新 2 条）。返回删除数。
- `pruneProfileSnapshots`：`version DESC` 取全部，**跳过前 2 个**，其余
  `created_at < now - 90d` 的删除。
- `pruneShortIntent`：先 `sqlite_master` 探测表存在，不存在返回 0；
  存在则 `DELETE WHERE evaluated_at < now - 90d`。

#### `DeleteRecommendationData`（`:186-232`）

顺序（不可调）：
1. 遍历 `ListEvents()`：统计 `dynamic_exposure` 条数与
   `payload.card_revision_ids` 长度之和（→ `exposures_removed` / `cards_removed`）；
   对 `provider_invocation` 按 `payload.attempt_id` 收据化，**只保留 9 个键**：
   `attempt_id` / `provider_response_id` / `usage` / `status` / `stage` / `provider` /
   `model` / `latency_ms` / `failure_reason`
2. 单事务：`PRAGMA secure_delete = ON` → `DELETE FROM profile_snapshot` →
   `DELETE FROM recommendation_event` → 若 `short_intent_state` 存在则清空
3. 回填收据：每条 `record_event`，`session_id="usage"` / `slate_id="usage"` /
   `event_type="provider_invocation"` / `topic_id=attempt` /
   `policy_id="topic-starter-provider-invocation-v1"` / `selection_mode="usage_retention"` /
   `propensity_reason="not_applicable"` / `created_at` 沿用原值
4. 写 `recommendation_data_deleted`（`policy_id="recommendation-consent-v1"`、
   `selection_mode="exclusion"`、`propensity_reason="user_deletion"`、
   payload = `{exposures_removed, cards_removed}`）
5. `VACUUM`

#### `IntervenedPrompts`（`:673-688`）

`session_bound` 事件建 `slate_id → session_id` 映射 → 遍历 `topic_click`，
要求 slate 在映射中**且** `payload.prompt` 非空 → 收 `(session_id, prompt)` 二元组。
Go 用 `map[[2]string]struct{}` 表达 Python 的 `set[tuple[str, str]]`。

#### `InterestDrift` / `ComputeInterestDrift`（`:100-176`）

- `interestDistribution`：`Counter(str(label).strip() for label in labels if str(label).strip())`
  → 归一化。**标签先 strip 再判空**，空集合返回 `{}`
- `interestEntropy`：`-Σ p·log2(p)`
- `jsDivergence`：中点为两分布均值；`_kl` 只累加 `p > 0 && midpoint > 0` 的项；返回 `(kl(p) + kl(q))/2`
- `ComputeInterestDrift`：`entropyDelta = |H(current) - H(previous)|`；
  `jaccardDistance = 1 - |交集|/|并集|`（并集空则 0）；
  `score = 0.4·entropyDelta + 0.3·jaccard + 0.3·js`；
  四个数值全部 `round(,12)`；`ShouldUpdate` 用 **round 前**的 `score` 与 `0.8` 做**严格大于**比较。

**已实测确认**（`topic_starter.py:155-174`）：构造 `InterestDrift` 时 `score=round(score, 12)`，
但 `should_update=score > _DRIFT_THRESHOLD` 读的是**局部变量** `score`，即未 round 的原始值。
Go 必须保留未 round 中间值做比较，只在返回时 round。

补充实测：穷举 2-4 个标签的组合未发现 round 前后跨阈值的样例（round 到 12 位对 0.8 附近的
偏移远小于比较分辨率），但语义仍按上述对齐，并用一条构造用例把该差异锁住。

## 6. 已知偏差

| 编号 | 项 | 性质 | 理由 | 回收条件 |
|---|---|---|---|---|
| D-1 | 不设 `_journal_mode=WAL` | 有意与 Go 侧先例不同 | 严格对齐上游 `_connect`（只设 `busy_timeout`）；用户 2026-11-19 拍板 | 出现并发写锁问题再评估 |
| D-2 | 不设 `MaxOpenConns(1)` | 有意偏差 | Python 每次新开连接，Go 用默认池最接近；且 `VACUUM` 不阻塞业务 | 出现连接膨胀或锁竞争再收窄 |
| D-3 | `connect()` 每次新建 `*sql.DB` | 结构偏差 | Python `with self._connect()` 用后即关；`*sql.DB` 是池对象，`Close()` 等价关闭 | 若实测连接开销明显，改为持有单个 `*sql.DB` 字段 |
| D-4 | 事件用 `map[string]any` 而非结构体 | 语言差异 | Python 侧即为 dict；16 类有 TTL 的事件 + 未列举类型形状各异，后续章节会扩字段 | 若后续需强类型校验，再引入结构体层 |
| D-5 | `QueryEvents` 非法字段返回 `error` 而非 `panic` | 语言惯例 | Python 抛 `ValueError`，Go 用 error 返回更符合调用方习惯 | — |
| D-6 | `pythonTruthy` 助手 | 语言差异 | Go 无 truthy 语义，`event_key_of` / 默认值兜底都需要 | — |
