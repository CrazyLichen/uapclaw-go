# Cron 工具实现设计 (9.38)

## 概述

实现 `internal/agentcore/harness/tools/cron/` 包，为 Agent 提供定时任务（Cron）管理能力。包括统一 cron 工具（action 路由）和 7 个遗留兼容工具，完全对齐 Python `openjiuwen/harness/tools/cron.py` 的架构与逻辑。

元数据层（`prompts/tools/cron.go`，8 个 MetadataProvider）已完整实现，本设计仅覆盖运行时逻辑层。

## 在 Agent 会话中的流程位置与作用

```
用户请求 → LLM 推理 → 工具调度 → [Cron 工具] → CronToolBackend → 外部 Cron 服务
                                         ↑
                               属于 9.38-49 内置工具集
                               在 Agent 会话生命周期内注册
```

核心作用：
1. **定时任务生命周期管理**：创建/更新/删除/启停 Cron 任务
2. **统一入口 + 遗留兼容**：一个统一 cron 工具通过 action 路由 8 种操作，同时提供 7 个独立工具名供旧版 Agent 使用
3. **会话绑定**：通过 `CronToolContext`（channel_id + session_id）将任务与会话/频道关联
4. **即时唤醒**：wake 操作允许 Agent 主动触发通知，RunNow 允许立即执行某个任务
5. **回填关系**：9.26 BrowserAgent 标注 `⤵️ 9.38-49 回填 Playwright MCP 工具集`

## CronToolContext 结构体 (backend.go)

对齐 Python `CronToolContext` (cron.py L14-26)：

```go
type CronToolContext struct {
    ChannelID string            // 频道标识
    SessionID string            // 会话标识
    Metadata  map[string]any    // 扩展元数据
    Mode      string            // 触发模式
}

func (c *CronToolContext) ToolScope() string {
    channel := strings.TrimSpace(c.ChannelID)
    if channel == "" {
        channel = "unknown"
    }
    session := strings.TrimSpace(c.SessionID)
    if session == "" {
        session = "default"
    }
    return channel + ":" + session
}
```

Python `or "unknown"` 双重空值兜底 → Go 用 TrimSpace 后空字符串判断，效果等价。

## 统一 cron 工具 — MapFunction 方案 (dispatch.go + factory.go)

统一 cron 工具使用 `MapFunction`（而非 InvokeFunction），因为 Python 的 `_dispatch_cron_action` 有 `**kwargs` 参数需要保留未映射字段作为 `flat_kwargs`。MapFunction 的 `invokeFn` 签名 `func(ctx, map[string]any) -> (map[string]any, error)` 天然保留所有 kwargs。

### dispatchCronAction (dispatch.go)

对齐 Python `_dispatch_cron_action` (cron.py L135-201)：

- 从 `inputs` map 提取 `action`、`jobId`（兼容 `id`）、`job`、`patch`、`includeDisabled`、`text`、`mode`
- 构建 `excludedKeys` 集合（与 Python 完全一致：action/job/jobId/patch/includeDisabled/text/mode/contextMessages/gatewayUrl/gatewayToken/timeoutMs/runMode）
- 收集 `flatKwargs`（排除 excludedKeys 后的剩余字段）
- switch 路由 8 种 action：status/list/add/update/remove/run/runs/wake
- jobId 缺失时返回 `fmt.Errorf("jobId is required")`，对齐 Python `raise ValueError`
- 未知 action 返回 `fmt.Errorf("unsupported cron action: %s", actionName)`

辅助函数：
- `strVal(m, key)` → 从 map 提取字符串
- `boolVal(m, key)` → 从 map 提取布尔值
- `mapVal(m, key)` → 从 map 提取嵌套 map

## CreateCronTools 工厂函数 (factory.go)

对齐 Python `create_cron_tools` (cron.py L204-308)：

```go
func CreateCronTools(
    backend CronToolBackend,
    context *CronToolContext,
    language string,
    targetChannels []string,
    defaultTargetChannel string,
    includeLegacyCompat bool,
    agentID string,
) []tool.Tool
```

- 计算 `scope = toolScope(context)`，`finalAgentID = agentID or scope`
- 统一 cron 工具：`BuildToolCard("cron", "cron_"+scope)` → `NewMapFunction(card, cronFn, nil)`
- 7 个遗留工具：各 `BuildToolCard(name, name+"_"+scope)` → `NewInvokeFunction(name, fn, WithCard(card))`
- `includeLegacyCompat=false` 时只返回统一工具

## 错误处理

| 场景 | Python | Go |
|------|--------|-----|
| jobId 缺失 | `raise ValueError("jobId is required")` | `return nil, fmt.Errorf("jobId is required")` |
| 未知 action | `raise ValueError("unsupported cron action")` | `return nil, fmt.Errorf("unsupported cron action: %s", actionName)` |
| Backend 错误 | `await backend.xxx()` 异常传播 | `result, err := backend.xxx()` → return err |

直接用 `fmt.Errorf`，不使用 `exception.BuildError`。MapFunction.Invoke 在外层用 `exception.StatusToolLocalFunctionExecutionError` 包装。

## 日志

Python `cron.py` 中**没有 logger 调用**，因此 Go 运行时层**也不补充日志**。保留 `logComponent` 常量定义为后续 Backend 实现预留。

dispatch.go 中仅添加防御性日志：
- 入口处：Debug 级别记录 `action` 和 `jobId`
- 不支持的 action：Warn 级别记录
