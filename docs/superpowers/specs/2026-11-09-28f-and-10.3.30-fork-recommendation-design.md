## 1. 概述

### 1.1 一句话

把 Go 的 `DeepAdapter` 从「单实例服务全部会话」改成 Python 的双形态结构，并在 child 上补齐 `prompt_suggestion` 的可独立部分；为此需要整层对齐 KV cache 亲和协议并接入 ReAct 主调用点，让模型重放请求与父调用逐字一致。同时把 topic 存储层与 recommendation 整包从 10.3.30 剥离，分别登记为 `10.7` 与 `10.3.31a~e`。

### 1.2 两条业务流的流程位置

**① agent 会话主流程（10.3.28f 所在）**

```
Gateway ──E2A──► AgentServer.dispatch
                    │
                    ├─ chat.send ──► AgentRuntime.Stream
                    │                   └─ UapClawSwarm → ensureAdapter → uc.adapter
                    │                        └─ AgentAdapter.ProcessMessageStreamImpl
                    │                             │
                    │                             └─ ★ 分流头：根 → child（每会话一份 DeepAgent）
                    │                                  └─ rails / tools / context engine 全在 child 上
                    │
                    ├─ 会话态 RPC（user_answer / compress / usage / recap / goal_control）
                    │   └─ 同上：根分流 → child 执行 → finally 淘汰空闲
                    │
                    ├─ 非会话态 RPC（extensions / packages / rewind …）
                    │   └─ 根上执行，先 EnsureInstance(ctx) 取根自己的 DeepAgent
                    │
                    └─ session.delete ──► provisioner 七阶段事务
                                            └─ dispose ③ CleanupSessionRuntime
                                                 └─ adapter.CleanupSessionAdapter(sid)
```

作用：让「该会话的 DeepAgent」这个对象真实存在。不做则 25.8 的 `stop_subagent_runtimes` 无可操作对象、会话删除只清一个空 map、切模型/切 rail 会污染所有会话。

**② 轮次生命周期 + 删除事务（10.3.30 所在）**

```
chat.send
  → 28f 分流头 → child
  → forks.RequestStarted(sid, personTurn)                          [30-4]
  → child 建 instance / rail 表含 PromptSuggestionForkRail          [30-3]
  → ReAct 模型调用
       react_model_call.go:152  contextWindow.GetMessages()        ← 历史来源
       :155-157  inputs.Messages / inputs.Tools 写回
       :170      hook 五步 → extraKVPairs
       :199      callLLMInvoke(..., extraKVPairs)                    ← 真正发出的请求
       :251      inputs.Response = aiMsg
  → rail.AfterModelCall（priority -1_000_000，最后读）
       → forks.SawMainCall(sid, mainCall{messages,tools,answer,model,parameters})
  → 轮结束 → forks.TurnEnded(sid, reqID, status, waiting, completion)
       ├─ 抑制分支：记 Debug(reason) → 不生成
       └─ 成功分支：go _fork(...) → forks._tasks[sid] = 在飞
            → 模型重放（前缀逐字不变 → 服务商 prompt cache 命中）
```

作用：记账（这轮主调用是啥）+ 取消（删会话/关服务/页面撤销时掐断在飞任务）。不做则 dispose 第①步仍是 Debug 空桩，会话删了后台任务继续持有 LLM 客户端。

### 1.4 术语表：两个「fork」同名不同物

| 术语 | 含义 | 归属 |
|---|---|---|
| `session.fork` / `/branch` | **复制会话**：搬历史 / metadata / 内存上下文到新会话 | R-5 的对象 |
| `PromptSuggestionForks` / `_MainCall.fork()` | **重放本轮模型请求**：复用服务商 prompt cache，只在回答后追加一句「用户下一句会说啥」 | 30-2 的对象 |

二者同名、不同物。`PromptSuggestionForks` 是全局单例（`prompt_suggestion.py:535`），只有三个内存表（`_turns` / `_tasks` / `_answered`），不复制任何会话。

### 1.5 上游怎么「去到历史数据」

结论：**上游没有读历史文件，它在模型调用那一刻从 ReAct 循环内部直接抄下真正发出去的请求**。

```
react_agent.py:1229  context_window = await ctx.context.get_context_window(...)
                       ↑ 历史来源：context engine 从内存攒的 messages + 工具结果 + 系统提示词
:1231  ctx.inputs.messages = context_window.get_messages()
:1232  ctx.inputs.tools    = context_window.get_tools()
:1790  messages=ctx.inputs.messages            ← 发给 provider 的就是这一份
       ctx.inputs.response = ai_message
prompt_suggestion.py:555  rail.after_model_call(ctx) → tuple(ctx.inputs.messages) 等
```

`priority = -1_000_000` 的注释是「Read the call after every rail that rewrites it」——排最后读，保证抄到的是 provider 实际收到的最终版本。

### 4.3 `_fork` 落半截

```
1. suggestionID = uuid
2. messages = [*call.messages, call.answer, UserMessage(SUGGESTION_PROMPT)]   // 前缀逐字不变
3. for i < call.maxIterations:
     if ConsentEpoch() != epoch → return
     reply = call.llm.Invoke(ctx, call.parameters 覆盖 model/messages/tools)  // ★ 复用父参数
     replies = append(replies, reply)
     usage = usagePayload(reply)                           // 用已有 UsageMetadata
4. 解析出 suggestion 文本（≤240 字符、单行、或 null）
5. 窄接口预留：
     if forkPublisher != nil { forkPublisher.PublishForkResult(...) }
     if readyPusher != nil   { readyPusher.PushReady(...) }
     未注入 → 记 Debug("fork result discarded: no publisher") 并返回
```
