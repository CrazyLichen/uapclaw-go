## 2. 已拍板决策记录

1. **时机（方案 A）**：17.7 现在做 harness 轨道；PUCT 停旗/pause/terminate 打 ⤵️ 挂 17.3，17.7 行标记部分完成 + 回填指针。
2. **检查点形态（口径①）**：`RaiseIfCancelled(ctx)` 转正保留原名原位——它是 Python `task.cancelling() > 0 → raise CancelledError` 语义在 Go 的唯一正确映射（ctx 取消/超时 → 哨兵错误）。改名/搬包无 Python 对应物，牵动 17.4d 既有接线。
3. **取消传播**：Run finally 取消判定由 `ctx.Err() != nil` 扩为 `ctx.Err() != nil || errors.Is(err, ErrTaskCancelled)`——对齐 Python"取消从子协程冒上来、本任务 cancelling() 计数为 0 仍判 cancelled"分支（iterative.py:221-226 catch CancelledError）。
4. **资源清理（选项①）**：登记不实施；auto_harness 清理随 17.4e 解禁。

### 3.2 Run finally 取消判定修正

`iterative.go` Run 的 finally 段（:3430-3459）判定改为：

```go
cancelled := ctx.Err() != nil || errors.Is(err, ErrTaskCancelled)
```

覆盖两个 Python 分支：
- 主任务被取消（task.cancelling() > 0）→ Go：`ctx.Err() != nil`
- 子协程取消冒上来（catch CancelledError 置 cancelled=True）→ Go：内部检查点/子调用返回的 `ErrTaskCancelled` 沿 error 链冒到顶层

`continuous.go` 对应段同改。emit 事件维持现状（cancelled→terminated / failed→failed）。

## 5. 已知偏差

| 编号 | 偏差 | 理由 |
|---|---|---|
| D-17.7-1 | Python `_raise_if_cancelled` 读 asyncio 当前任务 cancelling() 计数；Go 无此概念，映射为 ctx 取消检查 | 语言层无协程取消注入机制；ctx 是 Go 侧等价取消信道（17.1a call_scope 同款思路） |
| D-17.7-2 | Python catch `asyncio.CancelledError` 需 re-raise；Go 哨兵错误沿返回值冒泡，无 re-raise 形态 | 错误传播机制差异，语义等价（取消错误不被吞、顶层可判） |
| D-17.7-3 | Python 取消为运行时强制注入（任何 await 点可中断）；Go 仅在显式检查点与在途调用感知取消，检查点之间的纯计算段无法中断 | 协作式语义的有意收窄；检查点间距为一个完整工作单元（batch/attempt/issue），与 Python 检查点粒度一致 |
