## 1. 背景与流程位置

25.2b 是 scheduled dispatch（F_62）的**第二批：review 半区**。在 agent 会话运行时链路中位于 `TeamScheduler._scan()` 五遍幂等扫描的第三遍 `_reconcile_reviews`：任务作者 `member_complete_task` 自报完成 → 任务进 IN_REVIEW → 本半区负责派发临时 reviewer、计票裁决、结算/返工/升级。

上游 25.3（验证者与返工）已按 12-02 裁决 1 并入本批，25.3 收缩为零头。

四件事：

1. **派发**：IN_REVIEW 且 `enable_task_verification` 开启时，按 `task.reviewer` JSON 列（verifier/challenger 二元池 + inspector 打分池）给每个未投票 reviewer 派一次性临时 harness（build → run_once → dispose），带 `verify_task` + `view_task` 两工具。
2. **裁决**（verdict 纯函数）：二元池一票否决；inspector 池全员投票后平均 ≥0.85；任一池未投满 → UNDECIDED。
3. **结算**：pass → `settle_review("pass")` + leader digest（作者不被唤醒，F_119，作者侧由 task-outcome rail 在下次输入折叠告知——Go 已有 `TaskOutcomeTracker`，本批在结算点调 `Announce`）；fail → `meta_rework` + feedback 返工；轮次超限/停滞/连续无票 → 升级 leader。
4. **review 驱动的团队技能演进**（通道 B）：fail 结算后把 `{task_id, round, assignee, feedback}` 异步分发给 leader harness 上的 `TeamSkillEvolutionRail.handle_review_feedback`，归因（LLM 分类 + assignee 轨迹证据）→ 终态聚合 → 复用 rail 既有优化器/审批/落库管线。

### 1.1 轨迹数据面（本批核对后的事实，防实施偏离）

- **Python 生产主链**：`TrajectorySpanProcessor`（OTel SpanProcessor 子类，进程级 demand 单例）——每个成员的 span 在 `end()` 时由 OTel SDK 自动回调 `processor.on_end`，processor 规范化后**扇出到各订阅者的 pending 缓冲**（按 category + trace_id 匹配，deepcopy + identity 去重，缓冲满记 issue 丢弃）。processor 只分发不存。
- **rail 窗口**：EvolutionRail 基类在 `before_invoke` 订阅（team 订阅必须带 trace_id），`after_model_call`/`after_tool_call`/`after_invoke` 每次钩子 drain 自己的订阅缓冲并 merge 进 `_scope_windows[key]`（`("agent", session, member)` / `("team", team_id, session)`）。leader 的 team scope 窗口因此含**全员** span（同一条团队 trace）。
- **消费面**：通道 A（团队完成聚合演进）与通道 B（review 归因 `select_member_spans`）都读 rail 的内存窗口。成员自己的 `("agent")` 窗口供成员自己的 SkillEvolutionRail 用（订阅缓冲 per-subscriber、drain 即清空，所以成员必须自己订阅）。
- **不是主链的东西**：`InMemoryTrajectoryRegistry`（上游生产构造点为零，`TeamWorkspaceInfo.trajectory_registry` 恒 None——上游死字段）；rail 内置 `InMemoryTrajectoryStore`（兜底/回落）；平台 SQLite store（`trajectory_ui` 配置块，默认关，只喂前端轨迹 UI/诊断，rails 不读）。
- **TrajectoryRail 未废弃**：生产消费方是 `RSITrajectoryRail`（RSI 诊断链，领域 **17.6** 已登记回填点，见 IMPLEMENTATION_PLAN.md 17.6 行 25.2b 登记），团队链路不挂它。Go 侧 `trajectory_rail.go` 已有、保留。
