## 1. 背景与定位

PersonalContext（主动上下文）是**进程内常驻宿主服务**，不在 ReAct/rail 链路里：

- **启动期**：Python `agent_ws_server.py:1381` 构造 `PersonalContextHostAPI(home=<workspace>/.personal_context)`，preparation 阶段 best-effort 启动（失败不阻断主服务）。
- **请求期**：前端经 web WS 通道发 26 个 `PERSONAL_CONTEXT_*` ReqMethod，`ws_handler.handle_personal_context_request` 分发到 Host API。
- **作用**：用户把外部源（github/gitcode/feishu/rss/知乎/头条/浏览器书签/本地文件）采集成本地 Markdown 知识图谱；agent 会话经 `agent_support`（24.3c）消费；设置页提供集合管理、进度查询、图谱浏览。

**本批只做 Host 壳**（Python Host 半区 ~2,700 行）；Core（~26,000 行）拆三章后续回填。**前端 Go 仓已完整迁移**（`components/PersonalContext/`、`personalContextStore.ts`、`personalContextApi.ts`），在等后端。

## 2. 范围裁决（brainstorming 结论）

1. **方案 A**：24.3 只做 Host 壳 + 分批认领 Core；Host 方法空态合法（Python `_unconfigured_projection` 本身即合法形态）。
2. **Core 拆分**（依赖序）：
   - **24.3a** Core 基座：config/models/context_graph/status_codes/path_safety/source_markdown/source_metadata/source_link_book + context_pipeline 主体，~13,500 行
   - **24.3b** fetch 源：fetch/base + retry + 9 源（local_files/github/gitcode/feishu/rss_feed/browser_bookmarks/zhihu_reader/toutiao_reader/cursor_selection），~8,200 行
   - **24.3c** agent_use 面：agent_support + file_tools，~2,200 行
3. **Host 壳批内边界**：
   - ① 配置持久化半区随批（yaml 原子发布、模型自洽、fetch services CRUD 校验）
   - ② PAT/授权真实现挂 24.3b：github/gitcode PAT 验证 + feishu 设备码流程（lark-cli）均随对应 fetch 源回填；本批保留 `authorize_provider`/`get_authorization_status` 方法面，返回未授权空态
   - ③ 生命周期写路径"接受+落盘+未启动"空转态：configure/set_*_enabled/select_model 校验+落盘成功，start 只置状态不启动 Core；run 启动类（fetch_run_*）返回"运行时未就绪"错误，不假装运行
4. **授权三类结论**（修正讨论中的误判）：PAT 表单类 github(token)/gitcode(pat)；设备码类 feishu（lark-cli device-code，令牌不经过服务）；其余 6 源零凭据（Core `_normalize_credentials` 白名单硬性保证，传 credentials 直接报错）。

## 4. 数据流与空态语义（逐方法定性）

请求流：`前端 WS → web WS 分发点 → ws_handler.go（26 method switch）→ HostAPI（operation mutex 包全部写路径，对齐 _operation_lock）→ coreRuntime（本批恒 nil → 空态分支）`

| 方法族 | Core nil 行为 | 依据 |
|---|---|---|
| runtime_status | state=CREATED、configured=false 投影 | Python 未配置即此态 |
| get/patch_config、set_master/collection/agent_use、select_model | 校验+落盘 yaml 成功，内存态更新；Core 委托跳过 | ③空转态裁决 |
| fetch_list_services | 返回 yaml 已存 services | 数据在 Host |
| fetch_create/delete/patch_service | 通用校验+落盘；仓库类强制"先授权"检查照常 | ①范围 |
| fetch_run_all/run_one/stop_run/start/stop_service | 返回"运行时未就绪"错误（state 非 RUNNING） | Python Core 非 RUNNING 态本就拒绝，空态自然落入该错误路径 |
| fetch_get_run_status | 空 runs 列表 | 无历史=合法空态 |
| get_authorization_status / authorize_provider | github/gitcode：方法面+表单校验保留，验证走空态返回 not_authorized；feishu：not_authorized 空态；其余：authorization_unsupported | ②裁决 |
| context_stream_graph/stream_tree | start → 空 nodes → 空 edges → end 四事件后收尾 | 前端订阅协议 1:1，空图谱合法 |
| search_pages/get_node/get_source | 返回"上下文为空"错误 | 对齐 Core 未启动时状态检查错误 |

## 5. 配置持久化与模型自洽（①细节）

- 配置文件：`<workspace>/.personal_context/personal_context.yaml`，统一形状（全局开关/策略/模型 + `fetch_services` 列表 + `provider_credentials` 仅仓库类）
- 安全链：4 MiB 上限 → symlink 链逐级拒绝 → 临时文件写 + rename 原子替换 → 失败清理 → 读取缺文件返回未配置（非报错）
- 模型自洽 `_reconcile_model_selection`：model_id（稳定 ID）+ model_index（下标）双写；models.list 重排按 model_id 重对齐；失效回落第一个可用模型；无可用模型时 balanced/agent 强制降级 rules。依赖 Go 既有 models 配置读取面（27.x），实施时锚定。

## 6. 测试策略

单元（≥85%）：持久化链边界（4MiB/symlink/原子替换失败/缺文件）；模型自洽四分支；CRUD 校验（去重/上限 20/正整数/仓库类先授权/自带 credentials 拒绝）；error_messages 本地化。

集成（规则 7 自检跨 ≥3 子系统）：web WS 通道 → 分发点 → HostAPI → yaml 落盘；代表性 method 集合（status/get_config/patch_config/set_master_enabled/create_service/stream_graph 空态四事件帧序断言）；best-effort 启动失败不阻断 server 启动。前端 `personalContextGraphFetchStatus.test.mjs` 等既有测试可对照帧协议。

审计坑提醒：每个 `_test.go` 自带 `suite.Run(`、不支持 import 别名。
