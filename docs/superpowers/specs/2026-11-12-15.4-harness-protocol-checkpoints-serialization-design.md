## 1. 在 agent 会话中的流程位置与作用

### 1.1 调用链

```
宿主启动一次 agent 会话（web / chat / team 任一入口）
  │
  ├─ 单 Agent 路径（本仓 Go 已通）：
  │    DeepAgentSpec.build() → DeepAgent.Invoke / RunStreaming → _run_task_loop 自驱
  │    ❌ 不经过 harness_protocol
  │
  └─ 外部 CLI 成员路径（领域十五要新建，当前 Go 全缺）：
       spawn_teammate(external_cli)                            ← 15.16 / 15.13
         → HarnessProvider.Create(config)                      ← 15.5
         → harness.Start(HarnessContext)                       ← 15.1 ✅
         │    ├─ card.ValidateHost() 协商协议版本与宿主能力
         │    └─ ⭐ context.Checkpoint / context.CheckpointSink 注入 ← 15.4 定义其类型与校验
         → harness.Send(HarnessInput) → SendReceipt            ← 15.1 ✅
         → hooks / interactions 控制面                          ← 15.3 ✅
         → events() / turn_events() 观测面                      ← 15.2 ✅
         │    ⭐ 跨进程传输：HarnessEventToDict / HarnessEventFromDict ← 15.4（本节）
         → TurnResult 终态                                      ← 15.1 ✅
         → ⭐ checkpoint 保存 / 恢复 / CAS 冲突                    ← 15.4（本节）
```

15.4 是协议层里**唯一负责「让数据活着离开本进程」**的一节：15.1-15.3 定的是内存中的对象形状，15.4 定的是它们在 stdio 线缆上与宿主持久化存储里的形状。

### 1.2 三个平面之外的第四个通道

15.2 定了 observation / interaction / hooks 三平面。15.4 **不新增平面**，它横切两个已有平面，并引入一个独立通道：

| 平面/通道 | 15.4 做什么 | 阻塞 |
|---|---|---|
| observation | `HarnessEventToDict`/`HarnessEventFromDict`、`EventWireSchemaVersion`、未知事件无损保留 | 否 |
| **checkpoint（独立通道）** | `HarnessCheckpoint`/`CheckpointSaveReceipt` 构造校验、`HarnessCheckpointSink` 契约 | 否（宿主异步持久化，provider best-effort） |

checkpoint 不是三平面之一，而是独立通道：`README.md:84-86` 把它与 interactions/hooks 并列描述为 provider 状态持久化路径，`SPEC.md:209-237` 独立成章。

### 1.3 作用

1. **跨进程无损**：provider 跑在子进程（claude/codex/dsh），事件必须序列化过 stdio。没有 codec，15.2 的事件对象一条也传不出来。
2. **前向兼容**：`UnknownEvent` 是版本漂移的唯一缓冲阀——新 provider 发来旧宿主不认识的事件类型、或 `schema_version` 提高时，宿主不能崩、不能丢，必须原样保留再原样发回。
3. **可恢复性**：外部 CLI 会话跑几十分钟，进程可能被杀。checkpoint 让「agent 状态」变成宿主可持久化的信封，`REQUIRE_RESUME` 时能续上。
4. **防脏数据**：4 MiB 上限 + `FreezeJsonObject` 递归冻结，把「provider 把整个 SDK 对象塞进 data」这类错误挡在 sink 之前（`SPEC.md:219`）。
5. **幂等 + CAS 契约**：同一 `checkpoint_id` 重试返回原 receipt；旧 sequence 或期望修订号不匹配抛 `CheckpointConflictError`，**绝不覆盖新状态**（`SPEC.md:233-237`）。

### 1.4 首个生产消费者

- **codec**：`harness_providers/stream.py` 的游标与 `harness_providers/io_adapter.py` 的跨进程桥接 → 首个真实消费方为 **15.5 provider 基座**。
- **`HarnessCheckpoint` 值对象**：`harness_providers/base.py:776-813` 的 `_publish_checkpoint` → **15.5**。
- **`HarnessCheckpointSink` 的生产实现**：`agent_teams/external/member_runtime.py:124-152` 的 `_MemberSessionCheckpointSink` → **15.13**。
- **`jsonsafe`**：**9 个文件**引用（8 个 provider 侧 `mapping`/`observation`/`harness`/`options` + `agent_teams/harness/protocol_adapter.py`）→ **15.5 / 15.7 / 15.8 / 15.13**。

**本节交付时生产消费者为零属预期**（与 15.1-15.3 同一口径），契约面靠单测覆盖，不造「实现了但没消费方」的行为代码。

**步骤 5 的编码口径**（Q12 决策 B）：
- `json.NewEncoder(&buf)` + `SetEscapeHTML(false)` → 与 Python `ensure_ascii=False` 对齐
- `Encode` 会追加 `\n`，**必须裁掉尾部换行**，否则每个 checkpoint 多算 1 字节
- 序列化前先 `JsonValueToBuiltin(data)` 归一化
- 实测对照（`{"html":"<a>&</a>","cn":"中文"}`）：Go 33 字节 = Python `ensure_ascii=False` 33 字节；Python 默认 `ensure_ascii=True` 为 39 字节（**已登记偏差**）
- 单键中文场景（`{"cn":"中文"}`）：Go 15 字节 vs Python 默认 21 字节（实测 `checkpointDataSize` 断言值）
- 全 ASCII 数据两侧完全一致（`{"payload":"xxx"}` 均为 17 字节）

**seq/err 顺序**：上游是「先全部必填校验、再 sequence、再 optional」三段串行，Go 必须保持同一顺序，不得合并成一次遍历（规则 12.1-2）。

#### 5.2.2 13 个 `parseXxx`（Q6/Q7 决策 A）

```go
// parseOutputKind 解析并校验 OutputKind。
// Python: serialization.py:388 _enum(OutputKind, ...)
func parseOutputKind(value any, fieldName string) (OutputKind, error) {
	// 步骤 1：非 string 即报错
	//   → "<fieldName> must be a string enum value"
	// Python: serialization.py:517-518
	s, ok := value.(string)
	if !ok {
		return "", &HarnessProtocolError{Msg: fieldName + " must be a string enum value"}
	}
	// 步骤 2：合法值集合用 switch 常量（拼错编译不过）
```

#### 5.2.3 基础助手（8 个）与类型严格性

**`asInteger` 的四步**（Q11 决策 A）：

```go
// 步骤 1：拒绝 bool（Python: isinstance(value, bool) 优先排除）
// 步骤 2：整数族（int/int8…/uint…）直接转 int
// 步骤 3：float64 → 必须 !NaN && !Inf && v == math.Trunc(v) && 在 int64 范围内
// 步骤 4：其余 → "<field> must be an integer"
```

步骤 3 的范围检查不可省：实测 `float64(1e300)` 满足 `v == Trunc(v)`，直接 `int(v)` 在不同平台得到溢出结果（0 或负值）。JSON 里写 `1e300` 完全合法，`json.Unmarshal` 会原样解出，因此**这一项是必现路径**。

`-0.0` 通过校验并转成 `0`，与 Python `int(-0.0) == 0` 一致。

**`asNumber` 的三步**：

```go
// 步骤 1：拒绝 bool
// 步骤 2：整数族 → float64；float64 → 原值（NaN/Inf 此处不拒，交由 FreezeJsonValue 拒绝）
// 步骤 3：其余 → "<field> must be a number"
```

#### 5.2.4 字段路径前缀的两种写法（易错点）

机器抽取的上游字段路径清单：

| 函数 | 前缀来源 | 产出示例 |
|---|---|---|
| `errorFromDict(data, fieldName)` | **实参**（`f"{field_name}.code"`） | `model_request.error.code` / `turn_result.error.code` / `turn_result.termination.code` |
| `blockFromDict(data)` | **硬编码** `content_block.` | 无论嵌套多深都是 `content_block.data` |

因此 `errorFromDict` **必须保留 `fieldName` 形参**，不得写死；`blockFromDict`/`messageFromDict`/`usageFromDict` **不得**加 `fieldName` 形参。这是规则 12.1「方法归属与签名不得改动」的直接落点。

### 5.3 `jsonsafe.go`（`internal/agentcore/harness_providers/`）

#### 5.3.1 职责澄清

`to_json_safe` **不是**「检查类型是否支持 JSON 序列化」，它做的是**序列化前的类型归一化**：

```
provider SDK 对象
  → to_json_safe       归一化成纯 JSON 值（NaN→None、Enum→value、对象→str）
  → freeze_json_value  递归校验 + 冻结（拒绝残留 NaN / 非 str key）
  → 进 HarnessEvent / HarnessCheckpoint
```

两道工序串联且不可合并：`FreezeJsonValue` 是**严格拒绝**的（NaN 抛错，`models.py:36-37`），而 provider 数据里 NaN 常见（SDK 的 `usage`、耗时字段）。没有 `to_json_safe` 先把 NaN 洗成 `nil`，provider 吐一个 NaN 整条事件就构造失败。

这也解释了目录归属：它是 **provider 侧的脏数据清洗**（`harness_providers/`），而 `FreezeJsonValue` 是**协议侧的准入校验**（`harness_protocol/`）。

#### 5.3.2 分支映射（Python 10 条 isinstance 链 → Go）

| Python 分支 | 行 | Go 实现 | 状态 |
|---|---|---|---|
| `None/str/bool/int` 原样 | `:24-25` | 类型 switch | ✅ |
| `float` 非有限 → `None` | `:26-27` | `IsNaN`/`IsInf` → `nil` | ✅ |
| `Enum` → 递归 `.value` | `:28-29` | **并入 `reflect.Kind()==String`**（Q3 决策）：返回 `rv.String()` | ✅ |
| `os.PathLike` → `fspath` | `:30-31` | **不实现** | ⤵️ 偏差 |
| `bytes` → UTF-8 decode(errors="replace") | `:32-33` | `strings.ToValidUTF8(string(b), "\ufffd")`（仓内先例 `harness/tools/shell/output.go:108-110`） | ✅ |
| dataclass → 逐字段 dict | `:34-35` | **不实现** | ⤵️ 偏差 |
| 有可调用 `model_dump` | `:36-38` | 探测 `interface{ ModelDump(mode string, byAlias bool) (any, error) }` | ✅（接缝，本批无实现者） |
| `Mapping` → `str(key)` 递归 | `:39-40` | reflect Map/Struct→map | ✅ |
| `list/tuple/set/frozenset` → list | `:41-42` | reflect Slice/Array → `[]any` | ✅ |

**分支顺序约束**：`[]byte` 的 `Kind()` 是 `Slice`，必须在 slice 分支**之前**处理，否则会被展开成数字数组。对应 Python 中 `bytes`（`:32`）早于 `list`（`:41`）的顺序。

**Q3 修正记录**：原方案用 `rv.Kind()==reflect.String && rv.Type().Name()!=""` 判枚举，实测 `reflect.Type.Name()` 对预声明类型 `string` 返回 `"string"` 而非空串，该判据**不成立**（会把裸 `string` 误判为枚举、且 `type Alias = string` 无法区分）。正确做法是枚举分支**不需要单独存在**——`string`、`OutputKind("text")`、`type Alias = string` 三者 `Kind()` 都是 `String`，返回原字符串，语义与 Python 完全一致。
