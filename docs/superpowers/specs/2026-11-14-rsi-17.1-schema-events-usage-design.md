## 二、流程位置（通俗版，保留供 spec 读者理解）

RSI 是给 agent 装的"自我打磨"流水线：多轮"生成候选改进 → 测试打分 → 好则采纳"循环。17.1 是最底层的记账与传话基础件，不做任何决策：

1. **schema = 统一表格模板**：15 个数据契约，17.2-17.9 所有环节共用。
2. **events = 统一广播频道**：引擎每完成一步对外广播；规定先落盘再广播，广播失败不吞（上层决定补偿）。
3. **usage = 电表**：旁观记账的小会计（`ModelUsageObserver`），把回调框架上经过的每次模型调用抄一笔账；judge（评测 LLM，17.6）的调用也会被记账——电表是所有模型调用的旁观者。
4. 控制器（controller）是总指挥：发任务给 agent/judge、收结果、决定采纳、写盘；电表记账后随共享 state 落盘。

链路：控制器指挥 → agent/judge 调 LLM → 全局回调框架广播 → 电表记账 → 流水账落盘。

## 四、17.1a 细节

1. `call_scope.go`：三个 context 等价物——当前调用 ID、unified-completion 期望标志、观测抑制标志；`LlmCallScope` 进入/退出语义（保存旧值 + 还原，对齐 Python token；显式不使用 `ContextVar.reset` 的跨上下文防御——Go ctx 单向派生天然满足）。
2. `model.go` 接线：`Invoke` / `Stream` 开头生成 call ID 并进 ctx，`defer` 还原（覆盖 D6 全程）；事件数据结构 `LLMCallEventData` **不新增 call id 字段**（Python 也走 contextvar 而非事件数据）。
3. 观测抑制（`LlmObservationSuppression`）与 unified-completion 判断一并移植（usage 的 `_complete`/`_invoke_output` 分支依赖）。

## 五、已知偏差

| # | 偏差 | 理由 | 回收条件 |
|---|---|---|---|
| P1 | Python state 为裸 dict 无锁（asyncio 单线程安全）；Go 用 atomic（D7 拍板：totals/账本路径 atomic.Pointer，锁仅护去重与账本写入）+ -race 并发读测试固化 | Go 多 goroutine 必要防护，语义等价 | 无 |
| P2 | Python frozen dataclass → Go 私有字段+访问器 | 语言能力差异（D2 拍板） | 无 |
| P3 | Python `Literal` 联合 + TypeAlias → Go 接口+多类型 | 语言能力差异（D3 拍板） | 无 |
| P4 | aiofiles 异步写 → Go 同步 append（`os.OpenFile` append 模式，无 fsync，与 Python 一致） | Python aiofiles 亦不 fsync | 无 |
