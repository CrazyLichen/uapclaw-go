## 1. 背景与目标

领域十五（第三方 Harness 协议与外部 Agent 接入）中 15.17 是收尾测试章节（编解码/事件序单测 + stdio 双工假 CLI + 失败恢复）。调研发现：

1. **Python 上游无 codebuddy provider**（闭集 PROVIDER_NAMES = native/native_v2/claudecode/codex/dsh，factory.py:62），codebuddy 属 Go 侧新增第三方 provider，按规则 13 登记新章节 **15.22**。
2. Python 侧的"失败恢复"内容散在三处，且**没有真起假 CLI 进程走 stdio 的测试**（单测走 monkeypatch 假 SDK 模块，进程级契约走真 LLM 系统测试）：
   - `tests/unit_tests/harness_protocol/test_protocol.py`（958 行/29 用例）——协议单测
   - `tests/unit_tests/harness_providers/test_{claudecode,codex}.py` + `dsh/test_harness.py`——假 SDK 模块
   - `tests/system_tests/harness_providers/_contract.py`（407 行，8 条 provider 无关契约检查：run_text_turn / run_tool_turn / run_follow_up_turns / run_abort_turn / run_steer_turn / run_user_input_turn / run_resume_turns + assert_turn_invariants）——真 LLM 系统测试
3. Go 侧挂账到 15.17 的（15.1 spec 明确）：
   - `test_event_json_codec_round_trips_and_preserves_unknown_events`（test_protocol.py:743）——UnknownEvent 往返
   - 假 CLI 进程集成（stdio 双工 / 崩溃 / 鉴权失败 / 超时）
4. codebuddy CLI（本机 2.181.0 实测）支持 Claude Code 同款 headless 协议：`-p --output-format stream-json --input-format stream-json`（双工）、`--resume <session-id>`、`--mcp-config`、`--permission-mode`、`--model`。线格式为 Anthropic 同款 JSONL（帧样例见 §4.3）。

**目标**：
- 15.22：新增 `codebuddy` provider（第三方注册缝），形态对齐 dsh 包复杂度（无 codex 特有面），带真进程集成测试。
- 15.17：清 15.1 挂账（codec UnknownEvent 往返）+ 事件序不变量共享断言 + stdio 双工/失败恢复（假 CLI 三故障）+ 真 LLM 最小两条。

## 3. 15.22 codebuddy provider 设计

### 3.2 目录结构（对齐 dsh 包形态）

```
internal/openuapclaw/harness_providers/codebuddy/
├── doc.go          # 包文档（标注 Python 无对应物 + 实测帧样例来源 CLI 2.181.0）
├── provider.go     # CodebuddyProvider: Card/Create/ModelConfig + init() RegisterHarnessProvider
├── config.go       # CodebuddyConfig: cli_path/model/permission_mode/cwd/env/mcp_config + FromMapping 校验
├── harness.go      # CodebuddyHarness: Start/Send/turn_events/abort/stop（协议四相位）
├── transport.go    # TransportFactory 缝：默认 spawn 子进程；测试注入 fake
└── mapping.go      # CLI 帧 → harness_protocol 事件（4 类帧映射）
```

### 3.3 关键设计

**TransportFactory 缝**（对齐 dsh 的 SDKFactory 手法）：

```go
// TransportFactory 传输缝：默认 spawn codebuddy CLI 子进程；测试注入 fake。
type TransportFactory func(options TransportOptions) (Transport, error)
```

默认实现 spawn：
```
codebuddy -p --output-format stream-json --input-format stream-json \
  [--model <m>] [--resume <sid>] [--mcp-config <f>] --permission-mode <mode> [--add-dir ...]
```
stderr 尾读、inactivity/turn 双超时、Scanner 逐行 JSONL——手法对齐 15.13 `externalcli/transport`，代码独立实现（裁决 5）。

**线格式映射（mapping.go，4 类帧）**：

| CLI 帧 | harness_protocol 映射 |
|--------|----------------------|
| `{"type":"system","subtype":"init",...}` | turn STARTED（TurnLifecycleEvent）+ card 能力协商 |
| `{"type":"assistant","message":{"content":[...]}}` | text 块 → OutputEvent(ANSWER)；tool_use 块 → ItemLifecycleEvent(item_type=tool) |
| `{"type":"system","subtype":"usage_update",...}` | usage 归集（`_meta.codebuddy.ai/turnUsage` stages → cost 累计） |
| `{"type":"result","subtype":"success"/"error_*","is_error":bool,...}` | TurnResult：success→FINISHED；is_error/error_*→FAILED（结构化错误） |

**能力卡**：`MCP_TOOLS`（--mcp-config）+ `GRACEFUL_ABORT`（双工 input 发 interrupt/控制帧）+ `ENDPOINT_MODELS`；`--resume` 承接 resume_policy / checkpoint 语义（CLI session persistence 天然支持，export_checkpoint 返回 session_id 载体）。

**最小失败分类**（完整 failure_classifier.py 225/273 行仍归 15.7/15.8，注释标注）：进程非零退出码 / `result.is_error` / stderr 鉴权错误文案 / inactivity·turn 超时 → 四类最小映射。

**单测**：transport fake 注入驱动 4 类帧映射 + config FromMapping 校验 + result 三态 + abort 帧 + 超时路径（fake 挂起）。
**集成测试**：`tests/integration/agentteams/externalcli/codebuddy/`——假 CLI 真子进程 stdio 双工整轮（§4），audit 跨度自检（≥3 子系统：harness_protocol + harness_providers + transport/进程边界）。

## 4. 共享测试基建：假 CLI 脚本

位置：`tests/integration/agentteams/externalcli/codebuddy/fakecodebuddy/`（Go helper 小程序，TestMain 或 go run 构建）。

行为：
- 读 stdin JSONL，按脚本文件回放帧序列（`--script path.json`，用例注入）
- 故障注入开关：
  - `--crash-after N`：写 N 帧后 exit 1（崩溃恢复）
  - `--auth-fail`：回 result error + stderr 鉴权文案（鉴权失败）
  - `--hang`：挂起不回帧（超时，配合 inactivity/turn 超时用例）
- 15.22 用它测真进程映射；15.17 用它测 transport 层失败恢复——同一脚本两次消费。

## 5. 15.17 设计（第二棒）

1. **编解码单测**：补 `test_event_json_codec_round_trips_and_preserves_unknown_events`（test_protocol.py:743）的 UnknownEvent 往返（未知事件类型保留不丢、线格式字段不漂），落 `harness_protocol` 包单测——15.1 spec 挂账清账。

3. **stdio 双工 + 失败恢复**：假 CLI 三故障开关 × transport 层（崩溃/鉴权失败/超时），目标目录 `tests/integration/agentcore/harness_protocol/`（既有序列追加 suite，每个 _test.go 自带 suite.Run）。
4. **真 LLM 最小版**：`run_text_turn` + `assert_turn_invariants` 两条转 real_llm 套件（双守卫模式挂 tag；dsh 免费 model + codebuddy `hy4flash-free` 双路径）；其余 6 条契约（tool_turn/follow_up/abort/steer/user_input/resume）挂 ⤵️ real_llm 待补。
