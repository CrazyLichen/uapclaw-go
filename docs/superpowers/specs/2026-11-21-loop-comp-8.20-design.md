## 1. 目标与流程位置

LoopComp 是工作流组件族中唯一形成环的结构：把一段子工作流（LoopGroup）作为循环体，
按四种条件（array/number/always_true/expression）反复执行，直到条件不满足或
LoopBreakComponent 触发中断。内部实现完全复用 Pregel：AdvancedLoopComponent 自建小图
`START→condition→body→post_body→condition`（回边）+ `add_conditional_edges(condition, self)`；
LoopGroup 是 BaseWorkflow 子类、compile 出 CompiledGraph 执行（8.14 同机制嵌套一层）。

运行链：外层图 Vertex（pre_invoke 按 inputs_schema 从 state 归集 → is_subgraph 装信封）
→ LoopComponent.invoke 拆信封 → 现场造 ConditionInSession + callbacks +
AdvancedLoopComponent → 小图跑环（条件节点路由走 AtomicInvoke 链）→ OutputCallback
收割 → 结果作为 loop_1 节点输出写回外层 state。

## 4. 核心实现要点

### 4.1 BaseCondition 元组分支回收（8.19 D-19-2，本节必做）

`condition.go` 修改（Python condition.py:18-25 对齐）：

- 回调签名：`invokeImpl func(ctx, inputs, sess) (bool, error)` →
  `invokeImpl func(ctx, inputs, sess) (bool, map[string]any, error)`
  （Python tuple 的 `result[1]` 用 Go 第三返回值承载，拍板 6；不造 tuple 类型）
- `NewBaseCondition` 回调壳补步骤：
  ```go
  flag, updates, err := invokeImpl(ctx, inputs, sess)
  if err != nil { return nil, err }
  if updates != nil {                      // Python: isinstance(result, tuple)
      // session.state().set_outputs(result[1]) → AtomicNode 链 CommitCmp 原子提交
  }
  return flag                              // Python: result = result[0]
  ```
- `Condition` 接口面 `Call/Invoke/TraceInfo` 签名不变（Python `__call__` 对外也只返回 bool）
- `FuncCondition`/`AlwaysTrue` impl 返回 `(x, nil, nil)`——Python 返回裸 bool 非 tuple，
  不触发 set_outputs；**NumberConditionInSession 同样返回裸 bool**（number.py:22），
  只有 Array 系两个类返回 tuple——逐字区分，不顺手统一
- 8.19 埋的非导出 `inputSchema` 槽同时启用：Array 系构造传 schema，
  `get_inputs(input_schema)` 分支（condition.go:56-63）生效

### 4.2 condition/array.go（array.py 一比一）

- `ArrayCondition`：构造存 `_arrays`；invoke 读 `inputs.get(key, [])`（鸭子怪癖逐字保留：
  inputs 按 input_schema 取，min_length 实际不随 inputs 变——Python 如此，不修）；
  `current_idx >= min_length` 提前返回 False；否则 updates 写 state 返回 `(True, io_updates)`。
  input_schema 传入 `arrays`。
- `ArrayConditionInSession`：构造期 `_check_arrays` 算 min_length（上限
  `DefaultMaxLoopNumber=1000`，None/非 list|tuple 即 ValueError 语义 error）；invoke 读
  INDEX、`current_idx >= min_length` 返回 False；逐 key 断言 list/tuple、越界
  `IndexError/TypeError/KeyError` → 统一 ValueError 包装（f"Array loop error in '{key}':
  <error_details>" 逐字）；updates 写 state 返回 tuple。无 input_schema（`super().__init__()`）。

### 4.3 condition/number.go（number.py 一比一）

- `NumberCondition`（死代码）：limit 为 str|int（Union → Go `any` 槽 D-20-x 登记）；
  invoke `current_idx < inputs`（limit_num = inputs，鸭子怪癖保留）
- `NumberConditionInSession`：limit int；invoke 裸 bool；limit None → ValueError
  （Go 构造期收窄 int 后该分支为不可达防御，注释留档）

### 4.5 callback 三件

- `LoopCallback`（loop_callback.py）：嵌 graph.AtomicNode；`Call(loopStage, sess, loopTimes)`
  ≙ `__call__` → AtomicInvoke；`_atomic_invoke` 分派四阶段 → 抽象方法四 → Go 构造回调槽
  （D3 同款 nil panic）；输出非 nil → set_outputs。
- `OutputCallback`（output.py）：round_result_root 默认 "round"；first_in_loop 初始化
  results=[] update；end_round 校验 list + `len>=loop_times` 跳过 + `get_inputs(outputs_format)`
  append+update；out_loop `get(round)` → `_generate_output` 递归（dict 递归/引用路径
  path[0]==node_id 取 results[-1] 逐 key 下钻/兜底遍历 results 逐 key 下钻成数组）一比一；
  is_ref_path/extract_origin_key/nested_path_split 用 session/utils 既有面。
- `IntermediateLoopVarCallback`（intermediate_loop_var.py）：first_in_loop
  `get_inputs(intermediate_loop_var)` → 非 nil update+commit；root 包装；其余三阶段 nil。

## 5. 偏差登记

| # | 偏差 | 理由 | 回收条件 |
|---|------|------|---------|
| D-20-1 | Python `getattr(session, "_inner")`/`_inner.parent()`/`session.parent_id()` → Go `InnerNodeSession()`/`Parent()`/`ParentID()` 导出访问器（loop_comp.py:209/271/455）。语义注记：`InnerNodeSession()` = 剥门面取内层内核（Vertex 传入的 loop 节点 NodeSession 门面 → 内核 InnerSession），供下游继续构建会话对象（AdvancedLoopComponent 的 NodeSession/小图 compile）——**下游构建者收内核不收门面**；`Parent()` = 内核再上取 workflow 层父 session（LoopGroup 建 SubWorkflowSession、LoopSetVariable 定位 root 走这条线，与 8.14b 嵌套机制同源）。两者不可互换 | Go 非导出字段跨包不可达；访问器为 8.17/8.19 既有合规面，行为等价；Python getattr 缺属性延迟炸 vs Go 编译期早失败属语言固有错误时机偏差 | 无（永久偏差，等价性由访问器契约保证） |
| D-20-2 | Python `LoopGroup._drawable.set_break_node`（loop_comp.py:83-84）跳过 | D-19-1 drawable 缝（WORKFLOW_DRAWABLE env/DrawableBranchRouter/add_branch 三处未落）⤴️8.13 一并回填，避免半成品缝 | 8.13 实施时同 BranchRouter drawable 分支一并落 |
| D-20-3 | Python tuple 返回 `(bool, updates)` → Go 回调第三返回值 `map[string]any`（condition.py:21-23 ↔ condition.go 回调壳） | Go 无 tuple；多返回值天然承载，`Condition` 接口对外面不变（Python `__call__` 对外也只返回 bool） | 无（映射型偏差） |
| D-20-4 | `NumberCondition._limit: Union[str, int]` → Go `any` 槽 | Go 无 Union；该类为死代码（拍板 1），行为面仅 invoke 时 `current_idx < inputs` 与 limit 无关的鸭子怪癖，逐字保留 | 无 |
| D-20-5 | pydantic `LoopInput.model_validate` → Go 手写校验函数 | pydantic 无 Go 对应物；Optional 默认值/类型语义逐项对齐（8.15 WorkflowConfig 先例） | 无 |
