## 一、背景与流程位置

领域二十 process-cli 的 20.5 覆盖三件：session_entry（会话查询）、persistence（退出前落盘）、session_guard（跨进程互斥 + Agent 绑定）。前两件已分别随 20.3（`session_entry.go`，223 行）与 20.2（`persistence.go` + `app.go:267`/`client.go:402`/`machine.go` runtime_close 清理步）落地。本批回填剩余的 session_guard，并回填 `machine.go` 四处 ⤵️ 桩。

在 Agent 会话流程中的位置：

```
main() 入口
 ├─【1】会话查询分支（session_entry，已落地）
 ├─【2】RunMachine.startup
 │     :234-236  入参带 session_id → SessionLease.acquire()      ← 本批
 │     :268      create_or_resume_session
 │     :273-275  新建会话（lease 仍 nil）→ 补 acquire             ← 本批
 │     :276-282  bind_agent(definition, resumed)                 ← 本批
 ├─【3】执行轮（无关）
 └─【4】cleanup / finally
       :575-584  cleanup() → session_lease.release()             ← 本批
       （flush_session_writes 已随 20.2 落地，先于 release）
```

作用：

- **SessionLease**：同会话跨进程并发互斥。锁文件 `<sessions_dir>/.process_cli_locks/<sha256(session_id)>.lock`，非阻塞排它锁；冲突抛 `SESSION_BUSY`（retryable=true）。
- **BindAgent**：把会话钉到其声明的根 Agent。绑定文件 `<sessions_dir>/.process_cli_bindings/<sha256(session_id)>.json` 存 `{"schema":1,"fingerprint":...}`；已绑定不一致 → `AGENT_DEFINITION_SESSION_CONFLICT`；绑定文件损坏 → `AGENT_BINDING_INVALID`；续聊一个已有消息但无绑定的会话且携带自定义 Agent → 同码拒绝。
- **persistence**（已在）：5s 窗口排空 history/metadata 两写队列。

## 三、Go 侧结构

### 3.1 SessionGuardError

```go
type SessionGuardError struct {
    Message   string
    Code      string // SESSION_BUSY / AGENT_BINDING_INVALID / AGENT_DEFINITION_SESSION_CONFLICT
    Retryable bool
}
```

实现 `error` 接口；消息文本一比一复刻 Python 英文原文（协议字符串不本地化）。

### 3.2 SessionLease

- `NewSessionLease(sessionID string)`：sha256 → `lifecycle.GetAgentSessionsDir()/.process_cli_locks/<digest>.lock`，`os.MkdirAll` 建目录（对齐 Python `mkdir(parents=True, exist_ok=True)`）。
- `Acquire() error`：非阻塞排它锁；冲突 → `SessionGuardError{Code:"SESSION_BUSY", Retryable:true}`；成功置 `_acquired`。
- `Release()`：幂等，仅 `_acquired` 为真时解锁（对齐 Python `_acquired` 标记）。
- 构造函数不做 I/O（Python 构造只建 portalocker 对象，锁在 acquire 时才真正加）。

### 3.3 BindAgent

签名对齐 Python 的 mapping 入参：

```go
func BindAgent(sessionID string, definition map[string]any, resumed bool) error
```

步骤（逐条对应 Python :61-116）：

1. 目录 `<sessions_dir>/.process_cli_bindings/`，目标 `<digest>.json`。
2. `definition != nil` 时由 mapping 构造 `RuntimeAgentDefinition`（mapping→结构体转换，Python `from_mapping` 对应物；`machine.go:217` 已有 `ToDict()` 证明往返存在，缺 FromMapping 则在本文件补转换）并算 `RuntimeAgentDefinitionFingerprint`；否则 fingerprint 为 nil（JSON `null`）。
3. expected = `{"schema":1, "fingerprint":...}`。
4. 目标存在：读 + `json.Unmarshal`；OSError/编码/JSON 错 → `AGENT_BINDING_INVALID`；`stored != expected` → `AGENT_DEFINITION_SESSION_CONFLICT`；一致 → 返回。
5. `resumed && definition != nil`：读会话 metadata（见 3.4），`message_count > 0` → `AGENT_DEFINITION_SESSION_CONFLICT`。
6. 原子写：tmp 名 `<target>.<uuid>.tmp`（uuid 对齐 Python）→ `O_CREATE|O_EXCL` 写紧凑 JSON（`separators=(",",":")` 对应 Go 默认 marshal）→ fsync → `os.Rename` → finally 删 tmp。模式同构 `lifecycle.AtomicJSON`，但保留 Python 的 uuid tmp 细节，不直接复用 AtomicJSON。

### 3.4 GetSessionMetadata 绕缓存变体

Python `bind_agent` resumed 分支调 `get_session_metadata(session_id, cache_bust=True, enable_writeback=False)`。Go 现有 `session.GetSessionMetadata(sessionID)`（`server/session/session_metadata.go:272`，带缓存）签名不匹配。在本批补带选项读取变体（绕缓存直读 + 禁写回），落在 `session_metadata.go` 旁，不动现有签名与其调用方。

## 五、测试

单测（`session_guard_test.go` + 平台文件按需）：

1. Lease：构造后未 acquire 不持锁；acquire → 第二个实例 acquire 报 `SESSION_BUSY`（Retryable）；release 后可重新 acquire；release 幂等。
2. BindAgent 四分支：新绑定写入（校验文件内容 schema/fingerprint）；再次一致通过；指纹不一致报 `AGENT_DEFINITION_SESSION_CONFLICT`；文件损坏（写非法字节）报 `AGENT_BINDING_INVALID`。
3. resumed 分支：metadata `message_count>0` 且带 definition → 拒绝；无消息会话可收养。
4. 原子写：tmp 文件在成功/失败路径均不残留。

集成测试（`tests/integration/swarm/processcli/`，补 20.10 登记缺口）：

- 「同会话并发拒绝」：同一 session_id 先后两个 `--run-json` 真子进程，第一个创建会话期间（或直接复用已存在会话 + 阻塞假模型持有锁）第二个断言 stderr/JSON 记录含 `SESSION_BUSY` 且退出码符合契约。
