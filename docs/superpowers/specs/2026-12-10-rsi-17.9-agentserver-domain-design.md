## 二、流程位置与作用（通俗定稿，供 spec 审阅者理解）

用户在网页上的训练操作走独立「RSI 专线」，不入聊天链路：

```
网页前端（训练面板，features/rsi 已有产物）
  → Gateway（rsi.enabled 实验开关 + rsi.* method 白名单）
    → AgentServer（req_method 以 rsi. 开头 → _handle_rsi_request 等价物）
      → RsiAgentServerHandlers 分发（18 method 叫号）
        → RsiServiceContext 服务域（TaskStore JSON 文件 + services + worker 单队列）
          → HarnessEngineAdapter → HarnessProvider → 17.4d 单 harness 迭代引擎（已完成）
```

- **TaskStore 不是数据库**：每任务一个 `.uapclawswarm/rsi/tasks/<task_id>/task.json`（Python 注释明确"不新增 DB"）；状态机唯一入口 `update_status(from_states, to, cause)`；状态迁移触发 P1 推送钩子。
- **worker 排队不经过文件**：进程内有界队列（128）+ 常驻 runner 协程（并发=1），`await queue.get()` 挂起等任务，不扫盘。
- **事件队列**：引擎跑起来后经 `on_event` 回调把进度（P2）/树增量（P3）/用量事件吐进有界队列，消费协程分发给 projector（聚合进度/树）、usage_recorder（记账）、push_callbacks（推网页）；推送失败不影响训练。
- **懒装配**：首个 rsi.* 请求才建服务域、装 provider、跑 recover_workspace 对账；全进程复用。
- **热加载**：install 校验 manifest → 复制不可变版本 + 激活指针 → AM 广播 → 每个活 Agent unload 旧 harness（LoadRecord）→ load_plugin 新包；失败逆序回滚 + live 恢复；rollback 前置门禁：存在 QUEUED/RUNNING/PAUSED 任务即拒。

## 三、分节设计

### 17.9a 存储与任务契约

Python：`task_store.py`(231) + `models.py`(331) + `errors.py`(199) + `recovery.py`(140)。

- task_store：JSON 文件存储；状态迁移表 7 状态逐字对齐（CREATED→QUEUED/TERMINED；QUEUED→RUNNING/PAUSED/TERMINED；RUNNING→COMPLETED/FAILED/PAUSED/TERMINED；PAUSED→QUEUED/TERMINED；三个终态封闭）；非法迁移抛 `TASK_STATE_CONFLICT`；P1 钩子回调字段 `on_status_changed(task_id, old, new)`；delete guard（RUNNING/PAUSED 不可删，QUEUED 由服务层先转 TERMINATED）；文件锁用 Go 互斥等价（Python RLock 单进程语义）。
- models：RsiTask / RsiTaskView / TaskStatus / Scenario / ArtifactType 等契约逐字对齐；ArtifactType 枚举成员完整保留（本批只消费 HARNESS 轨）——规则 9.2.4。
- errors：RsiError 家族 + 各错误码逐字对齐（RsiBadRequest/RsiNotReady/RsiTaskNotFound/RsiTaskStateConflict/RsiDatasetInvalid/RsiScenarioNotSupported/RsiHarness* 等）。
- recovery：recover_workspace 只对账不重跑——QUEUED→PAUSED(cause=agentserver_restart.queue_lost)；RUNNING→读 provider 盘上快照（state.json），有终态收敛为终态（FAILED 带 failure_reason），读不到/非终态→PAUSED(cause=agentserver_restart.execution_detached)；单任务损坏隔离不中断整体，返回 summary。

### 17.9b 服务域逻辑（方案 C 范围）

Python：`services.py`(997) + `worker.py`(932) + `harness_provider.py`(840) + `harness_adapter.py`(217) + `event_consumer.py`(264) + `events.py` + `projector.py`(615) + `usage_recorder.py`(277) + `context.py`(340) + `materializer.py`(903) + `model_resolver.py`(306) + `validation_dataset.py`(66) + `artifact_files_service.py`(309) + `artifact_service.py` + `artifact_adapter.py`（仅任务文件存取子集，查询服务依赖）+ `plugin_catalog.py` 等 HARNESS 轨依赖件。

- RsiTaskService：create（materializer 物化任务目录：数据集/模型配置/harness refs 校验）、list/get（projector+usage_recorder+artifact_service 注入）、delete（worker+guard）、start/pause/resume/terminate 五操作转交 worker；RsiDatasetService/RsiReportService/RsiTreeService/RsiUsageService/RsiArtifactDownloadService/RsiArtifactFilesService 逐字对齐。
- RsiWorker：单队列全量对齐——enqueue（CREATED→QUEUED、幂等短路、_ensure_runner 唯一 runner）、cancel(pause/terminate)（转发 provider、supports_pause/terminate 判定）、resume（PAUSED→QUEUED、fingerprint 校验由 provider 负责）、执行链（adapter.validate_input → build_request → sink→有界队列→消费协程 → await adapter.run）、COMPLETED/FAILED 终态、终态后排空事件队列、slot 让出 / winding down / provider 快照轮询（无隐式墙钟超时）。
- HARNESS 轨真身：HarnessProvider（驱动 17.4d 引擎，state.json 断点落盘、pause/terminate 响应、on_event 回调）+ HarnessEngineAdapter（HarnessProviderContract：run/resume/read_state 等）。
- 事件链路：events（EngineEvent 契约）+ event_consumer（consume_queue）+ projector（进度/树聚合，load_from_disk/register_root 供 recovery）+ usage_recorder。
- 装配根：context.py（RsiServiceContext：bind_task_service/register_adapters/adapter_for/register_harness_provider/bind_harness_installer/recover_workspace）+ materializer + model_resolver + validation_dataset。
- **不做（偏差登记，见 §四）**：mock 双 provider、ArtifactEngineAdapter、ThresholdStoppingProgramProvider（真身随 17.3）、PaperArtifactProviderImpl（真身随 17.5）、provider_factory 的 ARTIFACT/mock 分支。
- **17.7 回填挂钩**：terminate → worker.cancel → provider cancel ctx → iterative.go 六检查点触达 `ErrTaskCancelled` 分支；复跑 `TestRun_内部哨兵取消_无ctx取消`；若 Go 侧实现为仅 cancel ctx 无内部哨兵形态，在 spec 论证分支退化理由后收敛测试断言。

### 17.9c AgentServer 接线 + Gateway

Python：`server/rsi/rsi_handlers.py`(322) + `agent_ws_server.py` 接线段 + `agent_manager.py:1651` + `interface_deep.py:10041` + `gateway/common/config.py:795`。

- 分发层：`_METHOD_DISPATCH` 18 项逐字对齐（I1-I13 + control/artifact/tree + harness lifecycle）；handle / handle_async 双入口（install 走异步）；统一错误语义 `{ok, payload}` / `{ok:false, error, code}`（RsiError→业务码，其他→INTERNAL_ERROR）；`_rsi_session_id` 私有标记（transport session 与 method payload 分离，供推送回源 WS）；三常量 `rsi.training.status.changed / rsi.training.progress / rsi.training.tree.delta`。
- 三条推送：P1 状态钩子（store 回调，FAILED 附 failure_reason_text，best-effort）；P2/P3 事件回调（register_worker_push 等价）；统一推送出口 `_build_push_message`（channel_id=web、event_type、session_id 从 task.config.rsi_session_id 取）→ Go 既有 gateway_push。
- 懒装配（`_get_rsi_handlers` 等价）：build context → register_adapters（仅 HARNESS）→ register_harness_provider（HarnessProvider，refs 提供方注入）→ bind_harness_installer(AgentManager) → RsiAgentServerHandlers 构造（构造期 recover_workspace + 绑推送）；`_rsi_harness_refs_provider` 三级解析逐字对齐：显式 package_id（同 chat 的 Plugin registry 校验，拒 MCP 依赖）→ RsiHarnessActivationStore 激活版 → RSI_HARNESS_ROOT env / workspace rsi/harness 下 initial_harness_refs.yaml → auto_harness packages 激活表（17.4e 跳过后该级为空表分支，代码保留对齐）。
- installer（RsiHarnessInstaller 段）：install（锁内：读引擎发布状态 → manifest 装前校验 → 复制不可变版本 → 激活记录/指针 → 广播）；list_versions（不暴露本地路径，is_active/is_initial/available）；rollback（门禁：QUEUED/RUNNING/PAUSED 任务存在即拒；指针写失败 live 恢复）；`_broadcast` → AgentManager `broadcast_rsi_harness_change` 等价（遍历 agent/code 模式活 Agent，ensure_instance → apply_rsi_harness_install；失败逆序回滚）→ DeepAdapter `apply_rsi_harness_install`（自身+会话子适配器，快照回滚，unload 旧 LoadRecord → load 新包）。
- Gateway：config 增 `rsi.enabled` 开关 + 原子更新接口（对齐 `update_rsi_enabled_in_config`）；web 通道 method 白名单放行 `rsi.*` 前缀；开关关闭时入口拒绝。
- **偏差登记（方案 C 连带）**：`RSI_PROVIDER_MODE` / `RSI_USE_MOCK_PROVIDER` 环境变量分支删除（mock 模式不存在），懒装配仅 real 路径。
