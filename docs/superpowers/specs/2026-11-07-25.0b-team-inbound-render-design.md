## 1. 本节在会话流程中的位置

25.0b 是「团队成员被唤醒时，团队状态块怎么渲染」的**纯渲染层**。它不决定投什么、不管理基线、不碰会话 IO。

```
成员被唤醒（任务指派 / 邮箱消息 / 看板变动）
  └─ DeepAgent 输入准入
       └─ on_user_message 回调（Go: task_loop/executor.go → react_invoke.go:367）
            ├─ ① dropSupersededSnapshots(parts)         ← 25.0b 提供函数
            ├─ ② parts.insert(0, renderClock(now))      ← 25.0b 提供函数
            ├─ ③ 折入未告知的任务事实（消息级，非附件）   ← ⤵️ 25.3/25.4
            ├─ ④ parts.insert(0, tracker.pendingText()) ← 25.0b 渲染 / 25.0c 决策
            └─ ⑤ join("\n") 成一条历史消息 → 25.0a 的 admitUserMessage
```

**`parts` 与 team inbound 的关系**（常被混淆，这里明确一次）：
- `parts` 是「一批输入的容器」，25.0a 引入（`UserMessageInputs{Parts, Source}`）。它只是运输带，不懂 XML、不懂团队。
- team inbound 是「运输带上装的一种货」。25.0b 渲染的六类标签都是一段字符串，最终成为 `parts` 的一个元素。
- 25.0b 只有一处直接碰 `parts`（`DropSupersededSnapshots(parts []string)`），其余全是纯函数：给参数、返回 XML 字符串。

**为什么必须在 `parts` 阶段动手**：一旦 join 成一条历史消息，①「哪条是哪条」的位置关系消失（`dropSupersededSnapshots` 无从下手）；② 再改历史会让其后所有 KV-cache 失效。

### 1.1 六类标签的分工

| 标签 | 落点 | 生命周期 | 本节职责 |
|---|---|---|---|
| `<team-inbound from message_id type time [for]>` | 会话历史 | 永久，只读 | 把「对方原话」与「框架补充」切开 |
| `<team-note kind>` | **嵌在被修饰块内部，最后一个子元素** | 随宿主块 | 让「这条提示修饰哪块」成为树上的事实，不靠前后位置猜 |
| `<team-clock now>` | 每条准入输入一次 | 永久，不刷新 | 只写绝对时间；模型拿最近时钟算「多久之前」 |
| `<team-event kind [task_id] [for]>` | 会话历史 | 永久 | 框架事件（任务 / 看板 / 名册变动） |
| `<team-context>`（可嵌套 `<identity>` → `<identity-conversion>`） | 会话历史 | **只投一次** | 成员身份 + 团队信息，是事实不是快照 |
| `<team-policy [tools]>` | 会话历史（framework 建队的 leader） | 长期有效 | 系统建队时补的团队准则 |

**时间为什么不用相对差**：历史只读。一条「3 分钟前」写进去，一小时后模型重读仍是「3 分钟前」。所以信上只写绝对时间戳，另配一条 `<team-clock>` 让它自己算。

## 4. 关键实现决策

### 4.1 HTML 转义：两类，不能混用

Python 的 `html.escape` 有 `quote` 开关，Go 的 `html.EscapeString` 只有一种（且比 Python `quote=True` 多转单引号）：

| 字符 | Py `quote=False` | Py `quote=True` | Go `html.EscapeString` |
|---|---|---|---|
| `&` | `&amp;` | `&amp;` | `&amp;` |
| `<` `>` | `&lt;` `&gt;` | 同 | 同 |
| `"` | **不动** | `&quot;` | `&quot;` |
| `'` | **不动** | `&#x27;` | **`&#39;`** |

**决策（用户已确认）**：
- `escText`（元素正文）：**自己写**，只转 `& < >` 三字符。与 Python `quote=False` 逐字一致。
- `escAttr`（属性值）：**用 `html.EscapeString`**。差异面收缩到「属性值里单引号写成 `&#39;` 而非 `&#x27;`」，XML 解析后等值，在函数注释里登记。

```go
// escText 转义元素正文：只转 & < >，与 Python html.escape(quote=False) 逐字一致。
// Python: _esc_text
func escText(text string) string

// escAttr 转义属性值。
// Python: _esc_attr —— html.escape(quote=True)，单引号输出 &#x27;
// 本实现用 html.EscapeString，单引号输出 &#39;。XML 解析后等值，
// 属已知偏差 D-1（见 spec §7）。
func escAttr(value string) string
```

### 4.2 名册 diff 保序（用 orderedmap）

Python：

```python
old_by_name = {m.get("member_name", ""): m for m in (old or [])}
new_by_name = {m.get("member_name", ""): m for m in (new or [])}
```

dict 语义有两条要同时对齐：**① 迭代保首个插入位置；② 重复键时后写覆盖前写（值取最后一个、位置取第一个）**。

Go 若用 `map[string]RosterMember`，迭代顺序被随机化，字节级对拍必失败。若用「切片 + 下标 map」手写，还要自己维护去重逻辑，绕。

**决策（用户指定）**：用项目已有的 `github.com/wk8/go-ordered-map/v2`（`fragment_manager.go` / `update_checker.go` / `coding_memory_tool_ops.go` 在用）。`OrderedMap.Set` 的语义正是「已存在则覆盖值、保留原位置」，与 Python dict 逐条对应，不需要任何手写去重。

```go
import "github.com/wk8/go-ordered-map/v2"

func DiffRoster(old, new []RosterMember) RosterDelta {
    oldByName := orderedmap.New[string, RosterMember]()
    for _, m := range old {
        oldByName.Set(m.MemberName, m) // 重复名：覆盖值、保留原位置（= Python dict）
    }
    newByName := orderedmap.New[string, RosterMember]()
    for _, m := range new {
        newByName.Set(m.MemberName, m)
    }

    var joined, left, changed []RosterMember
    for pair := newByName.Oldest(); pair != nil; pair = pair.Next() { // 保 new 顺序
        if _, ok := oldByName.Get(pair.Key); !ok {
            joined = append(joined, pair.Value)
        }
    }
    for pair := oldByName.Oldest(); pair != nil; pair = pair.Next() { // 保 old 顺序
        if _, ok := newByName.Get(pair.Key); !ok {
            left = append(left, pair.Value)
        }
    }
    for pair := newByName.Oldest(); pair != nil; pair = pair.Next() { // 保 new 顺序
        prev, ok := oldByName.Get(pair.Key)
        if !ok {
            continue
        }
        if memberFieldChanged(prev, pair.Value) {
            changed = append(changed, pair.Value)
        }
    }
    return RosterDelta{Joined: joined, Left: left, Changed: changed}
}
```

**两点对齐说明**：
- Python 是三次独立推导（joined 遍历 `new_by_name`、left 遍历 `old_by_name`、changed 遍历 `new_by_name`）→ Go 三次独立 `Oldest()→Next()` 遍历，顺序一一对应。
- `memberFieldChanged` 对应 Python 的 `any(member.get(f,"") != previous.get(f,"") for f in _TRACKED_MEMBER_FIELDS)`，`trackedMemberFields = ("display_name", "desc", "role", "models_used")`。

⚠️ **新增依赖**：`messages.go` 将首次在 `agent_teams` 包内引入 `orderedmap`。`go.mod` 已有该依赖（v2.1.8），无需 `go get`。

### 4.3 `format_absolute_time` 的时区

Python：`datetime.fromtimestamp(ms/1000, tz=utc).astimezone()` → 本地时区，再 `strftime("%z")` 拼 `+08:00`。

Go 对应：

```go
func formatAbsolute(loc *time.Location, timestampMs int64) string {
    t := time.UnixMilli(timestampMs).In(loc)
    base := t.Format("2006-01-02 15:04:05")
    offset := t.Format("-07:00")   // "+08:00" / "+00:00"
    return base + " " + offset
}
```

**注意**：Python `strftime("%z")` 在 UTC 下给 `+0000` → 拼 `+00:00`；Go `-07:00` 在 UTC 下也给 `+00:00`。一致。

**决策（用户已确认）**：`FormatAbsoluteTime` 对外无 location 参数（对齐 Python 签名），内部走 `time.Local`；测试通过**导出同包的测试辅助**注入固定时区，不改全局 `time.Local`，避免测试间污染：

```go
// FormatAbsoluteTime 渲染绝对本地时间，无相对差。
// Python: format_absolute_time(timestamp_ms)
func FormatAbsoluteTime(timestampMs int64) string {
    return formatAbsolute(time.Local, timestampMs)
}

// formatAbsolute 可注入时区，供测试固定时区用（Python 侧直接依赖 astimezone，无此注入点）
func formatAbsolute(loc *time.Location, timestampMs int64) string
```

时区在测试里固定为 `Asia/Shanghai`（`time.FixedZone("CST", 8*3600)`），golden 里写死 `+08:00`。

### 4.5 `snapshot_kind_of` 的前缀/后缀判定

```python
stripped = text.strip()
if not stripped.endswith("</team-event>"):
    return None
return next((kind for kind in SNAPSHOT_EVENT_KINDS if stripped.startswith(_OPEN_TAG % kind)), None)
```

**关键**：`frozenset` 的迭代顺序在 Python 里是实现细节（实际按哈希），但 `SNAPSHOT_EVENT_KINDS` 只有 1 个元素，无顺序问题。Go 用 `map[string]struct{}` 需注意**只有一个元素时**无歧义；若将来加元素，需保证顺序与 Python 一致 —— 加注释登记此风险。

## 8. 已核实的依赖与结论

### Q1：`external/format.py` 的 4 个函数怎么办

用户已选「全收，外部成员路径也通」。逐条核实依赖后：

| 函数 | 依赖 | Go 现状 | 结论 |
|---|---|---|---|

### Q2：`reply_hint_for` 的 user 分支

**已核：Go 侧没有 `ReplyHintFor`（全仓 0 命中），上游在 `i18n.py:1122-1138`。**
