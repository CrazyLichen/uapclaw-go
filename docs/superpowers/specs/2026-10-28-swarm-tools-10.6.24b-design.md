    env（≥32 字符）→ 密钥文件（≥32 字符，trim 后）→ 自动生成 64 hex 字符写文件 0600

**技术要点**：
- 令牌格式 `Base64URL(payload_json) + "." + hex(HMAC-SHA256)`，payload `{path, exp, sid}`
- JSON 序列化：紧凑分隔符（`,`/`:`）+ `SetEscapeHTML(false)`——对齐 Python
  `json.dumps(separators=(",", ":"), ensure_ascii=False)`（中文路径不转 \uXXXX）
- 签名比较用 `hmac.Equal`（对齐 `compare_digest` 防时序攻击）
- 验签失败 Warn、过期 Info（带 path 字段）、解析异常 Debug（对齐 Python 三级日志）
- `exp = time.Now().Unix() + expiresIn`；`expires_at = time.Now().Unix() + expiresIn`
- mime：`mime.TypeByExtension` 推断，失败默认 `application/octet-stream`
- 密钥文件权限 0600；目录 MkdirAll 0755（对齐 `mkdir(parents=True)`）
- 日志组件：包内先例 `logger.ComponentAgentServer`（mcp_command.go:50）

**SendFile 执行流（逐行对齐 Python L79-206）**：
1. 字符串参数 JSON 解析宽容处理：list→用之；解析出单 str→包裹；解析失败/其他类型→包裹原文
2. `os.Stat` 存在性分流 valid/missing（missing 逐条 Warn "文件不存在"）
3. 全缺失 → 返回中文错误串 "发送文件失败：所有文件均不存在" + 清单（error 为 nil，给 LLM）

6. **下载信息生成整块失败 → 回退基础模式**（仅 path+name，Warn "生成下载信息失败，回退到基础模式"）

7. `sendFileHistoryFunc`：role="assistant"、event_type="chat.file"、content=""、
   timestamp=当前秒（Python `time.time()` → Go 等价 `float64(time.Now().UnixMilli())/1000`）、
   extra={"files": files_payload}；**注入函数为 nil 时 Warn 跳过**（降级语义）
8. push msg 手工构造（**不走 BuildServerPushMessage**，对齐 Python）：
   `{request_id, channel_id, session_id, payload:{event_type:"chat.file", files}, is_complete:false}`
   + metadata 非空时浅拷贝带上；`sendFilePushFunc` 调用；**nil 时 Warn 跳过**
9. 返回 "成功发送 N 个文件" + missing 时追加 "以下文件不存在，未发送：" 清单
10. 整体 error/panic 兜底 → "提交文件失败: %s"（对齐 Python except logger.exception）

## 四、关键设计决策

1. **包布局（方案 C：单包+全注入，用户拍板）**：两个新文件都进 swarmtools 主包；
   push/history 双注入。理由：Python 的 lazy import + get_instance 单例在 Go 中等价物
   是"启动接线 + 包级函数"（push 方向 Go 编译期硬环无法 lazy 绕过；history 方向虽无环
   但注入与 push 统一模式，swarmtools 彻底不碰 server——零新依赖方向，
   sessionops 偏差清单不加项）。gateway 验签 import swarmtools 主包
   （app_gateway→cronbridge 先例，编译依赖面无实质恶化）。
2. **注入 nil 降级语义**：push/history 注入函数为 nil 时 Warn 跳过（不 error）——
   对齐 Python send_push 失败仅 warn 的容错语义。测试覆盖此分支。
3. **TeamManager 重复注册用 WithRefresh(true)（有意偏差，用户拍板方案甲）**：Python
   对已存在 ID 是"异常静默丢弃"（旧实例滞留 resource_mgr、新卡上 ability，疑似 bug）；
   Go 用 Refresh 显式替换，行为更正确（执行层拿到新 toolkit），SDK docstring 明说
   refresh 为 team-scoped 状态工具重绑设计。DeepAdapter 路径维持 Python 语义
   （already_registered 检查后走 Update，resource_mgr 不重复注册）。
4. **heartbeat 守卫收窄（对齐性修正）**：现状整函数早退是 11.10 回填时的简化；
   Python 守卫只包 cron 块。收窄后 heartbeat 会话也能刷新 send_file 上下文。
5. **push 消息手工构造**：不走 BuildServerPushMessage（Python 同款手工 map 构造，
   is_complete: false 是 push-only 字段）。
6. **品牌映射**：`JIUWENSWARM_FILE_DOWNLOAD_SECRET` → `UAPCLAWSWARM_FILE_DOWNLOAD_SECRET`；
   密钥文件路径走 Go 既有 `path.WorkspaceDir()`（env `UAPCLAW_DATA_DIR` → `~/.uapclaw/`），
   对应 Python `JIUWENSWARM_WORKSPACE` env / `~/.jiuwenswarm/`。
7. **令牌无状态设计**：不维护已发令牌表（HMAC 自校验）；exp 默认 600s。
   payload 含 sid 但 ValidateToken 不校验 sid（对齐 Python——sid 仅溯源字段）。
8. **中文返回串保留**：send_file 返回给 LLM 的结果串（"成功发送 N 个文件"等）
   逐字保留中文（LLM 提示词语义，非日志——feedback-logs-english 规则不适用）。

## 八、风险与缓解

1. **令牌跨进程密钥一致性**（AgentServer 进程生成令牌、Gateway 进程验签——Go 单体部署
   下同进程无问题；若未来分离部署，密钥文件/env 是既定共享机制，无需额外设计）
2. **workspace sync.Once 缓存与测试隔离**：SetUserHome 有配套缓存重置（paths.go SetUserHome
   已重置全部 Once），测试间须 Reset 避免串扰
3. **filename*=UTF-8'' 编码差异**：Python `urllib.parse.quote(safe="")` 对 `/` 也转义；
   Go `url.PathEscape` 不转义 `/`——须手动逐字符对齐（百分号编码表核对），测试用
   含 `/` 与中文的文件名断言
4. **并发 UpdateRuntimeContext**：同一 toolkit 跨请求并发刷新（fast 连续请求）；
   mutex 保护 + -race 回归
5. **heartbeat 会话行为变化**：守卫收窄后 heartbeat 会话也会注册/刷新 send_file——
   与 Python 一致，但需回归 heartbeat 既有测试（heartbeat_ 前缀用例）确认无副作用
