## 2. TeamSessionLifecycleAdapter 装配收编（主体生产改动）

### 2.1 流程位置

它是「swarm 运行时服务层 ↔ 团队运行时」的**会话生命周期端口**团队实现（Python `jiuwenswarm/runtime/team_session_lifecycle.py`；消费方 `service.py:4023-4031` 懒构造 `_team_lifecycle()`，六消费点 L1418/1424/1512/1748/2367/3500/4069）。不在 ReAct/评审循环内部，是包在外层的会话管理面：取消/暂停/终止按代次精准停资源（防误杀新代次）、等待者摘除、暂停完成通知、代次活跃判定（能否立即终态）。

与评审链的关系：构造时注册的 `set_round_state_reporter` 把团队轮 active/idle 回写协调器——**板清 → 持久 owner 置 waiting-for-input → 作者下一次输入可恢复并经 TeamPolicyRail 自然 claim 折叠 F_119 通知**。这是折叠链的上游前置。

## 8. 装配形态勘误（2026-12-05 复核，经用户裁决全改）

实施后与用户逐层复核 Python 源码，推翻初版装配形态：

1. **两条路径勘误**：Python 团队 pause/stop 有两条独立流程——①interrupt 意图流（`agent_adapter/interface.py:3256 JiuWenClaw._process_team_interrupt`）**懒 import `get_team_manager` 直调 `pause_session_runtime`，不经 adapter**；②执行取消流（`runtime/service.py:1418/1424/1512/4069`，ExecutionCancelCause）才走 `_team_lifecycle()` 适配器。初版把 adapter 装配挂到了①，属流程挂错。
2. **D-25.3-3（factory 缝撤除）**：`SetTeamLifecycleFactory`/`team_lifecycle_wiring.go`/`team_port_assert.go` 全删；`processTeamInterrupt` 回退直调 `team.GetTeamManager` → `PauseSessionRuntime(ctx, sessionID, reason, nil)`（对齐 interface.py:3279，懒 import 的 Go 等价物=普通 import，`agent_manager.go` 证明合法）。adapter 实体（swruntime，Python runtime/team_session_lifecycle.py 一比一）保留但**暂无生产消费方**——其消费点=执行取消流的 team 分支，该分支 Go 侧缺席（coordinator.CancelExecution 无 team 分支，`cancel_session_runtime` ⤴️10.6.19-23），装配随消费点补齐批落地（⤴️25.6，与 publish_pause_completed/remove_response_waiter 同批）。
3. **D-25.3-4（port 位置，修订为部分归位）**：`SessionRuntimeLifecyclePort`+`RuntimeResourceLease` 已上移 `runtime/session_lifecycle.go`（swruntime 顶层，对齐 Python `runtime/session_lifecycle.py` 文件位置——factory 撤除后二者消费方只剩 swruntime 同包，原"server/runtime 需引用"理由失效）。**残留偏差**：`SessionDescriptor`/`SessionLifecycleTarget`/participant 三接口/事件/登记表留守 `runtime/session/session_lifecycle.go`——被 session 包内 `session_delete.go` 消费，上移将使 session → swruntime 成环（Python 靠鸭子类型/懒 import 无此约束）。Python 单文件在 Go 按依赖方向拆两半。
4. **依赖方向核对结论**：server/runtime → harness/team、harness/team → server/runtime/skill、swruntime → server/runtime 三条边 Python 全同形（service.py:92 / team_member_skill_toolkit_rail.py:20 / service.py:91），无环、无漂移，"runtime 依赖 team"本就成立。
