## 1. 定位（通俗表述）

17.4d 是单智能体自我改进链路的**疗程管理者**：17.4b 是读化验单的医生（诊断），17.4c 是外科手术团队（开单动刀），17.4d 是主治医生——安排"基线体检 → 逐轮（诊断 → 手术 → 候选模考 → 晋级门）→ 发布冠军版本"整个循环，每轮进展写成 epoch 树事件对外可见。

plugin 包（`package_type=plugin`，含 manifest.json）是**被优化的专家智能体本身**（受训者/原材料），不是评估员；评估时由 SingleHarnessExecutionBackend 绑定 DeepAgent 真正跑题，打分由 17.6 的 judger 负责。`load_plugin_package` 是"拆箱验货"（解析+校验 manifest），Go 侧复用 `internal/agentcore/harness/resources` 的 `LoadPluginPackage`。

## 3. 主循环数据流

```
IterativeSingleHarnessRequest（数据集文件 / harness 引用 / 输出目录 / AutoCoordinatingHarnessConfig）
  → load_cases 载入用例 → _validate_and_filter_planned_batches → _validate_single_harness_refs
  → _load_or_create_state（断点续跑，见 §4.1）
  → _initialize_frozen_baseline（首轮把基线 harness 复制为不可变原始版本，手术只在副本上进行）
  → 逐轮（epoch）循环：
      ① evaluation_result_analyzer 读上轮诊断件（AnalysisUnavailableError 分支：匹配重放失败后永久豁免分析）
      ② MemberOptimizer（17.4c 全套：定责/选对象/开单/动刀/验证）
      ③ TeamEvaluator 候选评估（只跑候选声称能治好的题；打分桩 ⤴️17.6）
      ④ behavior_check：候选声称改动 vs 实际观察比对 → feedback_route 决定反馈路由
      ⑤ 晋级门 promotion_policy：
         - 非回归：候选均分 ≥ 基线 − EPSILON 容差（first_improved / targets_improved / full_evaluation_decision）
         - 完整性：complete_scores 要求期望用例全有分数
         - 包指纹：package_fingerprint 校验发布包与评估时一致
      ⑥ 通过 → _persist_promotion（发布新版本 + 登记）；不通过 → 记录原因进下一轮
      （循环内 _must_preserve_budget_for_siblings 预算守护、RaiseIfCancelled 各阶段接线）
  → _refresh_optimization_experience（刷新经验账本喂下一轮）
  → IterativeSingleHarnessResult（各轮门结果 / 最佳版本 / 发布引用）
```

发布路径（iterative.py 尾段）：MemberOptimizerPathLayout 布局 + staging 目录复制 + `synchronize_plugin_manifest` + `load_plugin_package` 验货两处（staging 验收、最终发布验收），路径越界（发布目录必须仍在 run 目录内）拒绝。

continuous.go 为平行入口 `run_continuous`：不设固定轮数，逐目标改进直到达标，收尾一次独立全量评估（`_full_engineering` 判定）。

## 4. 关键设计点

### 4.1 状态持久化与断点续跑
状态 JSON 落盘（含 improver_policy 版本/digest、候选门记录、已用预算、retained case ids 等）。重启时 `_resume_fingerprint_matches` 用 `_request_fingerprint`（数据集/harness/配置 sha256 组合）核对一致性，一致续跑、不一致新开。`_result_from_state` / `_prior_eval_refs_from_state` 从状态恢复结果。

### 4.2 预算与 usage
`_must_preserve_budget_for_siblings` 多候选保留共享预算；usage 走 17.1 已落地的 `rsi/usage.go` `ModelUsageObserver` / `bind_model_usage` / `model_usage_stage`（预算属 17.6，无桩）。

### 4.3 fake 注入缝（§9 拍板）
编排器对 evaluator 的调用面收敛为 17.4f 桩的现有签名（`evaluator/team_evaluator.go`，哨兵 `ErrEvaluatorNotImplemented`）；同包测试注入 fake evaluator 驱动分支。fake 与桩一起进删除清单 ⤴️17.6 回填真身后删（规则 8，届时锚点核查）。取消桩 `RaiseIfCancelled`（runtime_cancellation.go）按 Python `_raise_if_cancelled` 调用点接线，⤴️17.7 回填后删桩。

### 4.4 epoch 树事件
events_translate.go 对齐 17.1 已落地契约（rsi/events.go：NodeStageEvent / OnEvent / emit）：root_node_event（根）、epoch_node_event / active_epoch_node_event（候选节点，`_node_id` 带 iteration 号）、parent_node_id 保证树形、progress_event / case_stage_payload / analysis_stage_payload / source_reuse_stage_payload。harness_artifacts 列发布产物。

### 4.5 依赖现状（全部已有 Go 落地）
- `LoadPluginPackage`：internal/agentcore/harness/resources（17.4c verification 已用）
- `MemberOptimizerPathLayout` / plugin_manifest / hypothesis / loader：17.4c
- `EvaluationResultAnalyzer`：17.4b
- `AutoCoordinatingHarnessConfig` / data_loader / schema / text_encoding / model_call：17.4a
- `ModelUsageObserver`：17.1
- 25.1g reliability：已完结（2026-12-02），`BuildSingleAgentReliabilityRail` 真身 + 签名收窄 `*reliability.ReliabilityRail`，无需动作

## 5. 错误处理（一比一，不新增策略）

| Python 模式 | Go 等价 |
|---|---|
| `RuntimeError`（发布越界/checkpoint 过滤非法/staging 非法等，消息文案照抄） | 同文案 `fmt.Errorf` |
| `AnalysisUnavailableError` | 同名哨兵错误，分支顺序不调换 |
| staging 失败 `except: rmtree(staging); raise` | 显式 `os.RemoveAll` + 原 error 返回（不用 defer 改变顺序） |
| `_safe_candidate_error` 候选失败截断记录 | 同函数逐字对齐 |
| `_raise_if_cancelled` 调用点 | `RaiseIfCancelled` 接线（⤴️17.7） |
| evaluator 桩 `ErrEvaluatorNotImplemented` | 桩返回；单测经 fake 注入绕过 |
