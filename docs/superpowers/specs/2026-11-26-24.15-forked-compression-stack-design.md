## 1. 背景与流程位置

上游产品路径实际使用的上下文压缩栈是 forked preset 单链：`Offloader + SessionMemoryCompressor + Dialogue/CurrentRound/RoundLevel 三压缩器`（无两分支互斥）。

触发机制（双层）：

1. **装配层（rail）**：`ContextProcessorRail`（harness/rails/context_engineer/context_processor_rail.py:482-507）在 init 时把 processors 组装进 context engine，并注册 compression_recall 工具（`_register_compression_recall_tool`，顺手加进 Offloader `protected_tool_names`）。运行期钩子**不做压缩**：
   - `before_invoke` / `on_model_exception`：`fix_incomplete_tool_context`（修复残缺 tool_call/ToolMessage 配对）
   - `before_model_call`：注入 offload section + compression_recall section（system prompt builder）
   - `after_model_call`：session memory manager 更新继承 system prompt + 异步调度 session memory 更新
   - `after_tool_call`：刷新 task state runtime
2. **执行层**：`context/context.py:604 get_context_window()` 构建窗口后遍历 processors，逐个调 `processor.trigger_get_context_window(context, window)`（context.py:638）。forked 压缩器基座在此数 token、超阈值才压缩（compressor/base.py:181-258，phase=`get_context_window`，trigger=`passive`）。`get_context_window` 是模型调用前取窗口的必经路径。

压缩语义是"归档 + 召回"闭环（非丢弃）：压缩 → recall/archive.py 归档 → reinjection 按相关性重注入窗口 + compression_recall 工具主动召回。

## 4. 关键设计裁决

1. **结构忠实（规则 9/12）**：目录层级、文件归属、方法归属、方法内步骤一比一；每处移植注释写明 Python 符号与行号。
2. **触发面不新造**：压缩本体挂在既有 `get_context_window` 等价链（trigger 被动触发），rail 钩子只做装配期注册 + 运行期 section 注入/上下文修复，不引入新的触发层。
3. **序列化（feedback-json-tag-serialization）**：compression_dump/debug 落盘一律 struct json tag 直走 encoding/json，不写包装层。
4. **测试卫生（skills /tmp 禁令）**：凡目录扫描类构造一律 `t.TempDir()`。
5. **集成测试（规则 7）**：15a/15b 各补 `tests/integration/` 用例（15a：三压缩器超阈值触发链 + reinjection 回灌；15b：offloader 占位替换 + compression_recall 工具端到端 + agent_edit notes 编辑链），静态跨度不足走覆盖交叉验证达标。
6. **删除清单（规则 8）**：`filterActiveProcessors` 旧 session_memory 分支（ToolResultBudget/MicroCompact/FullCompact 处理器）、两分支互斥逻辑、仅供旧分支使用的测试桩，同改动删除，grep 锚点为空。
7. **集成测试完成标准（规则 6/11）**：本地 build + vet + 全量回归通过即交付推送，不主动追 CI。
