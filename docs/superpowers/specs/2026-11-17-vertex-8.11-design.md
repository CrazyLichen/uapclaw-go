## 1. 背景与流程位置

Vertex 是工作流图的**节点执行器**，Pregel 子域（已收口）与 Workflow 组件层（8.13-8.26）之间的枢纽：

```
Workflow(8.14) 构图 → PregelGraph.Compile(8.1)
    → PregelLoop.RunStep(8.3c ✅)
        → TaskExecutorPool.Submit(8.3b ✅)
            → nodeTask.execute → 调用 Vertex.__call__(state, config)   ← 本节
                → AtomicInvoke(8.10 ✅) 或 call()
                    → _run_executable_with_retry（retry/timeout）
                        → Executable.OnInvoke/OnStream/OnCollect/OnTransform（8.2 ✅）
                    → stream_call（COLLECT/TRANSFORM，由 StreamActor 首帧触发 ← 8.12 ✅）
                → 返回 {"source_node_id": [node_id]} → GraphState.SourceNodeID（8.8 ✅ 首个真实消费点）
```

**双链模型**：批入侧（INVOKE/STREAM，同步链，由 Pregel 调度触发）与流入侧（COLLECT/TRANSFORM，异步链，由 StreamActor 首帧 spawn）。混合节点两半经 `_stream_done` 握手对齐后，`call()` 才 `mark_producer_done` 交屏障——屏障语义成立的前提。

**顺序不变式（本节设计基石，由引擎屏障保证）**：每轮内"流侧先动、批侧后动"——

```
第 N 轮：上游执行（产 chunk → 下游 Send → IsDone 读 / 首帧 spawn streamCall）
  ↓ wait_all 屏障（happens-before 边）
下游批侧 call() → __call__ finally（call_count++）
  ↓ 下游任务结束
上游第 N+1 轮 → 才有下一次 Send
```

推论：`_stream_called` 检查窗口内两计数器无并发写方；`IsDone()` 读与计数器写全部被屏障定序；streamDone 槽位读写亦被屏障定序（新 spawn 要求旧 task done ⟺ 当轮结果已发出 ⟺ 批侧 await 已醒）。

## 4. 并发映射设计（brainstorming 拍板汇总）

### 4.1 原语映射（零锁方案）

| Python | Go | 备注 |
|--------|----|------|
| `asyncio.Future(_stream_done)` | 每轮新建 `chan streamResult{err error}`（缓冲 1，对应 set_result 不阻塞） | 流侧 StreamCall 开头新建；批侧经 `streamCalled()` 判定后收当轮 channel 并接收 |
| `asyncio.Event`（能力级 + 外层） | `chan struct{}` + close | 两级 event 链：注册完成→能力级 e close→外层 event close→Send 启动 processor（8.12 Send 先例） |
| `asyncio.Event`（_is_started/_is_call_started） | atomic.Bool / CAS（或并入计数器组） | trace 去重，见 4.3 |
| `_call_count` / `_stream_call_count` | `atomic.Int64` 各一 | 单写方；屏障定序保证组合读正确性 |
| `asyncio.gather(return_exceptions=True)` | channel 收割 | FIRST_EXCEPTION 纪律复用 8.3b TaskExecutorPool |
| `CancelledError` 分类收割 | `context.Canceled` 分类 | 8.3b D5 同款 |
| retry `wait_for`（包协程） | `context.WithTimeout` **真取消** | 对齐 asyncio wait_for 取消语义——非偏差 |
| call() 流等待 `wait_for`（包 Future） | select + 超时分支放弃等待，流侧 goroutine 继续跑 | 见偏差 D-1 |

**零锁依据**：所有跨 goroutine 的计数器/槽位访问对均被引擎屏障定序（§1 不变式），无真实并发写窗口。计数器保留 atomic.Int64 属防御性（屏障边已保证正确性）；streamDone 为普通字段。

### 4.2 偏差表

| 编号 | Python | Go | 理由 | 回收条件 |
|------|--------|----|------|---------|
| D-1 | call() 的 `wait_for(_stream_done)` 超时 cancel 的是 Future（结果容器），streamCall 本体继续跑完 | select+超时分支仅放弃等待，流侧 goroutine 不取消 | 结构对应：被等待对象是结果容器而非任务；Python 侧 set_result 落在已取消 Future 上的边角行为不复刻 | 上游改变等待结构时重新评估 |

历史偏差修正记录：讨论过程中曾误记"retry 超时不取消底层执行"，经查证 asyncio wait_for 语义后更正——retry 超时在 Go 用 ctx 真取消，**非偏差**。

### 4.3 关键机制设计

1. **流等待判定**：`streamCalled()` = `streamCallCount == callCount + 1`（只读对账）。True → 收当轮 streamDone 接收（select + COMP_STREAM_CALL_TIMEOUT_KEY 超时 → D-1）；False → `hasStreamCall && !IsEndNode` 报 `no stream data in`；End 节点放行走 sanitize。
2. **IsDone 门卫**（StreamActor.Send 消费）：`!firstFrame || IsDone()` 决定首帧是否 spawn 新一轮；防迟到帧导致 `stream = call + 2` 永久不对账。
3. **trace 埋点合并协议**：`_is_call_started`（CAS 置位）标记批入侧已记输入；`need_send = !hasStreamCall || streamDone 已收`；流侧 finally 补发 `trace_component_stream_input({}, send=True)`（条件：无批侧 或 批侧已置位）。`_is_started` 保证 component_begin 一轮一次（CAS）。
4. **能力级握手**：每能力一个 `chan struct{}`，策略在 `_pre_stream`（注册 generator 队列）**之后** close；streamCall 循环 `await e.wait()` 逐能力放行；`runExecutable` finally 兜底 close（异常不挂死）。
5. **End 节点 sanitize**：三层递归（dict/list 双轨）→ leaf 判 None/AsyncGenerator → ref path 解析 → `executed_nodes` 已执行判定 → 流源 pending 判定（actor_manager.should_sanitize_stream_source）→ AsyncGenerator `aclose` + 置空串。Go 侧 StreamReader/异步生成器以 8.12 的 StreamReader.Next(ctx) 消费形态承载，"僵尸 generator 关闭"对应放弃消费 + 队列不再拉取。

## 6. 测试要求（讨论点逐项覆盖）

### 6.1 单元测试（vertex_test.go + 修正后 stream_actor 回归）

| 讨论点 | 用例 |
|--------|------|
| 双链握手 | 混合能力节点：批入完成 → 流入完成 → call 返回；流入先于批入（streamCalled 判定）→ 等待；流入失败（err 经 streamResult）→ call 转抛 |
| `no stream data in` 分流 | 有流能力非 End 且零流触发 → 报错；End 节点 → 放行；纯批入 → 直通 |
| IsDone 门卫 | 迟到首帧 + IsDone=true → 丢弃不 spawn；首帧 + IsDone=false → spawn |
| 两级 event 链 | 策略注册完成前外层 event 不放行；能力异常时 finally 兜底 close 不挂死 |
| retry/timeout | 超时真取消（ctx 取消传播到能力执行）；重试 N 次后成功；收割后错误恢复 trigger_until 命中/未命中/STREAM 不可恢复 |
| trace 合并协议 | 纯批入立即 send；混合节点流侧补发；component_begin 去重 |
| sanitize | 未执行分支置空串 + 僵尸流源关闭；混合 End 流源全未执行 → set_data_source_count(0)；嵌套 dict/list 递归 |
| _post_invoke | schema 双轨、None 过滤、混合 End output merge、set_outputs |
| _process_chunk 三分支 | End 非子图 writer 写入 / End 子图 sub_workflow_stream / 普通 produce first_frame |
| 计数对账 | is_done 两等式分支；stream_called 判定；reset 清零 |
| **-race 并发** | 批侧 call 与流侧 StreamCall/Send 全链并发跑 `-race`，锁定屏障定序不变式（若未来某路径破坏定序，race 当场报出）|
