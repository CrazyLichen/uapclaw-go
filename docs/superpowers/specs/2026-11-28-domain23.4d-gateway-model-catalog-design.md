## 1. 在 agent 会话链路中的流程位置与作用

23.4a-c 造好了路由引擎（intellirouter 客户端、routing 编译器、模型池/分配器）；23.4d 是把**用户在配置面板选的"模型/模型组"稳定引用**翻译成引擎输入 `ResolvedModelGroup` 的入口层。Python 侧三个会话期消费点：

1. `jiuwenswarm/runtime/session_provisioner.py:788-790` —— create/switch 会话时 `ModelSelectionResolver().restore(selection)`：目录里已删除的引用回落默认，防会话起不来。
2. `jiuwenswarm/agents/harness/team/team_manager.py:1474-1483` —— team 模式把 `ResolvedModelGroup` 喂 23.4b routing 编译器 → `CompiledModelSelection` → IntelliRouterModelClient 按路由选 deployment（Go 侧 23.4b/c 已就位，等本批输入）。
3. `jiuwenswarm/runtime/cron/cron_job_mutations.py:357-358` —— cron 任务保存时 `resolve(selection)` 准入校验（**裁决 E：⤵️ cron 章节**）。

另有 `jiuwenswarm/diagnosis/model_resolver.py`（诊断面复用 resolver）——本批不实现消费方，仅保证 resolver 符号可复用；登记 ⤵️ 诊断章节。

## 3. 核心语义（逐条对齐，实施时按符号+行号落注释）

### 3.1 ModelSelectionResolver（model_routing_registry.py）

- `Restore(selection)`：`catalog.HasSelection` 为真原样返回；否则 `Choose(nil, 空 context)` 回落。
- `Choose` 五级回退：explicit → session_selection → spec_selection → 首个 `enabled && is_default` 组 → legacy_model_name 按模型名/alias 匹配（**恰好一个**命中才用，多个跳过）→ 默认模型（无默认取列表首个）；全空抛 `MODEL_GROUP_INVALID`("no model is configured")。
- `Resolve`：model 直取 `_model`；model_group 先 can_access 权限闸 → 组 enabled → route_id 收窄（unknown/disabled 各自错误码）→ 至少一条 enabled route → 逐 route 组装 `ResolvedRoute`（request_overrides/tpm/rpm/timeout）。
- `_model`：`model_client_config` 剔除 4 保留键（model_name/client_provider/api_base/api_key）入 client_options；`request_defaults` = `build_reasoning_model_request_kwargs(...)` 后 pop "model"；无 model_name 抛 `MODEL_SELECTION_DISABLED`。
- `ModelExecutionContext`：session_selection/spec_selection/legacy_model_name/can_access 四字段（can_access 为函数注入）。

### 3.2 reasoning 两文件（裁决 A）

- `reasoning_config.go`：`NormalizeReasoningLevel` / `ReasoningConfigForLevel` / `ResolveSamplingOverride`（按 api_base+model_name 查 23.3 endpointprofiles 采样覆盖表）。
- `reasoning_injector.go`：`InjectReasoningParams`（level→reasoning 字段注入 + 采样覆盖 + pop reasoning_level）与 `BuildReasoningModelRequest_kwargs` 等价 `BuildReasoningModelRequestKwargs`（agentos 旧 `max_tokens`→`context_window` 迁移、pop model/model_name/reasoning_level/_source、context_window 归一——按 §2.1 已加字段分支不 pop）。
- `apply_provider_compat_patches`：Python 是运行时给 core 打补丁；Go 无对应物（23.3 profiles 为静态表）→ 登记**已知偏差**（平台差异，永久）。

### 3.3 ModelCatalog（model_catalog.py）

- 构造持 config 快照（`load_models_config` 等价：defaults/agentos/by_id/groups 索引）；Go 对接既有 config 体系的模型段。
- `GetModel`/`GetGroup`/`HasSelection`/`ListPublicModels`/`GetPublicModelDetail`（reasoning_level bool→"on"/"off"、write_only_fields 剔除、agentos 只读）/`ListPublicGroups`（_PUBLIC_GROUP_KEYS 白名单 + routing 三 timeout 键）/`FindReferences`/`FindEmbeddedSelections`（agents/team 配置树递归）。
- `FindReferences` 扫描面：模型组 routes → session metadata.json → cron jobs（**裁决 E：⤵️**，扫描点保留，实现为空并注释）→ agents/team 配置树；**任何扫描失败 = RUNTIME_UNAVAILABLE 不可删**（防误删语义，不得静默跳过）。

### 3.4 连通性探测（model_config_validation.py 完整版，裁决 D）

- `ModelProbeResult` / `_model_probe_output`（content/reasoning_content/usage.output_tokens 三源判有输出）/ probe 请求构建与判定，一比一移植；探测用 mock 客户端测试。
- 其余校验函数（candidate 校验、route 结构、is_default 互斥面）逐符号对齐。

### 3.5 vendor_registry（裁决 B）

- `PlanKind` 三枚举（token_plan/coding_plan/custom_api）+ `VendorPreset` 数据表 + 查询函数，数据逐条照抄（含注释里勘误过的域名）；`icon_key`/`client_provider` 契约字符串不改。
- `volcengine_endpoints` 常量（ARK_* 四个 base）随文件带入。

### 3.6 RPC 面（10 个，接线既有 web RPC 注册表）

`models.get/upsert/delete/references`、`model_groups.list/upsert/delete`、`vendors.list/fetch_models`、`session.selection.set`。payload 契约键一比一照抄上游（协议字符串不得本地化）。`session.selection.set` 落 `model_selection_store` 等价实现（session_id 白名单校验 + 路径逃逸防御 + tmp+rename + Windows sharing 重试语义按 Go 现状对齐 10.3.28a metadata 写路径）。
