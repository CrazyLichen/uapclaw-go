# 10.3.7-11 回填审查修复设计

> 修复 10.3.7-11 实现中遗留的 ⤵️ 标记和逻辑缺陷，对齐 Python 源码。

## 1. 背景

10.3.7-11（适配器辅助）已实现 CodeAgentRail、EvolutionHelpers、RecapPrompts、SysOpBuilder 等核心功能，
但审查发现 6 个遗留问题：1 个 ⤵️ 标记应回填但未回填，2 个 ⤵️ 标记指向错误章节，1 个 ⤵️ 标记混用，
1 个热重载缺陷，1 个 modelCache 传 nil。

## 2. 修复清单

### 2.1 ListAvailableTools() 动态构建工具列表

**问题**：`agent_config.go:372` 的 `⤵️ 10.3.7-11` 标记表明应从共享常量动态构建，
当前 `groups` 和 `disallowedForSubagents` 已引用共享常量，但 `tools` 切片仍硬编码 23 个 ToolInfo。

**Python 对齐**：Python `list_available_tools()` 从 3 个数据源动态构建：
- `TOOL_GROUPS`（code_agent_rail.py）→ group→display names
- `_TOOL_DISPLAY_NAMES`（tool_display.py）→ internal→display
- `_TOOL_DESCRIPTIONS`（agent_config_service.py L28-52）→ display→description

**修复方案**：
1. `types/agent_tools.go` 新增 `ToolDescriptions map[string]string`（display→description），一比一复刻 Python `_TOOL_DESCRIPTIONS`
2. `agent_config.go` `ListAvailableTools()` 改为从 `types.ToolGroups` + `displayToInternal`（反向）+ `types.ToolDescriptions` 动态构建 `tools` 列表
3. 移除 `⤵️ 10.3.7-11` 标记

**构建逻辑**（对齐 Python L351-401）：
1. 从 `displayToInternal`（display→internal）构建 `internalToDisplay`（internal→display，去重）
2. 从 `types.ToolGroups` 构建 `displayToGroup`（display→group）
3. 遍历 `internalToDisplay`，查找 group 和 description，组装 ToolInfo
4. 补充 `types.ToolGroups` 中有但 `displayToInternal` 中没有的工具（如 LSP）
5. `groups` 和 `disallowedForSubagents` 已引用共享常量，无需改动

### 2.2 CodeAgentRail 热重载不生效

**问题**：`CodeAdapter.ReloadAgentConfig` 直接委托 `c.deep.ReloadAgentConfig()`，
而 `DeepAdapter.ReloadAgentConfig` 调用的 `getCurrentAgentRails()` 不包含 CodeAgentRail，
导致配置热重载时自定义 Agent 定义不会更新。

**Python 对齐**：Python `JiuwenClawCodeAdapter` 覆写 `_get_current_agent_rails()`，
追加 `self._code_agent_rail`，使 `reload_agent_config()` 内部自动调用子类覆写版本。

**修复方案**：
`CodeAdapter.ReloadAgentConfig` 不再直接委托，改为：
1. 调用 `c.deep.ReloadAgentConfig(ctx, configBase, envOverrides)` 做基础重载
2. 如果 `c.codeAgentRail != nil`，调用 `c.codeAgentRail.Reload(agent)` 刷新自定义 Agent 定义

### 2.3 TeamHelpers ⤵️ 标记指向修正

**问题**：`deep_adapter.go:840` 的 `⤵️ 10.3.7-11 TeamHelpers` 标记不准确。
TeamHelpers 的功能（process_team_message_stream、ensure_monitor_for_active_runtime、
evolution watcher 等）全部依赖 TeamManager（9.55-9.65），应指向 9.55-9.65。

**修复方案**：将 `⤵️ 10.3.7-11` 改为 `⤵️ 9.55-9.65`。

### 2.4 取消进化监听 ⤵️ 标记指向修正

**问题**：`deep_adapter.go:1074` 的 `⤵️ 10.3.7-11 EvolutionHelpers（进化助手）: 取消进化监听任务`
与问题 2.3 同属 TeamHelpers 范畴，依赖 TeamManager，应指向 9.55-9.65。

**修复方案**：将 `⤵️ 10.3.7-11` 改为 `⤵️ 9.55-9.65`。

### 2.5 Evolution 审批处理 ⤵️ 标记统一修正

**问题**：`deep_adapter.go:1125-1131` 的三个审批处理方法标记为 `⤵️ 10.6.3-10 / 10.3.7-11`，
混用了两个章节。这三个方法都依赖 `SkillEvolutionRail`（10.6.3-10），与 10.3.7-11 无关。

**修复方案**：将 `⤵️ 10.6.3-10 / 10.3.7-11` 统一修正为 `⤵️ 10.6.3-10`。

### 2.6 AgentTool modelCache 传 nil

**问题**：`agent_tool.go:247` 的 `agentDefToSubagentConfig(agentDef, model, modelCache, nil)`
中 `modelCache` 声明为 `nil`，导致自定义 Agent 的 `model` 字段（如 `"sonnet"`）无法通过
modelCache 查找对应 Model 实例，fallback 到父 Agent 的 model。

**Python 对齐**：Python `AgentTool._create_sub_agent()` 通过
`getattr(self._parent_agent, "_model_cache", None)` 安全获取，拿不到则传 None。

**修复方案**：
1. `DeepAdapter` 添加 `ModelCache() map[string]*llm.Model` 方法，暴露已有 `modelCache` 字段
2. `AgentTool.createSubAgent()` 使用匿名接口类型断言获取 modelCache：

```go
var modelCache map[string]*llm.Model
if v, ok := t.parentAgent.(interface{ ModelCache() map[string]*llm.Model }); ok {
    modelCache = v.ModelCache()
}
spec := agentDefToSubagentConfig(agentDef, model, modelCache, nil)
```

不需要定义额外类型，一行断言+定义，对齐 Python `getattr` 的 fallback 语义。
