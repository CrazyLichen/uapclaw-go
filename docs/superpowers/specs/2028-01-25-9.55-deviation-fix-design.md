# 9.55 偏差修复设计：消除 any 循环依赖 + 去掉适配器层 + FindRails 委托

> 日期：2028-01-25
> 范围：9.55 TeamAgent 实现后的 3 项偏差修复

## 背景

9.55 实现过程中，为打破 `runner → runtime → agent → runner` 循环依赖，在 `Runner.teamRuntimeManager` 使用了 `any` 类型，并在 `agent` 包中用运行时局部接口断言访问。同时为解决窄接口与具体类型签名不匹配，引入了 `kernel_host_adapters.go` 适配器层。此外 `TeamHarness.FindRails` 用反射实现而非委托 `deepAgent.FindRailsByType`。

本设计修复这 3 项偏差。

## 设计 1：提取 `agent_teams/registry` 子包

### 目的

消除 `Runner.teamRuntimeManager any` + 运行时断言，用编译期安全的接口替代。

### 包结构

```
agent_teams/registry/
├── doc.go           # 包文档
├── interfaces.go    # PoolAccessor + PoolEntry + PoolTeamEntry 接口定义
```

### 核心接口

```go
// PoolAccessor 运行时池访问接口。
// 打破 agent ↔ runtime 循环依赖：agent 和 runtime 都依赖 registry，互不 import。
type PoolAccessor interface {
    PoolEntry() PoolEntry
}

// PoolEntry 运行时池条目访问接口。
type PoolEntry interface {
    GetEntry(teamName string) PoolTeamEntry
    RemoveEntry(teamName string)
}

// PoolTeamEntry 池中团队条目。
type PoolTeamEntry interface {
    GetSessionID() string
}
```

> **方法名说明**：`PoolEntry()` 而非 `Pool()`，因为 `TeamRuntimeManager.Pool() *TeamRuntimePool` 返回具体类型，Go 不支持协变返回类型；`GetSessionID()` 而非 `SessionID()`，因为 `ActiveTeam.SessionID string` 字段会与方法名冲突；`GetEntry()`/`RemoveEntry()` 避免与已有的 `Get()`/`Remove()` 返回类型冲突。

### 依赖方向

```
registry          ← 定义接口（无外部依赖）
  ↑      ↑
  |      |
agent   runtime    ← 都依赖 registry，互不 import
  ↑
runner            ← teamRuntimeManager 类型改为 registry.PoolAccessor
```

### 改动点

| 文件 | 改动 |
|------|------|
| `agent_teams/registry/interfaces.go` | 新增 3 个接口 |
| `agent_teams/registry/doc.go` | 新增包文档 |
| `agentcore/runner/runner.go` | `teamRuntimeManager any` → `registry.PoolAccessor`；`GetTeamRuntimeManagerAny() any` → `GetTeamRuntimeManager() registry.PoolAccessor`；`SetTeamRuntimeManager(mgr any)` → `SetTeamRuntimeManager(mgr registry.PoolAccessor)` |
| `agent_teams/runtime/manager.go` | `TeamRuntimeManager` 实现 `registry.PoolAccessor`；`TeamRuntimePool` 实现 `registry.PoolEntry`；`ActiveTeam` 实现 `registry.PoolTeamEntry` |
| `agent_teams/agent/team_agent.go` | `removeSelfFromPool` 删除局部接口定义，改用 `registry.PoolAccessor`/`PoolEntry`/`PoolTeamEntry`；将 `runner` import 替换为 `registry` import（`runnerspawn` 仍保留） |

### 编译期检查

```go
// agent_teams/runtime/pool.go 或 manager.go
var _ registry.PoolAccessor = (*TeamRuntimeManager)(nil)
var _ registry.PoolEntry = (*TeamRuntimePool)(nil)

// ActiveTeam 所在文件
var _ registry.PoolTeamEntry = (*ActiveTeam)(nil)
```

## 设计 2：去掉 `kernel_host_adapters.go`，接口签名对齐具体类型

### 目的

消除适配器层，让具体类型直接满足窄接口，用 `var _` 编译期检查。

### 原则

窄接口方法签名 **与具体类型的方法签名完全一致**，不需要任何适配。

### 接口签名调整明细

| 窄接口 | 当前签名 | 对齐后签名 | 对应具体类型 |
|--------|---------|-----------|------------|
| `SessionController.ReleaseSession` | `(ctx context.Context) error` | 保持不变 | 改 `SessionManager.ReleaseSession()` → `ReleaseSession(ctx context.Context) error` |
| `TeamBackendAccessor.DB()` | `DBAccessor` | `database.TeamDatabase` | `*tools.TeamBackend` |
| `TeamBackendAccessor.ListMembers` | `([]any, error)` | `([]*database.TeamMember, error)` | `*tools.TeamBackend` |
| `TeamBackendAccessor.CleanTeam` | `(ctx) error` | `(ctx) (bool, error)` | `*tools.TeamBackend` |
| `DBAccessor` | 整个接口 | **删除** | 直接用 `database.TeamDatabase` |
| `TeamTableAccessor` | 整个接口 | **删除** | 直接用 `database.TeamDao` |
| `MemoryAccessor.SetExtractionModel` | `(model any)` | `(model *llm.Model)` | `*memory.TeamMemoryManager` |
| `MemoryAccessor.ExtractionModel` | `() any` | `() *llm.Model` | `*memory.TeamMemoryManager` |
| `MemoryAccessor.Close` | `()` | `(ctx context.Context) error` | `*memory.TeamMemoryManager` |
| `HarnessAccessor.RegisterMemberTools` | `(MemoryAccessor)` | `(*memory.TeamMemoryManager)` | `*agentteams.TeamHarness` |
| `HarnessAccessor.InjectMemberMemory` | `(ctx, MemoryAccessor) error` | `(ctx, *memory.TeamMemoryManager, query string) error` | `*agentteams.TeamHarness` |
| `HarnessAccessor.Model` | `() any` | `() *llm.Model` | `*agentteams.TeamHarness` |

### 改动点

| 文件 | 改动 |
|------|------|
| `agent_teams/agent/kernel_host_adapters.go` | **整个文件删除** |
| `agent_teams/agent/coordination/types/lifecycle_accessors.go` | 按上表调整所有接口签名；import `database`/`memory`/`llm` |
| `agent_teams/agent/session_manager.go` | `ReleaseSession()` → `ReleaseSession(ctx context.Context) error` |
| `agent_teams/agent/team_agent.go` | KernelHost 适配方法简化：直接返回具体类型，不再包装适配器 |
| 调用 `ReleaseSession` 的所有位置 | 补充 `ctx` 参数 |

### TeamAgent KernelHost 方法简化示例

```go
// 改前（通过适配器）：

    return &sessionControllerAdapter{mgr: a.sessionManager}
}
func (a *TeamAgent) TeamBackendAccessor() types.TeamBackendAccessor {
    return &teamBackendAccessorAdapter{TeamBackend: tb}

// 改后（直接返回具体类型，编译期保证接口满足）：

    return a.sessionManager  // *SessionManager 直接满足 types.SessionController
}
func (a *TeamAgent) TeamBackendAccessor() types.TeamBackendAccessor {

```

### 编译期检查（放在 `team_agent.go` 或独立文件）

```go
var _ types.SessionController = (*SessionManager)(nil)
var _ types.TeamBackendAccessor = (*tools.TeamBackend)(nil)
var _ types.WorkspaceAccessor = (*team_workspace.TeamWorkspaceManager)(nil)
var _ types.MemoryAccessor = (*memory.TeamMemoryManager)(nil)

```

### 空值防护与 Go nil 接口陷阱

当 `SessionManager`/`TeamBackend` 等为 nil 时，TeamAgent 的 KernelHost 方法返回 nil 指针。但 **Go 中 nil `*T` 赋给接口值会产生非 nil 接口**（type!=nil, value=nil），导致 `if x == nil` 判断失败。

解决方案：KernelHost 方法在返回前检查指针是否为 nil，若为 nil 则返回显式 nil 接口值：

```go
func (a *TeamAgent) SessionController() types.SessionController {
    if a.sessionManager == nil { return nil }  // 返回 nil 接口值
    return a.sessionManager
}
```

CoordinationKernel 使用方仍需检查返回值。

## 设计 3：`TeamHarness.FindRails` 改为委托 `deepAgent.FindRailsByType`

### 目的

对齐 Python `TeamHarness.find_rails` 委托 `self._deep_agent.find_rails_by_type`，删除反射实现。

### Python 对应

```python
def find_rails(self, rail_type: type) -> list["AgentRail"]:
    return self._deep_agent.find_rails_by_type((rail_type,))
```

### 改动

**`agent_teams/harness.go`**：

```go
// 改前（反射实现）：
func (h *TeamHarness) FindRails(railType reflect.Type) []any {
    if h.rails == nil { return nil }
    v := reflect.ValueOf(h.rails).Elem()
    // ... 遍历 struct 字段
}

// 改后（委托实现）：
func (h *TeamHarness) FindRails(railType reflect.Type) []any {
    if h.deepAgent == nil { return nil }
    rails := h.deepAgent.FindRailsByType(railType)
    result := make([]any, len(rails))
    for i, r := range rails { result[i] = r }
    return result
}
```

### 改动点

| 文件 | 改动 |
|------|------|
| `agent_teams/harness.go` | `FindRails` 删除反射实现，改为委托 `h.deepAgent.FindRailsByType` |
| `agent_teams/harness_test.go` | 更新测试用例 |
