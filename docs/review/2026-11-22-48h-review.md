## 严重（4 项）

### S-1 checkpoint 保存即死锁（25.5）
`internal/openuapclaw/agent_teams/agent/team_agent.go:2228-2248`
SetCheckpoint 拿着写锁（`namedCheckpointsMu.Lock`）往下走，leader 路径里调 `mergeCheckpointsIntoSession` → `checkpointsSnapshot` 又去拿同一把锁的读锁。Go 的读写锁不可重入，同一条执行线先拿写锁再拿读锁会永远卡住。后果：leader 带着团队 session 第一次成功存 checkpoint，整个流程就挂死。测试没炸是因为用例恰好走了提前 return 的路径，没进这条线。Python 单线程没这个问题，属于移植时新引入的。

### S-2 snapshot_length 修复没修到，count 还是恒 0（25.5）
b674fdd77（补 snapshot_length 生产注入点），`agent/agent_configurator.go` 闭包里 `GetCurrentContext(ctx, "", "")` 把 contextID 传了空串。而引擎的池键是 `sessionID + "_" + contextID`，存的时候用的是 `default_context_id`，拿空串去查永远查不到，返回 0。同仓 `fork.go:97` 调同一个函数传的是 `"default_context_id"`，可以对照。提交号称修了「count 恒 0」，实际没修到。

### S-3 表达式求值器整数除零直接崩进程（8.19）
`internal/openuapclaw/workflow/condition/expression.go:1249、1254`
`//`（整除）和 `%` 没有除数是否为 0 的守卫，Python 会抛 ZeroDivisionError 被包成错误对象返回，Go 直接 panic。表达式里写 `${a} // 0` 就能把整个进程崩掉。另有连带问题：Python 整除/取模是向下取整语义（`-7 // 2 == -4`），Go 是向零截断（得 -3），负数取模结果相反，分支条件会判反，偏差也没登记。

### S-4 R-6/R-7 回填写到了死账本上，整条链空转（25.2b）
`internal/swarm/agents/harness/team/team_manager_round_state.go`（efd111b46）
回填了四个方法（RegisterSessionWaiter/SetSessionGeneration/ReportRoundState/BroadcastEvent），但全仓**没有任何生产代码调用写入这三个账本**——只有测试在写。后果：
- `IsGenerationRunning`：代次账本永远空，带代次查询恒返回 false；
- `BroadcastEvent`：等待者账本永远空，广播永远没人收（比如 pause 完成的广播）。
Python 侧这些账本由 runtime attach 路径真实写入。这正是「依赖已实现但没回填调用上游」的典型案例：方法有真身，喂它数据的管道没接。另外 BroadcastEvent 实现里完全没按代次过滤（账本里存了 waiterGenerations 但广播时不用），一旦接线，过期代次的等待者也会收到事件。

### M-2 codebuddy 首轮会话标识前后不一致（15.22）
`internal/openuapclaw/harness_providers/codebuddy/harness.go:230-234,262,305-309`

### M-3 additionalProperties 非 bool 态语义写反（8.18）
fe10b1bf4，schema_utils.go 新增段。Python pydantic 对 dict schema 的 extra="ignore" 是**静默丢弃**额外字段；Go 注释写「非 bool→ignore（放行）」但实现是**保留**进结果，把 ignore 当成了 allow。

### M-4 表达式求值器三处小语义漂移（8.19）
`expression.go`：① bool 不参与数值比较/算术（Python `True < 2` 合法，Go 直接报错），而同文件 pyEqual 又收 bool，自相矛盾；② `1e`、`1.2.3` 这类坏数字 ParseFloat 失败后静默落 0，Python 是 SyntaxError，坏表达式悄悄变假；③ 字符串字面量 Quote→Unquote 回环把 `\n` 等转义弄丢，含转义的字符串比较会判错。

### M-5 digest 的 JSON 转义与 Python 分叉（17.4e1）
`feedback_analysis.go:1483` writeJSONString 用 `json.Marshal`，Go 默认把 `<`/`>`/`&` 转成 `\u003c` 等；Python `ensure_ascii=False` 不转。账本字符串含这三个字符时 digest 与 Python 不一致。黄金样例恰好没踩到，所以逐字节对拍通过是「躲过」不是「覆盖」。应改用 `json.Encoder` + `SetEscapeHTML(false)`。

### M-6 round 半值舍入方向不一致（17.4e1）
`meta_validation.go` 的 rounded 用 `math.Round`（四舍五入远离零），Python `round(x, 12)` 是银行家舍入。落在 .5×10⁻¹² 边界时宏平均可能差 1e-12，会翻转晋升判定的阈值比较。建议登记偏差或换实现。

### M-7 描述渲染三处静默吞错（15.16e）
`desc_render.go`：① 残留 `{{` 时返回空串，Python 是抛 ValueError——本批修的就是「描述全空串」，同类问题复发时又是静默空描述且无日志；② EN 缺片段时静默回退到 CN，Python 直接报错，属未登记的多余放宽；③ 重复 desc_key 被静默覆盖（Python 抛错），目录遍历出错时整个索引清空、全部描述变空串。

### M-8 providers doc.go 文件树失真（15.16f）

### M-9 评审协调器持锁做 LLM 调用（25.2b）
`review_feedback_evolution.go:267-268` OnTeamCompleted 拿着 c.mu 走完整聚合和演化（含 LLM 调用），期间所有 HandleReviewFeedback 排队阻塞。无死锁但延迟被放大，应快照后锁外做。同族问题：`ReportRoundState`（team_manager_round_state.go:50-62）持锁调回调，将来回调若回环取锁即自锁。
