### S-2 executor 流式接线错误被静默吞掉（938b0ecad）

`internal/swarm/server/runtime/interface.go:1791-1811`：

1. `taskErr` 在主 goroutine 里**立即**读，而任务在另一个 goroutine 里稍后才写——既是数据竞争，又是死代码；`errCh` 全仓无人读。
2. coordinator 执行失败只打 Warn 日志，然后关闭输出流——调用方拿到一个"零元素的正常流"，无法区分"出错"和"正常空响应"。提交信息声称"与原路径错误 chunk 语义一致"，实际原路径是会产生错误帧的，并不一致。

同一处的连锁问题：emit 回调 `out <- chunk` 不感知 ctx 取消，若调用方超时后停止读，桥接的两层 goroutine 会永久卡死泄漏（interface.go:426/1834/1844）。

## 一般（9 项）

### M-1 RSI worker 持锁往队列发数据，队列满会拖死整个调度器
`internal/swarm/agents/harness/common/rsi/worker.go:128` 附近：`Enqueue` 拿着锁执行 `w.queue <- taskID`（容量 128）。队列满且 runner 在跑长任务时，所有走锁的路径（包括 Cancel 取消操作）全部阻塞。一次入队风暴可以让"取消"也卡住。

### M-2 RSI 事件排空忙等 + 竞态判断，可能丢尾事件
`worker.go:405-409`：`for len(queue) > 0 { time.Sleep(1ms) }` 后立刻发哨兵。若 sink 在判断后还有一次写入，哨兵先入队，消费提前退出，尾部事件丢失。取消路径是有意丢弃，但这段对正常路径也生效。

### M-3 RSI 整包用标准库 log，违反项目日志规范
worker.go、event_consumer.go 等 12 处 `log.Printf`，未按规则 3 用组件级结构化日志，异常路径缺 `event_type` 字段。线上排查无法按组件过滤。

### M-4 回合账本请求表只增不删，长驻进程无界增长
`internal/swarm/agent_teams/.../team_manager_round_state.go:481-487`：`roundEndedRequests` 全文件无 delete，每回合累积一条；旧记录还可能让归档闸门误豁免未来同名请求。

### M-5 回合账本偏差登记未销账
同文件头注释仍写"回收条件=回合账本面落地后升级"——账本已随 6395b9bbe 落地，双表也已随 089fa4df6 合并，偏差 D-25.2b-15 已回收但文档未改。后续对齐者会误判账本仍缺失。

### M-6 死 keep-alive 违反"禁止消警"规则
`team_manager_round_state.go:367`：`var _ = strings.TrimSpace`（"保留 strings 引用供后续扩展"）。规则 8 明令禁止 `_ = oldFn` 消警，应删。

### M-7 循环组件 context 断链未随本批闭合
`internal/swarm/agents/harness/common/component/flow/loop/loop_comp.go:425,453`：本批 6c19e1aa3 专门给所有组件槽补了 ModelContext 下发，但 loop 组件内部 `Compile(loopSess, nil)` 硬传 nil——正是这次改的链路里漏掉的一个消费点，循环体内 LLM 拿不到 context，enable_history 在循环场景静默失效。未登记偏差。

### M-8 技能演进 review 域读侧无锁，存在数据竞争
`internal/.../skill/evolution/review/runtime.go`：D-15.21-3 声称"mutex 保护共享状态"，但 `ResolveScope` 解锁后返回内部指针，`ResolveSelectedProposals`（:352-442）、`RecordReviewResult` 等在**无锁**状态下读同一 scope 的多个字段，而写侧（:240-263）在锁内写。并发读写同一 scope 即 data race。另外"检查-使用"非原子（:354-436 的 Submitted 校验在锁外），两路可同时通过检查绕过"一次提交"约束。测试里也没有并发用例。建议随 15.24b submission 接线一并修。

## 大白话总结

这批提交整体兑现度不错：说是修了的真修了，说是删了的真删干净了，偏差也基本都登记在案。但有三个地方要重点说：

**第一，"依赖做好了却忘了接线"是这批最集中的问题，有三处**。简单说就是：A 章节做的时候给 B 章节留了个占位符，说"B 做好了就把真的换上"；后来 B 章节确实做完了，还打了勾，但没人回头换。结果现在线上跑的还是占位符——一个是后台生成的 ID 永远是空的，一个是文章抓取默认配置下必然报错，一个是文件下载链接永远是空的。这三处都是"查一下计划表就能发现"的机械遗漏，建议尽快补上。

**第二，最新的"chat 流式接线"提交有真 bug**。它把聊天执行丢给会话队列后，错误被丢进一个没人收的通道里，调用方只会看到一个"空回答"而不知道出错了；而且读这个错误的方式本身还有并发问题。这是这次唯一一处"标题说的和实际行为不一致"的代码，优先修。

**第三，两个刚交付的大块各有需要收尾的地方**：RSI 调度器在拿锁的情况下往队列里塞任务，队列一满连"取消"操作都会卡住；技能演进的审批域加锁只盖住了写、没盖住读，并发时可能出错。另外 RSI 那一批整个用的是普通日志，没按项目规范来，以后出问题不好查。

一句话：功能都到位了，主要欠的是三处忘接线、一处吞错误的真 bug，和两处并发收尾。
